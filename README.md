| 首页与正常单 | `src/application_window.py`、`src/normal_orders.py`、`src/normal_exports.py` | 持续工作区、事务确认归档、修订审计、逐店带号导出 |

| 新品关注与模板 | `src/new_product_focus.py`、`src/new_product_focus_ui.py`、`src/normal_exports.py` | 独立导入关注、按月复用、快照冻结、模板三表全量新品候选 |

计算顺序：选择需求归属仓及对应商品资料 → 原模型 → 一箱例外 → 禁用/停采排除 → 门店总预算分配。主仓禁用、可用数≤0或无商品时转从仓；从仓无货仍保留从仓需求，不新增“仓库暂不可供”类别。细则、字段映射和交互图见`docs/0.5.0分仓需求归属.md`。兼容模式保留0.4混合资料计算入口。
AS/BV 保留计算口径；执行数量/金额受排除和预算影响。启用预算后最低持有可能暂缓，不能沿用早期脚本“有销量必定执行补货”的结论。
当前版没有改成3.5+5天，没有应用两套日均统一或安全余量2/3/4天试验。

0.6操作与边界见`docs/0.6.0作业与参数说明.md`。每日记录和用户方案是本机资料，不随Git上传；计算完成或保存作业都不会自动修改门店默认，需明确点击保存默认配置。

## 运行和构建

已有本地环境可运行 `.venv\Scripts\python.exe src\app.py`。
打包入口：`powershell -File build.ps1 -BuildId rc1`。只接受干净且已提交的源码；新建`交付_<版本>_<构建编号>`及`build_<版本>_<构建编号>`，目标存在则拒绝。不再覆盖同版本目录。
完整流程及命令见`docs/版本管理流程.md`。`assemble.py --help`列出本次发行所需明确路径；拒绝混用其他提交的验收报告。
`requirements-build.txt` 记录本机观察到的应用与构建依赖；尚未验证全新电脑能完整复现构建。

## 版本控制

源码、默认配置、图标、构建/验证脚本、第三方许可、历史源码快照、选定发行证据进入 Git。
虚拟环境、运行包、构建目录、业务输入/导出 Excel、日志、本机配置、QA临时产物不进入 Git。
发行包继续保存在各自交付目录，校验清单和版本说明保存在 `releases/<版本>/<构建编号>`；0.3历史基线直接保存在`releases/0.3.0/`。
Git 记录不能代替发行包备份；已忽略的 EXE/ZIP 不会随 Git 恢复。

基线标签采用 `v0.3.0-baseline`，表示本次接管时的源码状态与交付包校验记录，不声称进行了同环境重打包或证明源码与EXE逐字节可复现。
历史 `versions/0.1`、`versions/0.2` 保留为收到的快照，不虚构历史提交时间。
下一次修改先建立分支，例如 `git switch -c feature/holding-policy`；每次提交一个可说明的变化。
后续修复递增补丁号，新增功能递增次版本号。新版本记录规则差异、验证结果和发行包SHA256后再打标签。
本流程不修改远程配置、不自动上传；当前远程状态以`git remote`为准。默认必卖清单及验收记录含业务数据，日后共享时须确定受众。

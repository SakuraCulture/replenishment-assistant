## 实际变化

1. 历史差异新增证据所属日期、补货单号、仓、商品、环节数量；同时给出本轮观察日期和当时参数。不会把上轮的减量描述成当轮行为，历史参数不会被当前配置替代。
2. 试算同时返回原有缺口、候选后缺口、到货前风险、未知风险与新增/加剧风险；`risk_count=0` 不再缺少必要的解释背景。新增只读 `stock_diagnosis_parameters` 查询完整基线/候选参数与来源。
3. 接口 Decimal 零序列化为 `0`，其他 Decimal 使用精确十进制文本；未知仍保留 null。只改变接口表达，不改变模型值及业务指纹。
4. AI 协助提供配置/修复、后台链路检查、明确的客户端状态。保留手动配置片段与 CLI 入口。配置只更新本应用条目，备份原配置，拒绝并发覆盖或无法安全合并的内容。
5. 每个明确登记的资料环境有固定本机入口；同环境升级启用时更新接口位置，客户端重载后连接新版。错误环境与新接口版本不一致会拒绝业务调用。损坏登记可以从修复按钮恢复，不把用户卡在无法启用的状态。

模块关系和操作步骤见 `docs/0.40.0AI口径与本机连接.md`。

## 换机与日常使用

在目标电脑完整解压本包 → 打开补货助手 → AI 协助 → 选择 Codex/WorkBuddy → 配置/修复本机连接 → 客户端重新加载、首次信任 → 检查本机连接 → 重新复制当前业务提示词。

绝对路径仍存在，因为客户端必须定位本机程序；现在由软件维护，不要求业务手工修改。新电脑必须本地配置一次。不能把旧电脑的会话文件、密钥、浏览器登录态或本机登记直接当成新电脑的有效连接。资料目录改变也要重新明确绑定，不猜“最近更新的库”。已运行的旧客户端进程不会在业务请求中途热切换。

WorkBuddy 本机实测中，仅改配置文件不会立即重载；在其自定义连接器重新打开配置并保存后加载，首次信任由人员完成。软件提示的“客户端重新加载”不是多余步骤。链路检查通过和 AI 已完成业务是两种状态，不能混称。

## 实际 AI 验收

Codex 三项自然语言验收通过：漏斗用时113.360秒，多轮复盘106.234秒，双店诊断155.468秒。日期、历史/当前参数、未知/零、原有4条/新增0条风险、理论货值与实际执行资金均说明正确，并读取了两个候选完整参数。其导出选择商品明细层级，5张表、440单元格与原生同层级导出严格一致，回答列明范围。

WorkBuddy 5.9.3（快速 GLM-5.3-Flash）实际处理5分34秒，22次工具调用，三项任务执行及数值/导出通过；综合8张表、2,390单元格与原生导出严格一致。但是**最终自然语言解释未全部通过**：

- “两店一致”表格使用每店10元，却混入两店合计4条缺口，还把箱规覆盖与缺口商品数合并命名；实际为每店2条、合计4条。
- “11-01足额履约仍缺货”的时间关系表述过强；缺货是签发时观察，不能凭之后的收货数量认定该轮足额到货后仍缺货。虽然同文提示实际到货时间缺失，这句话仍不合格。
- 已读取逐商品资料，但最终省略逐商品完整对比、到货前缺口和每店覆盖天数。

本轮新增的日期与风险字段在两个客户端都正常返回；WorkBuddy正确归属了10-29减量，也没有再把新增风险0等同于没有原有缺口。上述剩余问题是模型解释和完整性限制，不能宣称“所有AI回答已修好”。本版可试用连接维护与数据契约，业务采用仍需看原生对照。没有为迎合AI回答修改模型或旧业务预期。

52次工具调用均无直接接口异常；另记录一次Codex的历史查询异步失败：S2没有历史签发，之后仅核对S1并明确S2不可归因。两客户端均未采用试算。正式业务表摘要与当前作业快照不变；仅隔离AI任务/事件日志增加。WorkBuddy原配置已按字节恢复，临时后端已关闭；测试会话和客户端信任缓存未删除，客户端需重新加载配置清除内存中旧列表。

实际工具调用、输入提示词、最终回答和导出物按明确白名单保存于 `合成AI验收证据.zip`。不包含客户端原配置备份、连接密钥、登录态或日常业务库。客户端恢复结果见 `客户端恢复核验.json`。

## 复跑

在项目根目录，使用已有锁定环境；每次输出路径必须是新目录。

```powershell
.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p test_ai_contract_portability.py -v
.venv\Scripts\python.exe -X utf8 tools/verify_ai_portability_0400.py --out qa/0400_复跑对照
.venv\Scripts\python.exe -X utf8 tools/verify_ai_portability_exe.py --exe "交付_0.40.0_rc2/补货助手/补货助手.exe" --out qa/0400_复跑EXE
```

真实客户端验证需保持第一个终端运行，使用完全合成的独立工作台：

```powershell
.venv\Scripts\python.exe -X utf8 tools/serve_analytics_ai_acceptance.py --out qa/0400_复跑AI/workspace --bridge-exe "交付_0.40.0_rc2/补货助手/AI接口/补货助手AI接口.exe"
.venv\Scripts\python.exe -X utf8 tools/verify_codex_natural.py --workspace qa/0400_复跑AI/workspace --out qa/0400_复跑AI/codex --cases funnel,history,diagnosis
```

WorkBuddy 临时配置使用新工作台生成的 `clients.json`，明确启用并信任，输入相应业务提示词。测试后恢复原配置，建立工作台目录下的 `stop` 文件，等待 `final.json` 生成，再执行：

```powershell
.venv\Scripts\python.exe -X utf8 tools/verify_ai_contract_artifacts.py --workspace qa/0400_复跑AI/workspace --out qa/0400_复跑AI/核验
```

自然语言结论须另行复核，执行进程返回0不等于回答通过。`tools/seal_ai_portability.py` 固定核对本轮构建、测试、哈希、实际产物和客户端恢复后，才生成新的封存目录和ZIP；不推送或发布。

## 限制

- 新增验证使用合成数据；不是客户全部真实历史的质量验收，也不是资金节省或缺货率改善证明。
- 模型自然语言一次通过不代表以后不会误解；采用候选仍由人员明确确认。没有开放自动调参、采购或签发权限。
- 未在另一台物理电脑重新验收；本机测试覆盖不同目录/资料环境、升级移动和实际启动器。新机器的客户端安装、信任及登录仍需本机完成。
- TOML特殊复杂写法无法安全合并时拒绝覆盖，保留手动导出配置的入口。
- 没有重跑真实平台取数、跨平台采购或整夜定时作业。本轮没有修改这些链路。

# 补货助手 0.7.3 rc1 交付与性能报告

这是一份独立候选试用包，旧 0.7.2 和原数据保留。原五店完整作业流程与 25 文件检查/计算/浏览压力测试已通过；**不宣称任意规模全程零停顿**，已测得的限制见下文。

## 本次交付

1. 商品与新品明细按需显示，原生 Qt 排序/筛选，复用已有全行统计；原排序决胜和隐藏选择保持。
2. 大作业读取、保存前核对、签发及确认单导出由独立进程处理，分块传输完整数据；保留原每日存储、事务和修订检查。支持读取取消、关闭回收、失败后重试。
3. 完成固定基线逐字段对照、真实数据压力、三轮交替性能测量及 6 组实际 EXE 验收。沿用 0.7.2 的历史派生索引和后台查询并再次验收。

按本轮额外明确要求，禁用/停采在工作商品、新品选择及商品 Excel 中排除。原始计算与归档完整行不删；导出剩余商品的列、值、类型、顺序、样式和批注不变。内部“已排除”页保留表头，已知排除商品的必卖匹配/冲突明细同步过滤。原文件行数与去重数仍是实际导入审计数量。历史 JSON 审计仍完整，不作为门店商品单使用。只有已被排除的新品时，不再要求为它们补关注清单。

每日 SQLite / JSON / zlib 结构未变。原模型、一箱例外、预算、仓路由及默认参数源码未改；模型版本仍 0.3.0-rules，归属版本 0.5.0，作业与参数格式仍 1。没有采用 3.5+5 天、统一日均、安全天数试验或并行导出。

## 提速效果

同一电脑、同一 Python/依赖/真实快照；顺序为旧/新、新/旧、旧/新，逐个运行。下表为三次中位数（最小–最大），单位秒。Qt 源码测量包括建表、显示、筛选、排序和统计完成；EXE 的操作验证单独列出。操作系统文件缓存未清空。较早有任务重叠的诊断测量未进入下表。

代表门店 ZYD20251112：原始 23,579 行，工作范围 19,138 行，新品候选 12,884 行。新旧界面使用同一有效范围，避免把筛掉商品冒充提速。

| 操作 | 0.7.2 | 0.7.3 | 耗时减少 |
|---|---:|---:|---:|
| 首次打开商品 | 0.435（0.433–0.436） | 0.258（0.251–0.263） | 40.7% |
| 切换全部商品 | 1.167（1.163–1.212） | 0.281（0.276–0.283） | 75.9% |
| 清空搜索 | 1.291（1.277–1.301） | 0.287（0.282–0.292） | 77.8% |
| 按月销排序 | 0.869（0.857–0.878） | 0.058（0.056–0.059） | 93.4% |
| 打开新品选择 | 1.239（1.217–1.250） | 0.108（0.108–0.109） | 91.3% |

逐店原始数据见 ui_performance.json。不是每个动作都加速：CXTBLD20251127 首次打开商品中位数 0.258 → 0.387 秒；其切换全部、清空搜索、排序仍明显加速。SJHXD20260918 打开 12,971 个新品候选约 1.205 → 0.412 秒。

完整五店日作业共 84,693 行，规范 JSON 约 970MB：

| 指标 | 0.7.2 | 0.7.3 |
|---|---:|---:|
| 读取加恢复总耗时，秒 | 27.267（27.083–27.820） | 17.590（17.486–18.547） |
| 读取阶段，秒 | 10.877（10.641–10.993） | 17.547（17.442–18.503） |

总耗时减少约 35.5%。读取本身因进程启动和完整数据传输而变慢；移除界面上的大拷贝后，恢复阶段缩短到约 0.044 秒。所有完整快照规范摘要均为 `259fdb898581603ea1048cbfdded14fbeda2ecedd8425587cfcddecd604654ad`。

内存没有普遍下降：商品/新品测试峰值中位数 1459.9 → 1449.7 MiB；日作业读取/恢复约增加 1%。日作业由外部监督进程每 50ms 汇总主进程及其子进程 RSS，跨进程共享页会重复计入；界面响应由 25ms Qt 定时器记录。UI 组件测试用 50ms 采样线程，同样统计进程树。峰值不等于电脑全局实际新增物理占用。

## 实际 EXE 五店完整作业

实际冻结 EXE 使用独立数据库副本和数据目录，全部操作通过。下列是单次真实流程时间，不冒充三轮 EXE 对比：

| 操作 | 完成耗时（秒） | 最长界面响应间隔（秒） |
|---|---:|---:|
| 读取原作业 | 21.47 | 0.48 |
| 恢复到工作页 | 0.07 | 0.07 |
| 复制配置 | 15.42 | 0.07 |
| 保存完整作业 | 42.93 | 0.22 |
| 核对后取消覆盖 | 27.50 | 0.09 |
| 正常单确认归档 | 72.20 | 0.13 |
| 五店确认单导出 | 51.19 | 0.09 |
| 连续操作后再次读取 | 19.55 | 1.26 |

本轮完整 EXE 流程采样峰值 9774.4 MiB（约 9.55 GiB），无遗留子进程。保留完整快照格式意味着保存、签发仍需几十秒；进度界面可响应不代表数据操作已瞬间完成。确认差异超过 120,000 字符时明确提示并可导出完整 JSON，归档没有截断。

验收还包括：取消读取后重试；覆盖默认取消且原修订/摘要不变；独立写入冲突被拒绝；事务失败回滚；导出取消后保留已归档修订并可重试；真实文件对话框、门店全选/部分选择、4 槽自动补第 5 家；新品选择/预算预览取消与应用；参数默认复用、单店失效、历史只读；历史 23,579 行明细连续打开关闭 20 次、搜索/日志导出、读取进程异常后重启。6 组 EXE 报告及截图保留在 QA 目录。

## 25 文件压力与剩余限制

25 个真实输入文件共 390,433 行，完整检查、4 槽连续计算、逐店商品/新品浏览均通过；来源、文件/行顺序和全部逐商品计算字段对照固定基线为 0 差异。原五店沿用冻结的门店参数；额外实体明确使用 QA 标准方案、不限预算、同一主仓，不把测试设置当成它们的正式经营配置。

EXE 检查 117.80 秒，计算 64.49 秒。最大界面响应间隔 2.91 秒；首个新品窗口约 1.87 秒，其余商品/新品动作以完整 pressure_ui.json 为准。工作阶段加取证采样最大进程树 RSS 8040.2 MiB。

GC 事件记录确认了全堆垃圾回收的影响：源码压力计算阶段一次 2.93 秒；EXE 首个新品窗口的回收约 1.77 秒。没有通过禁用垃圾回收或改变业务值来掩盖停顿。**25 文件极限场景尚未达到全程亚秒响应。** 更大规模的完整日作业保存没有验收；保存/签发/恢复的全链路压力以原五店完整快照为准。进一步降低大批次停顿需要减少主进程持有的 Python 对象或进一步隔离计算编排，本次未展开该架构调整，也未改变每日存储。

## 等价性证据

- 固定基线 `84a0671bd81daa8c2e94a8648c2332b9fc8fa2a9`（0.7.2），独立归档源码。
- 33 组场景：单/多文件、不同顺序、重复/冲突、混合错误、双仓及真实 14,244 行预算场景，逐字段值/类型/字典和列表顺序 0 差异。真实汇总仍为不限预算 430 款/12,268.87 元；0 元预算 0；3,000 元 88 款/2,999.87 元；5,000 元 115 款/4,999.98 元；10,000 元 390 款/9,980.33 元；关闭一箱例外 422 款/11,890.07 元。这些汇总仅作辅助校验。
- 25 实体全量源码及冻结 EXE 都与独立基线逐店比对，入库检查/来源签名及所有业务行对照 0 差异，不按商品键重新排序掩盖顺序。
- 商品视图 2,330,867 次、新品视图 512,866 次检查通过。5 店实际门店单、内部报表及合成批次报表，在明确过滤的范围之外，工作表/列/单元格值和类型/样式/批注 0 差异。
- 白名单限于 loaded.loaded_at、result.created、result.task 的 pid/started/finished，以及 result.version 中 version/source_commit/build_id/built_at 的非业务构建字段（含源码与冻结环境 built_at 是否存在）。没有忽略整个元数据、扩大浮点容差或改旧预期。
- 初次未固定 Python 哈希种子时，原引擎对未知分类 set 补默认映射造成两处字典插入顺序不同，商品结果一致。该既有代码未改；双方固定同一 PYTHONHASHSEED=0 独立重跑后严格顺序一致，原失败日志保留。
- 原始 25 个 Excel、旧 0.7.2 EXE/ZIP、日常用户数据库校验值未变。测试均在独立目录，未写日常配置。

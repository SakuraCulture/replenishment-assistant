# 补货助手 0.50.1 rc1 交付报告

交付日期：2026-11-10。仅本地提交、打包，未推送、未合并。

## 结果与使用

翱象连接使用选定 Edge 用户配置中实际登录的身份，不要求用户填写平台账号 ID，也不再要求当前登录与旧的“账号 ID＋商家编码”固定配对才能连接。同一商家换登录人自动识别，复用全局组件和原浏览器用户配置，保留门店对应。

完整解压 `交付_0.50.1_rc1/补货助手_0.50.1_rc1.zip`，使用其中的 `补货助手/补货助手.exe`。沿用原 Windows 用户的本机配置，无需初始化数据。正常启动自动核验；应用已打开时，可在“连接检查 / 修复”重新检查。新采集、缺货率采集、新采购预览及定时补货新采集也会读取当前登录。

若实际切换了商家，连接仍可接通，但旧商家门店对应暂停使用；到“翱象连接与门店配置”核验当前商家的门店后保存。旧目录保留供核对，不能直接当成新商家已核验的门店。

## 已定位的问题与改动

原 `MachineSetup` 把保存的 `tenantBinding` 传给连接／重新核验，并在返回身份不一致时拒绝；失败后的释放流程会使连接退出，产生“浏览器打开后又断开”的表现。代码比较的是 `accountId` 与 `merchantCode`，本来就没有比较操作人 `userId`。因此，本次确认的是这条固定身份限制及其释放路径，未获取现场响应，不能断言那台电脑具体哪个字段发生变化。

- 增加独立的当前登录观察调用，复用同一浏览器工作进程和页面；启动及新业务入口先读取实际身份。
- 自动观察到的身份资料通过现有配置双文件恢复机制和并发校验更新；不覆盖同时发生的其他配置修改。身份不变时不重写配置。
- 同商家换人保留原门店；换商家不沿用旧门店有效性。配置窗口显示当前连接与需要执行的门店核验步骤，关闭窗口继续保留共享连接。
- 新采购预览不复用旧账号的模板；批量准备与单单准备均能获取当前身份的模板。
- 原采购、导出和收货任务保留原身份、任务号、回执和冻结依据；不通过修改历史身份让未知请求重新提交。
- 同商家、同一张本地订单的采集／采购防重跨登录人保留；采购结果未知时也不能换号重传。不同日期的新订单按自己的订单号处理。
- 更新旧采购身份不一致的业务提示，说明这是原任务归属核验，不再误导为“需要手填账号 ID 或重新配置连接”。同步随包说明和离线 HTML 手册。

连接观察、原任务身份校验分开实现；没有全局放宽 `sameIdentity`。平台登录响应内部一致性、门店编码、原生任务及逐商品核验继续保留。

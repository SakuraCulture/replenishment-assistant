# 补货助手 0.50.1 rc2 交付报告

交付日期：2026-11-10。仅本地提交、打包，未推送、未合并。

## 结果与使用

修复 0.50.1 rc1 的缺货率分析桥接缺陷：新增的"读取当前 Edge 登录"调用不在分析模块操作白名单内，采集在登录核验前被自行拦截，界面显示"分析不允许该翱象操作"。本版把 `setup.check_login`（登录核验）、`setup.status`（状态查询）、`setup.cancel`（取消）加入 `stockout_task.Bridge.AX_ACTIONS`，并在源码冒烟中固化桥接断言。只放行这三个登录动作；`setup.start`、采购、收货、绑定等其他业务动作仍被分析侧拦截，原任务身份核验与防重保护不变。

完整解压 `交付_0.50.1_rc2/补货助手_0.50.1_rc2.zip`，使用其中的 `补货助手/补货助手.exe`。沿用原 Windows 用户的本机配置，无需重新配置账号或初始化数据。rc1 的其余能力（跟随当前 Edge 登录、同商家换登录人复用连接、门店对应保留）与使用边界不变，见 [0.50.1 当前 Edge 登录与共享连接](../../docs/0.50.1当前Edge登录与共享连接.md) 与 [rc1 交付报告](../rc1/交付报告.md)。

## 已定位的问题与改动

rc1 将采集入口改为先调用 `aoxiang_current_login.current_configuration` 读取当前登录，但缺货率分析的桥接白名单未同步纳入该调用链的三个 setup 动作。此前测试分别覆盖了登录读取与缺货率分析本身，漏测了两者之间的桥接；属验证覆盖缺口，非模型或资料问题。

改动（固定源码 `b91c9d0`）：

- `src/stockout_task.py`：`AX_ACTIONS` 增加 `setup.check_login`、`setup.status`、`setup.cancel`；未放宽 `sameIdentity` 或其他身份核验。
- `tests/test_stockout_login_bridge.py`（新增，4 项）：生产白名单下转发当前登录与轮询并复用同一租约、取消路径不进入导出、登录失败保持失败且不上派发、仅三个登录动作放行而其余业务动作仍被拦截。
- `src/stockout_smoke.py`：离线冒烟中接入登录传输桩，断言生产桥接在原生导出前完成 `setup.check_login`/`setup.status` 转发。

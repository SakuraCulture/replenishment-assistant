# 0.46.3 rc1 交付报告

已修复采购已受理后的批次恢复误判。平台处理中单列为“已受理，等待核对”；继续操作会重新读取原任务，核验已有采购并关联，不重新上传。报错提供具体原因、影响及下一步，原始信息保留在技术详情。

## 本次修复

| 问题 | 原因与修复后行为 |
| --- | --- |
| 平台已经创建，本地却提示没有任务号 | 组件公开接口返回 `taskId`，批次错误读取内部 `receipt`。已按实际接口修正；有任务号继续核对，已有 BOUND 关联直接更新原批次。 |
| 第一次未完成就显示失败，重试不能识别结果 | 对已知原任务短时继续查询；等待后仍未就绪单列“已受理待核对”。“继续核对未完成采购”覆盖旧版本误标的 REVIEW 项，成功同批项不重跑。真正无回执或多个回执仍保护重复上传。 |
| 异常说明无法定位原因 | 采购说明区分平台处理中、原任务暂未找到、部分成功、账号问题及缺少回执，并给出处理入口。技术错误码折叠保存。 |
| 试算只报 `rows` 不一致 | 保持完整基线比较，说明首处差异的门店/商品、业务字段、原值与重算值；跨天在试算前说明日期及继续路径。 |
| 未签发旧草稿却提示去历史重导 | 区分旧日期未签发草稿与已有签发版本，明确转入今日草稿、核对输入并重算的路径。旧日期新增签发限制不变。 |

等待预算为 30 秒、重查间隔 3 秒，仅约束后续重查；当前已开始的核对动作会安全返回，不声称整个步骤必在 30 秒内结束。停止等待保留原任务身份。

本次初始只读诊断确认 6 笔任务均有受理回执，5 笔停留在等待后续核对；用户截图显示平台单已创建。此次修复没有重传、提交、审核、撤销或修改这些真实订单，也没有直接写入真实关联结果。升级后应在原批次点击“继续核对未完成采购”，由既有服务核验原任务及逐商品明细后关联。

# 0.47.2 rc2 启动自动连接与登录核验交付报告

日期：2026-11-07。本版将连接检查纳入正常应用启动，手动入口保留用于自动检查未完成后的调试。仅本地修改、隔离验证和独立交付；没有连接真实平台执行验证，没有更新真实业务库、真实浏览器设置或平台单据，没有推送、合并。

完整解压[0.47.2运行包](../../../交付_0.47.2_rc2/补货助手_0.47.2_rc2_启动自动连接.zip)，正常退出旧版后运行[补货助手.exe](../../../交付_0.47.2_rc2/补货助手/补货助手.exe)。保留完整目录；不需要手动点击连接。底部显示逐平台状态，异常时进入“连接检查 / 修复”。[使用方式与首次配置边界](../../../docs/0.47.2启动自动连接与登录核验.md)

## 实际发现

1. 0.47.1 启动只有连接状态观察器，明确不主动连接、不核验登录。原绿灯仅反映浏览器连接存活；这与用户要求的“启动即自动接通，手动只用于调试”不一致。本机只读检查确认已有翱象绑定与21家核验门店，聚水潭两仓均有启用绑定；不需要通过重新创建绑定解决日常连接。
2. 翱象连接复用原来只检查执行器是否退出和过去是否成功连接。浏览器或作业页断开后，执行器仍可存活，旧成功记录可能继续被借用。新增断开状态检查，登录复验和正常业务连接都不会继续复用明确断开的连接。
3. 原登录失败清理会关闭组件拥有的作业页。启动只读登录检查遇到需要登录时，现在保留并显示该页面，之后在同一连接上复核；错误账号仍拒绝采用，原绑定不变。
4. 连接状态栏有不受窗口生命周期管理的零延时回调，可能在 QLabel 已销毁后到达。改用窗口所有的定时器，并在更新前检查控件有效性；增加销毁后回调回归。

未在用户真实平台现场重现本次“登录检核坏了”的具体错误，因此不能断言用户当时只遇到第2项问题。上述均有当前源码、确定性测试或历史回归日志依据。

## 实现与边界

- 正常启动后，翱象与聚水潭在两个独立后台检查流程中执行。聚水潭按仓分别核验，一仓未登录仍检查另一仓；主窗口继续响应。
- 翱象新增只检查原浏览器和商家身份的请求，不扫描已配置的所有门店、不检查或创建导出目录、不保存新门店映射。首次从未建立商家与门店绑定时提示完成业务配置，不猜归属。
- 聚水潭新增“确保本仓连接”动作：已有手动或自动绑定原样复用，不自动迁移目录、不改变绑定版本、不重新启用停用账号。未配置仓自动准备独立浏览器，登录身份核验通过后保存；两仓同账号仍拒绝。
- 登录过期显示“需要登录”，每15秒自动复核，最长5分钟；超过等待时间明确提示手动重新检查。账号不符和配置异常不循环重绑。浏览器原生授权、网站登录及验证码仍需正常完成。
- 状态栏显示最近一次登录核验与时间。仅有健康浏览器连接不能获得“登录已核验”状态；旧连接回复不能给新连接或断开的连接显示该状态。后续业务仍按原规则检查身份和范围。
- 复用原会话所有者与独占操作权。原业务已占用时自动检查等待；人工业务、缺货率采集请求连接时自动检查安全让行；不会取消他人的业务任务。关闭应用先协作结束检查，再关闭组件连接，不强杀提交，不关闭用户整个浏览器。
- 启动不发起采集、导出、采购或仓资料采用，不创建缺货率数据库、不加载其事实表或页面。没有更改模型、预算、箱规、默认参数、归属及存储格式。

主改动为 `browser_startup.py`、`browser_startup_ui.py`、启动入口与连接状态栏；组件增加只读登录检查与既有绑定复用，业务入口只增加对启动检查的安全让行。仍使用模型 `0.3.4-rules`、仓归属 `0.5.2`、参数/作业/存储版本 `3/1/2`。0.47.1 的批量导出及原件重复表头修复保留。

## 保留的复现与限制

复查启动与定时任务的交接时，新增确定性用例复现：两仓已连接而翱象仍在检查时，定时调度未识别剩余启动操作，可能尝试争用会话。原有1134项回归曾通过，但未覆盖这个时序；没有以此认定完备。补充调度等待条件、专门回归和实际窗口断言，重新固定构建rc2并验证。rc1构建及原QA保留，最终交付仅引用rc2。[修复前失败证据](scheduled-gate-reproduction.txt)

## 限制与审计记录

- 本轮没有实际接管用户浏览器、点击授权或登录平台。首次真实升级的账号登录、浏览器策略与网络仍需实际使用验证；不能承诺跳过浏览器原生许可或验证码。
- 首次未建立的翱象商家与门店业务绑定仍需配置；程序不会为追求自动化猜测公司、门店或跨仓账号关系。手动配置入口仅在需要时使用。
- 新增启动时尝试打开所需浏览器的开销；未做低配置业务机、整机峰值资源、长时间休眠恢复或连续无人值守验收。没有性能数字或平台提速承诺。
- 不重测历史库删除性能；本轮的删除EXE验证只证明隔离功能流程。此前性能与失败记录保留在对应版本报告。
- 原始QA结果保留于 `qa/startup_connections_0472/`，正式发行证据仅引用最终代码的验证。没有以修改业务预期或跳过完整性核验换取通过。

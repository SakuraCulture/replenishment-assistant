# 0.7.0 rc3 交付与验收

本轮完成首页、持续工作区、历史正常单查询/日志、正常单确认后自动归档、带号门店模板导出、新品选择和共享预算，以及用户追加的独立新品关注清单。本轮不实现外部加盟商确认、实际下单和收货资料的历史关联。

## 版本和使用

- 分支：`feature/normal-orders-new-products`，没有自动合并或推送。
- 固定整理前基线：`a4176229182079bd4d886fa44e54798f6c218cee`，运行逻辑为已验收0.6.2。
- 构建提交：`72620bbebad0965e1c5fd5ac59c2256d2853647d`。应用0.7.0；模型仍0.3.0-rules；需求归属仍0.5.0。
- 本次可试用包：`交付_0.7.0_rc3/补货助手/补货助手.exe`。请保留整个文件夹中的 `_internal`，不能只拷贝EXE。
- 先在准备数据页导入补货建议和仓资料，再另导入新品明细，选择月份、商品编码列和关注列。无关注时明确选择“本月无关注新品”。随后计算、选新品、预览预算、确认归档、导出。关注清单保存复用；历史作业恢复使用当时清单。
- 同日每店一个正常单号，再次确认变化生成同号新修订；弹窗默认取消。普通保存草稿不等于签发。改参数或关注清单后需重新确认，旧修订不变。
- 本轮rc1出现Qt退出崩溃，未通过；已在后续构建修正。rc2被用户随后补充的空白缺货天数/关注清单/模板要求取代，不作为本轮最终试用包。旧0.6.2发行包保留。

## 业务和导出

- 新品识别：月销、可用、在途为有效数字0；缺货天数0或空白。原始空白保持空白，识别审计注明按0处理；其他缺失值不补造0。
- 新品默认不选。选中量为最小出库单位倍数；必卖新品参加原总预算分配，优先于普通动销；预算不足可能让旧商品最低持有暂缓，预览列明变化。
- 关注只决定本月/往期分组，不等于必卖、不自动选品。按商品编码精确关联，同编码关注冲突或未知关注值拒绝导入；原清单保留。跨月需换清单或明确无关注。
- 文件名 `YYYY-MM-DD门店名称（精简版）(修订整数).xlsx`。表顺序：往期新品、本月新品、中心仓动销补货清单。三表互不重复；新品候选全量导出，未安排量0，非新品的自动执行明细进入动销清单。
- 模板前20列、字体/格式、默认列宽/行高保持；数量来自当前冻结执行结果，价格来自基本售价，不采用模板中的旧新品公式。未知黑名单状态保持“未提供”，不虚构“通过”。
- 隐藏U:AB保留单号、修订、明细ID、签发原数、识别依据、分组依据、关注版本、安排说明；A1批注和打印页眉也带号。Q列供门店调整，0仅是未安排，不代表加盟商已确认取消；本版尚未读取回传。
- 正式导出不受临时筛选影响，不覆盖同名文件。禁用/停采、地采、缺价等新品候选仍列出但不可追加首铺；待核/排除信息保留在批注和追溯列。

## 已知限制

- 外部加盟商确认、下单、收货历史表的导入归档关联仍后续单独做；现在没有自动回传、发消息或实际下单。
- 日志页覆盖正常单签发、修订、正式导出，不是所有系统操作的事件分析平台。
- 当前只维护一份可复用默认关注清单；历史清单在草稿/签发修订里保留，不是独立跨月清单管理中心。首行须为表头，支持xlsx。
- 按用户模板保留窄列，长名称/编码显示可能被截断，可在Excel中拉宽；文本编码实际值保留。隐藏列用于追溯，不是防篡改或加密机制。
- 0.7可读取旧草稿；含新品执行量或关注快照的新草稿应继续在0.7使用，不应让旧程序交替编辑。同日草稿覆盖只保留最新，但正常单已签发修订及完整来源工作快照另存不丢。
- 只验证本机Windows及现有Python/Qt环境，未验证其他电脑或逐字节可复现构建。大历史库的长期查询性能尚未做容量测试。

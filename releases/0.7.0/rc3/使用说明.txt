补货助手 0.6.2 · 并行文件检查版 · Windows 64位试用版

本次0.6.2优化“检查文件”：单文件仍直接读取；多个文件最多2个读取进程。按原文件列表顺序归集，计算规则和数据格式不变。
读取并行数固定为2，与“同时计算门店数”无关。取消或关闭后停止提交新文件，等待最多2个在读文件结束并回收进程，再返回；不会强制终止文件读取。
具体验收范围及限制见随包验收记录；版本信息保存构建源码提交。

沿用0.6.0的作业与参数功能：
• 顶部“保存作业”：按中国标准时间一天一份，保存当前全部门店及状态，不受搜索/勾选范围影响。同日已有记录必须确认覆盖；减少的门店与失效结果会明确提示。取消保留原记录；失败不会损坏原记录。
• “作业记录”：当天可继续，过去日期只读；可导出有效结果。恢复使用当时数据和参数，不自动替换最新资料。已检查数据固化后原Excel移走仍可查看/重算；未检查的文件引用仍需原文件。“复制配置用于今日”需重新添加今天数据。
• “参数方案”：内置完整标准方案，可复制另存及保存新版本。每项超参有中文说明、影响和调整建议；旧版本不被新版本追溯修改。自定义方案须试算判断业务效果。
• 门店参数包含完整超参、分类权重和映射、仓周期、一箱例外。备货/到货请到“各仓周期”页改；通用depth/lead和极端缺货30天只读；w3自动计算。“与当前配置试算”不改变正式结果。
• “仅用于本次”与“保存为本店默认”分开。主表“保存所选门店为默认配置”同时保存参数、主从仓、预算。计算或保存作业不会自动改写默认；重启后复用明确保存的配置。原预算/主从仓文件保留作为迁移回退。
• 数据和参数变化后结果需重算；作业状态显示是否有未保存变更。跨午夜保存会核对日期；关闭未保存作业会询问。每日记录和用户方案只存本机，不上传云仓库。

一、启动
完整解压对应版本的ZIP，进入“补货助手”文件夹，双击“补货助手.exe”。版本与构建编号见“版本信息.json”和界面“版本信息”。
无需安装 Python 或 Excel；本地离线计算。
请保留旁边的 _internal 文件夹，不能只把 exe 单独拿走。

二、第一次试用
1. 准备数据：添加一个或多个补货建议Excel；每个文件可以含一家或多家店。在“河北仓”和“山东仓”卡片分别导入该仓商品资料；表内不需仓库标识，务必选对入口。资料保存为本机快照，后续复用不依赖原Excel；库存变化后需重新导入。可只维护一家仓。点击“检查文件”。旧混合资料可勾选兼容0.4模式，此时不启用主从仓。
2. 查看文件读取状态。一致重复自动去重；同店同商品内容不同，点击“处理重复冲突”，查看差异并选择保留来源。不直接相加库存；未处理冲突的门店暂不能计算。
3. 门店与参数：勾选本次门店。分仓模式下每店选择主仓、从仓（单仓选“无从仓”），可批量设置，主从仓不能相同且必须有已导入资料；需要下次复用时点击“保存所选门店为默认配置”。新门店必须选择“不限预算”或“限额补货”；限额金额必填，0表示本次不安排。每店共用一个预算，覆盖本店所有仓需求，不是每仓另给预算。
4. 默认仓参数：河北8+4天、山东8+5天。未知仓需填写；可逐店或批量维护完整参数方案，固定规则只读。
5. 点击“开始计算”。默认2个子进程同时计算，可调整1至4。已完成店可先查看；某店失败不影响其他店，可单独重试。“停止剩余任务”让已开始门店完成，不再启动排队门店。
6. 查看与导出：汇总按有效完成结果统计；失败、未运行、待重算的金额留空。点击门店进入商品明细，按必卖未补足、预算暂缓、最低持有缺口、禁用/停采、地采等筛选。点击商品行查看完整计算依据。
7. 修改一家店主从仓/预算/参数，只让该店结果过期；更新仓资料、共用输入或必卖清单，让共用批次结果过期。仓资料更新后必须重新检查本批数据再计算。旧结果可查看但不能导出。勾选需要重算的店后运行；未选的有效结果保留。
8. “导出本次补货结果”支持一份汇总Excel或每店分别导出（附汇总）。导出面板明确门店范围与完成状态；部分完成不伪装成全量成功。单店详情仍支持全部/当前筛选导出。目标已存在时拒绝覆盖。
9. 必卖清单一次维护、多次复用；导入成功后替换保存，错误保留旧清单。来源路径、参数、版本和清单信息随结果导出。

三、这版的业务口径
• 分仓需求先选归属仓：主仓启用（沿用既有非禁用口径）且可用数>0，优先主仓。主仓禁用、无货（可用数≤0）或无该商品，转到从仓。从仓也无货时仍标记从仓并计算需求，不添加“仓库暂不可供”排除项。单仓无货仍归属该仓。主仓可用数缺失/非数字时不猜成0，保留主仓并记录待核原因。
• 这一步只确定需求归属，不是下单承诺：主仓库存少于需求仍不拆单；不限制需求量、不扣减或预占仓库存，多店之间不争抢仓库存。实际履约能力需后续库存分配环节处理。
• 归属仓的基本售价、出库箱规、商品状态、分类与模型权重，以及该仓的备货/到货天数参与计算；不会借主仓的价格或箱规算从仓。备用状态沿用既有规则，不新增排除。
• 从仓禁用仍保留归属与计算建议，执行量按既有禁用规则置0；补货建议停采同样默认不补。若商品在其他已导入仓存在、但归属仓缺该商品，则标记资料待核，不借用其他仓价格。已导入的仓均无该商品才标地采。
• 查看商品详情可见主从仓选择依据；全部明细导出含主从仓、归属说明、两仓可用数/判断、资料路径及版本；汇总导出新增“分仓需求汇总”，各仓执行金额合计等于门店金额。
• 总预算针对本次新增补货金额，沿用商品资料“基本售价”计价，不把现有库存/在途价值算作本次支出，不加入运费等未提供费用。
• 顺序：原模型计算 → 一箱例外 → 禁用/停采排除 → 门店总预算分配。原AS/BV及模型参数不因预算而改写。
• 按已确认的业务取舍，先把资金分给必卖商品，再分给普通商品。即使普通商品有销量且无可用/在途，预算不足也可以暂缓，并进入“最低持有缺口”。预算不会为了最低持有或一箱例外而超支。
• 同组先保有销量且无可用/在途的最小出库量，再优先照顾预测持有天数小于到货时间的商品，逐个最小出库单位分配，随补入量更新持有天数。同天数优先单次出库金额更低的商品，再按商品编码保持稳定顺序。无正预测的恢复需求放在同组有正预测需求之后。
• 资金分配最多达到原执行候选数量，不因为“必卖”自动扩充数量或新增清单外输入。分配只采用本次门店销量库存及商品资料价格；经营分析中的历史销售额、毛利、SABCD/KVI不参与本版金额和排序。
• 必卖还没完全满足、但剩余金额已买不起任何一个必卖最小出库单位时，余额可分给买得起的普通商品。不能满足任何最小单位的余额保留，不拆箱、不超预算。
• 当前清单已内置：SKU明细中“必卖”和“必卖+冬季”共2,142款；199款冬季独有商品未纳入必卖。清单按商品编码精确匹配，不按名称或条码猜测。
• 查看清单可搜索商品、查看本次匹配状态。导入/更新可读原经营分析xlsx、单张商品清单xlsx（商品编码列必需，名称/分类可选）、CSV，或软件导出的JSON备份。有清单归属列时只取必卖。更新成功后整份替换当前清单；导入错误保留旧配置。
• 首次启动将内置清单保存到本机，后续自动复用。更新无需每天导入，也无需原经营分析文件一直存在。清单按全店通用保存，预算按门店编码分别记忆。
• 清单备份为JSON，保留完整长商品编码，可复制到另一台电脑导入。Excel维护长编码时务必保留文本格式。当前清单名称、版本、原文件SHA256进入结果，便于核对。
• 商品资料状态=禁用，或补货建议状态=停采，任一命中即默认不补；同时命中也只排除一次。状态筛选在原计算之后执行，不改变预测、库存额度、资金约束等计算。
• 区分“计算建议/计算金额”和“执行补货/执行金额”：已排除商品计算结果保留供分析，执行数量和执行金额为0。默认界面、顶部金额、补货清单使用执行口径。可在“已排除”或“全部商品”查看计算参考，不提供放行禁用/停采商品的操作。
• 原计算核心保持不变；未统一两套日均，未套用安全余量2/3/4天试验。
• 一箱例外只在原计算完成后执行。只有资料精确匹配、数据有效、导出补货状态正常、中心仓启用、有真实销量、箱规大于1、原建议为0、可用及在途撑不到到货、且确因库存额度或资金约束拦截时，才放行一箱。
• 非例外商品的计算数量与金额保持原模型结果。原模型已有建议也不会额外加箱。关闭例外开关并重新计算，可查看原模型计算结果；禁用/停采筛选仍生效。
• 缺失箱规按已确认规则补1；分类未配置时使用“无分类”的快销权重。基本售价作为金额单价。
• 销量、可用库存、在途、补货数量均按库存单位，不另做采购单位换算。
• 商品资料未匹配的标记“地采商品”。保留其销量、库存、原始行位置，本版不生成地采补货数量及金额，不把缺失价格当成0。
• 商品资料重复、商品编码异常仍进入“待处理”，避免把无法确定的匹配关系当成正常地采。
• 顶部金额为本次全店实际分配后的执行补货金额，已剔除禁用/停采。资金栏分别显示预算、已用、剩余、必卖/普通分配、未满足商品及最低持有缺口。原模型极端恢复在候选内保留，也受总预算限制。一箱例外卡片显示的是候选，最终是否分到预算以执行量为准。

四、结果有效性
更换文件或更新共用清单后相关门店需重算；修改单店参数/预算只使该店过期。切换查看门店不会使已有结果失效；过期结果不能直接导出。
运行中可取消。数据错误会显示原因；有效商品可以继续计算，待核商品保留待核状态。
输入工作簿只读；结果写到用户选择的新文件，原模型和源Excel不覆盖。
导出含概览、补货清单、明细、预算未满足、已排除、地采、待处理、一箱例外、全店必卖匹配、参数，保留输入文件SHA256及源行，便于核对。筛选导出的全店预算及全店必卖匹配仍明确标为全店口径，其余明细是当前范围。
本版不支持人工修改补货建议数量，不自动下单。

六、问题定位
错误提示会说明原因。界面日志位于用户目录AppData\Local\YoutuanTools\补货助手\app.log。
必卖清单位于同一应用目录下的settings\must_sell.json；每日作业、完整方案和门店默认配置保存在settings\workbench.sqlite3。旧store_budgets.json仅作未迁移门店的回退来源。软件升级不自动覆盖用户设置。跨电脑迁移每日记录及方案时，先关闭所有补货助手窗口，再完整复制settings目录；必卖清单也可单独备份导入。
本版完整模型参数可在“参数方案”和各店参数按钮中维护；按说明区分仅用于本次、保存为本店默认和保存命名方案。明确标为固定的规则保持只读。
软件使用Python、Qt/PySide6、openpyxl等组件，第三方许可随包附在 licenses 中。

## 实际问题与修复

截图显示已受理 8 家、已完成 2 家，一店 `TASK_NOT_FOUND` 后仍有门店停在进行中。代码核实存在三个恢复障碍：该异常会直接中断整批；已受理未完成任务不能结束本地采集；部分按钮操作没有在组件退出后重新建立连接。另发现历史列表刷新保留当前页，而任务查找只向后翻页，可能漏掉前页的已受理任务。

修复后，一店暂未找到任务时，其他门店继续轮询和收取；历史查找先回第一页。中断时按钮明确显示“已停止取数”，可以继续原采集，或先结束本次采集再新建。刷新、暂停、继续、重试、结束和新建入口补齐连接恢复。

本地结束与平台任务分开：明确单一任务号、范围确定的 ACCEPTED／RUNNING 任务保持原防重记录；新批次接续原 run、任务号、查询依据及采集日期，不重新导出。受理不明、多任务号、迁入任务未核清仍拒绝释放；未决记录不能直接删除。预览后变化检测、原子更新、确认取消和失败回滚保留。已采用文件、草稿、签发及原下载文件不变。

聚水潭增加“自动配置所选仓浏览器”：自动建立仓库独立 Edge 配置、以本地临时调试端口启动，首次正常登录后核验公司及账号并保存。旧手动目录、核验、勾选和保存入口收纳至高级设置。两仓独立；旧账号身份和待处理原任务保护保留；相同绑定再次核验不变更版本。没有复制登录态、关闭日常浏览器或修改全局浏览器策略。

运行逻辑改动集中在 `aoxiang_fetch_ui.py`、`aoxiang_acquisition.py`、`catalog_sync_ui.py`，翱象的 `aoxiang-ui.mjs`、`machine-runtime.mjs`、`machine-commands.mjs`、`machine-maintenance.mjs`、新增 `collection-recovery.mjs`，以及聚水潭 `accounts.mjs`、`service.mjs`。其余为版本、说明、隔离测试及封装工具。**删除的两份实现文件与 0.45.2 哈希一致。**

分页问题已在真实 Edge 的隔离模拟页面复现并验证；没有访问截图对应的真实平台记录，因此不把它断言为截图现场的唯一原因。

| 大库有缓存，三轮 | 0.45.1 | 39.34 | 231.0 | 2584.2 | 86.1 |

本轮对真实冻结样本的独立副本进行了单轮无缓存诊断：总计 **238.40 秒**，峰值 RSS **232.02 MiB**，读取 **2254.94 MiB**、写入 **108.77 MiB**。准备结束的临时库为 **7.67 MiB**，该数值不是所有临时文件峰值。

| 诊断项 | 耗时秒 | 依据 |
| --- | ---: | --- |
| 准备重写及引用依据 | 232.00 | 位于主库写锁之前 |
| 其中旧格式引用解析 | 146.93 | 28 次调用、10 次缓存缺失 |
| 其中内容块完整核验 | 69.16 | 16,222 次调用均无引用缓存 |
| 写入重写结果 | 0.19 | 一笔删除事务内 |
| 共享资料回收 | 3.13 | 保持原回收时机与完整性检查 |
| 清理索引 | 1.24 | 保留 UTF-8 完整校验 |

少量订单仍涉及大量历史，主要因为日作业共享快照需要过滤，以及回收原表／附件前必须确认其他存活历史的引用。仅扫描选中订单会遗漏未选订单和共享资料所有者，不能这样缩小范围。

仍有优化空间：旧 JSON 逐值解析和首次构建引用缓存占主导。可以继续研究解析开销，或覆盖各保存入口的增量引用维护；后者需要迁移、完整性和保存链路设计验证。本轮未上线未经验证的候选改法，没有改变删除范围、历史保留、同步回收、事务原子性、secure_delete、存储格式或计算模型。

这是带函数计时的单次诊断，不能用 246.20 与 238.40 的差值宣称新版本提速。Windows 进程 I/O 含系统缓存，不是物理磁盘占用率；RSS 不是整机或整个应用内存；尚未在低配业务电脑实测。详见 [函数耗时与输入哈希](deletion-profile.json)、[完整结果与业务签名](deletion-result.json)。

本次冻结输入哈希不变；与 0.45.2 同样本的删除预览凭据、结果、前后逐表业务签名零差异。没有新增签名忽略项。不同删除规模沿用上述既有对照，本轮没有重复测量。

## 已知限制与失败证据

- `browser_status_ui` 的 QLabel 销毁后回调警告仍在全量回归出现，属于既有问题，本轮未修。不能表述为警告消除。
- 如果平台确实找不到原任务，仍保留其身份并提示核对；不会通过新建批次偷偷重提。受理不明的门店不能解除防重；其余门店仍可处理。
- 首次正常登录、验证码和平台权限需要使用者完成。公司无法唯一识别、没有 Edge 或组织策略禁止调试时会明确停止，不猜身份、不修改系统策略。
- 首次浏览器实测失败于新 Profile 尚未写入 Local State。已修正为仅受管目录允许继续，并由活跃浏览器实际 Profile 路径核验；失败报告保留为 [browser-first-failure.json](browser-first-failure.json)，该 QA 浏览器已正常关闭。
- 新增专项首两次失败源于夹具断言指向了非持有任务的记录、尝试改写不可变任务号，以及未考虑排队中的维护锁。修正夹具与断言后 218 项通过；保留 [首次日志](focused-node-first-failure.txt)、[第二次日志](focused-node-second-failure.txt)。没有放宽未知受理或记录删除保护。
- 0.46.0 rc1 已构建，复查发现分页遗漏后未封装为最终候选；保留在原目录，最终交付为包含修复的 rc2。
- 0.45.1 曾误用样本，在删除前 StopIteration；原失败证据继续保留在 [此前失败报告](../../0.45.1/rc1/exe-first-fixture-failure.json)。本轮 EXE 删除使用正确的 `qa/deletion_0321/inputs`。

# 0.47.5 rc2：全部初始化与勾选采购任务

本版按用户明确的“开发环境、全部初始化”实施。已完成独立源码提交、完整回归、实际 EXE 验收与独立打包。未在当前开发资料目录执行初始化；未调用真实平台创建、删除或重传订单。

## 交付与使用

- 应用：`交付_0.47.5_rc2/补货助手/补货助手.exe`，必须保留整个目录。
- 压缩包：`交付_0.47.5_rc2/补货助手_0.47.5_rc2_全部初始化与勾选采购.zip`。
- 全部初始化：**参数设置 → 全部初始化（开发测试）**。确认页面列出当前资料目录和完整备份位置。安全退出后将原资料目录整体移为同级备份，再建立空白目录。重新打开后恢复程序初始默认。
- 采购批次：勾选需要处理的未处理、失败或待核项，点 **仅执行勾选项**；处理结束后未勾选项继续等待。已就绪预览仍需单独确认上传。
- 清理本地批次：勾选后点 **删除勾选本地任务**。只清理未产生平台采购身份的本地任务记录，不删除业务订单；有平台身份的记录仍应核对原任务。
- 详细说明：[全部初始化与勾选采购任务](../../../docs/0.47.5全部初始化与勾选采购任务.md)。

初始化覆盖订单、草稿、采集原件、作业记录和日志、缺货率数据、门店参数、必卖清单、应用连接配置、自动作业配置和本机平台关联。完整备份保留；外部输入/导出文件、其他交付版本、浏览器自身登录资料和平台采购单不删除。备份保留也意味着初始化不直接释放原资料占用的磁盘空间。

本机防重采购关联也随“全部初始化”移入备份。平台已创建的采购单依然存在，初始化后不能把旧采购当新任务重传；需要先在平台核实。这是本次确认的全部重置范围，未暗中保留普通参数或旧任务。

## 实际定位与改动范围

1. 原批次继续入口没有使用勾选范围，工作进程按整批未完成项执行。新增持久执行范围，停止、继续和失败重试沿用所选身份及原顺序，未勾选项不自动启动。所选预览成功、剩余项暂停时允许只确认上传已就绪的勾选预览。
2. 队列持久化的是订单当时的快照。原代码入队及部分执行路径未重新检查订单是否已经删除。本版在入队、准备执行和首次上传前补充只读存在性/回收站检查；同父单两仓按仓检查，不误伤另一仓。
3. 标准永久删除原本已在附加数据库事务中同步清理关联批次，本版没有改动该删除事务。新增核对覆盖旧残留、回收站可见性和过期订单快照重新入队/执行的缺口。只清理纯本地残留，已有平台采购身份及回执的项保留核对入口。
4. 空闲队列先只读检查，发现实际变化才进入写事务，并在写锁内再次核对。不因普通刷新额外争用写锁。
5. 全量初始化采用同盘目录移动作为完整备份，避免逐表清理遗漏。正常安全退出、日志关闭后才切换目录；多实例锁、旧版本进程检查、数据库占用检查与中断恢复记录保护切换。不会强杀正在提交的任务。

本机只读检查时，所查主资料目录的翱象批次表为空，未直接复现截图对应批次的历史形成过程。上述缺口由源码及隔离复现确认，不能据此断言截图中的每个残留都由同一条历史路径产生。

改动集中在 `application_reset.py` / `application_reset_ui.py`、应用启动与参数页入口、`aoxiang_order_guard.py`、采购队列/执行器/界面及对应测试。没有更改计算、预算、箱规、归属、参数默认值、普通订单删除对象或事务语义。

## 在哪里设置

| 时点 | 入口 | 生效方式 |
|---|---|---|
| 长期默认 | 参数设置 → 勾选门店 → 批量设置默认补货策略 | 下次导入带入，当前作业不暗中修改 |
| 计算前 | ②门店与参数 → 勾选门店 → 批量调整补货策略 | 仅本次或同时保存默认；已有结果失效后重算 |
| 计算后、签发前 | ④核对与签发 → 调整补货策略；本店明细也有入口 | 后台试算，核对开关、门店金额、商品变化和风险后确认；取消不改 |
| 方案及Excel | 完整参数方案；门店参数导入/导出新增两列 | 按中文表头；填开启/关闭，空白保持；其余参数不受专用开关入口影响 |

只关新品时复用原模型计算基础，重做新品选择和预算。改变极端恢复时重算选中门店。普通人工调整保留并重新确认风险；关闭新品会清除相关正数量安排，包括新品清单及人工改量，预览列出变化。重新开启不会自动选中新品。

极端开关只控制有效缺货天数≥30的恢复分支；普通缺货恢复、有销量双零最低持有、箱规倍数和已有在途21天限制保持。N>30且J>0依旧只废弃冲突缺货天数，不关闭普通销量预测。未知输入仍待核，不因关闭开关变成有效零值。

## 真实冻结样本影响

本表只关闭极端恢复，未额外选新品，使用原仓周期与参数。

| 预算/一箱例外 | 开启金额 | 关闭金额 | 减少金额 | 执行变化商品数 |
|---|---:|---:|---:|---:|
| 不限/开启 | 12,268.87 | 7,127.05 | 5,141.82 | 233 |
| 0/开启 | 0.00 | 0.00 | 0.00 | 0 |
| 3,000/开启 | 3,040.87 | 3,040.87 | 0.00 | 0 |
| 5,000/开启 | 5,005.37 | 5,005.37 | 0.00 | 0 |
| 10,000/开启 | 10,013.33 | 7,127.05 | 2,886.28 | 196 |
| 不限/关闭一箱例外 | 11,890.07 | 6,748.25 | 5,141.82 | 233 |

原有最多追加一个出库单位、超支≤5%的规则保持，因此部分金额超过设定预算。不限预算下非极端商品全字段一致；有限预算下非极端商品模型量及候选量一致，允许原预算策略重新分配执行量。3,000/5,000场景原本没有给这些极端商品分配执行量，因此开关不改变执行结果。以上是该样本实测，不能推断其他店必然减少相同比例。

## 实际程序验证

用新目录EXE、独立settings目录运行，报告记录frozen_exe=true、源提交和同一EXE哈希。验收通过：

1. 包内Windows spawn多店计算；读取Excel生成的合成极端/新品场景。
2. 实际Qt编辑与核对窗口，先取消再确认；其他门店结果完全不变。
3. 关闭后极端量与已选新品量撤销，人工数量编辑器拒绝绕过新品开关并提示原因。
4. 默认保存、作业保存恢复、重新检查输入带入默认、再次spawn重算仍使用关闭值；重新开启新品不自动选货。
5. 原签发快照不变，按原快照导出成功。
6. 原可读性18项及参数导入7组检查：拖拽、模板、预览取消、百分比和分类参数、默认导入生效、签发单隐藏单号及回传关联等。

新开关EXE验收约7.42秒，测试期间Qt心跳42次；这是小型合成流程的完成时间，不是全量性能基准，也不承诺所有数据规模耗时。原始脚本输出含截图记录和重复窗口步骤，不把这些当作额外独立业务测试数量。无真实翱象采集/采购操作，本轮未重验跨机安装和全新电脑重建。

## 试用、复跑与限制

运行 `交付_0.29.0_rc1/补货助手/补货助手.exe`，或解压同目录 `补货助手_0.29.0_rc1_补货策略开关.zip`。保留整个文件夹。旧0.28.0没有替换；请先保存并关闭旧版再打开新包。历史单保持原快照；旧模型草稿按既有只读/复制重算流程处理。旧EXE不保证理解新增关闭配置，不应继续编辑新版草稿。

建议人工重点核对：
1. 在②只关一家店极端恢复，计算后检查④状态、金额及恢复商品，其他店应保持。
2. 选新品后在④关闭新品，先取消核对一次，再确认；清单量归零，普通商品仍按预算结果。
3. 保存门店默认，再检查新输入；两个值应带入。用Excel只填一项，另一项及深度/在途/权重应保留。
4. 查询一张旧签发单，核对当时参数与导出保持原值。

QA位于 `qa/switches_0290`，含固定baseline.zip、inputs、before-final/after-final及完整报告。复跑命令见 `docs/0.29.0补货策略开关.md`；必须选新QA输出目录。构建命令为 `tools/build_from_commit.py --commit 4d1cedd1e8774f5ac3ba3c5495240decbbfdfd9d --build-id <新编号>`；封装工具 `tools/seal_restock_release.py`核对捕获源码、构建提交、EXE身份、保护哈希和ZIP所有文件。

所有验收使用隔离资料；没有向用户库写入、重签发或删除订单。没有对正在运行的日常库做静态哈希承诺。未迁移历史数据，没有额外规则试验（8.5天、统一日均等）。

## 定位与改动

旧删除流程把采购、付款、收货及平台待核状态当作删除前置条件。直接解除限制会暴露后台按数组位置回写、整日草稿重新保存已删门店、共享批次整批暂停及组件防重占用残留等风险。这些是本轮处理的链路问题，没有据此推断此前大库约 37 秒的性能瓶颈已经消失。

| 范围 | 最终行为 |
|---|---|
| 删除入口 | 不再使用“所有任务先停止”的通用维护门禁；一次勾选确认完整范围，不查询平台或要求先作废。其他维护入口原门禁保留。 |
| 后台回写 | 稳定 item_id、来源 oid、批次及执行令牌校验，重新查找项；位置只作展示。全批已删则正常结束，不重建空批次。 |
| 失效屏障 | 同一主事务写最小删除身份、日/店代次和清理待办；签发写锁内复查整日内容，草稿保存、恢复、AI 采用、旧定时结果采用保留代次检查。 |
| 主链清理 | 清除所选订单各修订、回传、付款、收货、生成、锁单关联及其索引。移除准确订单的内部号绑定、补号登记和解释日志；共享门店别称不删。 |
| 共享采购 | 每个版本裁剪所选 links，维护 digest/current 索引，保留其他 link 数量和共同原始行、金额、文件及保存时间。没有按数量猜分金额。 |
| 聚水潭批次 | 仅移除选中成员，保留剩余成员位置、控制轮次和原冻结数量。已锁库存保留原占用效果；自身已提交步骤的技术凭据支持原运行安全重放。 |
| 组件退役 | 纯本地指令必须有主库已提交删除依据；移出活动采购/收货集合及独占私有资产，最小技术标记防重放，迟到任务号不建立业务关联。 |
| 私有预览包 | 在生成前登记技术身份；未进入组件的包也能清理。历史未登记包只凭受管目录中原生任务的准确 oid 认领。每轮最多处理 16 个文件，不递归删除目录，不猜测未知归属。 |
| 晚到文件 | 生成结束后可重新激活清理待办，确认清理使用代次 CAS，避免旧确认吞掉新请求。文件占用或在途动作未结束时，业务删除已生效，余下清理可重试。 |
| 导出回执 | 裁剪本地回执的已删身份；晚到保存检查删除标记。共享回执保留未选身份，用户目录中已导出的 Excel 不删除。 |
| 界面 | 核验跨页全部勾选，删除后移除对应身份，不替换成同名新单；更新当前界面时保留未选门店新到结果，主资料变化则重新裁剪最新内容。 |

主要实现位于 `data_maintenance.py`、`deletion_barrier.py`、`aoxiang_workflows.py`、`aoxiang_workflow_runner.py`、`work_repository.py`、`normal_orders.py`、`jst_orders.py`、`jst_batches.py`、`export_receipts.py` 及组件 `order-retirement.mjs`。教程 HTML 第 14 章和使用说明同步更新，增加隔离演练截图；原 PDF 保留为明确标注的历史归档版。

同店同日两仓共享父单的确认范围没有变化。未选订单、共享原表、草稿未选门店及外部平台订单的业务范围保持。并发修改检测、完整性校验、取消、失败回滚和原任务重试继续保留。选中订单修订或范围变化仍拒绝整次删除；无关下游进度变化不再使确认失效。

## 事务、资源与限制

1. 实际读取本机主库、工作流库、两个业务索引及付款候选索引的日志模式，均为 DELETE，只读元数据，没有修改这些日常资料。删除连接在操作前及写锁内检查磁盘 rollback journal 条件，设置 FULL、secure_delete=ON；遇 WAL/内存/不兼容模式则在删除前拒绝，不自动切换日志模式。
2. SQLite 的 ATTACH 多库崩溃原子性要求磁盘主库与非 WAL 条件，且依赖系统/设备正确实现持久写入。组件 WAL 库不参与 ATTACH，由持久待办衔接。[SQLite ATTACH](https://sqlite.org/lang_attach.html)、[原子提交机制](https://sqlite.org/atomiccommit.html)。本轮受控进程中断不是物理断电，也没有模拟 COMMIT 中途的磁盘扇区损坏，不能扩大宣称。
3. 主业务删除不等待平台生命周期或组件网络任务；仍可能等待数据库写锁、主事务本地校验及磁盘清理。组件或文件清理未完成时，在“首页 → 数据与任务维护 → 查看 / 重试组件本地清理（不连接平台）”重试，正常组件请求前也会自动处理。界面区分“业务已删除”和“本地关联清理待办”。
4. 没有重测大历史库的已有缓存、首次无缓存或多种删除规模，也没有本轮新旧耗时、峰值 RSS、进程读写或物理磁盘负载对照。没有在低配置业务电脑或另一台 Administrator 电脑现场验证。本轮不宣称约 37 秒问题已解决，也不把整轮 GUI 验收时间当删除耗时。
5. 共享原始数量、金额、原文件及不具明确归属的历史资料保留；共享回执/事件的共同路径或错误原文不按订单猜拆。独立上游定时采集记录与仍被引用的仓资料保留；旧运行采用不能恢复已删门店。用户目录原 Excel、已导出文件和旧备份不清除。这不是取证级磁盘擦除。
6. 已发出的请求可能继续在平台完成；本地删除不会撤销外部采购单。相同有效源单的正常防重规则保留；删除后的新 oid 独立，不因旧活动占用阻止新单。没有用“上传前取消”伪装已进入上传边界的事实。
7. 使用完整 0.50.0 交付目录；旧 EXE 不认识失效代次及退役标记，不支持与本版同时写同一资料目录。旧交付保留供比对，不应混用旧写入器。
8. 既有 `browser_status_ui` 的 QLabel 销毁后回调警告未作为本轮修复对象，不宣称已经解决。本轮登录连接、导出菜单等真实平台现场问题也不在本次验收结论内。

封装及最终保护检查见 `release_artifacts.json`。本地标签为 `v0.50.0-rc3`；没有执行 push、merge 或修改真实平台状态。

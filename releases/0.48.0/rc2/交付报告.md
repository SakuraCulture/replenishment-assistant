# 0.48.0 rc2：AI 缺货率分析、审计可读性与签发恢复

已完成本期方案：AI 查询独立缺货率资料、固定日报比较与下钻，人工核对显示调整，签发导出失败的原修订恢复，回传识别说明，以及离线图文新人手册。模型与统计口径保持。自动生成并保存门店默认参数属于后续阶段，本包没有将提示模板冒充配参算法。

## 交付与入口

- 完整程序目录：`交付_0.48.0_rc2/补货助手`；主程序 `补货助手.exe`。
- 压缩包：`交付_0.48.0_rc2\补货助手_0.48.0_rc2_AI分析与签发恢复.zip`。正常退出旧版后完整解压运行，保留 `_internal`、`AI接口`、`AI入口`、`使用手册` 等目录。
- 缺货率 AI：门店缺货率 → 用 AI 分析当前范围；先按既有 AI 协助入口连接客户端。复制要求不会执行任务，客户端发起工具调用后才查询。
- 显示：显示与帮助 → 正文字号 / 表格行距。最终清单增加折叠筛选、列视角、常驻商品身份和全文查看。显示设置不进入计算参数。
- 签发失败：显示与帮助 → 导出任务与恢复；或订单跟踪中的同名入口。先核对任务，再只恢复勾选文件；读原修订，不重新签发、不覆盖用户文件。
- 回传：批量导入窗口 → 查看识别依据与候选 / 查看文件关联信息。旧修订、损坏标记和多候选保持明确拦截，不按商品相似度猜订单。
- 手册：显示与帮助 → 图文使用手册；或直接打开程序目录 `使用手册/index.html`。26 章、13 张实际 EXE 截图、41 页可搜索 PDF；HTML 支持搜索与放大原图。
- [实施范围与限制](../../../docs/0.48.0AI分析审计与签发恢复.md) · [图文手册](../../../docs/manual/index.html)。

## 用户故障与本次处理

用户已确认故障入口是“核对与签发 → 确认签发并导出”。当前源码本来已有 veryHidden 的“系统关联信息”，包含精确签发身份；本次保留该格式，增加保存后身份校验和只读查看。

已验证签发数据库提交与 Excel 写出分属两个阶段。新逻辑在签发前建立本地导出回执，分别记录签发状态、逐文件阶段、摘要和错误；文件占用等局部失败会明确显示已生成几份、原签发是否保留和恢复入口。Windows 归档发布不再依赖硬链接，改用同目录拒绝覆盖的原子重命名；导出清单或日志失败与 Excel 生成分开说明。

实际 EXE 在隔离目录用 Windows 独占句柄制造文件占用，观察到了部分导出失败；原文件哈希和签发修订不变，经过恢复窗口补齐文件后回传预览及保存成功。这证明该恢复路径可用；未取得用户原故障当次完整日志与原件，不能认定那次就是文件占用或已经定位唯一根因。

## 保留的失败证据

1. 第一轮全量回归 1251 次执行中，两处断言仍预期旧版 26 个 MCP 工具。更新为 32 个及新增 6 个接口的精确名称、读写权限检查后重跑；[原日志](retained-failures/first-regression.log) 保留。
2. 第二轮 1255 次执行通过，但导入测试夹具类导致 31 次重复收集。改用模块引用后，最终 1224 个独立测试全部通过；[原通过日志](retained-failures/second-regression-duplicate-collection.log) 保留，不把重复数当新增覆盖。
3. 初次源码界面驱动在嵌套弹窗中无法重入定时器。确认恢复已完成、没有提交任务后，仅停止隔离演练进程，修正驱动并用新目录重跑；[原记录](retained-failures/source1-driver.json) 保留。
4. rc1 EXE 前七组功能完成，验收脚本等待 CLI 退出却未及时读取标准输出，造成管道背压超时。改为流式写入独立响应文件后重建 rc2，完整流程通过；[rc1 原报告](retained-failures/rc1-exe-report.json) 保留。没有把它解释为业务采购或数据库失败。

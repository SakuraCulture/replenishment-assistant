## 已实施

| 范围 | 现在的操作与边界 |
|---|---|
| 统一维护入口 | 首页“数据与任务维护”进入参数、仓资料、批次、草稿及订单清理 |
| 参数维护 | 默认变更历史、逐字段差异、撤销导入、恢复旧默认、重置选定门店、恢复停用方案；后来又修改的门店不被旧撤销覆盖 |
| 仓资料维护 | 更新时保留完整旧/新快照，可恢复指定仓的已留存版本；不调整库存分配账 |
| 计算任务 | 失败门店在原批次单独重跑，保留其他店成功结果；运行中可排入重跑，安全停止后可新建草稿 |
| 翱象任务 | 采集及采购/收货任务支持失败项重跑，保留原身份、顺序和成功项；待核受理只核对原任务，禁止盲目重复上传 |
| 永久清理 | 预览关联范围、明确确认、并发校验、取消/失败事务回滚；清除业务订单、关联生命周期、任务、事件和索引，不新建回收站 |
| 草稿清理 | 按日期删除选定草稿；不删除已签发快照或门店默认，不隐式丢弃当前未保存内存草稿 |
| 辅助操作 | 公共按钮的返回、翻页、重试、刷新、停止、关闭使用标准图标、轻量样式、提示和可访问名称 |

计算结束后另开批次沿用原保存/放弃确认，新建的是空白草稿；翱象结束批次则将失败/未开始任务转入后续执行批次。两者含义不同，均明确显示，不改变业务日期和正常单唯一规则。

分阶段代码提交：`2a1cf82` 参数维护；`e69d214` 原批次重跑；`c9549af` 关联删除及交付入口；`8274e28` 高 DPI 默认变更表列宽修正。rc1 已通过逻辑验收，但截图发现新值列需横向滚动，因此另建 rc2，未覆盖 rc1。

## 使用限制与保护

- **彻底删除按“门店＋业务日”整单进行。** 两仓共享原始计算快照，选择一仓时预览会列出同店另一仓，须明确确认；不能只物理清除一仓的全部底层资料并保留共享父快照。此版本没有单仓完整物理清理。
- 没有新回收站。删除后软件内不能恢复；原磁盘 Excel、已导出文件、已有备份及外部平台采购不会随本地删除消失。仍被其他订单或当前资料引用的原件保留。外部防重复身份记录保留，不当作本地业务订单展示。
- 已锁单的必要库存占用保留在当前库存基准下，避免本地删除导致库存被再次分配；换成新库存基准后不重复扣减。运行中的任务和受理不明任务须先安全停止或核对。
- 删除不是法证擦除，不承诺 SQLite 文件立即变小或清除外部副本。提交边界内不强杀进程。长时间不返回的底层/平台调用仍需原超时或安全边界到达。
- 参数和仓资料只能恢复升级后已留存的内容，不能还原未记录的旧值。参数维护影响后续默认，当前明确编辑/历史恢复配置继续保留，需要显式应用并重算。
- 本轮没有真实翱象现场重跑联调；离线受理状态测试不能证明所有平台失败都可恢复。数据错误需修正数据，受理不明不得重传。
- 0.26.1 EXE、ZIP、原参数 Excel、冻结输入已核对哈希未变。没有本轮开始前的完整用户数据库字节基线，不宣称其整文件字节哈希已证明不变。已有两份未跟踪方案文档没有修改或纳入提交。

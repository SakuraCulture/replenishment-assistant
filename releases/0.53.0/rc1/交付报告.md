# 0.53.0 rc1 双仓独立执行与分仓删除

已实现按门店原双仓配置计算，按本轮勾选仓独立签发、执行和删除。只选山东不会改成单主仓计算，也不会把河北商品改归地采。

本包是独立候选包。385项封版定向回归、253项采购组件测试、9项实际EXE验收通过；本轮完整全量回归尚未取得最终通过结论，不能称已完成全部软件验收。

## 业务变化

- 双仓店可先签河北，同日相同方案稍后补签山东；某仓修订变化时另一仓保留原身份和原明细。
- 不同天供货请新建当天任务、采用当天资料再计算；不自动将旧库存销量当成今天依据。
- 只删除所选仓单及其本地关联，保留同店另一仓、其他订单和共享批次的剩余成员。已上传平台订单不自动撤销。
- 已删除的同日同仓不能由旧草稿或默认勾选恢复；本轮未实现同日已删仓的新身份重建。
- 历史、付款认单、回传、库存分配、导出恢复、经营分析及货盘按各仓自身生效版本读取。修复同店两仓不同来源修订不能同批回传、单仓更正误读另一仓回传值的兼容问题。
- 新版新增独立仓单元数据和现有格式的投影快照；共享配置、预算证据和仍有引用的原表保留，SKU业务调整及下游归属按仓裁剪。
- 新增合并仍按父单完整关联图去重/冲突隔离；已有父单不静默补入另一仓。重复包不重复新增，旧包不能复活已删仓。

模型仍为0.3.6-rules。model、engine、allocation、app_defaults、restock_policy、new_products和first_fill共7个文件与0.52.9 rc1逐字节一致；计算结果、预算分配、主从仓顺序、箱规和默认并发均未调整。

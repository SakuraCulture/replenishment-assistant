## 完成范围

外部 Codex / WorkBuddy 经 MCP stdio 控制台适配器连接当前用户本机命名管道，由原 Qt 工作台协调原检查、计算服务。没有引入模型 SDK、API Key 或另一套计算实现。

首期提供 12 个工具：当前工作台、资源查询、有效参数、准备计算、执行计算、任务进度、停止后续、失败重试、分页结果、决策解释、试算采用、定位原业务页。准备与执行分开，试算不覆盖当前作业；采用后仍未保存或签发。默认参数修改、删除、生命周期数量写入、正式签发和平台采购均未开放。

界面新增紧凑“AI 协助”区域、连接配置生成、任务进度、结果表单和人工接手。原页面仍可使用；AI 与人工共用预算解析、参数装配、预案选择字段和重算影响判定。人工改了依赖后旧结果不能采用，浏览筛选不会误使结果过期。

同一预览重复执行不启动第二份；断开客户端不取消已受理任务；重试沿用原输入、必卖和参数并合回原批次。会话只保留最近 3 个计算根批次及重试、5 个检查预览；任务记录不复制全量业务结果。原草稿和签发不受会话缓存释放影响。

实际结构、工具字段、可复跑命令和人工试用步骤见 [使用与结构](../../../docs/0.35.0AI协助使用与结构.md)。计划中的代次实现收敛为绑定有效业务状态的不透明指纹；不把浏览事件当成业务变化。计划中的模块责任按实际代码拆为 `automation_jobs` 与 `workbench_actions`，无重型依赖注入。

### 对照范围

基线与候选各自独立运行于同一锁定 Python 环境及隔离资料目录。真实样本 14,244 行；不限预算、0/3000/5000/10000 元、关闭一箱例外、标准/自定义参数；合成边界覆盖双仓、主从仓、缺资料、禁用停采、多文件冲突及顺序、错误输入、筛选/单店/多店导出。现有准入、新品、人工调整、存储和生命周期测试通过全量回归验证。

业务对照严格比较全部嵌套字段、值、Python 类型、字典插入顺序与记录顺序，不按键重排、不放宽浮点误差。Excel 比较工作表、行列顺序、值、类型、格式、样式。精确动态白名单：`loaded.loaded_at`、`result.created`、`result.task.pid/started/finished`、`result.version.version/source_commit/build_id/built_at`；Excel 仅 `structure_oracle.excel_snapshot` 枚举的时钟/构建单元格。未忽略模型版本或业务参数。

`model.py`、`allocation.py`、`one_box_exception.py`、默认配置及必卖、`normal_orders.py`、`normal_exports.py`、`order_lifecycle.py` 的基线与候选 SHA-256 完全一致，逐文件值见对照报告 core。

接口专项额外覆盖：先计算 A、恢复 B 后故意失败再重试，10 元预算按 B 必卖分配，A 商品 0、B 商品 10；显式新预案只覆盖勾选字段，已有预案不重新覆盖本次人工调参；人工改量过期、重算影响待核；双客户端共享任务、原客户端退出、重复请求、取消后重试、串行/并发、同资料环境第二连接所有者拒绝、历史准确修订及分仓单号解释、新文件原件留存、直接采用仅变当前工作台。

实际 EXE 使用合成两店，在真实 Qt、打包接口程序与 Windows spawn 中执行上述主流程。14,244 行对照及性能来自源码独立进程，不冒充 EXE 大样本验收。另实际运行本版 EXE 的旧参数维护验收：批量/单店、取消、默认保存、模板导入、全局映射、预案、历史恢复、双店计算均通过。

## 性能

同机同依赖、同一冻结真实输入、单店不限预算。每轮新进程、新隔离资料库；原服务和接口交替串行运行，每组 3 次。原服务是候选中的共用原检查/计算入口，不是旧版 UI 点击计时；旧版业务等价另由上面的固定提交对照证明。

| 指标 | 原服务：中位数 [最小, 最大] | AI 接口：中位数 [最小, 最大] |
|---|---:|---:|
| 完整检查与计算，秒 | 47.248 [46.871, 47.467] | 47.736 [47.205, 48.367] |
| 准备阶段，秒 | 42.577 [42.225, 42.895] | 43.282 [42.654, 43.775] |
| 计算阶段，秒 | 4.646 [4.572, 4.671] | 4.552 [4.453, 4.592] |
| 进程树峰值 RSS，MiB | 609.2 [555.3, 665.7] | 566.2 [566.2, 566.3] |

接口总耗时中位数增加 0.488 秒，约 1.03%，在首期增幅不超过 10% 的目标内。三次准备受理为 225/221/230 毫秒；60 次轻量任务状态查询 P95 38 毫秒，在 500 毫秒目标内。每轮结果严格对照为 0 差异。

内存按 Win32 每 20 毫秒采样主进程及所有后代进程 RSS 求和，跨进程共享页重复计数；这是采样峰值，不是唯一物理页或系统 Commit。接口组本次中位数较低约 43 MiB，但原服务组波动明显，不据此宣称接口有内存优化收益。长期保留试算有额外成本，已用上限约束并补测，不能把单批结果外推为长期会话峰值。

Windows 文件缓存未清空；MCP 适配器连接启动、原已检查输入预载在检查/计算计时外，实际重新检查 Excel、命令传输、按序计算、任务记录在计时内。查询延迟探针在结束后执行并从总时长排除。JSON 的 `isolated_startup_seconds` 仅为模块导入后构造 Qt/空工作区，约 0.13 秒，不代表 EXE 冷启动或生产历史首次索引。生产规模冷启动、多店长期聊天及网络模型响应未在本轮性能数字中验证。原始 6 次读数及精确统计口径见 `performance.json`；连续会话探索测量另留在 `qa/v0350/performance-final`，不混入本表。

## 环境、客户端与边界

原 `.venv` 的 Pillow 13.0.0 / setuptools 84.2.1 偏离锁文件；未修改它。新建 `qa/v0350/locked-venv`，Python 3.12.14，按带哈希锁文件安装全部 13 个依赖并通过版本检查、Qt 导入及 pip check。测试与构建使用该环境。环境检查只明确豁免检查器写死的 `.venv` 路径，未豁免依赖或版本检查；记录见 `environment.json`。

Codex 验证使用已安装 0.166.0-alpha.6 的 app-server MCP 客户端、独立 CODEX_HOME、临时协议上下文；未创建模型 turn，未提交用户聊天、未调用计费模型，也未覆盖日常 Codex 配置。实际发起并完成试算，并非只有自制 JSON 客户端模拟。

WorkBuddy 验证真实客户端完成首次信任、启动候选接口 EXE、列出 12 个工具；承载工作台是相同源码的隔离合成样本。未代其发起模型对话，因此 WorkBuddy 自然语言多轮执行仍需人工试用，不能称为该客户端全部业务流程验收。临时测试连接已从配置移除，其他连接和用户同期修改保留；正式使用请从新版“AI 协助”生成并添加正式连接片段。

当前上下文冲突按整个准备快照拒绝采用，可能要求重新准备未受某次单店编辑影响的其他店；首期以保守避免覆盖为准。已有新品选择或人工改量的重算先交回原界面核对。历史解释按原快照；未保存结果只在当前会话，退出后任务记录不会被伪装成可恢复草稿。

未接入平台自动采集/采购、正式签发/导出、默认参数保存、生命周期导入、删除或任意脚本执行。默认关闭本机 AI 连接，首次启用才增加两张任务元数据表并执行既有安全备份，不迁移原业务表格式。

已有 README 和项目进度等文档是其他会话工作，本次没有覆盖或纳入提交。新说明独立保存，代码查找以本版使用与结构为准。没有推送远端，没有替换用户正在使用的旧包。

## 九个实际业务案例

以下在独立 QA 数据库、真实 stdio MCP → Qt 工作台 → Windows 计算子进程链路执行。数据是明确标注的合成 A/B 两店，每店 125 个商品，含一条禁用商品。

| 场景 | 主要验证 | 结果 |
|---|---|---|
| 开工检查 | 查询资料与实际参数，B→A 顺序，原作业不变 | 通过 |
| 当前参数试算 | 两店逐行/汇总与直接业务服务相等；分页读取 125 行不漏不重 | 通过 |
| 两种备货天数比较 | 只改变 A 店山东仓 5/7 天，其他店与当前作业不变 | 通过 |
| 结果与异常核对 | 各店汇总、禁用商品出现在待核/排除查询中 | 通过 |
| 商品补货解释 | 指定任务、门店、仓及编码，返回已计算过程 | 通过 |
| 历史签发原因 | QA 创建签发，再按精确分仓单号读取原修订快照 | 通过 |
| 失败/停止重试 | 停止后重试；另注入瞬时失败，再用真实模型恢复；汇入原批次 | 通过 |
| 停止后续 | 排队门店停止，正在计算门店安全结束 | 通过 |
| 采用试算 | 只采用明确指定任务，不写门店默认、不新增草稿或签发 | 通过 |

合成参数比较的 A 店执行金额：5 天 22,816.00 元，7 天 26,784.00 元，差额 3,968.00 元。两次均与对应有效参数下的原业务服务逐商品相同；这不是实际门店业绩或收益预测。

界面另验证：打开案例窗不阻塞接口；复制内容绑定精确作业；默认预览不显示技术字段；比较必须单店且是供货仓；人工变更后拒绝旧提示词；采用前必须勾选确认；复制并返回会关闭窗口。测试恢复剪贴板，不使用日常业务数据库。

## 已知边界

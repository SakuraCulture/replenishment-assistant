# 补货助手 0.14.0 rc2 交付报告

已完成首页待办与实际下单关联，安全依赖升级和收货关联按用户要求暂缓。保留0.13.0，未合并、未推送、未替换用户正在使用的程序。

## 已完成内容

首页按店仓展示待回传、部分回传、未关联下单、部分关联、差异待核及旧修订待核；默认最近7个业务日，可一键查看不限日期的全部未完成。50单分页，支持跨页勾选、按勾选导出、独立暂缓/恢复/差异核实。旧版未标仓单可查看，不猜仓、不阻塞其它单。

采购导入支持多文件拖拽、标准模板、表头位置映射与可复用映射方案。精确绑定门店、仓、签发修订和商品；缺条件转人工选择。允许同店同仓采购行分摊到多个签发修订、多个采购单汇总到一个签发单；额外采购须明确确认。单位不明保持待核。

新旧差异完整显示后确认，采购按完整本版数量增加独立版本；同原件重复导入不累加，人工换算/关联保留。采购原件按字节留存，历史版本可读；关联调整新增采购版本，不覆盖原签发或加盟商确认。执行对照是新增独立导出，原四类导出入口和生成实现未修改。

## 规模测量

纯合成：500个门店正常单、1000仓单、5万签发行；采购5000行、100采购单。相同环境串行3次，独立数据库副本；下表单位秒，保留全部原始值于[规模报告](scale.json)。本版新增能力没有旧版同功能可比，不宣称“提速几倍”。

| 阶段 | 中位数 | 最小–最大 |
|---|---:|---:|
| 首页首次投影，1000仓单 | 4.512 | 4.194–4.863 |
| 首页相同范围再次查询 | 0.545 | 0.507–0.594 |
| 采购5000行：表头识别与读取校验 | 0.794 | 0.789–0.802 |
| 读取100个可关联仓修订 | 0.247 | 0.240–0.260 |
| 100采购单准备与差异校验 | 3.425 | 3.104–3.526 |
| 100采购单原子提交，含本次备份 | 0.256 | 0.249–0.276 |
| 采购导入后首页查询 | 0.781 | 0.702–0.878 |
| 100仓单合并执行对照导出 | 1.567 | 1.461–1.657 |

最终三次服务进程RSS采样峰值为 [119.6, 131.3, 132.9] MiB。统计间隔20ms，仅服务进程，不含Qt和spawn启动。所谓首次为应用投影缓存未建立，未清除操作系统文件缓存。实际EXE新功能完整进程树50ms采样峰值239.2 MiB，原流程405.3 MiB，两者测试动作不同，不作性能优劣比较。

## 保存及兼容边界

新增独立采购、关联索引和跟进记录表，不改原正常单、签发修订、原始商品附件、加盟商回传、参数和每日作业。写前保留原备份机制；准备阶段可取消，最终提交阶段不可中断，多单事务原子。取消可以留下备份或存储元信息，未声称数据库文件字节完全不变。

原签发、回传、采购、收货是四个不同口径；收货固定显示未接入，缺采购资料不能填0。实际采购价/金额只保存明示值，不用模型价格补造；未做缺价或混合币种的合并金额结论。旧EXE不显示新采购表，但既有签发/作业仍保持原格式。

## 限制和后续

- 尚无用户真实采购单样本：已验标准模板、可配置映射和合成异常，不代表所有ERP原格式都直接可用。首行须为表头，状态/单位必须明确。
- 无外部稳定明细号的更新需人工逐行确认身份；不做名称相似度或时间相邻的猜测关联。负数退货未接入。
- 旧修订上的采购不自动搬到新修订；需业务人员在采购版本中明确重分配。没有实际资料不自动判为未下单。
- 大历史首次查询和采购目录仍有读取成本；规模测量不承诺无限数据量恒定耗时。未验证全新电脑或全部Windows/DPI环境。
- 安全依赖升级、收货关联、补货效果分析本轮均未实施。

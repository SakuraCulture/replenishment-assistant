# 0.47.1 rc1 缺货率采集修复交付报告

日期：2026-11-07。针对缺货率采集串行等待、原生重复表头误拦截，以及验证时发现的空队列检查误取消完成修复。本轮只做隔离验证、本地提交及独立打包，没有调用真实平台、改写真实业务资料、推送或合并。

升级前正常退出旧版，完整解压 [0.47.1 运行包](../../../交付_0.47.1_rc1/补货助手_0.47.1_rc1_缺货率并行导出.zip)，运行其中 [补货助手.exe](../../../交付_0.47.1_rc1/补货助手/补货助手.exe)，保留整个目录。操作见 [本版说明](../../../docs/0.47.1缺货率翱象并行导出.md)。已有“重复表头”失败记录请到“采集与快照”选择原任务，点击“继续原任务 / 补失败项”；原任务已成功取得的文件继续读取，不用删除记录或重新导出。

## 原因与改动

1. **缺货率采集没有用上原补货的批量能力。** 原补货入口用一个 `replenishment.export` 命令携带全部所选门店；组件启用 `pipeline:true`，先提交各店、平台同时生成，再轮询收取。0.47.0 分析逐店建立单店命令，并等该店下载及解析完毕才继续。0.47.1 新建采集把尚未关联且无其他任务冲突的门店放进同一批次，逐店关联保存后才派发。组件代码、接口、浏览器操作方式没有改变。
2. **把所有重名列当成数据错误。** 本机已留存的五份翱象原生 V2 文件均为 54 列，第 43、45、47 列都是“毛利”。分析不消费这些字段，原补货读取器也允许未使用的列重名。新读取器沿用这个边界，流式投影只读取明确使用且唯一的列；月销、可用库存、商品编码及其他实际使用字段重复时仍拦截，提示具体列名、列位置和工作表。原件哈希、门店身份、商品编码、回执条数与完整性检查均保留。
3. **空分配队列的定时检查被当作正在执行业务。** 原分配后台每三秒启动检查线程，即使没有待办，分析的优先级判断也会看到 `worker` 并取消当前任务。现在仅在发现真实活动批次、进入处理之前标记执行状态；空检查不打断分析，真实分配工作仍优先。没有改变分配数量、库存占用或提交语义。

改动集中在 `stockout_acquisition.py`、`stockout_facts.py` 和分析入口的优先级判断；`jst_batches.py` / `jst_tasks.py` / `jst_task_ui.py` 仅增加真实工作开始标记。附带测试、隔离验收脚本、版本及文档调整。计算模型、预算、箱规、默认参数、归属规则、原订单删除核心和原存储格式不变。模型仍为 `0.3.4-rules`，仓归属 `0.5.2`。

并行的是平台生成文件的等待过程。浏览器查询及提交、下载、本地校验和解析继续逐份执行，不同时装载多店大表。分析资料独立、按需加载、每日计划默认关闭、原业务优先等边界保持。

## 任务恢复与结果等价

- 每店保存批次命令关联后才提交；丢失受理响应后重放同一命令，不另建任务。命令用途、门店完整范围、账号与绑定版本逐项核对。
- 暂停保留原命令与已受理平台编号。部分失败修订只重试组件允许重试的失败门店，成功门店不重新导出；本地已完整投影的门店也不重复解析。
- 原补货任务冲突只阻断对应门店，其余所选门店可组成分析批次；不取消或修改原补货任务。
- 升级前的单店命令继续按原编号接续，**旧任务可能仍逐店恢复**。本版新建任务才使用一个批次，不能为了并行而取消重建未知任务。
- 批次回执或文件身份 / 哈希不符仍拒绝采用；单店内容投影失败可保留其他完整快照。未放宽模型、指标或完整性预期。

调度对照中，原件哈希、全部商品事实字段及四种视角的汇总严格一致；仅快照随机身份不比较。测试另覆盖所选顺序、先关联再派发、混合旧单店任务、受理响应丢失、取消后恢复、只重试失败项、原业务冲突、原件篡改和跨店数据拒绝。

## 耗时和资源对照

新旧各三次、交替串行、每次独立进程。使用相同 XLSX 字节，固定 0.47.0 的采集调度函数与新函数对照，其余解析和存储依赖相同，目的是隔离调度差异；**不是两个 EXE 的完整版本性能对照**。模拟每店查询提交 40 ms、首店生成 1000 ms、其他店 600 ms。没有访问真实翱象，数字不能作为生产提速承诺。详见 [performance.json](performance.json)。

## 保留的失败及限制

- 首轮专项测试把两个独立采集放进仅支持一个仓操作的夹具，触发仓操作身份断言；拆成各自独立夹具后通过，没有修改生产预期。[原日志](retained-failures/focused-01.txt)
- 另一次专项命令缺少原分配测试所需的测试目录导入路径，且新增测试的 SQLite 连接未关闭导致 Windows 临时文件清理失败；修正测试环境和连接释放后 73 项通过。[原日志](retained-failures/focused-03.txt)
- 首轮窗口在剔除视角检查失败；隔离数据库四视角数值正确，日志记录任务被“原补货业务优先”取消。发现并修复空分配队列轮询被认作真实工作的问题，新增确定性优先级测试；完整窗口复验通过。[失败报告](retained-failures/source-ui-01.json) · [原日志](retained-failures/source-ui-01-app.txt)
- 全量回归仍出现既有 browser_status_ui 中 QLabel 销毁后回调警告；本轮未修复，不影响本次测试通过，不能视为已解决。
- 未调用真实平台验证本版并行采集速度，也未做低配置业务机、全新电脑或连续无人值守验收。原件检查是对已留存文件的只读复验，不是重新导出。
- 0.47.0 曾有一次无法完整定位触发来源的取消，其历史证据仍保留。本轮确认并修复空队列误取消这一具体原因，不反推历史那次必然同因。

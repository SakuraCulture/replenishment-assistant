# 0.33.0 rc1：批次库存与处理范围

已完成收敛方案的批次隔离、任务/导出衔接和兼容验收。独立分支 `feat/batch-stock-scope-0.33.0`。基线 `3a061518b4e75e40aeecc967527e52cab85b71be`；方案提交 `668c43a`，批次服务提交 `ae4a1cb`，界面及干净构建提交 **`d9709efb77399a34489f26294c63548698eb6424`**。证据另行提交，由本地标签 `v0.33.0-rc1` 定位；未合并、未推送。

## 实际变化

- 每次明确选择订单、顺序及每仓资料后建立分配批次。库存和占用按批次/仓/SKU隔离，下一批不扣上一批占用。原数值分配算法不改。
- 同一批的重试、停止恢复、局部重分配绑定原库存和原顺序；撤销同时阻止旧任务重启；开始另一批暂停原批未完成任务。
- 回传确认先进入待分配，准备批次后连续生成，不再自动按每家店单独启动库存池。旧未分批任务需要明确准备新批，不按日期/哈希推测迁移。
- 新生成单导出校验绑定本批，下一批更新库存不使它失效。回传变更、当前有效结果、撤销、锁单、付款/收货和现行准入保护保留。旧记录未改写，仍走原兼容校验。
- 订单跟踪进入聚水潭页继承日期、仓、锁状态和搜索；勾选则限定所选单。导出以当前筛选/明确勾选为范围，份数和金额同步显示。
- 新建、继续、重新分配与刷新列表分开。加载完成收起进度条；空结果给出原因和下一步。永久删除收进订单维护区；自动获取建议入口前移，签发保留一个主要动作。

首页待办重组、固定关键列、全局表格压缩属于UX审查后续阶段，本次未实施；未把整篇审查报告全部标为完成。

## 验证证据

`all-tests-final.txt`：692项完整回归通过，137.953秒。最终展示字段调整后又执行 `affected-final.txt` 的45项相关复验，通过；`backend-final.txt` 为此前24项批次/删除验证。`environment.json`：Windows x64 Python3.12.14，13项锁定依赖匹配，pip check通过。

新增 `tests/test_jst_batches.py` 为16项自建SQLite/Excel场景，无本机真实数据依赖。已有测试中“回传即逐单生成”和“聚水潭入口不继承筛选”的预期，依据本次已确认流程显式更新；不改变数值、准入或导出单元格预期来适配实现。

| 核查场景 | 实际结果 |
|---|---|
| A库存100，两店要40/80，输入顺序相反 | 按原回传顺序40/60；余额0；重复提交不多扣 |
| A占40，B选80，A未锁或已锁 | B预览80，保存80；A快照逐字段相同 |
| A尚未完成，B选60开始；随后恢复A | B从60开始；A暂停，恢复仍按自己的100分40 |
| 明确再次选同一仓资料 | 可建立独立新批，不靠哈希合并或拒绝 |
| 撤销40及后台队列再运行 | 释放至100；当前引用为空，旧任务不能复活 |
| 撤销尚未生成任务及提交在途旧预览 | 原预览拒绝；明确新建后可重新处理 |
| 局部重分配及重复提交 | 所选旧占用只替换一次；未选及旧快照保持；余额仍0 |
| 首店保存后停止，当前资料改1000 | 原批恢复第二店60，没有改用1000 |
| 首店注入提交失败 | 后店不抢库存；修复后仍40/60 |
| 两仓同一SKU，分别100/70 | 各自分40/70，不混扣 |
| 新批更新库存后重导旧批有效单 | 仍40件；值、类型、格式、列及文件顺序不变 |
| 新批当前资料标二类医疗、门店待核 | 分配0且无预留，准入未绕过 |
| 原批等待时回传改0 | 暂停并说明，无自动空转循环 |
| 删除已锁订单，批内还有其他店 | 清理成员和关联，已消耗库存仅在本批保留，防止再次分给其他店 |

同一批、同一冻结输入的独立新旧进程对照见 `comparison.json`：一仓10,000 SKU、10单合成样本，3轮AB/BA/AB逐个运行。全部生成字段按原顺序比较；Excel文件名、工作表/行/列顺序、值、类型、数字格式和单元格样式严格一致。**业务差异0，Excel差异0**，未排序重排、未放宽数值容差。

精确比较排除字段仅为生成快照顶层 `gid`、`operation`、`bid`、`saved`，以及新增的 `batch_id`、`batch_epoch` 审计标识。其余字段保留比较；不整块忽略元数据。新批不继承其他批预留是本次有意改变，独立场景验证，不把该变化称为“全场景数量不变”。

`protected-files.json`：model、allocation、one_box_exception、jst_allocation、默认配置、默认必卖清单、order_lifecycle共7个文件SHA与基线一致；旧0.32.2 EXE构建前后哈希一致。所有验证使用隔离资料目录；没有写日常用户库、原Excel、历史单或旧交付包。

`exe-report.json` 明确 `frozen_exe=true`，构建提交d9709ef。实际Windows EXE、原生Qt窗口、QThread及spawn读取进程验证了：

1. 导入槽读真实生成的合成Excel，选择仓；确认前不改全局库存。
2. 实际点击预览、确认、停止；40件保存后暂停，剩余单未写。
3. 关闭后重新进入原批；全局库存变1000仍分第二店60，库存替换控件禁用。
4. 实际选择批次，继承门店/仓筛选；1份/2份导出、重复导出严格一致；空筛选禁用，不导出隐藏单。
5. 导出中关闭等待安全停止；保存的生成单仍可再次导出。完成读取收起进度。

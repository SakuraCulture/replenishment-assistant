## 四条业务路径

| 使用目的 | 本版入口与完成结果 |
|---|---|
| 正常补货出单 | 拖入文件自动检查，进入门店核对，使用原计算队列；核对店仓、目录与签发差异，确认后签发并导出；完成区可打开目录、查看当日订单跟踪或继续作业。 |
| 订单生命周期落库 | 同一工作区拖入多订单、多环节文件；按单号自动识别，缺号付款按完整来源订单明确关联；预览订单×环节矩阵和逐商品差异，一次确认、整批事务保存。 |
| 异常或异议复查 | 按单号、门店或商品查找；同一订单详情切换签发明细、订单跟踪、决策依据。默认展示当时销量库存、有效参数、已有计算依据及后续数量；完整计算表、商品资料原表、内部签发明细仍独立导出。 |
| 参数维护 | 没有载入当日作业也可维护已保存门店的默认仓、预算和完整参数方案；保存默认与应用本次分开。保存默认不重算、不改变当前结果；并发修改默认时拒绝覆盖旧预览。 |

镜面名称统一为签发单、门店回传单、门店付款单、门店实际收货单。订单进度由实际资料推导，没有新增手工暂缓/恢复状态；没有把模型推荐另建为生命周期环节。

批量导入复用既有数量口径：0、空白、缺行的最终有效数量为0，同时保留来源区别；付款对照回传正数量，收货对照付款正数量。缺少整份上游资料时仅留存待核，不编造缺行0。同单同环节多份候选必须明确选一份，不相加；未识别或失败文件必须处理或明确排除。文件到达顺序可以逆序，核对仍按本单回传→付款→收货进行。

当前预览区每行有环节列，矩阵可点击定位。签发、生命周期数量及原文件分别留存；预览不写业务事实，取消不提交，失败整体回滚。最终事务提交不可强杀。备份/存储元数据可能在安全取消前产生，沿用原机制，不声称取消后数据库文件逐字节未变。

## 耗时与操作数

冻结合成样本：2仓、4件签发商品、4份来源文件。旧新版本同机同Python环境交替串行各3次；20毫秒采样当前进程及全部子进程RSS，未清系统文件缓存，不计人的阅读和确认时间。全部原始测量保存在 `lifecycle.json`。

| 环节 | 旧版中位数秒（最小–最大） | 新版中位数秒（最小–最大） |
|---|---:|---:|
| 读取 | 0.030（0.030–0.041） | 0.042（0.041–0.047） |
| 准备/核对 | 0.045（0.031–0.052） | 0.033（0.032–0.037） |
| 提交 | 0.025（0.023–0.028） | 0.027（0.027–0.029） |
| 取快照及导出 | 0.397（0.374–0.431） | 0.374（0.320–0.387） |
| 完整过程 | 0.496（0.471–0.541） | 0.475（0.423–0.501） |
| 采样峰值内存MiB | 49.52（49.49–49.61） | 49.41（49.35–49.44） |

总耗时中位数少约4.2%，但区间重叠且样本很小，只能认为这一样本基本持平。本轮价值是批量衔接与减少上下文重复填写；不能据此宣称真实大批量提速。读取和提交也存在波动或增加。

实际EXE验收是单轮功能测量，不作为旧新性能基准：自动检查0.55秒、两店计算0.57秒、签发导出1.27秒、混合单据导入0.44秒、打开复查0.93秒。整个演练11.11秒，50毫秒采样进程树峰值368.70MiB；Qt计时器最大间隔1.01秒，不能宣称全程零阻塞。重启恢复2.02秒，峰值203.11MiB。两个窗口逻辑尺寸1380×900和1080×720已截图检查；Windows显示缩放使截图像素尺寸更大。

自动化路径记录的业务操作组：

- 补货：拖文件→开始计算→签发导出→确认店仓范围→确认签发差异，共5组。仍保留范围与差异两次明确选择，尚未达到设计目标3组。
- 生命周期：拖4份文件→给缺号付款整单关联一次→打开预览→核对完整范围→保存，共5组。已知单号不重复填写；全部带号则不需要关联这一步。
- 复查：搜索订单→打开决策依据，共2组；上下文直达可少一次查找。
- 默认设置：选择门店→编辑默认→确认逐店差异。实际参数表单与持久化经过EXE测试；测试自动批准了固定的默认变化确认，不能称真人逐按钮操作验收。

这些不是用户操作观察，也不包含阅读、输入和业务判断的时间。尚不能宣称已达到“极致低认知成本”。

## 已知限制

- 真实付款ERP工作簿仍未提供，付款原表适配只验证截图同表头合成样本。任意表头或标题行不保证自动识别，失败时必须明确映射，不能猜字段。
- 没有限定订单的批量关联目前读取可关联订单集合；长期大量历史下的目标选择性能未做大规模基准。
- 历史缺失的原附件、参数或归因不会用今天资料补齐；没有实现历史算法多版本重放器。
- 当前预览矩阵表示“本批拟处理”，未提供环节是否已有有效资料仍由订单跟踪显示；没有把未提供误判为数量0或未完成。
- 没有新存储格式、云同步、自动催办、部分单业务或收付款执行。全新电脑复现构建未新增验收。
- 用户真实使用体感尚待试用；本轮已验证功能闭环，不能用自动化测试代替真人观察。

# 补货助手 0.52.1 rc6：数据位置与整库搬迁

本版在独立工作区整合0.52.0业务功能、0.51.10迁移退出与实例识别修复，并增加数据保存位置设置。当前操作未搬迁真实业务资料；真实库仍在原位置。未提交、推送、正式合并或自动替换正在使用的软件。

## 怎么使用

完整解压本包，打开“补货助手.exe”。保存草稿并等待业务任务结束，正常关闭采集专用浏览器，在“显示与帮助 → 数据保存位置…”选择D盘等本机磁盘的独立空文件夹。核对确认框后安全退出，校验、搬迁、归档后默认重开。第24章图文手册随包更新。

搬迁涵盖应用资料目录内的订单及修订、原件、回传、运营签发、分配、付款、实收、平台关联、参数、独立缺货率、日志、AI登记、专用浏览器和既有备份/待迁入材料。目录之外的Excel文件保持原位，导出位置另设。仅用于同一电脑、同一Windows用户；换电脑仍走原有完整订单迁移流程。

恢复ZIP保存在新盘的资料目录旁；逐文件核对归档后才清理旧副本。C盘保留少量启动控制、实例保护及兼容链接。请勿手动删除旧位置链接或并行打开旧版。新盘不可用会报错，不回C盘建立空库。归档未完成时保留旧完整副本，可在本页继续清理。本版无一键还原ZIP入口，恢复需单独核验。

## 安全边界与实现

采用持久计划和阶段记录：准备→等待安全退出→复制/数据库校验→提交位置→归档→完成/待清理。持久定位与诊断保存在可搬迁目录之外，退出阶段不构造Qt窗口；正常启动再报告结果。

仅允许当前启用的完整资料作为来源；独立环境变量启动不自动搬迁上级目录。持有原应用实例保护，协同关闭后台连接，不强杀提交任务和浏览器。流式复制并逐文件核对SHA-256，验证SQLite完整性及已提交WAL；不重写单据或历史路径。改名前后的来源均核对，捕获解除数据库锁至目录改名间的晚到提交；失败恢复原位置，保留已复制材料。

旧位置用目录兼容链接指向新位置。经搬迁凭据批准的物理路径变化才对聚水潭浏览器绑定等价，账号、公司、仓及防重事实保持原规则。本机AI环境身份保持稳定。恢复副本含本机登录资料，应妥善保管，不能给别的电脑或用户直接使用。

## 保留的失败证据

1. 首轮原生测试的Windows KnownFolder未采用隔离环境，误打开正式资料并开始向QA目录复制。在COPYING、尚未改名/写位置指针前，核实并停止自有测试进程33384；两份原库quick_check均ok，父单数仍2和18。原目录未移动、删除或替换；未以启动前逐文件快照验证常规启动元数据/日志是否变化。已统一自动路径解析，增加打开库前、测试操作前及后端当前资料身份校验。误复制约187 MiB的未完成QA副本未进入任何交付包；用户明确允许删除后仍被自动审批以“blocked by policy”拒绝，现仍保留。
2. 首轮WAL测试错误假设“活跃句柄存在时Windows也能改名”；已拆分为活跃占用必须阻断、无活跃持有人的已提交WAL必须完整搬迁，保留原失败日志。
3. 全量回归第一次1676项中1项默认路径接口兼容失败；保留原测试预期，修复自动路径与显式默认路径的区分，52项定向通过。
4. 第二次全量1678项中1项被同时运行的自有EXE验收进程阻断。PID29316在原生验收日志中可追溯；保护正确生效。关闭验收后该用例串行通过，最终全量另按串行执行；没有绕过实例保护。
5. 新增晚到提交复现测试先失败，补上切换前后复核；随后发现保护连接关闭时SQLite自身checkpoint会造成WAL字节变化的合法场景。仅对本次读保护连接停用关闭时checkpoint，保留完整WAL与原校验，27项搬迁后端通过；未改数据库日志模式或业务事务。
6. rc1构建因依赖目录是链接被原有完整性门禁拒绝，改用已核实的物理依赖目录，门禁保留。rc3/rc5期间源码发生修复变化，封版校验主动拒绝，均不作为最终交付。原生运营脚本第一次因输出不在允许QA根目录被拒绝，改用允许的隔离目录，未删除保护。HTML初测误把空放大预览图作为正文图片等待，修正为核对全部53张正文图片后通过。

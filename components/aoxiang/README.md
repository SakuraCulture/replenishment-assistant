# 翱象补货建议助手 0.2.1

Windows x64 受控测试版。使用本机已有的 Edge 用户配置及正常登录状态，导出指定仓店的补货建议，以及采购管理中的已有采购主单、商品明细。双击 `启动.cmd` 进入中文菜单；无需安装 Node、npm 或 Python。

0.2.1新增最新采购导入模板获取。菜单“9”输入`template`，或运行`启动.cmd purchase template`。程序从当前采购页面的原生按钮获取模板，核对字段及填写规则，并按文件哈希保留原版。受控导入的准备步骤也接入了自动获取，不再依赖手动维护的日期模板路径。

0.2.0新增菜单“9 采购单”。按仓店和自然日分别取得原生主单、商品明细，并核对主子单关联、逐单商品种数及日期范围。当前原生主单25列、商品明细43列；保留原始文件和原始重复明细。采购记录纳入迁移包，已知任务恢复下载，受理未知禁止重提。

0.1.1修复导出成功提示出现较晚时遮挡“历史记录”的问题。默认使用后台作业标签，不需要持续将网页放在前台。它通过Playwright/CDP操作网页元素，不使用屏幕坐标或控制系统鼠标。

0.1.1已在当前真实登录账号上实测郓城：后台复用后单次重导任务11374081完成，查询、任务成功数和原生文件均为16,035行、54列；旧日文件备份与新文件哈希均通过。实测使用发行包的独立浏览器执行器和作业引擎，未重走首次配置向导。

后台标签仍依赖已打开的Edge。首次配置绑定、远程调试授权及正常登录可能短暂显示页面；完成后关闭程序自己的绑定页，在同一已核对用户配置中新建后台作业标签。没有复制浏览器会话，也没有把正在使用的Edge改成无头进程。

升级时先从旧程序菜单输入`0`退出；若停在错误后的继续提示，先输入`q`回到菜单再输入`0`。解压0.2.1到新目录，双击其中的`启动.cmd`；本机配置、已知任务和已验收日文件沿用。首次使用采购能力会先备份本机状态库，再升级为版本2；旧0.1程序会拒绝读取新版状态，避免遗漏采购未决任务。不要同时运行两个版本。

已实测五莲、曹县、梁山三个仓点的导出与文件验收，并验证当日整批复用不新增导出任务。当前平台文件是“商品补货建议V2”，54列；旧52列仅用于恢复历史任务。

完整的双配置、两台Windows迁移验收尚未完成，请结合 `实现与验证.md` 和 `验收记录.json` 使用本测试版。

## 首次使用

1. 在本机 Edge 的已有用户配置中正常登录翱象。
2. 双击 `启动.cmd`，选择“连接与配置”，从程序发现的已有配置中选择目标配置。
3. 按提示在该 Edge 打开 `edge://inspect/#remote-debugging`，启用当前实例的远程调试；出现连接提示时允许当前这次连接。
4. 程序核对实际 Profile path、翱象账号和商家，再选择接收仓店点和本机输出目录。
5. 选择“开始运行”。同一日已有合格文件会显示“复用”；需要刷新时选择“重新导出今日文件”。

程序使用原生查询、全部商品页签、全部信息导出及任务历史。一个独立接收仓点只导一份；直接从“仓库/门店”选择时，不会把仓码当作经营门店编码。

## 常用命令

在程序目录打开终端：

```text
启动.cmd doctor
启动.cmd setup
启动.cmd targets --warehouse-name "翱象中显示的仓店完整名称"
启动.cmd run --batch default
启动.cmd run --batch default --foreground
启动.cmd run --warehouse-code 已保存的接收仓编码
启动.cmd resume --run 作业ID
启动.cmd rerun --warehouse-code 已保存的接收仓编码
启动.cmd results
启动.cmd help
```

`setup`、`targets`仅查询和保存配置，不创建导出。`run`只运行已核对并保存的对象；不会把没有配置的编码加入任务。

`--foreground`用于显示网页诊断；默认是后台标签模式。业务配置也可设置`browserInteraction.mode`为`background_tab`或`visible_tab`。后台模式仍会核对实际Profile path和业务身份，失败会停止，不会自动换到其他配置。

结果默认保存在系统“文档”文件夹下的 `翱象补货建议`，按商家、日期和仓点命名。作业CSV、JSON、日志和恢复状态位于 `%LOCALAPPDATA%\AoxiangReplenish`。移动程序目录仍使用同一份本机状态，不要手动删除状态库。

## 采购主单及商品明细

菜单选“9 采购单”，再选`export`。默认按**制单时间**筛选；日期是上海时区自然日，两端包含。`updated`按**更新时间**筛选；它与表内“采购日期”不是同一字段。

```text
启动.cmd purchase export --warehouse-code YCD20251613 --warehouse-name "优团生活·精品超市（郓城店）" --from 2026-10-01 --to 2026-10-31
启动.cmd purchase export --warehouse-code YCD20251613 --warehouse-name "优团生活·精品超市（郓城店）" --from 2026-10-31 --to 2026-10-31 --date-basis updated
启动.cmd purchase export --warehouse-code YCD20251613 --warehouse-name "优团生活·精品超市（郓城店）" --from 2026-10-31 --to 2026-10-31 --order-id PO202610311151281572
启动.cmd purchase list
启动.cmd purchase resume --run 采购作业ID
```

已在仓店目录保存的编码可省略名称；其他编码必须同时给出页面中的精确全名，程序用原生选择器和实际查询请求核对。一个日期范围自动分成逐日切片，每片依次导出主单及商品明细。正常运行先恢复或复用同范围作业；需要获取更新内容时显式加`--rerun`，另建一份快照，保留原文件。

输出位于本机输出目录的`采购单/商家编码/仓码/日期_时间口径/作业ID/`，含两份原生XLSX和`验收记录.json`。D16“采购单号”关联D17“采购订单号”。主单金额是订单粒度，明细中的订单总金额会重复，不能按商品行直接求和。明细保留基础单位、包装单位、箱规、采购及入库数量和金额。

每片先翻页取得可见主单号全集，再对照主单导出集合；明细必须全部归属于这些主单，逐单商品编码去重后的种数须与查询及主单一致。相同订单同SKU的物理重复行原样保留。明细创建/更新时间还须落在对应筛选日。文件大小、ZIP CRC、精确表头列位、仓码、任务成功数、长编码及SHA256均校验后才发布成对文件。

平台真实最大导出数量和跨多日最大窗口尚未测定。本版采用逐日切片，并设置每片3,000张主单、500,000行校验、64MiB单文件的工程限制；这些不是平台限额。采购原任务文件由浏览器上下文的认证GET下载并缓冲，补货建议仍使用签名结果流式下载。超保护值、表头变化、主子单不齐或任务失败会停止并保留原任务。采购历史页当前仅查询近30天任务；任务超出可见历史时不会自动重提。

当日查询无可见主单时只写零查询记录，不提交任务或制造空Excel。该结果受当前账号权限限制。新店、被删除单据、权限外单据不推断为业务零值。

## 最新采购导入模板

```text
启动.cmd purchase template
启动.cmd purchase template --json
```

使用已绑定Edge的现有登录，在“采购管理 → Excel批量导入创建 → 下载导入模板”获取当前文件。此命令不选择上传文件、不确认导入、不创建采购单。当前实测模板12列，表头第7行，基础单位数量从第8行填写；原生文件内包含样例行和隐藏选项表，原样保留。

每次调用都会重新向平台获取；本地已有相同哈希只复用归档副本。文件在输出目录的`模板/采购单/商家_身份摘要/原生版本/`，`latest.json`记录本次状态、时间、来源及哈希，每次获取另留记录。格式或压缩元数据变化且语义一致时自动接受；字段、列位、单位说明、外部订单选项、命名范围或样例行位置变化时，保存新文件并停止导入准备。下载失败、账号不符、模板损坏时不使用缓存继续导入。

当前页面显示一次最多添加12,000个商品，模板下拉校验范围为K2:K3001，两者分别记录，不能把校验行范围当作平台数量上限。真实临界及超限导入未测试。模板受10MiB文件、64MiB解压的本地保护值约束。

开发接口`PurchaseTemplateService.prepareImport()`在每次准备时自动获取并核对模板，已接入逐单受控测试的`prepare-case`，生成和封装步骤只读取本次记录中的模板路径及哈希。本次新增能力只实测取模板，没有再次执行业务导入；通用批量采购导入命令尚未发布。迁到新电脑后使用新机正常登录重新获取，模板缓存不随迁移包充当现行依据。

## 迁到另一台电脑

```text
启动.cmd migration export --file "D:\迁移包.zip"
启动.cmd migration export --file "D:\含结果迁移包.zip" --include-results
启动.cmd migration preview --file "D:\迁移包.zip"
启动.cmd migration import --file "D:\迁移包.zip"
```

先将程序发行目录复制到新电脑，再导入迁移ZIP。新机向导会重新发现本机Edge、已有配置和文档路径，并核对同一翱象身份。新机需要自行正常登录，迁移包不携带浏览器会话。

默认迁移业务配置和必要恢复记录；`--include-results`可附带已验收文件，导入时重新核对相对路径、哈希、实体和行数。导入不立即导出。已知未完成任务使用 `resume --imported 记录ID` 接续；无法证明受理情况的记录会继续阻断该仓点。

有采购记录时使用2.1迁移格式，携带采购主单、明细的全部任务记录及冻结查询；`--include-results`同时携带采购原生文件。采购作业使用`purchase resume --run 原采购作业ID`恢复；仅迁移记录而未携带文件时，恢复原任务下载。采购UNKNOWN记录迁入后继续阻断，旧迁移包不会抹掉本机的UNKNOWN。

正式迁出会停止本机执行器并将本机标为交接状态。仅复制配置快照可加 `--snapshot`；快照不代表源机已停止。需要在本机继续执行时，确认其他电脑停止同一商家批次后运行：

```text
启动.cmd migration confirm-handoff --source-stopped
```

没有跨电脑全局锁；同一商家同一批次应约定一台执行电脑。

## 出错时

- 使用 `resume` 继续原作业。已知任务只下载原任务，提交结果未知时禁止再次点击导出。
- 文件被Excel/WPS占用时，关闭该文件后继续；原日文件保持，恢复只完成本地保存。
- 已登记日文件缺失时，正常运行会恢复原任务文件。用户修改过的文件不会被自动覆盖。
- Ctrl+C停止后续作业并释放自有连接和标签，不关闭整个Edge。补货交互命令发生错误时保留连接，按提示继续原作业或退出；采购命令出错后用原作业ID恢复。
- 实际账号、字段、筛选或文件行数不符时停止并保留证据；零行、超限细分和多分卷暂不自动认定成功。

浏览器授权和正常登录仍由用户在本机完成。程序不修改补货参数，不加入补货单，不创建采购或调度任务。

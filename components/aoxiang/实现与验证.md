# 实现与验证

2026-11-01，版本0.2.1，受控测试版。

## 0.2.1最新采购导入模板

命令`purchase template`通过独立browser-worker复用当前已绑定Edge及同一账号。PurchaseUI打开原生“Excel批量导入创建”窗口，只点击“下载导入模板”，观察实际GET来源，再以浏览器上下文认证GET保存精确文件，拒绝重定向、错误页和超过10MiB的文件。不固定模板V2地址；后续版本号变化且结构兼容时可直接接受。取模板期间拦截导入任务的写请求，不选择文件、不点确定，并取消空窗口。沿用原有背景标签，不改用户Edge下载设置或登录。

`purchase-template.mjs`用ZIP CRC和XML解析核对主表、12列表头及列位、基础单位及金额说明、样例行位置、隐藏枚举表、数据校验和命名范围。原文件按商家身份及SHA256归档；语义摘要不包含ZIP时间戳或样式。`latest.json`只作本次结果索引，导入准备始终重新获取，失败时无离线回退。新语义文件原样保存并返回NEEDS_REVIEW；受控导入的准备步骤因此停止，不能把不兼容更新当作普通模板替换。

实际受控准备脚本已调用`prepareImport()`；其构建和保留原生封装脚本改为显式本次目录，并读取本次自动获取记录的模板路径和哈希，去除历史日期路径默认值。已完成测试的旧单和旧文件未再次运行。该接口和下载命令属于本版；通用批量导入命令尚未发布。

新增7项检查，覆盖相同文件每次重取、失败不回退、样式更新、字段/填写规则/隐藏表/命名范围/样例行漂移、缓存被修改、身份不符及暂停；隔离Edge验证原生按钮选择、取消空窗口、HTML拒绝和PUT拦截。全套52项通过。真实登录的正式CLI命令已取得6953字节原生模板，SHA256为44c4f65dbbb82ae03244c9a2e1427b8a1c44cddbb8eef8857017c8009902eefa，12列、隐藏选项表保留、导入提交数0。平台页面数量提示12,000与模板校验范围K2:K3001分别保留；没有进行临界或超限导入。证据在`dev-evidence/template-cli-live-0.2.1.json`和`验收记录.json`。

## 0.2.0已有采购单导出

业务入口为采购管理`#/chain/order/purchase`，只查询、导出已有单据。D16使用“导出主单”，D17使用“导出子单明细”，不涉及补货建议生成采购单，也不创建、修改、作废、结算或发送消息。

采购页使用Fusion的`next-*`组件，适配器独立于补货建议的AntD组件。制单时间控件`#date`映射`start/end`；更新时间`#modifiedDate`映射`modifiedStart/modifiedEnd`。原生确认框是`.next-dialog-quick`，确认文字为“确认现在导出吗？”。输入弹层日期后须按Enter提交控件内部状态，再点弹层确定。导出筛选与查询完全一致时才接受任务号，保留原生`orderType=3`和`merchantSubBizType=CONSIGNEE`隔离范围。

当前原生主单25列，新增末列“制单人”；旧24列样本不充当现行契约。商品明细43列，但与旧43列的字段顺序、名称不同，按本次新导出文件固化。D16第1列采购单号关联D17第1列采购订单号，D17第8列仓码、第13列商品编码、第41/42列创建/更新时间。主单计数、主单号集合、逐单商品种数、子单关联和日期均复核；不按订单+SKU删除物理明细。

采用逐仓逐日切片，默认制单时间，可指定更新时间及精确采购单号。固定保护值为3,000张主单/日、500,000行校验、64MiB单个原生文件；它们是工程限制，平台真实最大行数、最大时间窗口及超限行为未验证。可见父单为零时只登记查询记录，不生成虚构Excel。当前历史页原生查询参数为近30天，不能保证更早任务可恢复。

采购旧GEI任务号为复合文本。其历史记录`fileUrl`实际是任务名`.xlsx`，并非带签名的OSS地址；现场下载按钮发出`/gei/import/task/errorFile/{taskId}`的认证GET。本版复用已核验浏览器上下文请求该精确原任务，拒绝重定向和下载机制变化，原生字节不改写，不读取或迁移Cookie。该方式会缓冲原生文件，区别于D13流式下载。

采购状态独立存入同一SQLite库的`purchase_runs`，首次启用先做一致性备份和校验，再升级库版本1→2；旧0.1程序拒读2，避免未决任务被旧版迁移遗漏。每种导出在操作前记录意图与SUBMITTING，受理ID不可替换；UNKNOWN及错误范围阻断继续提交。已知任务恢复原下载，本地保存失败只恢复原文件；输出作业ID目录避免覆盖旧快照，发布前完成主子单成对验收。

迁移格式2.1携带采购冻结范围、原任务、未决状态和可选原生文件，有记录数量及集合哈希；2.0仍兼容既有D13迁移包。迁入先保留未决记录再做新机绑定，原机/新机交接沿用原规则。采购文件重新核验，发生同任务ID冲突或文件哈希冲突时保留现场。

本次真实样本为郓城`YCD20251613`、2026-10-31，采购单`PO202610311151281572`。第一组已有受理任务由正式协调器恢复下载、校验和发布；随后正式适配器与协调器另做一次明确重导，各提交主单、明细任务1个并验收。最新主单任务`GEI@SAAS-CHAIN-PLAN-QZC-SUPPLY-PURCHASE-ORDER-FOR-MAIN-ORDER-EXPORT@261101162035@8516`成功1行；明细任务`GEI@SAAS-CHAIN-PLAN-QZC-SUPPLY-PURCHASE-ORDER-MULTI-UNIT-EXPORT@261101162048@1441`成功259行，失败均为0。原生文件分别25列和43列，逐单259种商品与查询一致，主子关联无孤儿。源代码在原有一条授权长连接内运行，没有为独立worker另建一次现场授权连接。开发证据在`dev-evidence/purchase-resume-acceptance.json`、`purchase-rerun-acceptance.json`。

只读查询另验证2026-01-01至10-31的345张可见主单，共12页，枚举345个不重复单号，没有为这段期间提交导出。更新时间10-31查询确认`modifiedStart/modifiedEnd`映射，返回1张单据；按更新时间提交新的原生导出文件未独立实测。最终45项测试通过，包含采购恢复、文件被修改后的显式重跑、UNKNOWN迁移后阻断重跑、Fusion确认提示及同名仓店定位。业务配置现场前后完全一致，采购未决数为0，结束后释放自有连接。

## 0.1.1修复与后台标签

现场错误为：任务受理后，程序立即用`isVisible()`检查“我知道了”按钮；React弹窗晚于该检查出现，遮挡后续的历史记录按钮，最终发生等待超时。新版为这个特定导出提示注册动作前处理器，在历史按钮可操作性检查时关闭提示并等待其消失。不关闭其他业务确认弹窗，不使用强制点击穿透遮罩，也不重提导出任务。

默认使用后台标签。原生打开的短期绑定页先证明物理用户配置，然后在同一browserContext中创建`background:true`作业页，再次读取实际Profile path。关闭自己的绑定页后，作业页保持后台渲染；不将用户整个Edge最小化、隐藏或关闭。需要观察页面可加`--foreground`。

新增隔离Edge组件测试：迟到提示、无关确认弹窗保留、后台标签归属、渲染会话和自有页面清理。测试使用独立临时空配置，无用户登录信息；不把它当作第二套真实商家配置。此前现场三仓结果属于0.1.0，保留为已有能力证据。

随后按用户要求完成真实登录账号实测：确认旧版无未决任务后停止其空闲CLI，原worker通过IPC断开释放连接，Edge保留。使用0.1.1发行包中的BrowserClient、独立browser-worker和Coordinator，核对Profile 1物理路径及账号后，以后台标签对郓城先复用再单次重导。复用没有新提交；重导只新增任务11374081一次，查询16,035行、任务成功16,035行/失败0行、原生文件16,035行/54列，文件只有YCD20251613一仓。

导出后历史记录自动轮询成功，最终页面只有历史记录弹窗，没有出现原先遮挡按钮的错误，未做手工页面恢复。新日文件发布成功，旧任务11372232的文件在`.staging/backups`保留并核对原哈希。配置文件哈希未改变，worker锁释放，原Edge主进程仍在运行。本轮没有重走首次配置向导，也不替代双真实配置和两台Windows验证。详细结果见`验收记录.json`及开发目录下`dev-evidence/live-background-0.1.1.json`。

## 已实现

主进程负责中文命令、配置、SQLite状态、流式下载、文件验收及发布；独立浏览器工作进程保持一条已授权连接。固定随包 Node 24.22.1、Playwright Core 1.62.1，不依赖系统PATH或安装开发环境。

Edge安装、已有用户配置及系统文档路径自动发现。用一次性本机标识页选定标签，再在同一标签读取实际Profile path；随后核对翱象账号和商家。只控制程序自有标签。自有标签保持渲染，关闭时释放；不修改共用浏览器的下载目录或下载行为。

每个仓点先重置并查询，绑定本次实际发出的查询请求，读回单仓编码、全部商品条件和总行数；提交前复核表单。意图及SUBMITTING状态落盘后才允许点击原生导出。受理响应按实际请求关联意图，精确任务号落盘；列表缺失、超时和断线不触发重新提交。

已知任务结果使用临时签名地址直接流式写入自己的暂存目录，不发送浏览器Cookie或Authorization。限定已验证的HTTPS结果主机、任务路径和同一对象；处理403后只刷新同任务地址。

原生XLSX字节保持不变。检查ZIP魔数、CRC、工作表、列位、仓码、实际行数、关键键、长编码和SHA256；不依赖错误的dimension，不合并重复毛利列，不按SKU粗暴去重。实际文件行数还必须与任务成功数及原查询行数一致。

同日合格文件复用并保留原采集时间；文件缺失恢复原任务。显式重跑验证新文件后，记录发布意图、备份原文件并替换；失败保留旧文件，恢复不重新导出。

本机协调器和浏览器执行器各有独占锁。状态损坏、缺失或未知版本时停止，不重建空状态库继续导出。作业结果输出CSV/JSON，日志隐藏签名地址、密码和会话内容。

配置、必要未决记录和可选已验收文件可导出迁移包。迁入先记录未决证据，核对配置差异，再重新绑定本机环境；已知任务携带冻结日期、范围和行数，旧版缺证据的记录保持阻断。结果文件重新核验，冲突保留。恢复集合有独立数量和集合哈希，避免删减记录后以空包解锁。

## 相对原开发规格的明确补充

1. 当前平台已经使用V2原生54列、基础/包装单位分列；新任务使用D13-all-info-2，历史V1仍按52列契约恢复。更换字段版本不解除同仓未决阻断。
2. 允许直接选择已核对的接收仓点，经营门店引用可以为空；不伪造经营店到仓的映射。真实经营店关系自动同步及一仓多经营店的现场映射验收仍未完成。
3. 任务受理接口现场使用sc-gei业务主机，与历史查询主机不同，均使用原生页面发出的请求进行识别。
4. 迁移恢复记录补充冻结查询、日期、原运行模式、口径版本；在新机恢复原任务，不拿当前查询冒充历史快照。
5. 导出前按文件工程保护上限预留暂存与发布空间。默认压缩文件保护上限1GiB，不是平台限额。布局模板及资源参数可在业务配置中调整，未知字段会拒绝。

原方案文档保持只读，本补充说明实际实现与变更依据。

# 0.53.4 订单计数与采购本地预检

## 查询数量不同，先看未显示原因

在订单跟踪及回传、运营签发、付款、收货工作页，查询提示区分三种数量：

- 日期/关键词范围：符合日期和搜索的有效仓单总数。
- 符合当前筛选：再按本环节、限定所选订单、仓、锁状态及进度筛选后的数量。
- 本页显示：当前分页实际显示的行数。

例如范围13单、当前筛选12单、本页12单，表示1单未符合当前筛选，并不等于新增或删除了一张订单。点击“查看未显示订单”，可查看该单的补货单号、门店编码和名称、仓、当前进度及全部实际排除原因。原因可以同时有多项。改变筛选后重新查询，入口随当前查询更新。

“本环节全部”包含正在等待本环节的订单以及已经留存本环节单据的订单。旧流程没有运营签发记录的待付款单，不会仅因待付款而出现在运营签发列表。列表仍保留原排序、分页和业务选择范围；回收站及已删除的订单不会因为这个说明入口重新出现。

## 采购预览先检查本机付款，再核验浏览器

从付款核对选择订单并生成翱象采购预览后，程序先在本机只读检查付款依据。检查未通过的项目显示具体原因；不会为该项核验登录、获取模板、预留或上传采购任务。这避免一批本地准备不合格的订单逐单刷新翱象页面。

本地检查通过的项目仍按原流程逐项核验当前登录身份，冻结付款数量金额并生成预览；确认上传时再次检查依据。预检通过不代表允许使用后来已改变的付款资料，也不会自动确认付款。

## 按具体原因继续处理

| 原因 | 含义 | 下一步 |
| --- | --- | --- |
| 当前签发下尚无付款资料 | 没有对应有效签发修订的付款单 | 在付款核对导入或确认本单付款资料，再重建采购预览 |
| 付款资料已留存、尚待核对 | 上游未就绪时保存过付款资料，仍处于待核留存 | 先处理提示中未就绪的上游，再在付款核对重新核对本单 |
| 上游未就绪或依据变化 | 回传或运营签发仍需核对 | 按提示先核对对应环节，再核对付款单 |
| 付款对照依据已变化 | 当前上游与付款留存的版本或摘要不同 | 查看提示中的环节及旧/新版本，在付款核对重新核对本单，再重建采购预览 |

“依据变化”不按日历日期判断。11月11日的有效付款单可以在11月14日处理。相同版本号下摘要不同，也会明确提示内容摘要变化，不以版本号相同代替完整校验。

只有未建立平台采购任务的本地准备项，才提示“未进入上传，可结束本地准备”。已经发起或受理的旧任务仍沿原任务核对；这次修改不重发、不撤销平台采购单。

## 版本与范围

本版保留0.53.3 rc2的分配恢复和备用商品放行。计算模型、数量、价格取舍、箱规、预算、默认并发、单据依赖、旧流程路由、并发修改检测、取消、删除保护和平台防重规则均沿用原逻辑。修改只涉及查询解释、本地检查顺序和错误说明。

请完整解压独立包，在业务安全结束后正常关闭旧版，再打开新包中的“补货助手.exe”。旧交付包保留；不会替换正在使用的软件，也不会自动重放业务任务或改写付款事实。

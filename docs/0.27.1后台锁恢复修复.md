# 0.27.1：维护与后台队列锁冲突修复

修复 0.27.0 中一次 `database is locked` 使后台持续停止、后续删除被“没有调度权”拦住的问题。模型 0.3.3-rules、仓归属 0.5.1、已有数据格式和删除范围不变。

## 现在怎么处理

- 订单/草稿维护开始到预览确认、取消或执行结束期间，暂缓新的后台调度写入。事务仍按原范围整体提交或回滚，实例互斥锁不移除。
- 数据库暂时繁忙时显示“2秒后自动重新检查”；轮询采用零锁等待，不在界面线程等10秒，不创建新采购身份或重复提交不明任务。
- 锁释放后自动恢复轮询。真正的结构等错误保留具体原因，并记录日志。
- 首页增加“重新检查后台”。另一实例退出后可用它重新申请后台调度权；真实队列故障处理后可重新核对原任务。
- 另一实例还持锁、平台任务未安全退出、程序正在关闭时仍会阻止维护。不能靠反复点击绕过保护。

本地维护检查后台所有者和当前写入任务，不再把队列故障状态一概当作没有删除权限。关联数据在确认后再次校验，状态变化时拒绝提交。

## 不变与未纳入范围

计算规则、参数值、数量金额、签发和Excel导出没有调整。订单永久删除仍按门店＋日期、包括两仓共享父单；没有新增回收站。外部平台订单及被其他业务引用的原件仍保留。

“本机采集记录”的单项移除/整批清理是另一处已识别缺口，本次只修锁冲突，没有新增该功能。真实翱象受理不明记录不自动重发。本轮平台测试使用隔离数据及禁止外部派发的测试队列。

## 验证与试用

新增锁竞争、空闲只读、自动恢复、维护退出、结构错误、另一实例持锁/释放、关闭保护、写锁后重核到期计划测试。EXE验收保留实际Qt队列定时器运行，检查UI心跳、锁释放恢复，以及删除预览取消/确认、另一店结果保留。验收证据和构建哈希见 `releases/0.27.1/rc1`。

试用时先正常保存、退出旧版，避免旧版仍持有后台锁；从新目录运行完整程序。若保留另一个窗口，首页会明确显示占用，待其正常退出后点“重新检查后台”。不要删除锁文件或强杀正在提交的任务。

```powershell

.venv\Scripts\python.exe -m unittest discover -s tests -p test_queue_lock_recovery.py -v

.venv\Scripts\python.exe tools\verify_maintenance.py compare --qa qa\queue_lock_0271
.venv\Scripts\python.exe tools\verify_maintenance.py exe --exe '交付_0.27.1_rc1\补货助手\补货助手.exe' --fixture qa\aoxiang_integration_20261101\inputs --output qa\queue_lock_0271\exe-new-run
```

# 0.32.2 任务快照与聚水潭依据修复

基线：0.32.1 `9f302f241c5979c1e23dc40d4ab55f96a5020d19`。独立分支 `fix/restored-profile-retry-0.32.2`；本轮不合并、不推送，不覆盖旧交付、用户资料或既有签发。

## 五项问题与边界

1. **恢复后重跑必卖清单串用**。输入、参数、必卖清单和待重跑队列作为一组任务缓存清理。恢复当天作业后的首次重跑从已恢复内容建立完整快照；同任务普通重跑仍沿用该任务的快照。新建、重新检查输入、删除当前工作区订单时使用同一个清理入口。未重跑门店原结果不变。没有修改历史草稿存储格式，也不自动重算历史单。
2. **新分配准入标签回退**。已保存的当前仓商品资料优先作为准入标签依据；该仓未维护默认资料时，才采用本次明确选用的库存基准资料作为准入依据。缺列、缺商品不能回退到旧标签伪装成无标签。两仓任一当前依据明确含“二类医疗”仍触发资质审核。库存数量、价格、箱规保持分配选用的冻结基准；当前默认资料更新不会重置库存账或改变历史预留。生成快照的 `catalog` / `bid` 记录库存依据，`admission.catalog_revisions`、`catalog_sources` 记录准入资料版本和来源，`context` 记录门店准入版本。后续新安排按新依据检查；不自动撤销既有订单。
3. **普通导出入口不一致**。生成面板的手动导出、保存后自动导出及其他按所选单导出均经 `jst_exports.export_checked`，检查生成单、签发、回传、锁单及库存基准后再调用结果页共用服务。依据变化后提示到结果页核对，不输出旧单。结果页“其他订单操作 → 导出勾选旧结果（需核对）”继续单独确认，文件名加 `_旧版本_<生成标识前12位>`，四列及原数量不改，避免覆盖正常文件。
4. **最低模板缺标签**。仓资料两个模板入口统一使用带“商品标签”表头及填写说明的模板。导入缺列旧资料仍保留原值及兼容读取，但在采用/保存时提前提示执行字段待补。列存在、单元格为空是无标签；整列缺失仍是未知，不能自动补成空标签。
5. **逐单重复解析全仓资料**。一次提交首次完整读取及校验仓资料移到数据库写事务前；后续逐单只核对文件身份、大小和纳秒修改时间等标记。支持的资料写入和分配提交使用相同仓级文件锁，按固定仓顺序先取得文件锁，再进入数据库事务；最后提交前再次检查。缓存仅存版本及文件标记，限本次调用，不新增持久缓存。更新、删除、损坏或准入记录变更仍拒绝旧预览；原逐单部分成功、同仓停止和更正整批原子性保留，不改成并行写库。

普通导出在校验完成时固定生成标识；此后其他窗口产生新版本，不将已开始的文件悄悄换为新版本。底层 `jst_exports.export` 是既有不可变快照写表工具，保留内部/历史兼容调用；普通UI不得直接调用它。更正后原版本仍可读取，不回写旧数量。

## 本轮验证与性能口径

专项先在原实现复现，再修复；原失败记录保留。676项既有及新增回归通过。新增6项任务恢复和12项聚水潭依据测试；覆盖0预算/不限预算、复制及拥有型恢复、同批重跑、两仓医疗标签、缺标签、库存与价格冻结、逐单更新、最终提交前异常变更回滚、受支持资料写入等待提交边界、旧结果重导和模板。

单仓10,000 SKU合成样本，1/10/30张订单，固定同一数据库、同一预览、同一Python/依赖，AB/BA/AB交替串行，各3次。计时包含准备结果验证、安全备份及提交；不含预览生成和Excel写出。OS文件缓存未清，不代表冷盘性能或真实门店全链路耗时。

所有新版本整仓读取均在写事务外。该对照的新旧提交记录、库存预留、导出文件名/工作表/行列/值/类型/样式摘要一致；它证明相同合法预览的提交和导出等价，不代表应受准入拦截的错误预览仍保持原数量。新增审计字段为 `admission.catalog_sources`；医疗或缺标签实际受限时执行减少是预期修复。模型及预算核心没有变化。

实际EXE结果、准确构建提交、哈希、测试原始值和限制以 `releases/0.32.2/rc1/交付报告.md` 为准。源码Qt走查不能替代EXE验收。

## 复跑

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -p test_retry_profile.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -p test_jst_current_basis.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe tools/verify_current_basis.py run --out qa/current-basis-new-run
```

性能工具自行生成数据，输出目录必须是新目录。实际程序走查提供 `--retry-profile-smoke <QA目录>` 和 `--jst-basis-smoke <QA目录>`；前者自行生成两店两商品数据，后者需先把性能工具 `seed-1` 复制为该QA目录的 `settings`。两者要求 `REPLENISHMENT_DATA_DIR` 严格等于 `<QA目录>/settings`，禁止使用日常目录。所有操作由QA窗口及其子进程执行，不接入翱象或聚水潭平台。

## 人工试用

- 同窗口先算清单A，再恢复今天清单B的失败门店，点击该店重跑；核对必卖版本、数量和预算。无需重启绕过缓存。
- 冻结库存之后更新默认商品标签为二类医疗，待核验门店重新预览分配应为0，原因可见，库存不占用。
- 生成后更新库存基准，生成面板再次普通导出应提示需核对；结果页明确旧结果重导应输出带旧版本名称的原单。
- 下载最低仓资料模板：标签列保留，可明确留空；删除整列再导入应提前提示缺字段。

## 经营分析导出

移除原“门店SKU供应商类目”四维期间表。门店经营分析导出的前八张表按用户截图及新增维度组织：

| 工作表 | 每行的分组维度 |
|---|---|
| 日期汇总 | 签发业务日期 |
| 日期-必采汇总 | 日期、必采属性 |
| 日期-店-仓 | 日期、门店、供货仓 |
| 店-仓-日期-必采 | 门店、仓、日期、必采属性 |
| 日期-店-SKU-仓 | 日期、门店、SKU、仓；同时展示必采属性、上游供应商和原类目 |
| 已剔除SKU明细 | 业务排除的逐SKU事实及原因，原数量仅供核对，不纳入其他汇总 |
| 店-类目-日期-必采-仓 | 门店、原商品类目、日期、必采属性、仓 |
| 店-供应商-日期-必采-仓 | 门店、大仓上游供应商、日期、必采属性、仓 |

不同日期分行；类目与供应商分别作为独立切面，不把两者和SKU强制捆成一个组合。门店及SKU编码、名称并列，表头可筛选，首行冻结。原五段数量/货值/去重SKU、共同比较范围的比率、可售天数及三种单号继续保留，另附单号关联明细、逐轮天数和口径。订单经营分析保留原订单漏斗，再附同样的八切面；商品明细及逐轮导出入口保持原范围。

供应商、原类目仍来自签发时本仓冻结资料和原件，不读当前资料回填历史。缺失或来源冲突只标记维度待核，不减少原本纳入的商品。业务待核行保留在日/店/SKU表的待核条目数与提示中；比较指标只用纳入行，缺失不补0。类目/供应商汇总不改变原指标算法。

“商品编码数量”是本组该阶段正数量的去重SKU数，跨组不可直接相加作为总体。商品数沿用库存单位执行量统计，混合单位明确显示；可售天数采用原冻结预测和价格加权，不能跨组求和。三种单号逐行对应，超过单元格容量时指向完整关联明细；大量维度依据指向逐商品表及原商品明细。勾选导出时八表都只处理所选订单。

## 本月新品首铺默认量

继续读取实际归属仓商品资料“新店新品首铺数”，按库存单位：

- 缺失、空白、0、负数、非数字、超范围或首铺来源不符时，默认取本次商品的最小出库单位；不跨仓借首铺数。
- 有效正数按箱规向上对齐。例如箱规6：缺失取6，资料1取6，资料7取12，资料31取36。0.13按最小单位0.125对齐为0.25。
- 原资料值及冻结来源保留，界面说明回落和对齐依据。已有本次维护数量保留，手工改量沿用原箱规校验；往期/未归期新品规则不变。
- 最小出库单位本身无效时保持待核，不能猜箱规。默认不选品，仍须勾选、预览预算并确认应用，旧签发不回写。

这只改变首铺候选的默认值；正常需求模型、必采最低持有、准入、预算和箱规校验不变。

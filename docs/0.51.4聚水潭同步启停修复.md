# 0.51.4 聚水潭自动同步启停修复

截图中的报错由`components/jst_catalog/src/service.mjs`统一账号配置门禁触发：原来“启用/停用”和更换账号共用待处理任务检查，已有受理未完成任务或待采用文件就拒绝操作；开关还递增`bindingVersion`，可能使原任务的冻结绑定失效。

本轮将启停分开：只改变所选仓的`enabled`，以独立启停版本检查过期请求；账号、公司、浏览器绑定版本和原批次不改。已有原任务和文件不阻止启停，另一仓不受影响；重新启用仍可继续原下载任务，不重新导出。旧设置缺少启停版本时按0读取，无需重建配置。实际更换账号的并发检查、待处理任务保护和仓隔离仍保留。

停用不撤销平台任务、不清空文件、不关闭浏览器，也不强制中止运行中的请求或提交。运行中需用“停止本次同步”安全停止；停用时继续原任务会明确提示先启用本仓，不再误报账号配置变化。

界面显示停用/启用结果及原任务保留说明。新增7项组件测试覆盖受理未决、待采用文件、原任务恢复、并发启停、账号保护、运行中不强停、重启保留及停用后不能新建同步；组件全量65项通过。源码窗口39项通过，验证实际点击、关闭重开、重新启用、原文件及其他仓不变、正常采用和连接安全退出。全部使用合成隔离资料，无真实平台操作。

最初测试夹具使用了非数字公司/用户标识，重启核验被原账号有效性检查拒绝，修正为有效合成身份后通过；另一次窗口测试重开后默认选了另一仓，改为明确选择原山东仓后通过。失败日志保留，未放宽账号核验或任务校验。

本次同时按用户“exe更新”要求打包0.51.4 rc2，纳入已通过回归的断货保底双零修复、首铺最小量/箱规向上对齐及经营分析八切面。继续保留“不提交、不推送、不合并”的边界，使用带完整清单及SHA256的未提交源码快照构建；不把基线Git提交冒充完整构建源码。首轮rc1构建辅助脚本调用了不存在的校验模块方法，尚未开始生成EXE即停止；修正构建脚本接口后使用独立rc2目录重建，失败日志和目录保留。成品与最终验证结果见`releases/0.51.4/rc2/交付报告.md`。

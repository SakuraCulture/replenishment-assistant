# 0.53.7 生命周期性能与锁单恢复

门店回传、运营签发、付款、收货仍从原入口导入、核对完整范围后保存。本轮不增加业务参数，不改变数量、金额、币种、SKU/仓单顺序、重复处理、空白/缺行转0、清单外提示、供货归属、分配规则或默认并发。

## 三项性能改动

1. 付款、收货与回传一样，保存预览阶段完整核验过的进程内认证证据。提交仍读取完整当前行并哈希全部原文字节；身份、版本、保存时间、原摘要与原文全部相同才复用紧凑投影。变化、证据缺失/修改、跨进程均走完整解码。证据不写入单据或数据库。
2. 一次核对内按精确单号复用父单/仓解析；数据库data_version变化就失效。每行的来源、修订、门店、仓、隐藏页及重复校验仍执行，提交仍核对当前源单、删除屏障和上游。批量入口已经拥有隔离副本，内部步骤复用该副本；直接调用公共接口仍建立自己的副本，界面扫描结果和用户文件不被修改。
3. 库存分配复用已冻结的整批文本及其摘要，只保留最近一次编码。每个写事务读取当前删除标记，相关删除范围变化时重新编码；沿用原过滤规则。每张单的校验、事务、事件、库存序号、更正批原子范围、部分成功/取消/继续顺序均保留。

原件校验、付款认单关系、实际金额/币种、单位换算和上传前复核都不减少。不改变存储格式、secure_delete、同步持久性或首次备份。

## 聚水潭锁单短暂占用

点击“确认所选已下单并锁定”遇短暂读锁时，只有SQLite明确返回SQLITE_BUSY、事务仍未提交、且回滚成功，才释放锁后重新开启事务并重复全部源单、生成单、上游和付款/收货保护校验。原数量与库存预留不重复扣减，成功事件只保存一次。

等待有统一截止时间。界面显示“锁单尝试已安全回滚，正在重新核验”，安全回滚后可以取消；最终提交阶段仍不可强行中断。提交结果不明、非BUSY错误或回滚失败不会自动重试。失败仍显示原始原因，不强制解锁、不终止其他程序、不重复外部平台请求。更正解除锁定仍需原有原因及付款/收货保护。

## 验证范围

基线是上一轮0.53.6 rc2的冻结源码，不是未经核实的最新主线。新旧对照使用同机6张仓单×2000 SKU的隔离合成数据，旧/新、新/旧、旧/新三轮串行，独立进程与数据库副本。对比完整计划、回执、逐表有序业务签名及进度边界，并记录保存、核对准备、进程RSS和读写。实际打包EXE另外验证四环节导入保存、分配、短读锁恢复、原件变化拦截和退出重开。

具体通过结果、构建源引用及性能数字见交付报告。进程I/O含系统缓存，采样RSS不等于整机或整个应用内存。本机合成测量不是业务电脑容量保证；不包含网页上传和平台等待，也不声称保存后列表刷新已经整体提速。

自然转付款、翱象采购轻量视图和签发投影进一步优化未纳入本轮。旧版本和验收证据保留，不替换现用程序、不执行真实迁移或真实平台作业。

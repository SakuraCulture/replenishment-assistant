# 0.32.1 彻底删除订单性能修复

基线：0.32.0 `2b7a811d72b050e2a6c6c3180aa4a162b53ccda9`。本地分支 `fix/order-deletion-0.32.1`。模型0.3.4-rules、需求归属0.5.1、存储格式2不变。不合并、不推送，不对日常用户库执行测试删除。

## 使用

订单跟踪或决策复查中勾选订单，点“彻底删除订单”，先核对完整范围，再确认永久删除。同店同日两仓共享原计算快照，仍按完整门店当天单据删除。没有增加回收站。

准备与清理阶段显示阶段进度、累计用时和最近进展；可以取消或关闭进度窗，窗口会等待安全停止。最终提交短暂禁止取消；已经提交的删除不会因为关闭窗口而撤销。刷新失败时明确提示“订单已删除，页面未完成刷新”，请重新查询，不能理解为删除失败而重复操作。

第一次清理历史资料仍需扫描共享附件引用，耗时随历史数据量增长。扫描结果在删除成功时缓存；取消时不发布缓存。缓存复用会再次核对内容摘要，新增或变化资料重新检查。具体实测见发行报告，不承诺秒删。

## 根因与修改

原路径在预览和提交前重复展开完整签发数据，持有写锁时深拷贝和重编码当天作业，并把所有旧JSON及存活内容块集中展开后扫描引用。大量历史数据下，内存与CPU开销同时增长；内层循环缺少取消检查。删除后的主线程还会重建整份工作区。

现在：

1. `data_maintenance.snapshot` 逐块确认仓单范围；`maintenance_storage.Editor` 对既有清单树编辑，只重写涉及门店的块，旧压缩JSON逐段解析。保留空值、类型、数组顺序、日期与原校验。
2. 准备工作写到专属临时SQLite，在取得写锁前完成；取得锁后重新核对签发、关联记录及当天共享作业的精确版本与成员集合。并发变化拒绝提交，不覆盖其他窗口。
3. 共享文件引用使用两张可重建缓存表：`maintenance_chunk_refs`、`maintenance_legacy_refs`。按内容及缓存摘要校验；逐块释放内存。存活资料仍引用的文件保留，失去引用的内容与文件按原规则清理。
4. 删除请求通过现有Windows spawn作业进程处理，Qt只负责展示进度。取消贯穿读取、准备、等待写锁、SQL及引用扫描；事务异常整体回滚。最终提交进入不可中断边界后不强杀进程。
5. 内存工作区只移除受影响门店，保留其他门店结果和控件，不再完整snapshot/restore_job。派生索引按原匹配含义一次扫描，不逐订单重复扫大字段。

`ijson==3.6.0` 仅用于旧JSON的增量读取；Windows构建锁定wheel SHA-256，并随交付带许可证。来源：[官方实现](https://github.com/ICRAR/ijson)。新编码沿用现有分块格式；未涉及的旧归档不主动迁移。

## 保留边界

- 模型、预算、一箱例外与默认业务配置不改。未选门店原签发、数量金额、来源、参数及导出规则不改。
- 外部已下单的库存占用不因本地删除而恢复；原平台身份防重复依据保留。未完成平台任务仍要求先安全处理。
- 磁盘原Excel、已导出的文件及旧备份不删除。彻底删除是软件业务数据删除，不是物理磁盘擦除；SQLite文件大小也不保证立即下降。
- 日常库不预先批量迁移，不做自动VACUUM，不创建新的业务归档去处。事务内新增引用缓存属于派生元数据。
- 临时准备文件正常退出或取消时清理；系统异常断电可能留下系统临时目录文件。不自动删未知临时文件。

## 验证与复跑

便携回归：`.venv\Scripts\python.exe -m unittest discover -s tests`。

专项：`.venv\Scripts\python.exe -m unittest discover -s tests -p test_deletion_bounded.py -v`。

对照工具：`tools/deletion_qa.py`，冻结原提交、隔离数据库，按旧/新、新/旧、旧/新顺序逐个测量。默认3GiB内存保护；所有删除只发生于QA副本。`run --fixture small --rounds 3 --name 新目录` 可复跑小库比较；large使用诊断冻结库。`--warm-cache` 只复制已验证引用缓存，不更改业务数据。每次使用新输出名。

实际程序：设置 `REPLENISHMENT_DATA_DIR` 为独立QA输出的 `settings`，运行 `补货助手.exe --deletion-smoke <测试输入目录> <QA输出目录>`。仅接受隔离位置，验证真实Qt、spawn、旧格式解析依赖、预览取消、处理中关闭、重试、剩余门店及刷新。它是脚本驱动的真实EXE验收，不是人工易用性或新电脑重建验证。

人工试用建议：先选一店，取消预览确认数据保留；再执行删除，观察阶段进展，尝试中途取消并重新查询；最后确认删除，核对两仓及生命周期记录消失、未选店仍可复查。原始Excel与已导出文件应仍在。

最终性能原始值、等价差异、EXE SHA及完成状态集中在 `releases/0.32.1/rc3/交付报告.md`，不沿用旧版验收结论。

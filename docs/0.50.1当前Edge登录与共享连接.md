# 0.50.1 当前 Edge 登录与共享连接

翱象使用选定 Edge 用户配置中的实际登录身份。用户只需选择浏览器和用户配置，不需要输入平台账号 ID，也不需要固定“账号 ID＋商家编码”才能连接。

## 换登录人后怎么用

1. 在已选择的 Edge 用户配置中完成登录。
2. 正常启动时自动读取当前登录；已经打开应用时，可点底部“连接检查 / 修复 → 重新检查”。新采集、新采购预览和缺货率采集前也会读取当前登录。
3. 同一商家换人，保留已有门店目录和门店对应，自动更新实际身份资料。业务操作仍按当前登录权限核验，不把旧“登录成功”作为本次成功。
4. 若实际切换了商家，连接可以接通，但旧商家的门店对应暂停使用。到“翱象连接与门店配置”选择并核验当前商家的门店，保存后再开始业务。目录保留供核对，不按名称猜测对应。

这些入口共用原组件会话和选定 Edge 用户配置。只打开、关闭配置窗口不会清空配置或另外创建一条连接。浏览器断开时才重建失效连接；首次远程调试许可、网页登录和平台权限仍由 Edge／平台决定。

## 旧任务怎么处理

已创建的采购、导出和收货任务保留创建时的真实身份、平台任务号及本地防重依据。读取当前登录不会把历史任务改成新身份，也不会重新上传或创建导出。

同一商家下仍有同店未完成采集时，换登录人不会绕过原任务保护。应查看原采集及已保存回执处理。若原采购归属和当前身份不同，提示会明确说明“原采购身份不同”，它不表示需要手填账号 ID 或重新配置浏览器。

新采购预览不会复用旧账号的模板；会按当前身份获取模板。已上传、受理未知的原采购继续保留原回执核对和禁止重传保护。

同一商家、同一张本地订单的采购防重跨登录人保留，包括结果未知的原上传；换号不等于允许再传一遍。不同日期的新订单仍使用自己的订单身份。

## 实现边界

保留身份响应内部一致性校验、门店编码校验和原任务严格身份校验。配置中的旧字段 `tenantBinding` 继续保存自动观察到的身份资料，供任务留痕、门店对应和防重使用；它不再是连接时必须匹配的手工固定身份。不同商家的门店不能混用。

不修改补货模型、预算、箱规、归属规则、业务数据或平台订单。0.50.0 删除失效屏障与组件退役机制继续保留。现场换账号是否受平台权限或浏览器策略影响，仍需在对应电脑验证；隔离测试不代表已实际登录该业务账号。

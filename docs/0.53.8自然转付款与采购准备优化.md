# 0.53.8 自然转付款与采购准备优化

本轮只落实用户点名的两条剩余链路：生成单直接核对付款、翱象采购准备及其原有依据复核。数量、金额、币种、商品与仓单顺序、校验和默认并发不变。签发投影优化仍单列后续。

## 使用方式

在聚水潭导入单结果页，继续使用“按当前筛选核对付款”或“按勾选核对付款”；核对范围并确认后才保存。取消不保存，同一生成单重复确认不新增版本，也不重复扣库存。

翱象采购仍从原付款核对入口生成预览；原商家、门店、供应商、付款、准入、原件和上传前核验均保留。准备本地文件不表示已上传或付款，价格仍执行既有两位小数四舍五入规则。

## 改动边界

- 自然转付款：同次已完整解码和校验的上游单据，逐次重新读取完整原文并核对进程认证证据，字节完全一致才复用投影；缺失、变化或证据被编辑均重新完整解码。新计划继续携带有效证据，提交仍重复执行源单、删除屏障、当前生成单、版本、上游及计划指纹检查。
- 采购准备：生命周期快照默认读取行为不变。仅内部采购入口使用紧凑模式；签发原快照、全部生命周期环节（含收货）依旧读取并完整校验，原数量转换、缺行/清单外、旧回传完整性、健康状态检查照常执行。校验后及时释放不再使用的大对象，不保留页面对照行，不再复制已经归本次调用独占的付款快照。返回采购依据仍保存完整原付款内容，格式不变。
- 没有持久缓存、存储格式变化、延后回收、分批提交或降低默认并发。没有改变采购防重或平台上传调度，没有调用真实平台。

## 测量与验收

相对于0.53.7 rc1冻结源码，使用6张仓单、12000行合成数据，独立进程和数据库副本，三轮旧/新交替串行，对照完整计划、回执、逐表有序签名及进度。记录耗时、20毫秒采样进程RSS和Windows进程读写。

测量只覆盖本机后端；原件解析、测试库复制和生成测试数据在计时外，不包括网页处理或实际业务电脑等待。上传前复核可能以少量额外处理换取较低峰值内存，不承诺每个阶段均提速；实际数字及限制见交付报告。

定向回归、真实Qt窗口及实际打包EXE分别保留证据。采购界面使用明确的离线测试传输，只允许本地配置与列表返回；实际本地付款读取、采购文件生成、展示和上传前核验正常执行，不宣称测试了平台上传或真实组件登记。失败记录保留，旧交付不覆盖，不替换现用程序，不自动迁移真实数据，未推送或合并。

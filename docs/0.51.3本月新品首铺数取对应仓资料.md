# 0.51.3 本月新品首铺数取对应仓资料

用户要求：本月新品入店数量维护，使用对应仓商品资料中的“新店新品首铺数”。

## 改动

原新品窗口默认使用最小出库单位，仓资料导入也未保留这个字段。本版把它作为分仓资料可选字段导入、导出，并将原值、仓、仓资料修订、原件SHA、工作表和源行号带入本次计算快照。主从仓选择后使用实际归属仓的资料，不把山东量给河北，也不使用未选的另一仓。

在“选择门店并安排新品 / 安排本店新品”窗口，按已有本月/往期分组：

- 本月新品未维护时，默认填本次归属仓“新店新品首铺数”，按库存单位，不乘箱数、不自动凑整。
- 当前作业已有人工维护数量，重开窗口继续保留，不被新默认值覆盖。
- 往期/未归期新品保留原最小出库单位默认量，本轮不扩大范围。
- 缺列、空白、0、负数、非数字、超出数量上限，或来源仓/修订不符，显示待维护和原因，不补成1箱。0不自动安排首铺，可不选择或明确维护正数量。
- 正数但不符合箱规时显示原数值，预览明确提示；人员维护成合法数量后继续，不擅自上下凑整。
- 首铺字段表头重复不选首列或末列，只让该字段默认量待维护；价格、状态等原资料仍可正常导入和计算。商品编码及既有必需字段完整性规则不放宽。

默认仍不勾选商品。批量选择只选择数量、箱规和原准入均合法的可选项；“全部新品/资料待核”可查看和维护缺失量。预览前列出全部需处理SKU，原窗口保留，不产生无反应或关闭后再报错。

## 保持的业务规则

新品候选识别、月度关注清单分组、禁用/停采/日配等准入、必采最低持有、预算分配和箱规校验不改。字段只给一次首铺候选默认量，不是永久库存下限；最终安排仍可能因预算变化。原模型AS及中间值保留，新首铺需求走原新品预算预览和确认应用。

不自动选品，不因关注清单导入就修改已计算数量，不覆盖历史签发。计算模型0.3.5-rules、归属0.5.2、参数3及存储格式2不变；只新增向后兼容的可选快照字段。

## 使用

1. 更新或重新导入对应仓商品资料，保留准确表头“新店新品首铺数”。分仓模板也已新增该可选列。
2. 重新检查/计算未签发门店，让新字段进入本轮资料快照。旧仓缓存或旧计算快照缺字段时不会借最新资料改写旧结果。
3. 在新品窗口选“本月新品”，核对归属仓、首铺数量和“资格/提示”中的来源；缺量到“资料待核”维护，已有人工数量会保留。
4. 勾选需要的商品，预览预算变化，确认应用。尚未勾选不增加补货；旧签发不回写。

# 0.33.1：翱象采集结束与记录删除

在“获取翱象补货建议”窗口的本机采集记录右侧，新增两个独立按钮。

- **结束本次采集**：预览当前批次的门店及阻塞这些门店的旧采集记录；默认取消。确认后不再继续未采用的采集，释放相关门店，允许新建任务。已验收文件仍可采用；旧批次其他门店保持原状态和顺序。
- **删除采集记录**：仅已结束、已取消或全部成功的记录可删除；默认取消。删除本机采集列表、组件命令/事件及独占的逐店采集元数据。不存在回收站。保留原下载文件、已采用文件与清单、日文件资产、每日草稿、参数和签发/生命周期数据。

## 处理目前被卡住的任务

1. 保存当前工作，正常退出旧版，启动本目录新版。
2. 打开“获取翱象补货建议”，选中被卡住的本机采集记录。
3. 若仍在执行，先点“停止后续取数”，等待安全暂停。
4. 点“结束本次采集”。预览会说明是否同时结束同门店的旧失败任务；核对后确认。
5. 状态显示“已结束，可新建任务”。可重新选门店获取，也可点“删除采集记录”。

结束/删除都是本地操作，不撤销或删除翱象平台任务，不需要浏览器授权。结束不会将校验失败的文件改为合格。删除不清理文件磁盘空间，也不删除任何草稿或订单。

## 原因和边界

旧版查询行数与下载行数不同时，主任务标成完成有失败，底层尝试却停在 DOWNLOADED 并继续阻塞同门店；随后被阻塞的新任务进入 NEEDS_REVIEW，界面没有结束入口。新版允许放弃有明确平台完成回执的未验收结果，同步结束其关联门店任务，既不降低行数校验，也不改补货规则。

平台仍在运行、受理情况不明、迁入任务未核清或文件正在恢复保存时，保留防重保护并显示具体门店/平台任务号。先继续原采集并核对状态，不通过删除数据库或强杀进程解决。该版本不新增在线受理消歧工具。

删除后保留最小防重标识（命令编号、指纹、确认凭据和删除时间），拒绝迟到的旧命令重放；这不是可恢复的业务记录。确认预览绑定具体状态，状态变化必须重新预览。维护在组件事务内整体提交，失败回滚；主程序断开后重新打开窗口会从组件状态补齐结束/删除结果。已结束项目不会被“继续”或“重跑其他失败门店”重新执行。

## 代码入口

`aoxiang_fetch_ui.py`：入口、预览确认、刷新列表。`aoxiang_jobs.py`：本机同步及仅元数据删除。`machine-maintenance.mjs`：结束范围、状态证据、事务、防重标识。`machine-entry.mjs` / `machine-protocol.mjs`：组件协议。`state.mjs` / `coordinator.mjs` / `machine-runtime.mjs`：结束状态及调度隔离。

应用版本 0.33.1；模型仍为 0.3.4-rules。商品匹配、销量预测、预算、箱规、签发和生命周期口径不变。当前目录含共享配置；保留旧版作为交付留档，不应将新旧版同时连接到同一用户资料目录操作采集。需要退回旧版继续采集时使用维护前备份，不让旧代码重新处理新版结束状态。

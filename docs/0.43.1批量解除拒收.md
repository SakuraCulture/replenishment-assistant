# 0.43.1 批量解除拒收

入口：参数设置 → 门店拒收清单。

1. 用门店、商品编码、名称或原因搜索，必要时选择状态。
2. 逐条勾选，或点“勾选当前筛选”一次选中全部可解除项，不限于屏幕可见行。旁边显示条数及门店数。已解除项不可选；“已到期”但未解除的记录可以明确解除。
3. 点“批量解除勾选拒收”，核对涉及门店数、条数及完整商品明细，默认取消。确认后一次保存，列表刷新；可切换“已解除”复核。

筛选、刷新或更换导入范围会清空勾选，不将隐藏记录带入解除范围。点击行高亮只是查看详情，不代表勾选。取消核对保留当前勾选、不写数据。

## 范围与性能

- 精确使用门店编码+商品编码，不按行号或只按SKU解除，不影响其他门店同SKU。
- 仅把所选拒收的active置false。资质、拒收原因、到期日、原始来源和未选记录全部保留；历史订单及计算规则不变。
- 当前作业中受影响门店仍按原逻辑标为需重算，不自动加量。解除拒收不代表豁免资质、禁采或仓禁用等规则。
- 核对绑定读取时的门店准入快照；确认前有并发变化则整批拒绝，要求刷新，不能覆盖他人修改。提交异常整批回滚，含变更事件。
- 预览、保存走后台任务；预览可取消。正式提交按钮明确显示提交中，不可中断；原安全备份保留。
- 使用Qt表格模型绘制勾选框，不为7000条创建7000个控件；选择集按业务键维护；按店深拷贝和版本复核，一次批量保存、一次备份，不逐SKU提交。
- 合成70店×100商品=7000条，三轮独立数据库测量查询/准备/保存。保存包含原备份、版本检查及事务。暖文件缓存且验收库较小，不将该耗时保证为真实历史大库备份耗时。原始值和实际EXE时长见交付记录。

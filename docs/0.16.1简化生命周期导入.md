# 0.16.1 简化生命周期导入

基于0.16.0（0d1753d）。本轮只简化生命周期的填写与关联；计算模型仍为0.3.3-rules。原签发导出、历史快照、仓资料和数量规则不变。旧版保留，不合并、不推送。

## 只用补货单号关联

每店、每仓、每天的补货单号对应当前唯一有效签发。导入不再要求填写或选择签发修订。批量回传/收货文件填写分仓补货单号；从单张订单详情导入时，单号可以由系统带入。付款仍先选一张店仓订单，导入一张原付款单；本轮不新增付款批量导入。

历史签发修订、环节版本、哈希仍由系统内部保留，用于追溯、防止并发覆盖和读取旧单，不要求使用者维护。导入旧文件里的修订字段或隐藏修订属性不再决定关联目标，按单号对照当前有效签发。原始文件留存。若预览后签发被更新，保存会拒绝，须重新核对；不会把预览数据写到另一个签发快照。

补货单号不存在、单号与选择的订单不一致、文件明确写出的门店/仓与单号矛盾，均停止保存。不能按名称或日期猜单，也不把旧两仓总单号猜成某个仓单。

## 回传最低模板

|字段|要求|填写方式|
|---|---|---|
|补货单号|批量必填；单张订单详情可自动带入|使用原签发单已有单号，不另编|
|商品编码|必填|沿用签发商品编码，保留前导零|
|门店确认数量|必须存在此列|填门店本次要货数；明确0、空白、缺行确认后都按0|
|商品名称|选填|帮助人工核对，不作为模糊匹配依据|
|备注|选填|有需要时填写|

表头直接标注“必填/选填”，绿底必填、灰底选填，数量空白的含义另有表头批注和填写说明。程序识别这些标记，无需用户删除括号说明。

可以继续让门店直接修改原签发单的“补货数量”并回传，无须抄写成新模板。回传单号、回传日期、签发修订、门店编码、供货仓、数量单位、折算系数、换算依据不再出现在回传最低模板及常规映射填写区。

## 其它环节与自动信息

- 付款沿用现有13列原表，商品编码、数量、商品金额、内部订单号作为必需业务字段；其余原表信息保留核对，不要求补填没有的信息。单位与回传一致，不乘箱规，不记录付款时间。
- 收货最低模板保留补货单号、商品编码、实际收货数量、收货单号、收货日期；商品名称、备注选填。收货单号/日期属于实际业务事实，不用导入时间代填，沿用原要求。
- 门店、仓、签发内部版本由补货单号确定；正常输入默认库存单位。已有文件/已保存映射中明确给出的单位换算仍按既有校验读取，不静默改变数量。
- 签发建议、上环节数量、差额均由系统读取或计算，只在核对界面展示；导入表无需重复填写，即使带着“上环节数量”也不拿它覆盖已归档事实。
- 回传对照签发，付款只对照回传正数量，收货只对照付款正数量。缺列/非法数字不会当作空白0；未导入整单也不是0。
- 上游内容更新后，下游仍需按既有规则重新核对，保留原事实，不自动串用不同签发记录。

## 入口与验证边界

公共生命周期按钮支持多文件回传/收货；单订单详情限定该订单。导入后直接进入按单号归集的整单核对，不再出现签发修订选择弹框。字段映射仅展示需要用户提供的业务字段并标注必填/选填。

这次没有把商品资料、补货建议、必卖清单改为通用映射，也没有新增自动寻找表头行；仍按之前入口能力执行。生命周期最低模板第一行为表头。实际付款ERP原Excel仍未提供，同表头合成测试不能代表所有真实文件。

随包“导入模板”目录包含三个最低模板。完整验收、构建提交和校验值以releases/0.16.1下本次交付报告为准。

# 0.36.0 业务待办与核对

基线 `35b33de022be33958ec57851f722130feb328d7a`，独立候选，不合并、不推送。计算、预算、箱规、准入、签发及生命周期存储不改版；模型仍为 0.3.4-rules。

## 业务使用

- 首页保留四个业务入口，增加待回传、待付款核对、待收货核对、需重新核对及最近未完成分配批次。前三项按生命周期缺失资料统计；需重新核对可能与之重叠，不相加。全日期查询可停止、重试，查询不是业务完成进度。
- 准备页直接获取翱象建议、手动导入两仓资料。首次连接、历史资料恢复、旧版混合资料兼容放到可展开的维护区。启用旧版模式会展开兼容区，不把正在使用的旧入口藏掉。
- 门店页直接选门店、主从仓及预算；“更多参数设置”保留批量编辑本次参数与方案管理。顶部参数设置维护默认；逐店参数继续查看实际值。
- 核对页可筛选计算失败/待重算、数据待核/缺价/最低持有及完成门店。正常预算缺口不计阻断。门店、状态两列横向滚动时保持可见；筛选只影响展示，导出仍以原导出窗口明确选店为准。
- 生命周期无记录时说明是限定订单、日期搜索、仓锁筛选或无待处理项，并提供清空筛选和本环节全部。回传可进入付款、付款可进入收货，继承勾选或固定订单范围。清空筛选不解除固定订单范围，也不会生成任何业务事实。

## 结构与不变范围

`business_flow.py` 复用 `daily_batch.read` 与 `jst_batches.listing`，投影首页待办、空态及核对分组；无写库。

`business_flow_ui.py` 负责后台首页查询、折叠区、共享原表模型的固定列与展示筛选。通过原 `StageDialog` 进入环节，关闭时停止查询进程；不复制业务计算实现。

`application_window.py / business_scenes.py / batch_app.py / warehouse_ui.py` 仅安装这些控件；`lifecycle_home_ui.py` 增加空态及保持范围的导航；`history_read.py` 仅新增只读查询分派。

本轮 QA 工具支持 60 店、120 店仓单、12,000 条签发行的合成数据，144 种日期/仓/锁/搜索/环节组合和跨页导出。旧/新业务对照严格比较字段、类型、顺序及 Excel 样式；精确动态字段白名单见发行证据。备份恢复将 `source_files` 的二进制原件也纳入逐值比较。

## 验证与限制

完整证据与复跑命令见 `releases/0.36.0/rc1/交付报告.md`。真实翱象原件只保留在本机 QA，不纳入 Git 或运行包。

- 本轮 AI 连接及自然语言模型验收按用户要求暂缓；保留两份先前隔离验收工具，未将尝试计为通过。
- 冷索引仍需要读取历史记录，新首页会增加后台查询工作；有明确进度、可取消。没有改存储格式，也不承诺消除首次等待。
- 性能对照使用相同合成样本、同环境、AB/BA/AB 各三次；Windows 文件缓存没有清空。原生峰值内存只统计服务进程，实际 EXE 心跳另记。
- 单张真实完成单的主子单及实收验证，不代表全部 28 张均测过，不代表历史签发/付款自动关联或创建到收货的连续真实闭环已完成。
- 本机 EXE 验证不替代新版本第二台机器与业务人员主观使用体验验收；对比度和读屏本轮未测。

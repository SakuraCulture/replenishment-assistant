# 0.52.6 核心链路性能优化

本轮仅实施已批准的前三项。模型0.3.6-rules、计算、数量、箱规、预算、默认值、归属、交易原子性和文件顺序不变；不调用真实平台，不重放真实签发，不执行真实迁移。旧交付保留，新包独立。

## 修改

1. 签发核对：`order_review.build`产生的完整字段差异直接用于技术详情，避免同一旧新结果再做一次`revision_diff`。结构化完整差异由工作进程持有；JSON准备时沿用原编码器做完整可序列化校验，不再同时保留完整JSON字符串。实际要求JSON时逐块写入临时文件，再沿原流程发布；Excel仍输出所有差异行，页面仍最多显示200条。新核对开始即清理旧核对材料，失败不能导出前一次差异。
2. 生命周期和经营分析：SKU追加查重使用集合辅助，输出仍为原列表。初始商品顺序及原先的重复处理、环节顺序、首次出现顺序保持；不排序，不以集合代替输出，不改变完整性与数量校验。
3. 历史和跟踪：历史来源只读取所需仓的`source_sha256`元数据；生命周期版本按日期范围内订单身份读取，并保留这些订单全部修订的历史提示；生成任务、有效生成和锁单资料按查询所涉订单读取。SQL参数分段，避免大范围查询超出SQLite变量数限制。全局签发头的前后并发核验、缓存摘要校验、删除可见性及筛选计数阶段保持。

历史`kind=list`返回的`records`是门店下拉框和最近记录所需的完整目录，本轮保留该契约；不把仅当前页面当成完整范围，不改缓存格式，不跳过完整性校验。异常资料的识别和报错继续保留。

来源元数据查询只读取所需路径，所读清单及内容块仍按原机制校验；不会为一个来源摘要读取全部仓商品正文，也不能把这种查询当作整库重验。热缓存沿用旧版存储后的字段排列，不改变商品列表顺序。

## 验证与边界

以冻结0.52.5 rc1为旧版，使用独立合成库和固定输入。先比较完整值、类型和顺序，包括JSON字节、全部Excel差异行、生命周期与经营事实、日期/门店/仓/状态/锁单筛选及分页计数；通过后按旧新、新旧、旧新各一对进行三轮独立进程性能对照。诊断剖析不计作正式性能测量；构建与回归不在计时窗口并行运行。

定向回归覆盖取消、并发修订、失败回滚、原修订重试、已删除记录、缓存损坏、旧修订提示、重复SKU和200条之外的完整差异；实际打包EXE另验真实Qt签发、跟踪、导出、异常反馈及新旧完整输出对照。原生与放大显示分别检查。实测数字、构建身份及失败材料位置以本版独立交付报告为准。

Windows进程I/O含系统缓存，不代表物理磁盘负载；采样峰值是被测工作进程的RSS，不能当作整机或整个应用内存。合成对照不代表低配业务机或现场原单。本轮不承诺删除、模型计算或Excel样式写出的耗时改善，也不把先前现场空异常认定为内存不足。

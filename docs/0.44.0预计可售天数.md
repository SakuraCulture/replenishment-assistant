# 0.44.0 预计可售天数

在五段经营分析上新增只读指标。模型版本保持0.3.4-rules，仓归属0.5.1，参数/作业/存储格式仍为3/1/2。当前候选验收结果以 `releases/0.44.0/rc1/交付报告.md` 为准；本使用说明不是通过验收的证据。

## 如何使用

1. 打开“五段经营分析”，选择业务日期、门店、仓和必采属性，点击查询。
2. 将“漏斗指标”从商品货值切到“预计可售天数”。默认共同对比至签发；若要查看执行落实，选择“实际收货”后再次查询。
3. 顶部显示共同可比范围。所选环节前资料不完整的订单不参与该漏斗；未选择的后续环节显示“未纳入比较”。未取得不是0。
4. 下方门店汇总显示最新业务日的覆盖，订单表显示各订单自己的轮次；双击门店→仓→订单进入商品明细，再双击商品查看中文公式及风险说明。
5. “门店逐轮天数”查看历史不同业务日，不把多轮库存累加。旧归档缺预测依据时保留空值及原因。
6. 导出选择门店/订单经营分析、当前商品明细或门店逐轮天数。所选订单导出仍按原选择范围执行；旧报表文件不覆盖。

## 三种天数不能混用

- 现货可售天数：制单时可用库存÷当时预测日均。
- 含在途覆盖天数：(制单时可用＋在途)÷当时预测日均；不是货架现货。
- 五段新增可售天数：本环节数量÷当时预测日均。实际收货新增5天只表示收到的这批货支持5天，不表示门店今天还有5天库存。
- 签发后静态覆盖：(当时可用＋在途＋签发量)÷当时预测日均，不扣等待期销售，不承诺到货前不断货。

预测日均沿用冻结的“预测日均×趋势修正”。门店/仓汇总为 Σ(数量×签发价)÷Σ(日均×签发价)，是本次有效商品的货值加权覆盖，不是实际库存周转。零数量仍在分母样本内。缺价商品可以查看单商品天数，但不进入货值加权。

新品无有效预测、缺库存单位、负库存、缺历史字段、跨仓依据冲突等分别提示，不能静默转0。同日同店同商品跨仓的预测、价格、单位和库存依据一致时，需求分母只计一次，订单新增量累加；不一致停止门店合计，不猜选一仓。多日期门店覆盖只看标明的最新业务日；更早记录在逐轮表中。

## Excel与AI同口径

原精简报表37列保留，后接5列新增可售天数（AL～AP），数值格式1位小数。门店导出附“门店逐轮天数”和“可售天数口径”；商品导出保留原明细表，并附“可售天数商品”和口径说明。天数空值的原因在单元格说明或明细列中，不把整列转成文本。

原生、Excel、AI都调用 `coverage_metrics`，不分别实现预测或加权。

AI调用顺序：核对 `workbench_context` → `query_order_funnel` → `task_status`确认完成 → `order_funnel_results`分页 → 按需 `export_order_funnel`。

- `query.coverage_through`：model / signed / return / payment / receipt，默认signed，控制顶部共同可比截止环节。
- `order_funnel_results`：原各层级条目增加 `coverage`；顶部coverage提供定义、依据日、共同范围。`level=rounds`读取分店分仓逐轮结果。
- `export_order_funnel`：原store/order/detail继续有效；新增 `level=coverage_rounds`。
- 只是只读分析及明确写本地报表，不增加签发、采购、删除或自动调参权限。原有业务快照ID不因增加派生指标而变化，另有指标版本coverage-1。

## 实现与边界

`coverage_metrics.py`负责纯计算和共同样本，`coverage_exports.py`负责附加表与说明；主分析服务只附加顶层coverage，原事实、历史诊断和原漏斗统计不改。导出新鲜度检查保留，但不重复计算不会参与业务指纹的覆盖投影。

实际MCP测试中补齐了界面原本允许的“分类留空＝全部”输入约定；并修正AI连接断开重复清理已释放Qt对象时的异常。两项均不修改业务数量、存储或生命周期规则。

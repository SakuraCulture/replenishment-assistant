# 0.46.2 删除流式处理优化

本版接续 0.46.1 rc2（8795b78），分支 perf/deletion-stream-0.46.2。只优化现有删除处理；存储格式仍为 2，模型 0.3.4-rules、归属 0.5.1 不变。旧格式支持不恢复，0.46.0 的采集恢复与聚水潭自动配置继续保留。

## 改动

1. 引用缓存直接从源库只读查询，临时库仅保存新增或失效条目。每个源内容块仍核对压缩摘要，缓存本身仍核对内容校验值；失效时仍解压校验原内容并重新提取引用。临时结果仅在删除成功的同一事务中发布。
2. 对当前写入器的有序字典结构，把原快照完整摘要、指定门店筛选和输出摘要合成流式遍历。被删除字段仍完整读取并计入原摘要，任何校验失败均不发布结果。单块原始字节缓存仍以 8 MiB 为限；没有改成把整天数据装入内存。
3. 当前格式允许的宽映射、整体块及非标准容器继续使用已验证的原有处理路径；这不是旧格式兼容。两条路径保存相同业务内容和原格式。

同一天相同快照的重写复用、写锁内源记录集合与字节复核、data_version 并发失效规则及全量清单/内容块引用校验沿用现有实现。未改删除对象、共享原件归属、未选门店和队列保护、平台订单、取消、回滚或重试；没有改变 secure_delete、回收时机或一次事务提交。

## 验证与性能口径

基线从固定 Git 提交归档，输出使用新的 qa/deletion_0462 目录。既有业务预览、结果及逐表有序签名比较保持，另用原 Reader 独立重读存活快照完整字节，核对清单摘要和所有内容块，防止只比较摘要声明。

历史派生大库延用 0.46.1 的固定当前格式样本。另新增当前版本原生写入的合成库：3 天、每天 8 店、每店 12000 行；随机追踪字段只用于放大历史体积，不是业务数据。每个业务日相同内容同时保存为签发工作快照和草稿，覆盖既有去重行为。两类样本分别报告，不冒充真实业务电脑性能。

最终验收采用新旧交替、串行运行，包含有缓存、首次无缓存、多日多父单及小库；性能期间不并行执行构建或回归。耗时含预览和删除，不含复制样本及独立验收计算。Windows 进程 I/O 计数含系统缓存，不能作为物理硬盘占用率；RSS 为删除工作进程采样峰值。首次无缓存仍需完整历史块核验，优化不取消这项成本。

完整结果、源码提交、EXE 验收及限制以 [0.46.2 rc1 交付报告](../releases/0.46.2/rc1/交付报告.md) 为准。应用候选使用 `交付_0.46.2_rc1/补货助手/补货助手.exe`；保留 0.46.1 rc2 及全部既有版本，不推送、不合并。

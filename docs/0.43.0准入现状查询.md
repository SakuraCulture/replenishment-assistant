# 0.43.0 门店准入现状查询

## 业务入口

在“参数设置”上方直接点击“二类医疗资质”或“门店拒收清单”，不需要先导入文件或勾选参数列表。两类页面独立，已有旧维护入口继续兼容。

二类医疗资质页默认展示全部已知门店，包括当前作业、已保存参数、门店目录和独立准入记录中的门店。显示门店、当前有效状态、登记状态、核验人、核验日期、到期日、拒收中款数及备注。可以筛选有效、待核验、无资质、已到期；没有资质登记的店明确显示“未登记 / 待核验”，不等同于已确认无资质。

门店拒收清单默认只显示拒收中，支持查看已到期、已解除或全部。显示门店、商品编码、商品名称、拒收原因、到期日及当前状态。搜索支持名称、编码、原因等；多个搜索词同时满足。到期当天仍有效；拒收未设到期日持续至手动解除，资质未设到期日沿用现有规则，不新增有效期。

## 完成常用操作

1. 查现状：进入对应页面，搜索门店或商品，按状态筛选。上方统计为本次读取的全体记录计数，表格注明当前范围及显示条数。
2. 看详情：选一条，点击“查看所选详情”或双击，进入只读表单。没有 JSON 或原始文件路径堆叠。
3. 维护：选择门店/记录，点击维护；在表单中修改资质或解除拒收，核对变化后保存。拒收页另有“选择门店添加拒收”，可为尚无拒收记录的已知门店添加商品。缺少门店时可先导入门店目录或准入模板。
4. 导入：在对应页面下载模板，填表后点击导入（支持拖拽）。先核对差异再保存；成功后自动定位本次导入涉及记录，包括刚导入但已到期的记录。点击“显示全部记录”解除这层导入范围限制，状态筛选仍以当前选择为准。
5. 导出：导出当前筛选的现状表，另附查询日期/状态/搜索/范围说明。查询结果表不是导入模板；更新资料使用“下载导入模板”。长编码按文本保留，筛选顺序不变。

## 边界和数据来源

- 门店准入保存在既有 `store_admission`，不依赖 `stores` 参数表。删除整条门店参数不会删除准入记录；新页面仍可查询，且不会自动重建参数行。
- 门店名称展示优先使用当前作业、参数记录、目录，再使用准入原始导入中的名称；缺失名称保留空白并显示编码，不猜名称。
- 登记状态是人员保存的状态；当前有效状态按查询日计算。例如登记“已核验”但日期过期，展示“已到期”。日期变化后点击查询/刷新重新读取；不是后台持续监控。
- 查询为单次 SQLite 只读事务加门店目录只读加载，取消可退出；资料异常明确报错。目录损坏时有可见警告，仍可查其他来源，不将局部名单冒充完整目录。
- 保存继续复用原版本核对、原子事务和变更事件；并发更新拒绝过期预览。操作期间或只读历史中禁止维护，查询与导出仍可用。
- 拒收维护不会重写资质；资质维护保留拒收和原始导入来源。原来源保留为原始导入证据，后续修改仍记录到既有变更事件。
- 查询、导出、取消不改变准入；明确维护后按既有逻辑使受影响的当前门店结果失效、要求重算。历史签发、回传、付款、收货不变。
- 不改变准入规则、模型、预算、箱规、仓归属、历史存储格式及既有业务导出；模型仍为0.3.4-rules。

## 代码索引

`parameter_scene.py` 直接入口 → `admission_overview_ui.py` 查询/筛选/导出界面 → `admission_overview.py` 只读归集、有效状态与查询导出。

维护和导入继续走 `admission_ui.py` → `admission.py` 原保存服务。核心 `admission.py` 未改。新增模块没有另一套准入判定；有效状态的展示边界由回归与原 `admission.check` 对照。

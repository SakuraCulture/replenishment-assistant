# 0.48.7 翱象采购单价两位小数

用于确认付款后的翱象采购预览及上传，不改变补货计算、签发、分仓、付款事实或数量。

## 本次修正

此前采购文件只填数量和商品金额，由平台反算单价；金额除以数量可能出现三位以上小数。根据现场反馈，翱象会因此拒绝导入。新预览采用以下明确规则：

1. 用原付款商品金额除以已确认的基础数量，按十进制四舍五入（ROUND_HALF_UP）保留两位采购单价。不是银行家舍入，也不是只改Excel显示格式。
2. 原生模板 E 列填写两位采购单价，F 列采购金额留空，避免平台“金额优先”再次反算出高精度单价。
3. 冻结采购预期金额为“两位单价×基础数量”，四舍五入到分；按行合计。平台实际金额若不一致，继续严格待核，不容差放行。
4. 原付款金额、基础数量、版本及摘要保留；预览逐行展示原付款金额、采购单价、采购金额和舍入差额。单笔、批量上传原确认框同时显示汇总差额，无额外确认步骤。

例如：10元／3件 → 3.33元／件 → 采购金额9.99元，差额−0.01元。5.35元／2件 → 2.68元／件 → 采购金额5.36元，差额+0.01元。差额随数量累积，不保证只有几分钱；很低的单价也可能舍入为0.00，预览会如实列出。

## 如何使用

使用0.48.7，在付款核对后重新生成采购预览，核对数量、两位单价、采购金额、舍入差额和供应商后上传。采购仍只创建为待提交，不自动提交、付款或入库。

旧的未上传预览不能直接上传；先取消原本地预览，再生成新预览。已经发起上传的任务必须继续核对原任务，禁止为了采用新舍入规则重新上传。原任务、原文件及旧的精确金额校验保留；人工核对已有采购单的只读路径兼容旧文件。

## 验证与限制

验证覆盖二进制浮点易错的2.675、恰好半分、循环小数、分数数量、零金额、大数量、逐行差额、金额汇总、Excel真实单价值、原件结构保持、文件篡改、旧预览防上传和旧任务核对。Python与Node分别以精确十进制／整数比值计算，逐项核对，不跳过原有完整性与并发检查。

验收以本版独立发行记录为准。未调用真实翱象导入、未创建平台采购单；平台分数数量的实际金额舍入行为仍需现场观察，若与冻结金额不同会保留原任务待核，不能据隔离验证宣称已通过真实平台验收。

3. 控件未就绪也提前记录已尝试提交。持久化提交意图移至真实派发前；派发后的未知响应仍保留不明状态，禁止自动重发。
4. 下载行出现不代表任务已完成。等待原任务明确完成，再校验类型与查询条数；完成但不匹配、原生失败仍拒绝下载。`native-history-row.json`保存真实完成行，33项组件测试及8项独立无网络Edge检查覆盖这些分支。
5. rc4实际EXE截图发现两仓采用后进度条仍为50%。最终返回的采用回执比最后状态事件更新，成功回调现按最终批次同步进度条；rc4留存为发现问题的构建，最终候选改用rc5，EXE验收增加完成进度断言。

失败记录保留在live-run-1至3。一次QA任务在导出控件派发前失败，经明确前置条件证据恢复未提交状态，恢复前完整备份与说明在`pre-dispatch-recovery*.json`。之后已受理任务从未重置。未对正式状态文件作此修改。

# 0.52.4 搬迁SQLite事务日志校验修复

2026-11-13操作e46ced488a0643439ef14aa2aa53c4bf在资料复制完成后的数据库检查阶段失败，位置没有切换。真实失败副本中的河北仓Edge扩展活动库ExtensionActivityEdge有未恢复rollback journal。只读独立复制件复现SQLite扩展错误776（SQLITE_READONLY_ROLLBACK）；另一独立复制件正常恢复后integrity_check为ok。诊断前后源文件与失败副本的数据库、日志SHA未改变。不是这条错误证明订单库损坏或D盘只读。

旧实现对资料范围内所有SQLite一律mode=ro执行integrity_check，没有处理浏览器等资料仍含待恢复事务日志的情况。本轮只修复该校验流程，不改模型、数量、预算、箱规或业务单据。

每次将一份SQLite及-wal、-journal复制到新盘的一次性独立目录，分段核对副本字节后，仅在这个校验副本中允许SQLite正常恢复并做完整性检查。SHM在独立目录重建；原库、正式搬迁副本与归档继续按原始SHA保存。串行只保留一库临时副本，按需预检磁盘空间，完成后清理自己创建的临时目录。

不删除或忽略真实journal，不使用immutable跳过恢复，不直接以rw打开原资料或正式搬迁副本。journal包含super-journal尾标时保守阻止：其中可能有绝对外部路径，不能因为复制了文件就默认恢复不会触及原位置。损坏、空间不足、跨库日志引用及临时清理失败明确报错；SQLite错误带相对路径和扩展错误码。复制、源范围复核、完整性、单实例、取消和失败回滚继续保留。

入口仍为“显示与帮助 → 数据保存位置”。保存草稿、等待原任务结束、正常关闭采集专用浏览器，选择独立空目标后重新校验并确认。独立进度窗口显示正在检查的数据库；失败不会自动重开平台或重放搬迁。此前失败副本保留，不覆盖或自动删除。

应用0.52.4，模型0.3.6-rules。原0.52.3及更早交付保留。实际EXE、定向回归和隔离合成场景结果以本版独立交付报告为准；真实复制件只作诊断对照，不冒充合成回归或整套真实搬迁成功。本轮不自动迁移真实资料，不提交、推送或合并。

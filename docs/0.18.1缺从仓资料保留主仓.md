# 0.18.1：从仓缺少商品条目时保留主仓

基线0.18.0 `7f5eccfd80e271dad1bc7d66fa99f6c198c56956`。独立分支 `fix/warehouse-fallback-0.18.1`。应用0.18.1，需求归属能力0.5.1，模型仍0.3.3-rules；不改变存储格式，不改写历史单，不自动合并或推送。

## 本次修正

主仓有商品条目但无货或禁用，从仓没有该商品条目时，保留主仓归属，整套使用主仓价格、箱规、分类、状态、原表来源及仓周期。不再把它放在没有商品资料的从仓下显示“匹配待核”。

|主仓|从仓|归属与处理|
|--|--|--|
|有货|任意|主仓|
|无货或禁用|有商品条目|从仓；从仓无货也保留需求；从仓禁用仍排除|
|有条目、无货|无商品条目|主仓，正常计算需求|
|有条目、禁用|无商品条目|主仓，计算参考，执行数量仍为0|
|无商品条目|有商品条目|从仓|
|无商品条目|无商品条目|地采|
|库存未知|任意|原规则：保留主仓，库存待核不当成0|

停采继续排除。主从仓仅判断需求归属，不限制需求、不拆单、不预占仓库存；精确商品编码、重复/无效编码处理和缺箱规默认值不变。单仓供货保留原逻辑（未配置仓有资料的边界不顺带调整）。

## 使用

保留原0.18.0目录，启动新目录中的EXE。已经计算的草稿需要重新计算才能应用新归属；历史已签发单保持当时快照，不自动换仓。重新签发当日单仍按原有差异预览及覆盖确认执行。

恢复主仓资料会让部分原先待核商品产生有效需求，因此不限预算总金额可能增加；限额预算下会按原分配规则在全部有效需求中重新分配。禁用/停采商品仍不会因为回主仓自动补货。

## 验证与代码查找

- `src/warehouse_catalog.py:route_store`：唯一生产业务修改。只在主仓精确匹配且从仓明确“资料未匹配”时回主仓；保留完整元数据。
- `tests/test_warehouse_fallback.py`：无用户文件的双向主从仓、资料来源、周期、数量、排除、无效编码与顺序测试。
- `tools/verify_warehouse_fallback.py`：冻结基线独立进程计算；真实14244行及双仓样本，标准/自定义参数、预算/关闭一箱例外；新结果对照旧引擎使用正确主仓整条记录的独立期望。
- `src/preissue_smoke.py`：实际EXE导入、spawn计算、签发前修改、归档、分仓文件、第二次启动恢复验收（合成数据）。
- 原始输入、模型/一箱例外/预算/默认配置、旧0.18.0交付包哈希分别检查。完整差异保存在独立QA目录，验收证据与复跑命令见 `releases/0.18.1/rc1`。

新回退行审计 `routing.version=0.5.1`；未命中本规则的旧归属路径保留 `0.5.0`，避免对未变化商品制造审计差异。应用版本信息的 `routing_version=0.5.1` 表示具备新能力。对照只允许明确的运行时间、进程、构建信息及此应用级版本不同，不忽略逐商品归属审计。

实际测试使用冻结回归销量和复制的仓快照，不能当成截图中未保存洪门店当次作业的金额。日常数据库未用于运行测试。

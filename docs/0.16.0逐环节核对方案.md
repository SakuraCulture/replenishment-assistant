# 0.16.0 逐环节核对方案（2026-10-31确认）

开发基线：0.15.1，a48a5ca0c61fc6bf736c0cb27c2173cb487d72ba。模型保持0.3.3-rules。本文是实施口径，实际验收另记，不把方案描述当作已完成。

## 链路与数量

工作页计算、核对、确认归档后即已签发。链路为：已签发 → 门店回传 → 门店付款 → 实际收货。不增加模型推荐阶段、部分单或暂缓/恢复跟进状态。

每个日期、门店、仓和签发修订独立关联。四个数量独立保存，不回写原签发。回传对照签发明细（含0数量新品）；付款只对照回传要货数>0；收货只对照付款数量>0。单据已导入并确认后，范围内明确0、数量空白、缺行均按0，分别保留处理来源。整张单未导入不是0。非法数量、缺数量列、公式无缓存、错单不按空白处理。

每次更新为完整版本，不累计。上游变更时，下游保留原先依据和数量，提示重新核对；预览与提交均绑定签发及上游确切版本。后环节先到可留存，未有有效上游前不生成缺行0；补齐上游后显式重新核对。正常比较按上游顺序，额外商品按来源顺序追加。

## 回传沿用签发样式

发给门店签发单，门店直接修改“补货数量”，导入后读取为门店确认数；不要求另填模板。新品可由0改正数，空白、删行均按确认范围归0。原签发数来自归档，不从回传表反推。

导出回传单沿用原签发版式、列顺序和三个工作表，数量写门店确认数。保留归零商品；差额、归零原因只在核对界面与生命周期对照表呈现，不追加到门店表。原件可独立原样下载。

## 付款原表（最新确认，覆盖旧方案要求）

直接适配内部订单号、线上订单号、店铺名称、买家账号、下单时间、平台站点、商品编码、商品名称、箱规、数量、商品单价、商品金额、辅助码这13列。

- 商品金额就是实际支付金额，直接保存，不另加实付字段，不用模型价格重算。
- 数量与回传单位一致，不要求添加单位列，不乘箱规；截图的箱规仅供核对。
- 不增加门店编码。先选择对应店仓订单，再导入一张付款单；付款批量导入、门店编码和自动关联后续再做。
- 不记录实际付款时间，不把下单时间映射成付款时间，不新增付款时间必填项。原文件里的下单时间原样留存。
- 内部/线上订单号同时留存；源单商品编码精确匹配，辅助码只做可解释的唯一匹配，冲突不猜测。
- 源单没有币种字段时保留“源单未提供”，不擅自新增必填列或猜币种。

## 导入交互与边界

选择文件/拖拽 → 字段识别及工作表范围 → 关联确切订单 → 差异预览 → 确认保存。普通模板仍是备用入口。付款单一次只处理所选仓单的一张完整来源订单；不静默合并多份外部订单。

预览提供上环节数、本环节数、差额、旧本环节版本数与处理原因，以及全部/变化/明确0/空白转0/缺行转0/清单外筛选。筛选不改变保存范围。清单外商品须明确核对；全部无法匹配须核对目标，不直接整单归0。空文件不自动归0，可明确选择目标并确认整单全部0。错误文件/读取失败工作表不当作缺行。

保存完整版本保留原件、哈希、源行、原值、有效值、处理规则及上游版本。提交前可取消，最终短事务不可强杀；批量事务保持原子性，预览后变化拒绝保存。旧schema按旧口径读取，不批量改写历史；需采用新规则时重核生成新版本。

首页显示最早缺少单据及导入入口；回传全0提示无要货，无需付款/收货，付款全0提示无需收货，不伪造后续单据；上游更新导致待重核时优先提示重新核对。签发0但有新品候选仍允许回传选品。

## 功能分组和导出

生命周期导入、业务单据导出、计算/原始依据、维护管理分组。三个导入与三个导出采用镜面名称“门店回传单/门店付款单/门店实际收货单”；原签发导出仍叫“门店确认单”。删除/恢复分开。

完整计算表保留全链计算；商品资料原表原样留存；签发/确认单动销只含正数，新品含0候选。回传导出同签发样式，付款/收货导出保留有效0及原因，对照表保存四数量/三差额。没有相应阶段数据不导出假0单。

保留多选导出：每店每仓每修订单独文件，或同仓合并多订单；不混河北/山东。默认目录沿用0.15.1。选单/版本与文件数量先预览，商品筛选不悄悄改变整单导出。付款批量导入暂缓不影响既有批量导出。

# 0.30.0 订单级、门店级生命周期对比

在“订单跟踪”查询日期、门店、仓和进度，点击“导出订单级对比”或“导出门店级对比”。可以导出勾选订单（含跨页勾选），或当前查询筛选的全部订单（跨所有页）。不需要逐页全选。填写搜索后先点查询，导出使用最后一次成功查询的条件。

门店报表只汇总本次范围内的订单，不自动扩大为该店全部历史。每张店仓签发单只计当前修订一次。山东、河北订单在订单表分别列出；门店总表合计两仓，并附分仓表。聚水潭生成单不是额外生命周期。

## 文件内容

| 工作表 | 用途 |
|---|---|
| 门店级对比（门店报表） | 每店一行；订单数，各环节有效订单数、去重商品款数、货值及可比差额 |
| 门店分仓对比（门店报表） | 每店每仓一行，避免双仓差异互相抵消后无法定位 |
| 订单级对比 | 每张店仓单一行；签发、回传、付款、收货状态、商品款数、货值、差额、实际付款 |
| 差异商品明细 | 编码、名称、库存单位、签发价、各环节数量及相邻环节差额；包含缺价或待核资料 |
| 实际付款金额 | 每订单、币种的源单实际金额及缺金额行数；保留待核付款记录并标明状态 |
| 统计口径 | 查询范围、导出时间、缺数据及计价说明 |

原“导出勾选单商品级明细”仍使用旧的逐商品导出实现，既有签发、回传、付款、收货、计算表和商品资料原件导出不变。

## 金额与缺数据边界

1. 用户确认的口径：所有环节货值 = 该环节数量 × 签发快照中的基本售价；不读取最新商品资料价格。付款单实际金额另列。
2. 签发 → 回传 → 付款 → 收货。差额是后环节减前环节，负数表示减少。不同商品库存单位不同，不把瓶、包、箱混加成一个总数量；商品数量在明细保留。
3. 未导入、旧回传不完整、上游更正后待重新核对、无需后续环节，都不等同于已确认0。已确认整单中的0、空白、缺行按现有生命周期保存规则解释，不修改保存逻辑。
4. 环节总货值仅含有效订单的已计价部分，同时列有效订单数和资料提示。两环节差额只合计两端都有效且资料齐全的订单，并列“可比订单数”。不能直接用覆盖范围不同的两个环节总额相减。
5. 清单外追加商品签发数量为0。没有签发价时保留缺价，不套用现价；相关货值差额不算成0。商品款数按正数量编码计数；门店跨日期/仓去重SKU，但货值仍按每张单相加。
6. 实际付款金额按源单币种保存。多币种不混加；未标币种不假定人民币。订单表允许查阅待核源单金额并标状态；门店有效付款总额只含有效付款单。
7. 已结束只表示无后续待办，不表示四环节数量完全相等。

## 交互及一致性

两个按钮语义固定。默认范围为已勾选订单；无勾选时默认当前查询筛选全部。确认窗口说明所含订单数和金额口径，默认取消。后台读取有订单进度，Excel写出有行进度；压缩保存期间提示完成后响应取消。完成后可打开文件/文件夹。

全筛选导出会重新读取符合原查询条件的当前订单，数量变化时要求刷新；同数量的集合更替仍以导出时查询结果为准。所选旧签发修订已变化、归档已删除/不可见、快照身份或校验不符时拒绝导出，不静默使用另一张单。生命周期记录在同一只读事务内读取。后台不写业务表，仅原有查询索引可按需更新。

新报表使用新文件名；同名文件拒绝覆盖。取消、读取异常、写出失败时不发布半份报表，压缩完成后安全检查再发布。原签发导出的既有同名覆盖规则保持。

## 结构与性能边界

`lifecycle_home_ui` → `lifecycle_comparison_ui`（范围与后台进度）→ `lifecycle_comparison`（只读订单投影、汇总和Excel）。复用 `order_lifecycle.snapshot` 的原始事实、健康状态及数量规则，不重算模型、不分配库存。

`snapshot` 增加可选已读取签发参数；原调用路径保持。相邻仓单共用同一门店签发读取，缓存最多两份签发大对象；提取后只保留汇总和差异商品。Excel沿用流式写表。`daily_batch.read` 仅增加显式 `all_matched` 内部选项，默认分页结果不变。

大范围差异商品仍需驻留投影列表；未承诺无限历史规模或固定秒数。压缩阶段无法立即打断；不强杀数据库或Excel写入。新汇总不补造历史缺失资料，不更改旧格式与修订关系。

# 0.46.4 作废采购核对与删除恢复

本版处理“平台采购已经作废，本地订单仍无法删除”的流程阻挡。沿用 0.46.3 的原任务恢复与防重复上传，不修改补货计算、付款、采购内容或删除范围。

## 原因

只读核对本机记录后，截图的 11 行来自两组记录：

- 00:49 的原上传批次有 5 笔结果待核，第 6 笔此前已关联采购单。
- 09:13 的重复采购预览有 6 笔。每笔先生成了本地文件，随后被原采购任务的防重规则拒绝；这些新的预览编号没有进入组件采购台账。

旧判断把“有本地采购文件”当成“已取得平台采购身份”，导致重复预览不能结束。同时，原上传结果只允许核实待提交采购单；平台单已作废时，即便能找到原单也被拦在完整核验之前。

用户提供的平台截图显示这 6 张采购单为已作废；这不是本轮实时平台查询结果，也不能说明由谁作废。本次开发没有操作真实平台或删除真实订单。

## 处理现有记录

1. 正常退出旧版，打开完整的 `交付_0.46.4_rc1/补货助手/补货助手.exe`。
2. 在“翱象批次作业”选择 **11-07 00:49:05 的采购上传与核对批次**，点击“继续核对未完成采购”。软件沿原受理任务号查询，不再上传采购文件。
3. 软件核对原导入回执、唯一采购单、店仓、供应商及全部商品数量和金额。原生主单和商品明细均证实已作废后，显示“已关联，平台已作废”，保留采购单号，作废单独计数。
4. **11-07 09:13:56 的采购预览批次**显示“重复本地预览，可结束”。可以勾选并“结束所选本地准备”；这组未成功建立新任务的失败预览不再阻挡删除。原上传批次不会因此结束或消失。
5. 回到订单删除页，重新勾选并核对完整删除范围。已核实的原采购不会继续以“结果待核”阻挡；仍须完成原有的外部订单及整单范围确认，再执行删除。

也可从删除阻挡页选择仍待核的原上传记录，点击“查看并处理原任务”，再执行第 2 步。同店同日两仓共享父单，删除仍按原有整单范围执行；未选门店、共享原表、未选草稿门店与平台订单保持原语义。不会自动删除未被阻挡的子集。

此前已关联的第 6 笔保留原关联，不会因为重试另外 5 笔而重复执行。其行提示明确为“上次核验结果”，不把旧待提交快照冒充平台实时状态；本地删除确认仍要求核对外部订单。

## 核验边界

| 情况 | 本版行为 |
| --- | --- |
| 重复预览被 `PURCHASE_ALREADY_RESERVED` 拒绝，且无受理、关联、上传或成功预留证据 | 识别为本地准备，可结束；原采购身份保留 |
| 记录有上传、回执、订单号、绑定或成功预留证据 | 不允许按重复本地预览结束 |
| 原任务全量成功、唯一原单及逐 SKU 原生文件一致，状态为待提交 | 沿用原自动关联 |
| 同样严格核验通过，主单和所有商品行均为已作废 | 关联历史采购事实，明确作废；不当作有效采购成功，不释放防重复上传身份 |
| 已完成、未知或缺失状态 | 不自动改成作废或待提交，保留待核并说明状态问题 |
| 缺回执、多单、错店、错供应商、外部订单、缺行、数量金额差异、文件哈希变化 | 继续阻挡，保留原任务，不重新导入 |
| 原核对文件已完成，但平台状态已变化 | 仅对该单新建一组核对文件；原文件和任务保留 |
| 原核对文件仍在处理中或提交结果未知 | 恢复已有导出任务，不重复提交未知任务 |

平台查询编码仅用已有 `0=待提交` 规则作一致性检查，不猜测“作废”的数值编码。作废结论由主单与逐商品原生文件的明确“已作废”状态共同证明。若平台不能提供作废单完整明细或缺少原回执，仍保留待核，不能仅凭截图解除。

本版没有批量作废平台单据、重新导入采购、清空组件防重复台账或新增“强制删除”入口。

## 改动与验证

改动集中在 `aoxiang_workflow_state.py` 的任务分类、`purchase-create-service.mjs` 与 `purchase-create-contract.mjs` 的原单核验，以及队列状态和错误说明。组件错误详情保留；已完成旧核对文件可按精确单号刷新，未完成任务沿原任务恢复。

Python 隔离测试验证删除、未选订单、同店两仓、并发版本、取消回滚及禁止绕过的证据；组件测试使用合成原生 XLSX 核对逐商品明细、防重复身份及状态；实际打包 EXE 再验证界面流程。每次使用新的 `qa/deletion_void_0464` 子目录，不覆盖旧证据。

## 限制

应用版本 0.46.4；模型 0.3.4-rules，仓归属 0.5.1，参数/作业/存储格式版本 3/1/2。删除数据算法、事务、`secure_delete`、取消、回滚、重试沿用原实现；没有放宽逐商品完整性要求。

本轮是删除阻挡恢复，没有重测大历史库的耗时、内存、进程读写，也没有低配置电脑实测。历史性能应查看其原发行报告。

真实这 5 笔作废单能否通过核对，仍以用户运行后的原任务及平台原生文件为准。既有 `browser_status_ui` 的 QLabel 销毁后回调警告不在本版修复范围。

保留 0.46.3 及现有旧包。独立分支、源码提交、验收证据和标签仅在本机，不推送、不合并。

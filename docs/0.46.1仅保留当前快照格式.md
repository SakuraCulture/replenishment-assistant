# 0.46.1 仅保留当前快照格式

根据用户确认“没有旧数据，删掉旧格式”，从本版移除早期整份 JSON 压缩快照的兼容支持。当前分块存储仍为格式 2，没有引入新的存储格式，也没有执行业务库清空或迁移。0.46.0 的采集恢复和聚水潭浏览器自动配置继续保留。

## 使用变化

- 新保存、读取、归档和删除仅处理当前分块快照。当前版本正常产生的数据不需要用户转换。
- 数据维护保留“创建数据库备份”，直接选择一个新文件名。备份逐条校验后发布，支持取消，不能覆盖已有文件。不再提供旧格式兼容副本和历史格式转换选项。
- 旧快照读写、旧快照流式解析、引用缓存及删除预扫描均已移除，运行依赖不再需要 ijson。
- 如误选含旧快照的资料库，会明确提示使用保留的 0.46.0 版本。删除预览、事务开始及共享资料回收前均检查格式，避免遗漏未选资料的引用；不会默默忽略旧记录。
- 备份是主 SQLite 数据库副本，不包含库外原件、浏览器登录状态等其他目录。原有首次写入前的数据库备份机制保留。

## 保持的业务约束

不改模型 0.3.4-rules、预算、箱规、默认参数或归属规则。同店同日两仓共享父单的删除范围不变；未选订单、共享原表、其他门店草稿和平台订单的保护不变。完整性校验、并发检测、取消、失败回滚、重试、secure_delete 和单事务提交保持。没有新增 VACUUM、分批提交或延后回收。

旧格式与旧计算模型是不同概念：当前分块格式中保存的旧模型结果仍按既有规则只读。其他业务字段的历史兼容规则不在本次删除范围内。

## 验证与性能口径

测试数据全部位于 `qa/current_storage_0461`。原冻结样本、0.45.0/0.45.1/0.45.2/0.46.0 交付与原验收证据保持不动。

为了对照本版支持的输入，用固定 0.46.0 源码在独立 QA 副本中将旧快照转换为格式 2，逐表有序业务签名保持一致。此步骤仅构造测试样本，旧转换实现只从 Git 档案载入，不进入运行包。该派生样本不等于业务电脑的新库，也不能与之前含旧快照样本的耗时直接比较。

新旧程序使用完全相同的派生大库和当前格式合成样本，交替串行运行。分别测首次无引用缓存、有完整引用缓存，以及多天多父单删除。Windows 进程读写量含缓存，不代表物理硬盘占用率；RSS 是删除工作进程采样峰值，不是整机或整个应用内存。计时排除复制样本与验收签名计算。

旧格式不存在时，旧解析分支本来就不会运行。移除兼容本身不等于显著提速。当前分块数据仍须核对共享附件、完整快照和当天未选门店，不能为速度跳过这些检查。实测结果、固定源码提交及 EXE 验收见本版交付报告。

## 复核入口

`tests/test_current_storage.py` 覆盖旧格式拒绝、并发加入旧资料后回滚、重试、草稿保护、备份精确性、覆盖拒绝、取消及损坏拒绝。原删除、维护及业务测试使用当前格式构造样本，业务预期不变；原旧格式成功读取测试替换为停用后的拒绝测试。

`tools/prepare_current_storage_qa.py` 仅构造独立 QA 样本；`tools/run_current_storage_qa.py` 执行新旧串行对照。两个脚本固定使用全新的本版目录，已存在则拒绝。旧版性能和格式转换证据应在对应 Git 档案内复跑，不拿旧结论替代当前验收。

已知的 browser_status_ui / QLabel 销毁后回调警告未在本次修复。未在低配置业务电脑实测，未操作真实平台。

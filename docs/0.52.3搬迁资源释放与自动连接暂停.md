# 0.52.3 搬迁资源释放与自动连接暂停

本次只处理同一台电脑更换资料保存位置的退出、占用检查和自动连接时序。模型仍为0.3.6-rules，订单、数量、预算、箱规与平台单据规则不变。

## 这次真实失败发生了什么

操作5a4c7922a8aa4def95a30e0a64f8b35b在2026-11-13 00:16:53+08:00改名C盘旧目录时被Windows拒绝（WinError 5），没有切换位置。D:\补货助手数据已经是复制后的目录，但不是已启用资料；C盘原位置继续使用。旧版随后立即自动重开主程序，00:17:00才开始聚水潭登录检查，所以日志不能证明浏览器先启动并造成该次失败。

事后无法确认原始目录占用者，也不能把“权限拒绝”直接等同于某个浏览器持锁。隔离环境分别复现了程序当前工作目录位于来源目录内、Qt生命周期内持有目录句柄两种自占用；后一项是显式句柄模型，不代表已经证明实际文件选择器就是此次占用者。

## 修复

1. 打开“数据保存位置”即暂停自动登录重试、连接状态轮询和自动任务派发。确认前协作取消仅用于启动核验的只读检查，等待其释放租约；业务任务仍须安全收尾。取消、关闭或安全退出失败后恢复原开关和计时器，不修改持久自动同步偏好。
2. 窗口安全退出后，先销毁全部Qt应用资源再开始复制。把原有QLockFile转交非QObject保护对象，整个交接没有解锁间隙，第二个实例仍不能打开业务库。
3. 当前工作目录若位于搬迁范围内，先移到独立控制目录；只读进度进程和成功重开的工作目录也使用该控制目录，避免继承旧路径。
4. 复制前及切换前向Windows核实目录改名权限，探测只打开并关闭自己的测试句柄，不删除、不改名、不解锁其他程序。检查不能保证以后没有新占用；真正改名仍有异常回滚。程序本身安装在待搬目录内时明确阻止开始。
5. 仅成功才按勾选项自动重开业务主窗口。失败停留只读进度/结果窗口，保留原始堆栈、阶段和副本；不自动再连平台或重放搬迁。新诊断同时记工作目录和程序路径，便于定位以后类似问题。

文件摘要、SQLite完整性、WAL清单、源目录复核、单实例及写库占用保护全部保留。未把“浏览器占用”校验整体删除，没有强制关闭浏览器。

## 如何使用

完整解压独立0.52.3修复包，从资料目录以外运行。保存草稿、等原任务结束、正常关闭采集专用浏览器，再进入“显示与帮助 → 数据保存位置”。核对位置与恢复副本路径后确认，独立窗口持续显示阶段进度。

失败时先查看原因，C盘原资料继续保留。本机D:\补货助手数据已有未启用副本，不能直接覆盖；请保留它，另选独立空文件夹，例如D:\补货助手数据_新位置。恢复副本仍需完整归档并校验后才清理旧业务副本。

本轮只使用新建合成数据与隔离目录验证，不调用真实平台，不重跑真实迁移，不移动、删除或覆盖任何真实资料。原0.52.2 rc4及更早交付保留。具体测试数量、实际EXE及冻结源码依据以独立交付报告为准。

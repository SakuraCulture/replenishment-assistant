## 唯一推荐入口

在本目录使用PowerShell 7运行。当前已核验PowerShell 7.6.5、Windows x64、CPython 3.12.14。

```powershell
.\dev.ps1 Help
.\dev.ps1 Doctor
.\dev.ps1 Test
.\dev.ps1 Test -Optimized
.\dev.ps1 Run
.\dev.ps1 Build -BuildId 新的候选编号
```

- Doctor：核对项目Python、锁文件中12个依赖版本、QtCore/QtWidgets导入及pip check，记录分支/提交。失败直接停止，不自动安装或升级。
- Test：便携单测；固定PYTHONHASHSEED=0，避免旧分类映射中set遍历的随机键序影响跨进程对照。
- Run：源码应用使用qa/dev/settings，启动前先检查环境。不会打开日常使用的作业库。开发资料与正式资料需分别导入，不自动复制。
- Build：复用原build.ps1，强制指定构建编号；只从干净提交构建，拒绝覆盖旧目录。不会打标签、发布或推送。
- 脚本临时设置的Python路径变量、哈希种子和数据目录在退出时恢复；不修改系统PATH、注册表或全局Python。

Doctor/Test记录写入qa/dev/runs/时间-随机编号，每轮独立目录。开发界面的资料保存在qa/dev/settings，后续不能把这个目录当无用缓存随意删除。

## 目录分工

|目录/入口|内容|整理原则|
|--|--|--|
|src|运行代码、图标、默认业务配置|Git纳管；业务改动独立分支与验收|
|tests|不依赖真实Excel的便携自动测试|日常修改先跑；不能代替业务对照|
|tools、根目录verify_*.py|归档、导出、历史兼容、真实样本、性能、EXE检查|历史脚本含固定路径；运行前读参数和写入位置|
|docs|业务说明、结构、版本流程、开发说明|以当前版本说明为准，保留历史沿革|
|releases|已提交的验收记录、哈希、报告、截图|发布依据，不按缓存清理|
|交付_0.10.0_rc1|当前试用包及ZIP|保留完整文件夹；不要只复制EXE|
|交付_0.9.2_rc2及其他旧交付|回退和历史验收对象|本次均保留，用户此前要求保留0.9.2|
|build_*|PyInstaller中间产物、spec和构建信息|可作为后续清理候选，先保留构建信息；不是本轮删除对象|
|qa|冻结输入、旧源码、数据库、回传、输出、性能样本和额外依赖|不能整体删除或直接搬移；复跑和保护哈希常引用原路径|
|qa/dev|新的开发运行数据及每次环境/单测记录|统一新工作入口；与旧发行验收目录分开|
|versions|项目收到时的早期源码快照|历史证据，不混入当前运行代码|
|.git|分支、提交和标签|不重建、不重写历史；Git不备份被忽略的EXE和业务数据|

根目录验收记录.txt是0.1.0历史资料；不能当当前验收报告。根目录旧Excel、spec及无版本号“交付”目录本次没有挪动或删除，不凭名称判断是否废弃。

## 后续工作流程

1. git status核对状态，确认实际分支；当前开发基础来自0.10.0，不能误从较老main开始。
2. 开独立任务分支，先读相关代码与当前版本文档。
3. Doctor → Test；涉及业务再固定输入、配置、旧提交并做独立对照，涉及UI/进程则做实际EXE验证。
4. git diff --check → 本地提交 → Build指定新编号。
5. 核对包内构建提交、实际EXE、输入/用户资料保护哈希；保存releases记录后再打本地标签。
6. 只有用户要求时推送分支/标签；不默认合并main，不自动上传业务输入或发行ZIP。

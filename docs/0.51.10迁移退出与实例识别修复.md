# 0.51.10迁移退出与实例识别修复

本文记录0.51.10独立修复的来源和边界：它基于实际故障交付0.51.9 rc3冻结源码，当时不包含另一个0.52.0分支的业务新功能。0.52.1随后在独立分支整合两者，并增加资料保存位置设置；本文件下述“不修改业务计算”是该退出修复自身的范围。各版旧交付保留，不自动替换当前软件，不执行真实迁入。

确认迁入后，先持久记录准备材料和等待退出状态，再协同停止线程、连接、关闭窗口，最后替换目录。退出错误处理只写持久日志，不创建QMessageBox；迁入结果由下一次正常启动的窗口报告。正常运行中的错误对话框继续可用。

| 状态 | 含义 |
| --- | --- |
| PREPARED | 已校验并准备材料，原库未替换 |
| WAITING_EXIT | 已确认，等待线程、连接和窗口安全结束 |
| APPLYING | 正在校验、获取锁、构建替换目录或改名；具体阶段单独留存 |
| COMPLETED | 正式目录中已有本操作完成凭据，原库完整备份保留 |
| FAILED | 未完成或已回滚；保留原始错误、准备材料及已有备份 |
| CANCELLED | 用户取消，原库未替换，原迁移包保留 |

状态和计划保存在资料目录旁的`.settings.order-migrations`；持久异常及退出阶段日志在旁侧`.settings.diagnostics`，不依赖即将替换的目录或已经关闭的普通日志句柄。界面“完整订单迁移”可查看上次结果。准备目录存在不表示已迁入；旧版没有状态凭据的材料不会自动重放。

修复默认启动路径：恢复检查、实例资料租约与实际`settings`目录保持一致，不再检查上一级目录。目录改名中断时，先在独占租约内恢复原库或核对完成凭据，再打开仓库；已准备但未开始替换的请求只提示，不自动执行。

实例识别继续保留用户全局QLockFile、本机激活通道和资料目录独占租约。优先使用进程同步句柄判断运行/退出，不用名称、窗口或“拒绝访问”单独放行。无法确认仍阻断；启动中进程、活跃子进程与真实实例受保护。对稳定的旧无线程/无句柄、无命令行/路径且创建者已消失的弃置子进程，需两次创建时间一致的CIM记录和独立Toolhelp快照共同确认，且仅在已有实例锁或资料独占保护内排除；不终止或修改该进程。PID变化或复用、父进程仍在、状态缺失均保持阻断。

原始16:11事件的直接致命错误已由转储确认是QApplication不存在时构造QWidget。此前Python异常尚无足够证据还原；本修复没有把推断冒充根因。冻结版真实隔离导入已复现“误将残留37788判为运行实例，apply在替换前拒绝”，这解释当前重试失败，不证明它是首次中断原因。最终调查、未解部分和真实EXE验收见独立交付报告。

本次不修改模型、箱规、数量、预算、单据匹配或业务计算。真实原库、待迁入目录和旧锁文件均未清理；真实恢复需后续单独执行。

# 0.26.1 门店默认重新载入

本版修复“保存/注入了门店默认，重新检查补货建议后仍使用旧值”的一条已复现路径。基线是0.26.0提交07e7f31e41926b644f18206418f69502a9b71a91，独立分支fix/store-default-reload-0.26.1。模型0.3.3-rules、归属0.5.1、配置schema2和存储格式均不变。

## 使用

打开0.26.1，导入补货建议并检查文件。在“门店与参数”的“查看生效参数”查看实际值：备货/到货周期看“各仓周期”，快销/日百覆盖看“分类超参”。“模型超参”里的通用周期和通用概率是回退值，有分仓周期/分类值时不代表实际商品所用值。

检查结果明确统计采用已保存默认、保留本次调整/快照、尚无门店默认的门店数。门店编码须精确匹配；不按相似名称套参数。没有保存预算方式的门店仍需选择预算，不自动假定不限预算。

如果本次已明确调整参数，会继续保留。要完全采用最新默认并舍弃旧作业配置，可“新建今日草稿”后导入；已有未保存变更仍会按原流程询问，不自动丢弃。历史草稿、历史签发和计算结果不会因默认参数变更而被回写。

## 根因与修正

`Workbench.loaded_ok` 原先先调用 `populate_stores` 读取持久化默认，随后无条件回填旧界面的 `store_presets/store_ui`。这使界面已经检查过门店时，后续注入的新默认被旧值遮住。全新窗口首次导入在基线中可正确载入，不能将该缺陷泛称为所有注入失败。

现在记录上次检查时载入的设置来源，重新检查时由 `store_defaults.reload_record` 分三个组处理：完整参数方案、主从仓组合、预算方式和金额。当前组仍等于上次载入值或此前保存默认时，采用最新默认；明确修改过的组保留。门店勾选独立保留，解决冲突后恢复可计算门店勾选。参数组作为整体保留，避免混合两个方案的部分参数。

来源记录仅在当前窗口内存中存在，不改变JSON/SQLite或作业格式。恢复/显式复制草稿没有此默认继承来源，保持历史快照；新建草稿后重新采用当前默认。计算任务始终使用界面 `selected_settings` 的完整有效配置，计算公式及商品规则没有修改。

```powershell
.venv\Scripts\python.exe tools/verify_store_parameters.py exe --exe '交付_0.26.1_rc1/补货助手/补货助手.exe' --fixture qa/aoxiang_integration_20261101/inputs --output qa/default_reload_0261/exe_rerun
```

可选 `--plan` 读取本机已冻结的88店注入计划；只写该验收目录，检查88店实际参数通过新导入回调传到计算任务。此处使用合成销量行壳，不代表重新计算88家门店的真实销售数据。

验收结果、构建提交和哈希以 `releases/0.26.1/rc1` 的交付报告为准。没有取得用户当次出错门店/结果快照，因此本版可确认修复已复现的覆盖路径，不能证明用户所有异常均由它导致。

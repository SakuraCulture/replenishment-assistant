# 0.7.2 历史、日志及商品明细性能

固定基线：0.7.1 / a831049a78e41f33369ce06b28709f3080324087。模型0.3.0-rules、仓归属0.5.0、参数/每日作业格式1不变。
本轮仅实施设计A/B/C，每日作业存储与完整大作业恢复不改。旧包保留；独立分支本地开发、打包，不合并、不推送。

## 操作
首页和历史列表会立即显示加载提示；首次为旧归档建立索引需等待，过程中可切工作页。之后按日期倒序/店码原顺序显示，每页100单，首页最近10单。查询仍为原来的字面子串，保留商品名称、编码和摘要信息匹配；输入停止275ms或回车后查询。旧结果加载中有明确状态，不把尚未完成视为无结果。
归档明细只读，选择修订后异步读取。输入关键词只筛选已载入的轻量行，导出仍是该修订全部确认单范围。关闭即取消请求并释放视图。完整审计提供概要、单商品、参数来源和完整JSON保存，不再直接把百MB全文塞入文本框；大文本预览明确截断，保存完整JSON不截断。
日志仅分页展示，每页100条；导出当前查询始终包含全部匹配记录，固定查询快照、字段和顺序不变。工作明细搜索同样防抖，大结果汇总显示“统计中”，正式导出会先应用尚待执行的搜索。

## 模块与边界
- normal_orders：新增只取头部；旧list兼容入口每单解码一次；get独占解码树使用相同规范JSON指纹，省略只为删根字段而做的深复制。正式confirm/fingerprint实现保持原逻辑。
- history_read：只读源库，模块顶层Windows spawn入口；摘要、商品搜索与显示投影写入同设置目录的archive_index.sqlite3。它是可丢弃派生数据，不能作为签发或导出依据。
- history_tasks：最多1个独立历史读取进程、1个执行任务和1个最新待办。新请求取消旧回调；重读取在安全边界响应取消，关闭主窗口回收本应用持有的只读进程。不会改变门店计算并发设置。
- history_ui：轻量QAbstractTableModel归档表、按需审计、日志分页。大快照留在子进程，界面仅接收展示投影。
- ui_results：初始化信号合并、列取值/排序键缓存、单个后台汇总任务及最新待办。保留原Qt筛选/排序与同值次序。
- application_window：首页只读摘要；工作结果签发状态异步核对、按结果对象与关注对象失效；此展示缓存不用于正式确认。正式操作仍读权威修订并完整校验。

索引绑定源数据库身份、oid、修订、源digest、保存时间与索引格式；单修订写入事务原子发布。缓存内容校验失败重新构建，SQLite损坏缓存另名保留后重建。源库不迁移。退出软件后可删除archive_index.sqlite3重建，它不包含唯一业务记录；不要删除workbench.sqlite3。
第一次索引仍须读取校验所有归档，因此完整加载不等于秒开；已有完整索引的读取速度单列报告。查看已缓存历史的完整性以最近建索引时的验证为基础，正式导出必定重新校验源快照。文件被替换、修订或digest改变会失效；不要手工改业务库。

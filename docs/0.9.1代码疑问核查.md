# 外部代码疑问：按当前 0.9.0 基线核查

审查对象为本地干净提交 364929c，不把别的版本结论直接套用。复现：`tools/audit_review_questions.py`（正常及 `python -O`），证据 `qa/inbound_091/review_probes*.json`。本次只正式修改已批准的在途保底、对应风险及日志交互；下面明确哪些是事实、哪些不成立、哪些尚未修复。

|编号|核查结果|本次处理与后续边界|
|--|--|--|
|1 取整容差|成立。allocation.apply 用 Decimal 计算整包数后，候选量偏离倍数超过 1e-8 就抛错；1.000001 或 0.999999 的合成候选可复现整店失败。input_adapter.business_checks 也检查步长，但检查单位与 allocator 不完全一样。不能宣称所有浮点漂移已被统一消除。|新增可复跑模型步长/预算测试。保留原失败策略，未擅自“忽略某SKU”或加大容差；后续应统一步长规范，并明确异常商品隔离是否允许部分门店结果。|
|2 SHA256 使用 assert|对当前业务快照不成立。storage_chunks.load/manifest/Reader 使用显式 ValueError；normal_orders.get 也显式拒绝指纹错误。python -O 错误哈希仍被拒绝。|无须假设 EXE 永远不优化。仍有 engine 的一箱隔离 assert、QA脚本 assert；它们不是当前快照校验防线，也不夸大为生产代码完全没有 assert。|
|3 核心零自动测试|说“零”不准确：已有 verify_090_fixes 等合成自动场景以及结构/预算/一箱回归，并非全部绑定真实 Excel。但缺少集中、便携的核心单测确实影响使用和发现边界。|新增 tests/test_rules.py，标准 unittest 可运行 12 组核心/预算/例外/哈希测试，正常与优化模式均执行；本次还固定旧提交与真实签发批次逐字段比较。不能声称测试已穷尽所有参数组合。|
|4 行号契约|位置耦合成立。batch_service.prepare 用 records[export_row-2]；table_records 保留原枚举行号，当前空行跳过不会重新编号。不能仅凭“过滤空行”断言当前已经错配，但将来若桥表筛选/重排且未保持源序号，确有静默错配风险。|现有多文件、空值/长编码、冲突来源及内存桥等价测试继续运行。后续宜显式来源ID并检查键与源序，不在本轮重构匹配链路。|
|5 每店全量 pickle|部分成立。batch_service 已按店切 normalized / warehouse_rows，并非每店传所有门店商品；其他共享元数据/商品快照仍可能重复序列化，且父进程先 deepcopy 完整 loaded。work_transfer 的分帧是作业 IO，不等于已经解决计算进程共享。|本轮不重构。后续优先瘦化进程输入，再评估只读进程初始化或按需快照，需测峰值内存、spawn、取消和门店隔离。|
|6 Excel读4次|确有表头识别、表格读取、前后哈希，prepare 还会核对源哈希；两次哈希是顺序字节读取，不是两次完整 Excel 解压解析。故“4次完整读表”不精确，但 IO 重复是真成本。|不删变化检查。后续可同一只读文件快照完成一次哈希及一次解析，需定义源文件变化窗口与缓存值一致性，不能只为提速取消保护。|
|7 单元素列表及深拷贝|成立。engine.run_calculation 每行 adapter.execute([(d,m)])；前置/结果有深拷贝。|本轮不改复制/所有权，避免新旧结果相互污染。后续拆单行适配接口、测复制收益及原快照不变性。|
|8 失败只有str(exc)|部分成立。普通 Worker 已 logging.exception；批量门店 future 失败及 BatchWorker 主异常主要传 str(exc)，缺少完整可定位上下文。|'KeyError V' 不能作为好用的业务提示。后续补门店/SKU/源行、诊断ID和完整堆栈，区分用户可修数据错误与程序错误；不要把日志中的完整商业数据或凭据对外发送。|
|9 w/z零保护|正常整数销量下有 sales_state 分支保护新近动销，但存在可复现的小数边界：H=1、I=14、J=14+1e-12，z=0 且极小 a 落入平稳后上升，原 calculate 除零。经 input_adapter 会标记“计算异常”，不是健康0；有阻塞分支另有异常传播风险。|明确记录既有边界缺陷；未擅自选一个趋势回退值改变预测公式。后续应单独规定 z=0 的业务回退并做模型版本验证。|
|10 依赖没锁|“没锁”不成立，requirements-build.txt 使用 == 固定 12 项运行/构建包，脚本记录干净构建提交。尚无带 wheel 哈希的完整离线锁，也没有全新电脑重建验收。|实际 EXE/ZIP 哈希、构建提交、依赖版本和文件清单随发行保存；本机重建成功不等于新电脑可复现或逐字节构建相同。|
|13 配置优先|程序有明确顺序：标准/已存方案→门店绑定→本次修改，仓周期覆盖通用 depth/lead；路由后 parameter_schema.apply 重新绑定每店权重。参数编辑可见方案版本和值，历史可见有效设置，但没有每个参数完整的覆盖来源轨迹。|本轮让当时参数真正可找到和导出；不声称已实现全部优先级可视化。后续做逐参数“来源/覆盖/生效值”对照，需沿现有优先级。|
|14 无快捷键|基线没有专门 QShortcut，Qt 控件仍有 Enter/Esc 等默认键。|本轮日志商品/操作查询新增 Ctrl+F；未给全应用每个动作加快捷键。|
|15 冲突逐条处理|成立，现有每组一个候选选择框。|后续可按来源批量提出选择，但须展示受影响组并确认、支持撤销；不默认全选第一份，不在本次改变冲突决胜。|

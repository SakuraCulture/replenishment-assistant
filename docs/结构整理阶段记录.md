# 0.6.1 结构整理阶段记录

固定基线为 e50072cc00c6997aed9fe1113012192210ad7eb3（已验收0.6.0）。模型0.3.0-rules、归属0.5.0、存储格式1不变。测试只使用qa/structure_061；frozen.json记录源文件、复制输入、方案、仓快照、旧交付及日常资料哈希。旧0.5/0.6对照不作为本次验收。

## 阶段1：启动与公共界面

app只负责启动/日志/异常/创建Workbench，历史MainWindow访问懒加载legacy_window。多店窗口继承SessionWindow而非旧MainWindow；SessionWindow只显式建立共享状态，不创建页面或调用虚方法。页面建设完成后再连接工作台状态。

ui_controls提供样式、按钮、文件控件；ui_tasks提供线程及任务生命周期；ui_results提供商品表/筛选/详情与结果导出交互；ui_session提供共享会话及必卖清单交互。旧单店窗口隔离在legacy_window，界面模块不再反向导入app。

验证：stage1/equivalence.json，22个0.6.0冻结对照场景及3个Excel全字段/类型/格式对照，差异0；stage1-ui-final原窗口交互验收通过。所有原始输入、冻结资料、旧交付及日常设置哈希不变。工具以门店+商品编码比较完整记录及全部嵌套元数据；白名单只含明确的时间、进程、临时路径和打包版本字段。

后续阶段完成后继续追加；未记录完成的阶段不得视为已验收。

## 阶段2：结果口径、展示字段和导出

result_semantics是排除、候选/执行数量金额、原因、状态、汇总和持有天数的唯一实现。display_fields集中UI/Excel共用字段及两种报表差异。xlsx_exports集中单店、多店导出和基础写表，明确保留两种样式。engine与batch_service通过导入别名保留旧入口，无第二套实现；runtime_support统一取消异常与检查点。进一步清理legacy_window遗留的公共方法副本，原窗口仅保留特有流程。

验证：stage2-final/equivalence.json，22场景及3份Excel零差异；stage2-ui-final界面验收通过，取消异常类身份一致。Excel对照改为解码XML按坐标比较所有单元格类型、值、样式引用、完整样式表及工作表结构，避免构建百万个GUI式单元格对象；没有放宽业务比较或增加排除项。

## 阶段3：契约、字段索引和默认配置

app_defaults统一仓库名称、原8+4/8+5周期、供货选项与默认配置读取；每次读取仍返回独立配置。data_contracts只提供静态类型，不构造新对象、不转换数值、不改JSON/SQLite。字段与数据契约文档逐一列出A:BX以及执行、来源和审计字段，并说明既有配置优先级。

阶段复查发现batch_service内仍有遮蔽导入别名的旧export_batch函数，已删除该副本；实际多店导出现在调用xlsx_exports的唯一实现。没有重写前一阶段提交。

验证：stage3-complete/equivalence.json（完整重跑，含上述清理）；stage3-ui/work_ui_report.json；stage3-compat/report.json。旧0.6.0数据库副本可直接打开，方案版本、门店绑定、完整历史载荷及恢复重算相同。字段契约没有存储迁移。

## 阶段4：内存适配替代临时Excel

read_table只负责Excel读取，table_records负责表头/空行与源行；prepare与prepare_records共享完整匹配主体。多文件归集、分仓快照和旧混合资料冻结快照使用bridge_table投影原中转语义，无文件写出/读回。原显式Excel入口保留；没有改变匹配、归属和算法。

先验证边界再接入：42项真实写出/读回与内存对照，在lxml和打包使用的etree环境各通过一次（memory-lxml-complete、memory-etree-complete，零差异）。首次etree检查发现CR文本换行归一差异，已按原写入器区别保留；缓存公式测试也改为按XML节点设置缓存，避免依赖序列化空标签写法。最终全量stage4-verified/equivalence.json：27场景（增加真实批量、冻结混合资料重建及参数试算）加3份Excel，差异0；旧输入、发行和用户资料哈希未变。参数试算曾暴露阶段2的semantics导入遗漏，已补回并加入独立基线对照，不作为既有缺陷掩盖。

stage4-workbench-fixed覆盖方案实际生效、试算隔离、修订冲突、写入失败回滚、无源文件恢复及旧混合入口；stage4-ui原窗口流程通过。算法三文件与默认配置逐字节未变；adapter_structure_check证明完整匹配主体和其他算法函数AST一致。原整文件适配器哈希断言改为上述结构守卫和独立严格对照，未放宽数值容差、删业务字段或更改旧业务预期。

此阶段通过后提交。最终版本号、干净提交构建、正式回归和实际EXE验收仍须单独完成，见最终发行记录。

# 0.52.2 资料搬迁可见进度

确认搬迁后，独立进度窗口先出现，主业务窗口再安全退出。复制、摘要校验、数据库完整性核对、切换、恢复副本归档与旧副本清理均有阶段说明。复制、哈希及ZIP读写每处理1 MiB检查一次更新时间，最多约每秒落一份小状态记录；这些记录在移动范围外，不写业务库。

百分比只表示当前阶段。数据库检查不伪造剩余时间或总完成率。复制阶段包含原件和副本核对读取，其处理量与磁盘净写入量不同。完整完成、新位置已启用但清理待处理、失败并恢复原位置分别展示。

进度窗口没有重新搬迁、取消或写业务数据的按钮。关闭它不会中断搬迁；再次打开应用可查看正在执行的原操作，不开放第二个业务窗口。没有独立窗口就绪确认时不进入搬迁。原操作结束后可从“显示与帮助 → 数据保存位置 → 查看最近一次搬迁进度与结果”查看。

每项搬迁使用独立身份，保留自己的状态文件；准备下一项后，旧窗口不会跳到新任务。正式实例及其他工作进程的占用保护继续执行，仅明确的只读进度入口不计为业务写入进程。中断后仍先通过单实例保护，再恢复原位置或已提交的新位置；进度查看不会自动重放复制。

额外诊断：目录扫描失败明确报错，不能静默漏过子目录；文件范围变化记录增减数量及有限样例。

隔离复现并修复一个搬迁缺陷：干净关闭的WAL模式数据库原来没有WAL文件，搬迁的SQLite占用保护会自行创建该文件。原实现使用建锁前的清单，在复制结束误报范围变化。现在先取得保护，再冻结复制清单；只允许本次保护明确生成的WAL扩展首轮清单，其他新增/减少文件和目录仍拦截，WAL同样复制、计算摘要并做完整性检查。未跳过校验、降低SQLite保护或修改存储格式。本轮不修改补货模型、数量、预算、箱规或单据。

完整归档并清理业务副本后，若仅剩已排除的SQLite共享内存文件或实例保护文件及其原有目录，结果列为“搬迁完成、保留少量技术目录”，不再永久误显示“清理待处理”。不会为消除提示而删除这些技术文件；未知文件或新增目录继续保留并提示核对。

本机2026-11-12那次操作90128a8715a44e2caac1433cc8629310，在旧版0.52.1 rc6复制结束后因“资料文件范围在复制期间变化”停在切换前；原C盘位置和D盘未完成副本保留。当前事后差异包含专用浏览器资料及重开后的运行文件，无法仅凭事后快照确认当时具体哪个文件先变化。进度改进不代表这次真实搬迁已成功，也没有自动重试或清理真实材料。

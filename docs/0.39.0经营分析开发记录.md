## 阶段 1：统一五段与原生看板

新增 `order_analytics.py`、`order_analytics_exports.py`、`order_analytics_ui.py`。
入口：订单跟踪 → 经营分析；首页也有独立入口。没有当前计算任务或 AI 连接也可使用。

模型建议包含原启用的一箱例外、位于总预算和人工安排之前。纳入模型有量但最终签发为 0 的商品；门店、仓、订单和商品原顺序保持。必采/非必采按当时必卖依据，未留存清单单列属性待核。五段统一排除门店禁采、对应仓禁用和淘汰品。未导入与确认零值分开。

按门店、分仓、订单、商品下钻；分页每页100条，导出包含全部筛选页。支持固定/滚动日期常用视图、查询取消和安全关闭。导出复核确切查询快照，写入临时文件后发布，取消/变更不留下完整名半成品。看板查询只读业务库；常用视图属于本机显示偏好。

源代码验证：新增 16 项纯逻辑测试、3 项 Qt 隔离界面测试通过。新功能尚不能据此宣称实际 EXE 验收通过。一次缓存测试初始把同内容两仓误期望为读两次，实际按相同 SHA 只解析一次；改为核对不同原件哈希数，保留首次失败日志。

## 阶段 2：AI 查询与导出

MCP 和 CLI 共用协议新增 `query_order_funnel`、`order_funnel_results`、`export_order_funnel`。查询和导出后台执行、操作键幂等、结果分页最多100条，绑定查询快照，最多保留3次分析结果。原生页面可复制包含精确日期/范围的 AI 指令，不自行发送。

隔离 Qt 网关验证：查询幂等、跨页、数据变化拒绝旧结果、工具权限、AI/原生 Excel 值/类型/样式/工作表/行列顺序一致。精确动态差异白名单仅“统计口径”的生成时间。

## 阶段 3：多轮证据复盘

新增 `history_diagnostics.py`、看板“多轮复盘”页、同名报表工作表和 `store_history_review` 只读接口。查询可选择1至30轮，默认8轮，提供近90天快捷范围。先复盘签发减量、门店少要、下单减少和实收短少，不把未知到货时间当成准时，也不拿滚动月销差额冒充期间销量。

6项证据归因测试通过；经营分析/API/Qt组合22项通过。多轮复盘仍不是连续库存回测，也不承诺判断出真实因果。

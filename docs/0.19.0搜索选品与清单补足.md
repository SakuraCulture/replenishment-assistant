# 0.19.0：搜索选商品，直接形成补足清单

基于0.18.1提交 `43a84dd31ab6576a56b20f0b0f5ded093071fb88`，独立分支 `feat/product-picker-0.19.0`。模型仍0.3.3-rules，归属仍0.5.1。保留原Excel导入、已保存清单及0.18.1主仓回退修正；不改预测、箱规、库存、预算或分仓规则。

## 少量商品怎么操作

1. 门店计算完成后进入“最终清单 → 按清单补足 → 搜索选商品”。在清单管理入口也可以预先选择、保存商品，未计算门店时不能预览补足。
2. 输入商品名称或商品编码，勾选需要的商品；可筛选资料仓、分类，也支持空格组合关键词。两仓相同编码只展示一款，两仓名称均可被搜索命中。搜索仅用于找到商品，实际匹配仍按完整编码。
3. 换关键词不会丢失已勾选商品，底部显示总勾选数和筛选外勾选数。“勾选当前筛选”仅增加当前可见范围；“清空全部勾选”明确清空全部。“只看已勾选”在当前搜索和仓/分类条件下查看已选商品；清空搜索、选全部仓/分类即可查看全部已选。
4. 选择“加入清单”，可逐商品填目标，或填写统一目标，选择“有货即可 / 补足目标持有量”和适用库存状态。小批量按默认“有货即可”时，可直接“选好并预览补足”，自动命名临时清单，无须先保存或制作Excel。
5. 按原流程核对箱规后的实际数量、金额、整店预算和风险，确认后应用到草稿；签发仍走原确认流程。生成清单/预览都不等于签发。

## 已有清单如何补选

读取已保存清单或导入Excel后继续“搜索选商品”。已有商品显示“已在清单”，不可重复勾选；新增商品按勾选顺序追加，原行顺序、原目标、关注和备注保留。清单中的“移除选中商品”仅作用于当前编辑副本，不会立刻改已保存清单或历史单。

可以“保存为新清单”或“保存当前清单新版本”；保存新版本仍检查原版本是否被其他窗口修改，发生冲突会拒绝覆盖。也可只用于本次，不强制保存。

新查询商品默认未标“关注”，沿用文件未填写关注的口径；若勾选“本次仅使用关注行”，查询新增的未关注商品不会参与。该开关默认不勾选，普通查询选品无需使用它。

## 业务边界与追溯

- 查询覆盖已维护的河北/山东仓资料；旧混合资料入口也可使用本次已匹配商品。名称、分类、状态和“本次门店记录”只是辅助选择。
- 仓筛选只帮助查商品，不指定供货仓；实际应用仍逐门店按主从仓归属取价格、箱规和仓周期。
- 商品资料存在但本店缺销量库存记录时，显示待核，原补足预览会列出“缺本店销量库存记录”，不补造数据。禁用、停采、地采、缺价和其他待核仍由原规则拦截。
- 有货即可/目标补足、箱规倍数、人工0保护、预算和21天风险确认均复用原实现。不重新运行模型、不重新分配未选商品。
- 查询清单保留选品时的仓资料版本、原文件校验、工作表及源行；不伪造Excel附件。签发快照保留清单，历史“签发前调整”表单新增显示该商品的选品依据；旧历史无新增字段、不回写。
- 名称/编码检索不支持条码；当前维护仓快照没有稳定的统一条码字段，本轮不另读原Excel或猜测条码。
- 搜索准备放在后台线程，有进度、可取消；子任务不写商品资料或用户配置。弹窗取消不改变清单和作业。

## 人工试用建议

|操作|应看到的结果|
|--|--|
|选一款，换关键词再选一款|两款仍都勾选，显示筛选外勾选数|
|两仓相同编码、不同名称|只有一款，两种名称都可搜到；实际仓归属不被筛选改变|
|已有清单再选相同商品|显示已在清单，原目标不变|
|选新商品，直接预览|形成临时清单，不要求先填名称、保存或上传文件|
|设置目标35，实际箱规24|由原补足规则向上按箱规计算，预览实际数量与超过目标量|
|选择禁用/停采或缺本店数据商品|预览列为未应用，不填0冒充有效数据|
|选完取消|当前清单和正式结果不变|
|保存、重启再用|商品、目标和选品依据仍在；签发后历史表单能查依据|

## 实现与复跑索引

`stocking_selection.py`：只读检索投影、精确编码去重、追加建单。`stocking_ui.py`：异步查询、虚拟表格、勾选与清单编辑。`preissue_ui.py`：传递本次所选门店范围。`history_forms.py`：只对有查询依据的调整显示附加表单。

`preissue.py`、`stocking_lists.py`、`model.py`、`one_box_exception.py`、`allocation.py`、`warehouse_catalog.py`及默认配置均保持原实现。沿用原JSON和SQLite结构，仅清单行增加可选 `selection_sources`；历史签发单和既有导出结构不变。

便携验证：`python -m unittest discover -s tests -p test_stocking_selection.py -v`；完整项目验证：`./dev.ps1 Test` 和 `./dev.ps1 Test -Optimized`。冻结真实数据对照：`tools/verify_picker_regression.py`。实际EXE：`tools/verify_preissue_exe.py`。验收、限制和构建哈希以 `releases/0.19.0/rc1` 为准。

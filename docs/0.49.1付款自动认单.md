# 0.49.1 付款自动认单

修复0.49.0中“已找到唯一完整匹配，但仍要求选择企业、确认门店别称”的问题，以及聚水潭付款表追加的“签发单号／补货单号”列被忽略的问题。

## 使用

在付款核对中导入聚水潭付款文件。默认使用自动模式，不需要填写签发单号、选择企业、选仓或先维护门店别称。界面自动显示对应的门店、仓、签发单号及识别依据。之后核对实际付款内容并确认保存。

自动认单只解决文件属于哪张订单；不自动确认实际已经付款，不改变商品、数量、金额，也不把缺行补成实际支付。

## 自动识别依据

1. 文件有明确的签发单号时，读取“签发单号”或“补货单号”列，核对当前签发身份。两列并存或重复表头会报明确冲突，不默认选第一列。
2. 没有单号时，完整比较有效分配单的商品编码、逐商品库存单位数量和金额；在全部相关日期内只有一张完整匹配，就自动关联。店名差异不再要求先手动确认，同店两仓可同批识别。
3. 重复导入相同文件不会新增付款版本。已保存的内部单号再次导入，原订单及原分配仍有效、逐商品和数量一致且无其他候选时，金额更正自动关联原单，同时显示金额差异。
4. 日期及生命周期不能掩盖重复候选。原订单删除、重新签发或分配变化，不能套到另一张同号新订单；预览后的并发变化仍阻止整批保存。

默认模式不根据仓名或付款表店名猜聚水潭企业。认单对应单独保存在本机，以来源内部号、原表店名、冻结的原订单及分配身份记录；不新增企业身份、不改门店主资料或企业门店别名。付款与认单对应在同一事务内保存或回滚。

“更多候选筛选”仍提供指定企业及原有维护入口。指定企业后核对其已验证供货仓，不能把其他企业仓单保存到该企业来源下。正常自动模式不要求操作这些设置。

## 出现冲突时显示什么

| 情况 | 新版行为 |
| --- | --- |
| 完整明细唯一，未选企业或店名有差别 | 直接显示“已自动识别”，带出门店、仓、单号 |
| 正确签发单号 | 直接识别；付款数量或金额变化仍在核对页保留 |
| 签发单号属于另一门店，但明细完整匹配本店 | 显示单号指向和明细匹配的两个对象，不忽略错误单号 |
| 少商品、错商品编码、首次导入金额有变化 | 展示候选的缺少、多出、数量不同、金额不同款数及部分商品编码；不能称为完整匹配 |
| 同款同量同金额对应多个有效订单 | 明确显示多单重复，不按最近日期或第一张猜测 |
| 原关系已删除或修订失效 | 明确说明原对象失效，不按相同单号重新关联 |

选中来源行，下方固定显示完整识别原因，可滚动复制；不必依赖被截断的表格列。

## 本轮案例

使用此前7份付款案例和独立冻结订单库验证。01山东仓、02河北仓、未追加错误单号的03别称、04新内部号自动识别；先保存01后，05增加一分钱自动认回原单并显示差异。06少一款、07商品编码错误被明确区分，未保存为付款。

用户后来在03中填写的 `BH-20261108-CXT20260623-ZC-SD` 属于东阿店，其175款、6685.95元明细完整对应 `BH-20261108-TBBLHDYJ20260617-ZC-SD` 恒大御景半岛山东仓。该修改版单独验证为单号冲突；原文件保留。本轮正向03使用此前ZIP内的未填号原件，不抹掉用户修改。

测试只使用隔离数据库，不连接平台，不修改正在使用的订单资料。模型、预算、箱规、归属、采购两位小数规则、库存分配与删除逻辑不变。全量回归、实际EXE及案例证据见[交付报告](../releases/0.49.1/rc1/交付报告.md)。

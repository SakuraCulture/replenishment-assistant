# 0.51.0 订单迁移、单实例与仓店缺货分析

应用 0.51.0；计算模型继续使用 0.3.5-rules，仓归属 0.5.2、参数 V3、快照存储 2 均不变。本版不改预测公式、箱规、预算或归属规则。

## 移交一台电脑上的完整订单

入口：订单跟踪 → 完整订单迁移／导入与参数导出（全部本地资料）。

1. 等计算、采集和后台作业安全结束。导出范围是全部本地订单，不受列表当前日期、筛选和勾选限制。
2. 选择“导出完整订单迁移包”，保存到应用资料目录之外的新 ZIP。包内包含整个订单库：全部签发修订、每日草稿、原始文件、回传、库存基线与分配、付款、实收、三种单号、共享关联、删除失效标记、平台任务和防重事实；并携带门店默认、预案、必卖清单和当前仓资料。
3. 将 ZIP 交给接收电脑。选择“校验并导入完整订单迁移包”，先检查版本、文件集合、文件摘要、数据库、快照和库内原件完整性；核对数量及备份目录后再确认。
4. 确认后软件安全退出，再整组替换。目标原资料完整移入同级“订单导入备份”目录；出现重命名中断，下次启动先恢复或确认已完成的提交。
5. 重新打开软件，核对订单与三种单号。迁入的未完成作业与计划保持暂停，先核验原平台结果，再从原业务入口继续。已经发出的平台请求不会撤销，也不会因为迁入就自动重发。

导入采用完整恢复，不进行订单混合。目标电脑的连接配置、登录、本机 AI 配置及两个独立缺货分析板块保留；这些资料不从来源电脑导入。迁移包不携带浏览器 Cookie、用户配置目录或机器连接绑定。

原路径缺失会写入清单并显示数量；库内已留存原件仍完整携带。不能恢复来源电脑本来就没有保留的文件。迁入文件有路径与内容摘要映射，读旧路径时可找到随包留存的副本；签发内容、任务身份和原校验摘要不因此改写。第二次迁移继续保留这些旧路径关联。新选的现有文件仍按实际文件读取。

迁移包含经营数据，请按团队原有资料管理方式保管。完整备份不自动删除。不要将不同目录中的几张 SQLite 表或数据库文件混合拼接。

## 只交接参数

同一入口选择“导出全部门店参数与预案”。Excel 包含已保存的分仓周期、通用参数、分类参数、分类映射、补货策略、供货关系及预算；附预案全部版本和当前必卖清单作核对依据。界面未保存的临时修改不包含在内。

前七类业务表可沿用现有参数导入入口核对差异后应用；附加的预案与必卖清单页供查阅，不会自动写回。移交全部订单与关联记录时使用 ZIP 迁移包。

## 再次打开应用

同一 Windows 用户只打开一个主业务窗口。第二次启动先唤醒原窗口，恢复隐藏或最小化状态；同时存在的原应用模态窗口也会被带到前台。旧版没有通信入口时，按实际主进程与窗口身份唤醒；启动未完成时提示等待，不另开一个业务窗口。计算、分析和组件工作进程继续按原架构运行。

## 查看完整计算逻辑

决策复查 → 选择历史仓单 → 导出完整计算表。保留“完整计算建议表”和“字段与口径说明”两张表。

按行查看门店、商品、供货仓、类目、标签、商品／采购状态、销量、库存、在途、周转；接着看当时生效的周期、分类权重和参数，以及预测、额度、箱规、保底、预算、人工改量到最终签发的数量链路。供货仓库存和原商品资料来自当时快照或留存原件，缺失项空白并注明原因。

不再递归展开文件路径、进程、来源数组和不参与计算的旧参数。原始商品资料下载与签发模板继续使用独立入口；历史结果不以当前参数或当前仓资料补填。

## 门店预计销售天数

入口：门店缺货率 → 商品与待核；同字段进入商品明细导出。

`预计销售天数 =（原可用库存 + 原在途库存）÷ 月销 × 30`

例如月销30、可用9、在途6，结果15天。按本次明确公式使用原值，负库存可以得到负天数；月销不大于0、库存／在途缺失或无效时留空并说明原因。此值逐店、逐商品、逐观测日计算，不将不同商品库存单位混合成一个“平均销售天数”。现有门店缺货率分子、基数和排除选项不变。

## 跟进大仓缺货

入口：大仓缺货率。页面未进入且未启用计划时，不创建分析库、扫描原件或启动工作进程；仅保留小型导航与计划标记。进入本板块后才加载业务能力。

1. 勾选山东仓、河北仓，点击“采集今日大仓资料”。复用全局聚水潭连接，仅在本板块留存，不更新补货默认商品资料、库存分配基线或门店缺货率资料。也可明确标仓后导入独立原表；导入前核对原表是本次库存，导入时间留存为观测依据，不补写历史。
2. 基数：本仓资料全部商品，剔除虚拟分类任一标签含“淘汰”的商品、商品状态为“禁用”的商品，以及商品标签拆分后精确包含“日配”的商品。日配专区、非日配不命中日配排除。
3. 缺货数：剩余商品中可用库存小于等于0的支数；除以剩余支数得到大仓缺货率。没有月销条件；考核品没有另行剔除。不同仓同编码分别计数，期间按仓商品日加权，缺采日期不补0。
4. 影响排除判断的字段缺失、状态空白或有效基数中的库存无效时列为待核，暂不显示百分比；已确定剔除的行不因其库存缺失阻断其他商品统计。
5. 在“切面分析”管理多套组合，可自选供货仓、供应商编码／名称、分类与一二三级类目、商品编码／名称、日期、状态、虚拟分类、商品标签及顺序。同维多选为或，跨维为且；双击分组可继续钻取。导出每套组合一张表，每行一组数据，包含全部筛选结果；超过 Excel 行数时明确续表。
6. “商品与待核”可查看纳入、剔除和待核的逐条原因。“采集与快照”支持原任务继续、重新采集今日、用原件离线重算、结束本地准备、日志删除。日期范围删除先预览全部快照与商品行；只清本分析数据，无引用原件通过可重试待办清理。
7. 每日采集默认关闭，仅在应用运行且显式启用后执行；使用已保存的仓选择。业务忙时让行；跨日任务不把今日库存写入昨日。离开时默认安全暂停，可明确勾选离开后继续；完成后释放工作进程。

完整验收与交付路径在本版交付报告中记录。真实平台、低配业务电脑和现场新人使用尚需各自验证，隔离演示结果不作为这些场景的实测结论。

# 0.50.0 订单删除与任务失效

本版允许直接删除指定订单的本地链路，无需先处理采购待核、付款或收货状态。模型、预算、箱规、默认值、主从仓归属和采购正常防重规则不变。不包含独立 0.49.4 性能分支。

## 业务操作

1. 在“订单跟踪”勾选准确订单，点击“彻底删除勾选订单”。
2. 核对完整清单。同店同日两仓共享父单，仍按父单完整删除，不能只删一个仓子单。
3. 勾选一次确认，点击“永久删除上述订单”。取消确认不删除任何内容；进入最终提交后等待安全结束。
4. 删除后重新查询。未选订单及共享批次的其他部分保留，可以继续原批次。
5. 如果组件暂时离线，主业务删除仍已完成。“首页 → 数据与任务维护 → 查看 / 重试组件本地清理（不连接平台）”可查看并重试余下文件清理。正常组件请求前也会自动重试。

外部平台采购单、已发出的请求、用户目录内导出的 Excel 和备份不撤销、不删除。已发出的请求仍可能在平台完成。不能把本地删除理解为平台撤单。

## 实现与边界

- 队列项使用稳定 `item_id`，后台写入携带批次、项身份、来源 oid 和执行令牌。删除后的数组位置不作为后台写入依据。移除某项后，晚到结果既不能恢复该项，也不能变成下一项的失败。
- 主事务记录技术失效身份、删除操作号、日/店代次及组件清理待办；不在这些标记里保留商品、付款或收货明细。这些标记不是回收站。
- 每日草稿、签发写事务、旧作业恢复、AI 采用和定时结果采用带代次检查。旧内存内容不能只因重新预览或使用最新 CAS 修订就恢复已删门店。用户重新计算的新内容可以正常保存和签发。
- 签发检查覆盖整日写入内容，在写锁内再次检查，防止仅校验本次签发门店却带回其他已删门店。
- 生成、锁单、收货保存和采购派发保留源单校验。生成失败审计和历史解释日志不会重建已删订单的孤立记录。
- 删除提交时重新读取最新下游数据。无关任务进度不使确认失效；所选订单修订或完整范围变化仍拒绝整次删除，须重新确认，不静默采用子集。
- 共享采购资料每个版本只移除所选订单的 links，维护摘要和当前索引。其他 link 的数量保留。共同原始行、原始金额、原文件及版本时间不能按关联数量猜分金额，因此保留共同事实。无明确归属的数据不凭店名、日期认领删除。
- 聚水潭批次保留其他成员的位置、控制轮次和原冻结分配量，不重新分配删除释放的库存。已锁订单占用转入技术库存保留，避免虚增库存。重放原冻结运行只认自身已提交步骤的技术凭据，不采用其他运行的库存序号。
- 组件退役为独立本地事务，通过主库已提交删除依据核准范围；活动采购及收货记录和独占私有资产退出活动集合。保留阻止旧命令重放的最小身份、请求摘要、上传边界事实及迟到任务号，不伪装成“上传前取消”。共同资产仍被其他任务引用则保留。
- 组件离线、文件占用或在途动作未安全结束时，主事务不等待平台结果。待办持久重试，完成后再确认清理结束。不能强杀正在提交的工作。
- 独立上游资料（例如定时采集运行、当前仓资料、其他订单仍引用的原表）保留；删除不按相同店名或相同日期误删这些资料。旧上游运行采用受代次约束，不可复活旧单。

## 日志模式与恢复

主库、翱象工作流库及附加索引使用磁盘 rollback journal（DELETE / TRUNCATE / PERSIST），删除连接设置 synchronous=FULL、secure_delete=ON，并在写锁内复查实际模式。WAL、内存库或不满足条件时，明确提示且不删除，不自动切换日志模式。

SQLite 只有在磁盘主库与非 WAL 条件成立时，才为 ATTACH 多库事务提供跨库崩溃原子性；仍依赖操作系统与设备正确实现持久写入。[SQLite ATTACH](https://sqlite.org/lang_attach.html)、[原子提交机制](https://sqlite.org/atomiccommit.html)。组件自己的 WAL 库不附加进主事务，由清理待办衔接。

验收区分受控进程中断与真实断电。本轮用独立子进程在提交前、提交后退出并检查主库和工作流库恢复，没有进行物理断电或 COMMIT 中途损坏扇区注入，不能宣称覆盖所有硬件失效。

## 版本使用

保留旧交付以便比对，但同一资料目录请使用完整 0.50.0 交付。旧 EXE 不认识新增失效标记，不支持与本版同时写同一目录。不得拿旧业务备份覆盖当前库后宣称删除保护仍然存在。

存储分块格式仍为 2，新增的是技术防护表和组件本地退役协议。升级组件前自动备份组件库；标记结构缺失或版本不兼容时停止重放，不重建空防重库。

本轮验证、失败记录、源码提交和 EXE 路径见 `releases/0.50.0/rc1/交付报告.md`。不以本轮结果宣称大历史库删除提速，也不宣称已验证低配置业务机或真实平台。

# 0.52.8 订单新增合并导入

默认保留本机数据，新增“合并导入订单（保留本机）”。原“校验并导入完整订单迁移包”仍为整组替换恢复，另列说明，不能混用。

## 业务用法

来源电脑导出完整订单迁移 ZIP；接收电脑进入“订单跟踪 → 完整订单迁移／导入与参数导出”，选择最上方的合并导入入口。核对表显示“新增、完全重复、冲突、本机已删除”及逐单原因，选择一行可看全文。

只确认“新增”部分；其他独立无冲突订单不会被某个冲突一起拦住。有共享采购、库存分配批次或任务依赖时，冲突会隔离该关联组，不能留下缺失成员的半条业务链。没有新增时确认按钮不可用，直接返回，不修改本机也不要求退出。

确认后安全退出；在本机资料完整副本中合并、完整校验后切换。原目录保留为完整备份，不删除原 ZIP。重开提示实际数量、备份路径和逐单结果文件；失败保留原库、迁入材料和原始错误。

## 首版规则

| 情况 | 处理 |
|---|---|
| 本机不存在、关联无冲突 | 新增完整父单、修订、环节事实、原件与必要任务身份 |
| 相同身份、完整关联完全相同 | 跳过，不因重复ZIP或重新导出再新增 |
| 已有同一订单，但回传、分配、付款、收货等不同 | 保留本机，显示冲突；不自动补齐 |
| 同日同店/同号但内部身份不同 | 显示冲突，不改号，不强行当成同一单 |
| 本机已删除或已退役 | 不从旧包恢复 |
| 来源自身同时存在活订单和删除/退役标记 | 作为来源状态矛盾隔离，不误报成本机已删除 |
| 共享批次、平台采购单或任务身份冲突 | 隔离相关订单组，保留无关新增项 |
| 原件、快照或必要依赖缺失/损坏 | 明确原因；不能以不完整链作为有效新增 |

重复判断比较整条订单关联，不只看签发摘要、文件名、更新时间或版本号。迁入暂停造成的技术状态变化有独立去重凭据；本机后续产生新业务事实后，旧来源不能再被错认成完整重复。

## 保留范围与边界

- 门店参数、预案、必卖清单、日草稿、当前仓资料和本机当前库存指针保留；历史分配仍保存来源冻结基线、库存占用和顺序，不将两机库存相加或再次扣减。
- 保留本机浏览器连接、登录、AI配置及独立缺货率数据；不把另一台电脑的登录状态当成本机已登录。
- 迁入的未完成派发任务暂停，受理回执、平台采购号、上传尝试和退役防重事实保留，不自动上传、下单或收货同步。不暂停或覆盖本机既有任务记录。
- 原件按完整SHA校验和复用；同绝对路径在本机存在不同内容时，隔离相关订单，不覆盖路径映射或改写签发正文。
- 新版ZIP纳入逐文件导出恢复回执，导入时只重绑定其本机数据库路径；旧ZIP未包含的回执不能凭空补出。
- 未知、非空、不能安全归属的业务结构必须明确报告不支持，不允许忽略后声称完整迁入。不同表结构或组件协议不能靠SQLite自动转换或覆盖绕过。
- 本轮不做已有订单后续记录补齐、双向同步、冲突强制覆盖、来源删除同步、参数合并或自动重算。

## 事务与恢复

沿用安全退出、进程保护和目录替换日志。SQLite源数据用backup读取已提交内容，包含WAL场景；本机数据库写锁保持至切换前，再释放文件句柄，实例互斥仍保留。所有合并写入发生在独立副本；多库中途失败也不会发布部分结果。替换前中断恢复原目录；新目录已经生效则以准确完成凭据确认，不重放导入。

预览及提交复核同一来源和相关本机依据；预览后发生真实冲突必须重新核对，不能静默少导入。保留完整摘要、原件校验、取消、失败回滚和单实例保护，不执行真实平台调用。

测试、实际EXE验收、失败证据、构建快照及已知限制以独立交付报告为准。模型、预算、箱规、数量、归属、补货计算默认并发以及0.52.7采购连续提交策略不变。

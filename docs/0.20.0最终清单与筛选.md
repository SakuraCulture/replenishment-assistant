# 0.20.0 最终清单与筛选

基线：0.19.1 `05711cc15929e59c0cf5537ebfd37f474b15981c`。应用版本0.20.0，模型仍为0.3.3-rules，仓归属0.5.1，存储格式2。不改计算、归档格式或既有签发及历史导出。

## 怎么用

1. 完成计算后进入“④ 核对与签发”。门店列表保留人工改量金额、新品金额及原预算列；顶部压缩，给门店列表更多空间。这里统计的是已应用结果。
2. 打开“最终清单／改量”。顶部按店展示拟签发金额、人工改量商品金额、较自动增减、新品金额、新品较自动增减及预算余额。选择某店只展示该店金额；搜索、仓筛选不改变整店金额。
3. 双击数量直接修改，不需要先勾选。箱规24仍只允许0、24、48……；非法输入保持待修正，不计成有效新数量。Tab、回车或鼠标移开提交单元格后，金额更新。正在输入期间不移动商品行，结束编辑后更新排序和筛选。
4. 商品分组、数量、调整来源、预算状态、必卖是独立条件，可以组合“山东仓＋本月新品＋人工改量＋正数量”。“更多筛选”展开其余条件；括号款数表示保持其他条件时该选项可匹配的数量。原快捷条件保留，仍与组合条件同时生效；“重置筛选”清除条件，不清除勾选。
5. “核对修改与预算”后确认风险，再“应用最终数量”。编辑预览不会修改正式作业；重新改量会使原核对失效，旧风险不再当作当前结论。风险分别查看未核对、待确认、已确认；无风险也明确提示已核对。
6. 批量改量、填写原因和恢复自动量默认只处理“当前可见勾选”。需要包含隐藏商品时，明确改选“全部勾选（包含筛选外）”。筛选外勾选保留并显示数量；确认框列出作用范围与涉及门店。
7. 门店商品详情的“查看排除商品”只读查看禁用、停采和原因，不会恢复补货资格，也不把这些商品加入签发或原工作导出。
8. 新品选择窗口也分别提供分组、选择状态、预算状态及必卖条件。预算状态表示当前已应用结果，新的选择仍须“预览预算变化”后应用。原“未获预算”改为可区分的“部分安排／预算暂缓”。

## 金额口径

- 人工改量商品金额：直接人工改量商品的当前最终金额，改为0仍可查。旁边增减额以干预前的自动安排为基线。
- 新品商品金额：原签发单“本月新品＋往期新品”范围的当前最终金额。新品较自动增减单列，不能把新品总额叫增加额。
- 两项允许交叉，不相加作为总额。例如新品自动48元、人工改为96元，人工金额96、人工增量+48、新品金额96、新品增量+48；整单只计96元。
- 恢复成自动正数量且不再保留清单来源的无效人工覆盖，会按原核对规则不再算人工调整；人工0和清单成员仍按原规则保留。
- 缺价与缺自动金额依据单列待核，不补造成0成本。地采不计入人工或新品金额。
- 编辑窗口是“未应用预览”，只统计已成功提交的合法数量；未输入完成的文本不入账。不在每次输入时重跑预测、预算或签发核对。
- 关注清单未确定时显示“新品归期待核”，不猜测本月／往期；这只是显示提示，未改关注清单、签发分组或新品规则。

## 筛选和导出边界

搜索支持名称、编码、条码，空格分开的词需同时满足；最终清单额外支持门店名称和编码。此为明确的查找交互更新，不改变导入时精确编码匹配。

原快捷范围和新增组合条件同时生效；可按各条件及计数核对，不按完成顺序重排数据。没有改变签发全量／分仓导出，也没有增加或删除Excel列。内部筛选导出仍按用户当前可见范围；新增组合条件会记入该次筛选说明，其选择带来的范围变化属于用户显式筛选。

## 稳定性与实现索引

- `preissue_ui.py`：数量编辑器绑定持久的源模型索引；动态过滤关闭，编辑器关闭后再按Qt协议刷新代理；数据更新不再发送孤立的布局变化通知。风险状态在改量后失效；批量范围明确。
- `draft_review.py`：复用原自动结果恢复入口，以只读投影维护金额；初始扫描后逐商品增量更新，不写回业务行或存储。
- `review_filters.py` / `ui_review_filters.py`：共享查找、分组、状态谓词及组合筛选控件。金额及分组与原核心预览／原导出用独立测试核对。
- `ui_goods_fast.py` / `ui_results.py`：原商品详情组合筛选与独立只读排除查看。
- `new_product_ui.py`：新品筛选维度拆分，编辑器绑定源行并延后刷新。
- `batch_app.py` / `application_window.py`：缩减头部占用、整理改量与签发动作，不改变入口对应的业务操作。

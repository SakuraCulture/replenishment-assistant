# 0.40.1 门店补货订单漏斗导出

## 使用

在“五段经营分析”查询业务日期、门店、仓和必采分组，选择“门店漏斗监控（模板样式）”或“订单漏斗监控（模板样式）”，导出当前范围或所选订单。AI 的 `export_order_funnel` 使用同一导出服务，`level=store/order` 无需增加参数。`level=detail` 仍输出原商品明细。

参考用户提供的《门店补货订单漏斗.xlsx》：深蓝标题、蓝色表头、浅色交替行，大盘／山东仓／河北仓并列，分区显示指标及阅读提示。用户确认保留五段，数量与货值都展示。本次是业务报表样式接入，不是将用户工作簿作为业务数据库导入。

## 工作表顺序与作用

1. **漏斗汇总**：统计范围、按单位分开的五段数量、五段货值、实收覆盖、完整周/月环比。
2. **必采漏斗、非必采漏斗、属性待核漏斗**：相同布局，分别查看当时必卖属性；不拿当前清单补写历史。
3. **门店数量记录**：一单一单位一观察分组，五段数量及同样本比率。全部与分类分组不相加。
4. **门店货值记录**：一单一观察分组，按签发价的五段货值及同样本比率。
5. 原有门店、分仓、订单、商品、待核、实际付款和多轮复盘明细继续保留，便于追查。单独商品明细导出不加前面的监控表。

原模板的“数据录入”改为自动生成的数量/货值记录，无需再手填门店档案和数量。门店按现有编码关联，不引入按名称匹配。用户原表、公式和业务记录不会被覆盖。

## 统计边界

- 链条为模型建议 → 签发 → 门店确认 → 实际下单 → 实际收货，不合并模型建议与签发。计算、预算、箱规、签发和生命周期存储均未改变。
- 数量以库存单位为准，同名单位分列合计，瓶/包/箱不混成总数。单位缺失不猜测，不计入数量合计，可回查商品明细。相同单位合计也不代表商品价值或销量可互换。
- 货值仍按签发时基本售价；实际付款金额另列。全为缺价时新增监控格留空，有部分价格时显示已计价部分，并显示缺价条目数；原有分析明细口径保持。
- 门店禁采/拒收、对应仓禁用、已核实虚拟淘汰标签等沿用原来的冻结依据与排除规则，五段一致；资料待核不冒充纳入。
- 未导入、过期、无有效记录留空；经确认的实收0保留为0。比率分母为0时留空，不封顶100%。
- 数量比率用两环节均有效且同单位的商品集合，不要求价格有效。货值比率用两环节均有效且已计价的商品集合。禁止用不同覆盖范围的阶段总值直接相除。
- 实收覆盖率为纳入商品均有有效实收数量的订单数／纳入漏斗订单数；样本实收率为付款、实收均有效且有签发价的同一商品集合实收货值／下单货值。
- 周/月环比沿用模板“两个完整自然周期”原则，以报告截至日期确定周期，仅计算模型至下单的已计价货值；未覆盖两个周期时留空提示，不悄悄扩大查询日期。实收受成熟度影响，不强做周/月环比。
- 原模板的GMV影响估算、到货延迟、未找到收货单等缺少可核实依据，不根据差额猜填。新增逐店记录用补货单号追溯，没有伪造聚水潭/翱象外部单号。
- 文件是只读分析快照，表内数值由软件计算完成，不承诺手改Excel后自动重算。需更新数据时重新查询导出。

## 实现与验证入口

- `src/funnel_monitor_export.py`：业务汇总投影、模板配色、列宽、分组、按单位数量与周期覆盖检查。
- `src/order_analytics_exports.py`：原生/AI共用入口；原有过期复核、取消和临时文件原子发布继续保留。
- `src/order_analytics_ui.py`：导出名称提示模板样式。
- `tests/test_funnel_monitor.py`：混合单位、缺价、空/0、分组、同样本分母、周期、取消、文本编码和样式。
- `tools/verify_funnel_monitor.py`：固定基线导出逐格对照、原资料保护、所选订单范围、AB/BA/AB串行计时及合成样例。

复跑（输出目录需为新目录）：

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p test_funnel_monitor.py -v
.venv/Scripts/python.exe -m unittest discover -s tests -p test_automation_analytics.py -v
.venv/Scripts/python.exe tools/verify_funnel_monitor.py --output qa/funnel_monitor_rerun
```

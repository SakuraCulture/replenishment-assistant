# 0.40.4 经营分析精简导出

按本次业务确认，常规经营分析只导出37列。基线 `d4c09157e1998cc0373ca1f2c9b30ce31ca53df0`（0.40.3），分支 `feat/lean-funnel-export-0.40.4`；旧包保留，不自动推送合并。

## 表和字段

选择“门店经营分析（精简37列）”：门店经营对比、门店分仓对比、订单五段漏斗三张表。
选择“订单经营分析（精简37列）”：只导出订单五段漏斗。
两种入口均不再附带监控大盘、周月环比、商品证据、付款原表、多轮复盘和统计说明页。
单独选择“当前商品明细”仍可取得原商品字段的明细及待核表，不自动夹进常规经营分析。
AI 的 export_order_funnel 与界面用同一导出实现；MCP/CLI 查询和软件看板保留原分析事实。

固定列顺序：

1. 门店编码、门店名称、供货仓、补货单号、业务开始时间、业务结束时间、必采分组。
2. 模型建议、签发、门店确认、实际下单、实际收货：每阶段依次列商品编码数量、商品数、商品货值（15列）。
3. 签发/模型建议、门店确认/签发、实际下单/门店确认、实际收货/实际下单、整体实际收货/模型建议：各列商品编码数量比值、商品数比值、商品货值比值（15列）。

## 口径

- 商品编码数量：本阶段有效数量大于0的去重SKU款数。同商品跨仓、跨单在门店汇总中只计一款，因此款数不应把分仓行简单相加。
- 商品数：业务明确选择，各商品库存单位数量相加，包/瓶/个等混合；只作为执行数量统计，不代表相同实物单位。
- 商品货值：各阶段都按签发时单价计算。保留原已知货值口径，正数量缺价不补0；明确数量0的货值0，完全无有效依据留空。实际付款金额仍在原查询/明细里，不追加到本次37列。
- 比值：后段÷前段，只比较两个阶段均有效的共同商品集合；货值还要求单价可用。分母为0或无共同资料留空，允许超过100%。所以部分订单还没收货时，不能直接拿整列阶段总量相除来复核同口径比值。
- 未导入、过期待核的阶段留空，不当作没有需求。已明确为0的阶段保留0。
- 必采依据当时清单；全部、必采、非必采、属性待核保留。全部是合计口径，不能与分组再次相加；无该组商品则不造空分组。
- 业务开始/结束时间沿用本行签发业务日期的最小/最大值，不假造时分秒或收货结束日期。门店汇总跨多单时补货单号留空，订单表写精确单号。
- 原门店禁采、对应仓禁用、虚拟分类淘汰等排除口径不变，待核条目不混入有效漏斗。没有改补货计算、历史归档、签发文件或平台数据。

表头批注保留必要定义，不增加解释列。编码作为文本写入；数量为数值，货值两位小数，比值百分比；冻结前7列和表头，可自动筛选。

# 0.51.1 付款绑定与采集登录修复

接续0.51.0和8fc7ef8的手册补充，仅修复付款核对、旧采集维护和登录核验。保留旧交付、样本及失败证据；不连接真实平台，不直接清理业务电脑，不推送、不合并。模型0.3.5-rules、预算、箱规、默认参数、商品归属规则及业务存储格式不变。

## 付款选了单还进不去

原`match_payment_rows`读取旧签发结果，用SKU曾被分配到另一仓这一事实拒绝当前整单关联。商品编码不能证明这次付款属于哪个仓，这个额外拦截已移除。辅助码和条码也不参与归属判断。

自动认单仍比较完整商品、数量和金额；无法唯一确定时不猜单。明确选择整张目标仓单后，实际付款商品及金额可以进入核对页；清单外商品和差异保留展示、确认和历史版本，不偷偷改成旧签发数量。文件明确携带的订单、门店、仓或修订互相冲突，以及源单已删、快照变化等检查继续生效。

原来核对失败只写底部小字，容易被理解为没反应。现在核对或保存失败会弹窗显示原因，并提供完整详情，同时保留来源文件、目标选择和页面内说明。进入核对页不等于保存，正式保存后查看回执。

## 已结束旧采集删不掉

隔离重放确认：旧版可能把本地命令和run设为ENDED，同时留下`resumePending=true`及ACCEPTED等原平台事实，新版本据此仍认为门店有未决导出。本轮补齐旧状态升级缺口。

第一次打开此类库前自动SQLite备份到组件状态目录`recovery/before-ended-collection-*.sqlite`；若同时需要旧订单退役升级，则使用已有`before-order-retirement-*.sqlite`备份。只对身份、原run、门店范围及各引用项均能证明明确结束的记录补齐退役标记，清除可恢复占用。原任务号、受理状态、原文件和采用资产保留，不伪造平台成功或上传前取消。修复有事务和幂等保护，晚到回执不能恢复占用。有活动接管者或证据不足的记录不自动结束。

升级后可删除已结束采集日志，不删除订单、草稿、采用文件或平台任务，不需要平台先完成。

## 今日任务被另一个旧记录拦住

原入口检查全部未完成记录，下方却可能显示另一条历史。现在列出冲突的原日期、相交门店名称及编码、状态和记录号，自动定位第一条实际冲突记录；未受理本地意向也显示门店行和原因，未选门店不变。

真实未完成任务仍保留：需要原结果就继续原任务；明确要新文件就勾选上方门店，使用“重新导出所选门店”，核对范围后结束所选旧项并建立独立采集。其他门店和旧原件保留。旧平台任务可能继续完成，不能把“日期旧了”当作没有受理。

## 已登录但核验一直等待

隔离Edge已复现：SPA页面打开后只切换hash路由，不会重新调用`getLoginInfo`，原实现等待不会出现的请求，最终报`IDENTITY_CHECK_FAILED`。手动刷新能恢复身份请求，与用户反馈相符；未取得业务电脑现场日志，不能宣称是现场唯一原因。

现在已有同源页面会切到建议页并刷新当前文档，刷新前安装本次身份监听，读取当前Edge实际登录身份。导航或身份读取临时失败只再核验一次；未登录、身份不符不反复刷新。不沿用旧绿色状态冒充成功，不重新配置账号ID，不创建或重放导出任务。原任务身份与范围校验保留。

界面区分本次登录核验与下方历史记录，显示阶段和已用秒数；失败停止不确定进度，保留诊断环节。网络或页面权限持续异常仍会提示，需在连接检查中排查。

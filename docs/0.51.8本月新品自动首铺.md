# 0.51.8 本月新品自动首铺

## 已核实的两个原因

1. 代码原来仅识别“新店新品首铺数”，本机留存的山东、河北聚水潭原表实际列名都是“新店新品首铺数量”。旧解析快照因此丢失该列。只读重解析后，山东9205行、河北4494行均识别到该字段，原始文件和日常配置未修改。业务端当次原表未直接取得，不将本机样本冒充业务电脑复现。
2. 原有功能只在新品维护窗口填默认量，关注清单仅做本月/往期分组，未勾选并应用则最终仍为0。即便缺少字段，窗口也会回退到最小出库量；因此列名问题本身不能解释所有最终0数量。

用户本轮明确要求“没走这一步，希望本月新品自动带量”。本次新增自动候选规则 `monthly-first-fill-1`，普通补货模型公式仍为0.3.6-rules；不会把所有无销量商品一律转为首铺。

## 升级后的操作

1. 更新或重新导入各仓商品资料，然后在本次作业采用最新资料并重新检查。已丢失该列的旧缓存、旧计算结果，不会因换EXE而自动补字段。
2. 导入与业务日期同月的新品关注清单，核对门店供货仓和“新品铺设”开关。
3. 对未签发门店重新计算。符合原新品资格的本月关注商品，自动读取实际归属仓首铺量，无需再逐项勾选新品。
4. 核对最终数量、资金和导出。本月新品的签发执行量会自动带出；原模型的AS仍保留原值，原始数据和首铺来源可追溯。
5. 需要改量或不安排时，打开“选择门店并安排新品”，修改或取消自动安排，再预览预算变化并应用。人工修改和最终清单调整不会在重开窗口或导出时被自动覆盖。

## 数量和边界

- 兼容“新店新品首铺数量”和旧称“新店新品首铺数”；两列同时存在或任一表头重复，不擅自择一，提示来源异常并按已约定的最小出库量回退。
- 缺失、空白、0、负数、非法首铺值使用最小出库量；正数向上对齐箱规。例：箱规6，缺失取6、资料7取12、资料19取24。保留资料原值。
- 自动范围为当月关注、满足现有新品资格、资料匹配且门店允许新品铺设的商品。沿用月销/可用/在途为有效0、缺货天数为0或按既有规则允许空白，以及日周销量一致性等限制；缺失库存和负库存不擅自当作0。
- 禁用、停采/禁采、日配及其他准入排除优先；供货仓以实际归属为准，不借另一仓的首铺数。非本月新品仍保留原选择流程。
- 自动首铺先形成候选，再与普通需求一起走原预算分配。预算为0或不足一箱时最终仍可能为0；提示会区分预算原因和原资料问题。不保证每款都足额，不绕过必采优先级、预算与箱规。
- 不改历史签发、旧付款、平台单或已经保存的人工修改；旧作业恢复不自动改量。主动重新计算时按已有确认流程处理人工修改。旧版本已冻结的定时任务沿用原任务设置，新定时任务才冻结新规则上下文。
- 手工工作台、AI计算任务及新建定时任务均冻结当月清单和业务日期；恢复/重试沿冻结上下文执行，不读取途中改动的清单。
- 自动首铺只保留逐商品必要的原候选字段，以便稍后人工维护；不为每家自动保留第二份完整计算结果。

脚本使用标记的合成资料，真实点击工作台计算入口并运行计算子进程，验证自动量18、预算限量12、预算0原因，以及新品维护中改量为12的实际预览应用。不调用真实平台。

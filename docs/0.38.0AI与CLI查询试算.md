# 0.38.0 AI / CLI：查询、参数核对和独立试算

本轮以 0.37.0 主线 `ecdc9e197d1c748eae1c78fb434fda4a7a77a9e5` 为基线。应用版本升级，模型仍为 **0.3.4-rules**。MCP 的 `replenishment.tools.v1` 保留兼容入口，新增查询不改变原计算、预算、签发、导出和存储格式。

## 业务人员怎么用

1. 打开本版本完整交付目录中的补货助手，进入「AI 协助」，启用本机连接。
2. 「生成连接配置与 CLI 使用说明」导出两份客户端配置片段和一份命令说明。添加到 Codex / WorkBuddy，不覆盖整份已有客户端配置；旧版本路径不会自动改写。复制配置不是完成连接验证。
3. 关闭设置或其他业务确认弹窗。到「AI 常用业务」选场景，核对门店，复制提示词。现在共十个场景，新增「查看定时补货进度」。
4. 开工检查先看**本次作业**，再对比**已保存默认**。两者不同不表示计算错误：恢复的历史草稿和本次人工调整可以保留旧快照。需要采用新默认时回工作台明确操作，AI 不自动覆盖。
5. 试算检查就绪后才计算；计算结果先核对，明确采用仍不等于保存或签发。

定时查询只看安排、执行阶段、门店进度和异常。不会替人员启用定时器、补跑、暂停、取数、更新仓资料或采用结果。「计算完成」表示等待核对，绝不表示已经签发。

## CLI 使用

程序仍在 `AI接口/补货助手AI接口.exe`。无子命令的 `--connection ...` 仍按原 MCP stdio 工作，已有客户端配置语法不变。CLI 与 MCP 共用同一个本机接口，必须有正在运行且主动启用连接的工作台，不直接查业务数据库。

软件生成的 `补货助手_CLI使用说明.txt` 已填写本机程序与连接路径，直接复制其中 PowerShell 命令即可。以下为通用示意：

```powershell
& '.\AI接口\补货助手AI接口.exe' version
& '.\AI接口\补货助手AI接口.exe' tools
& '.\AI接口\补货助手AI接口.exe' --connection '<软件生成的连接路径>' doctor
& '.\AI接口\补货助手AI接口.exe' --connection '<软件生成的连接路径>' call workbench_context
& '.\AI接口\补货助手AI接口.exe' --connection '<软件生成的连接路径>' call effective_parameters --arguments-file '.\参数核对.json'
```

`参数核对.json` 为 UTF-8 JSON；示例编码必须替换成接口返回的真实门店编码：

```json
{"stores":["准确门店编码"],"scope":"current"}
```

`scope=defaults` 查询已保存门店默认及当前全局分类映射，尚未保存的门店返回 `STORE_DEFAULT_NOT_FOUND`，不猜默认门店。预算的原始金额与模式同时保留；未设置不视为 0 元。空列表只查询零家门店，不扩成全部。

定时工具参数示例：

```json
{"kind":"scheduled_runs","offset":0,"limit":50}
```

```json
{"run_id":"上一步返回的准确id","offset":0,"limit":50,"after":0}
```

运行状态中的 `stores.next_offset` 用于门店翻页；`next_after` 用于事件续查，`has_more_events` 为真时还有事件页或需要再查一页确认。运行中可以产生新事件。默认一次 50 条、最大 100 条。列表顺序沿用原服务（运行记录从新到旧、门店沿冻结顺序），不按任务完成顺序改排。

CLI 输出 UTF-8 JSON：`ok/result` 或 `ok=false/error`。退出码 0 为请求成功，2 为参数、连接或业务拒绝，3 为接口未完成。`--arguments` 支持简短 JSON，但 Windows 引号易误读，复杂参数优先文件。参数文件不接受重复键、NaN 或超限消息。

试算调用顺序：workbench_context → effective_parameters → prepare_calculation(mode=trial, 新 operation_key, 原 context_token) → task_status → prepared 后 run_calculation → task_status → calculation_results。不得把受理当完成。状态不明查原任务，不换 operation_key 重复创建。参数试算只接受原维护服务开放的字段路径，不把预算、路线、策略或映射混进数值超参。

## 连接失败时

- `NOT_CONNECTED`：先核对是否运行本版本、该资料环境是否启用连接，再重新生成配置。CLI doctor 不会偷偷打开程序或改配置。
- `INVALID_CONNECTION`：配置不完整；在对应软件窗口重新启用、重新生成连接配置。诊断不回显密钥。
- `VERSION_MISMATCH` 或 doctor 的 `versions_match=false`：使用该交付包配套 AI 接口，更新客户端程序路径。
- `UI_WAITING`：完成或关闭原业务弹窗，不绕过确认。
- `STALE_CONTEXT`：刷新软件中的场景提示词重新核对，不拿旧令牌覆盖结果。
- `BUSY`：已有手工作业、AI 任务或定时计算/结果采用在运行，等待该步骤完成。定时进度仍可查询；不自行停止定时任务。

以前 WorkBuddy 的断连报告不等于本轮已经修复该电脑的配置。CLI 和实际打包桥接验证证明工具链可用；真实客户端仍需启用连接、配置正确路径与信任授权。本轮不改客户端正式配置，不运行真实平台导出，不声称十种提示词在各 AI 模型上均自动成功。

## 结构与复跑

`automation_bridge.py` 同时负责 MCP stdio 与 CLI；所有业务命令经 Client → QLocalSocket → `automation_gateway.py`。`automation_protocol.py` 为同一契约；`automation_queries.py` 只投影既有查询服务。计算继续用 `automation_jobs.py` → 原参数装配、batch_service 和 engine。定时查询不调用 due/manual/resume/change，也不读取 scheduled_values 大块结果。

```powershell
.\qa\v0350\locked-venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -p 'test_automation*.py' -v
.\qa\v0350\locked-venv\Scripts\python.exe -X utf8 tools\run_automation_ui.py --out qa\新的源码验收目录
.\qa\v0350\locked-venv\Scripts\python.exe -X utf8 tools\run_automation_ui.py --exe '交付_0.38.0_rc1\补货助手\补货助手.exe' --out qa\新的EXE验收目录
```

冻结对照：`tools/verify_ai_refresh.py freeze/before/after/compare --qa <新目录>` 依次执行。复用已有本地回归输入 `qa/governance_032/inputs`；缺少该未入库数据集时不能声称完成真实/既有数据对照。自动测试中的合成场景可独立复跑。发行报告记录实际执行结果，不将上述命令说明作为通过证据。

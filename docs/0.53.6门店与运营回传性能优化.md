# 0.53.6 门店回传与运营回传性能优化

门店回传和运营签发文件仍按原入口导入、核对完整范围后确认保存。不新增参数，不改变数量、SKU顺序、同值重复处理、缺行/空白转0、清单外商品提示或后续分配规则。

本轮减少三类重复工作：

- 核对预览按同一仓单身份复用已检查状态；每行仍核对来源关联。数据库data_version或头信息变化后重新检查，冻结每份计划时再次核对，提交仍复核当前源单与删除失效标记。
- 在原完整性校验点，同次生成写入JSON和原有路径无关摘要。所有字段仍接受原JSON类型与有限数校验；内容未变时不保留无用的完整待写字符串。
- 对预览时已经完整解码、检查版本/格式/摘要的旧单据，保留进程内认证的紧凑证据。事务内仍读取完整当前记录、计算全部原文字节摘要；身份、版本、保存时间、原摘要和原文字节全部相同，才复用上游核对需要的投影。任何变化、证据修改、缺失或跨进程均走原完整解码。

证据只存在临时计划中，不写入单据、数据库或导出文件。实际存储JSON字节与原摘要格式不变，不减少secure_delete、同步持久性、首次备份、并发检测、取消或失败回滚；仍一次原子提交全部所选单据。

## 对照方式

基线为0.53.5主线7d76889。使用同机合成6张仓单、每单2000商品（共12000行），保留20列额外原表字段。旧/新、新/旧、旧/新交替串行运行，各轮使用独立进程与数据库副本。比较完整计划（仅剔除新增的进程内复用证据）、回执、列表及逐表有序内容签名；同一受控时间戳便于逐字段对照。

首次门店/运营回传从文件走真实核对入口；未变单据测量使用原件重核API。SQL副本只在本轮签名、报告和首轮完整事实压缩包保存后清理，冻结输入和失败材料保留。性能具体数字、定向回归和实际EXE结果见本版交付报告。

## 边界

不改变计算模型、预算、箱规、供货归属、业务范围、事务原子性或存储格式，不降低默认并发。保存后的列表刷新沿用原路径，本轮没有宣称列表整体明显提速。

实测为本机合成观察，不是业务机复现、低配容量保证或所有历史库性能承诺。Windows进程I/O含系统缓存，采样RSS是被测进程，不能当作物理磁盘利用率或整机内存。本轮不联网调用平台，不改真实订单或自动替换现用程序。

## 提交时短暂读锁

rc1首次实际EXE流程通过，但退出重开后重复保存遇到SQLite提交占用，完整验收未通过，原包与失败材料保留。原实现只在BEGIN重试，COMMIT仍受150毫秒连接等待限制。现仅对COMMIT返回SQLITE_BUSY且事务仍有效的情况，成功回滚本次尝试、释放锁后重开事务，并重复所有源单、版本、上游、内容校验。等待有统一截止时间；取消可在安全回滚后生效。提交结果不明、非BUSY错误或回滚失败均不自动重放。未更改数据库日志模式、持久性或业务原子性。具体原生持锁者未完成跟踪，不将其归因于某个已确认后台进程。

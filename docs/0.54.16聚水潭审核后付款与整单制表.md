# 聚水潭下单后付款回读与整单制表

在「订单跟踪 → 聚水潭导入单 → 自动下单」预览并点击「确认导入」。程序按原企业、仓账号、店铺及线上单号回查。查回「已付款待审核」即记下内部单号并读回整单。页面列出原分配与平台逐商品数量、成交单价、商品金额以及运费和平台应付。无法解释的金额差额需人工核对。

未确认的仓单保留在「付款核对 → 待处理」。点击该单的「核对聚水潭付款资料」，实际付款后勾选确认并保存。已有正式付款时，对照原版本及差异，相同商品数量和金额沿用原版本。

自动下单的仓单保存正式付款后，仍在「待付款」显示已保存的付款版本。助手使用空闲的已核验聚水潭连接回查原单，核实状态为「发货中（打单拣货）」且明细与正式付款一致时，锁定该付款版本并直接转「待收货」。付款版本或明细有变化时，在「付款核对」沿原单核对。

保存和恢复保存前沿原单重新核验。平台状态正常推进且身份、明细一致时可继续保存，原单取消、身份冲突或明细变化时重新核对。断线后从原下单任务点「核对原单」或「补取付款资料并核对」。历史客审和销售出库资料可从「历次付款资料」查询。

较短的商品串沿用原多商品表。超过 32,767 字符时用「单商品」格式，每款商品一行，复用同一线上单号。数量按原分配，单价留空由平台取当前基本售价。平台预览须核出唯一一张订单、同一标识、完整商品数量、可核验金额及收货资料。若出现拆单、资料缺失、同名商品无法区分、超出 3 MB 或 30,000 行，保留原生成单供核对。

经营分析的「实际下单」采用已核实的原单数量。翱象采购使用人工确认的正式付款版本。到货后按原采购号同步并保存实收。

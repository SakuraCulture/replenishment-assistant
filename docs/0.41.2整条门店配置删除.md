# 0.41.2 整条门店配置删除

用户确认要清理的是整条脏配置。0.41.1仅清空参数、保留仓和预算，不符合这个目的；本版替换该按钮的含义，不自动处理真实资料。

## 操作

参数设置 → 默认查看“已保存门店配置” → 勾选一店或多店 → **删除所选门店配置** → 核对门店编码、仓和预算 → 确认删除整条配置。

一次删除整个已保存记录：补货参数、通用参数、策略、默认参数预案绑定、主从仓、预算、该配置记录保存的名称和时间。0.41.1中已经变成“未保存参数”的残留记录同样可以删除，不要求先补参数。

删除后记录从已保存列表消失，刷新和重开不会重新出现占位行。下一次新作业如再次导入该店，系统只自动填写内置计算参数，主从仓和预算重新核对；没有明确保存，不生成新的长期配置。

“本次作业门店”单独查看当前临时配置，已删长期配置但仍在当前任务里的门店标明“未保存配置 · 仅本次作业”。当前任务可继续；若要重新开始，应走新建作业。这里不删当前任务、历史草稿、签发、生命周期或门店目录。

## 边界

- 未选门店不变；公共参数预案、补货预案名单及其中明确指定的参数不删除。跟随默认的预案下次使用内置参数，但缺仓/预算仍需要核对。
- 独立门店资质和拒收清单是业务准入记录，不随参数配置清理，避免误删资质限制。全局分类映射不重置。
- 确认默认取消；后台安全备份后一次事务删除。预览后配置变化则拒绝并要求刷新；写入失败整体回滚。
- 延用现有变更记录和备份，可明确恢复；不新增回收站。恢复不会自动覆盖当前作业。
- 较早版本单独记忆过仓和预算。本版依据现有删除审计，在新作业中不再采用被删门店的旧JSON记忆，避免配置复活；这些兼容文件不批量改写，其他店不受影响。重新明确保存该店配置后，以新保存值为准。
- 旧程序不认识新的删除语义；保留旧版不表示可以用它打开删除后的资料继续作业。需要回退时使用删除前的备份副本。

## 代码与验证

- `parameter_presets.remove_store_configurations`：选中整行删除、比较预览版本、写锁、历史记录及回滚。
- `parameter_preset_ui.delete_store_defaults`：沿用内部函数名，界面已明确改为整条配置删除；后台执行，不直接清空当前任务。
- `parameter_scene`：已保存配置与本次作业分开，删除后不残留空行。
- `work_repository.removed_store_config_codes` / `workbench.populate_stores`：只在新准备时抑制已删除配置的旧仓/预算记忆，恢复历史跳过此处理。

# 数据与任务维护实施记录

基线：0.26.1 / 06ea3253c5f0b9e0f35d250cdf88c661294755e9。独立分支 feat/data-task-maintenance-0.27.0。模型规则、默认业务参数、签发与导出业务口径保持。

## 操作入口

首页“数据与任务维护”集中进入参数、仓资料、批次、每日草稿、订单清理和存储副本功能。原业务页仍保留相应操作，名称与动作一致。

- **默认参数错了**：参数设置 → 默认变更记录 / 撤销 → 选中导入 → 核对逐店逐字段差异 → 保存。后来又修改过的门店会列为冲突，不被撤销覆盖。恢复历史配置也是先看当前差异再确认。
- **清除门店特殊设置**：勾选门店 → 重置勾选门店默认。完整方案（包括分类覆盖及两仓周期）、主从仓和预算分别明确选择。停用方案可从“恢复停用方案”重新启用。
- **仓资料导错了**：准备数据 → 恢复以前保存的仓资料 → 选择明确仓与版本 → 确认完整替换。历史库存不代表今天库存；此动作不调整聚水潭库存分配账。
- **个别门店计算失败**：计算进度行尾“重跑此任务”。沿用原计算设置；其他门店成功结果保留。还有门店计算时可先排入重跑，当前运行项结束后自动继续。修改参数或输入后，应使用原门店设置/检查入口重新核对、计算，不能把新旧依据混用。
- **翱象某项失败**：采集页或采购/收货批次行尾重跑，成功文件/订单保留，继续使用原 run、采购或下载任务号。平台受理不明只能核对原任务；没有唯一受理号时禁止重传。采集正在运行时需先安全暂停，再重跑失败项。
- **旧批次卡住，另开一批**：计算页可“结束本批并新建”，先安全停止，再按原保存确认保存或放弃当前草稿并新建。翱象批次的同名入口将失败/未开始项转入后续执行批次，保留成功项及原采购身份；运行或待核项必须先停止/核对。业务日期和正常单唯一规则不变。
- **清理草稿**：草稿记录 → 彻底删除选定草稿。已签发的快照、订单及门店默认保留；当前未保存的内存草稿不会被隐式丢弃。
- **清理订单**：决策复查或订单跟踪勾选 → 彻底删除 → 完整关联范围预览 → 明确确认。取消、状态变化或提交失败整批不生效。没有新回收站；旧版已移除记录单独列在一次性整理筛选中，可恢复或永久删除。

## 重要边界

1. **订单彻底删除目前以“门店＋业务日”的正常单为单位**。两仓共用计算原始快照，选中一仓时，预览必须显示同店另一仓并要求明确确认；不支持只清掉一仓的全部底层数据而保留同一共享父快照。若不想删除另一仓，取消操作。
2. 关联清理包含全部签发修订、回传/付款/收货、生成结果、相关任务、事件、索引和草稿中的该店数据。其他门店签发结果不变。跨正常单共享的旧采购资料需全部关联单一同选择，否则拒绝删除。共享原件/内容块仅在无存活引用时回收。
3. 磁盘原Excel、已导出的Excel、已有备份及外部平台订单不会删除。外部平台防重复身份记录仍保留；不能把本地删除当作外部作废。已锁单删除保留当前库存基准下的必要占用数，刷新为新库存基准后不重复扣减。
4. 运行中的写任务不能直接删除。可安全取消处回滚；最终提交阶段不可强杀。删除是业务记录清理，不承诺法证级磁盘擦除、SQLite文件立即缩小或从外部副本擦除。
5. 参数历史从升级后第一次保存开始记录；仓资料从升级后更新时保留旧/新版本，不能凭空还原更早未保存的内容。参数维护只改变后续默认；当前明确编辑或恢复的历史配置仍保留，需明确应用并重算。
6. 本轮未使用真实翱象账户上传/下载做现场验证。原任务重跑与未知受理防重放通过离线组件测试；真实异常平台任务是否能恢复仍取决于平台状态。不能用重跑修复真实资料错误。

## 界面和代码索引

导航/分页用左右箭头，刷新、重试、停止、关闭使用 Qt 标准图标及轻量样式，保留提示、可访问名称与键盘焦点。关闭不代替停止，删除保留明确文字和范围确认。

| 仓资料保存/恢复 | `warehouse_catalog.py`、`warehouse_ui.py` |
| 计算失败重跑与安全结束 | `batch_app.py`、`workbench.py` |

| 标准辅助图标 | `ui_controls.py` |

## 建议业务试用

先使用副本/测试单，不要拿唯一正式记录验证永久删除。

1. 改两家门店默认，再单独改其中一家，撤销前一次导入：后改的一家应提示冲突，另一家恢复；本次计算不应偷偷变化。
2. 两店计算后重跑失败店：另一个店的金额和数量应保留，重跑结果仍能继续签发。
3. 停止本批后新建，核对草稿保存/覆盖确认仍出现。
4. 删除预览先取消，再用测试单确认；订单跟踪、决策复查中均不再出现该店当日订单，另一家不变。
5. 旧版已移除记录可恢复；新删除不会再进入回收站。
6. 核对分页箭头、刷新、重试、停止和关闭的提示与动作分别正确。

## 复跑

在项目目录使用 `.venv\Scripts\python.exe`：

```powershell
$env:PYTHONUTF8='1'; $env:QT_QPA_PLATFORM='offscreen'
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -O -m unittest discover -s tests -p 'test_*maintenance.py' -v
components\aoxiang\runtime\node.exe --test components/aoxiang/test/*.test.mjs
.venv\Scripts\python.exe tools\verify_maintenance.py compare --qa qa\maintenance_0270
.venv\Scripts\python.exe tools\verify_maintenance.py exe --exe '交付_0.27.0_rc2\补货助手\补货助手.exe' --fixture qa\aoxiang_integration_20261101\inputs --output qa\maintenance_0270\exe-new-run
```

EXE 验收目录必须是新的隔离目录。真实输入冻结集留在本地 QA，不进入源码库；便携逻辑测试自行生成数据。最终构建提交、哈希与实际验收以 `releases/0.27.0/rc2` 为准。

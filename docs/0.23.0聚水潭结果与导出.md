# 0.23.0 聚水潭结果与导出

从“订单跟踪 → 聚水潭导入单”，或回传确认后的“查看分配结果”进入。默认显示今天的业务批次；历史订单切换业务日期即可。不继承总览的生命周期、仓和搜索筛选。显式从所选订单进入时，会显示限定范围，可点击“查看当日全部”。

## 日常操作

1. 先看本批需求金额、已分配金额、减少金额、减量SKU和可导出份数。门店先汇总，展开看仓单，双击才进入商品明细。
2. 点击底部“导出本批全部”，直接导出当前有效结果。也可勾选门店或单仓后点“导出勾选”；父门店支持部分选中。搜索和仓筛选只用于找单，不改变“本批全部”的范围；查询条件改变清空勾选。
3. 导出后仍留在原页。第二次仍点同一按钮；同名直接覆盖，文件被Excel占用时关闭Excel再点“重试未完成导出”。停止后保留完成文件，重试只处理原未完成记录。
4. “打开导出文件夹”查看文件。“更改本次目录”不改全局默认目录；全局位置仍在“导出设置”。

已导出、已锁单、已付款、已收货不会隐藏已有有效分配。默认不会生成一次就自动写文件；人工“更新资料与重算”内可明确勾选自动导出。回传确认后的后台生成仍正常运行，结果页打开和导出期间也可继续生成后续单。新就绪单不会混入已经开始的文件任务，可再导出。

## 边界

- 每店每仓一个文件，原文件名和四列保留：商品编码、单价、数量、订单号。只导出正数行，严格按当时保存的商品和生成顺序。重复导出仅增加导出日志，不改分配量、价格、预留、锁单、回传或付款记录。
- 零分配和回传无要货仍显示，但不生成空文件。待生成、待处理、需核对与可导出明确区分；缺价不冒充0成本。
- 回传/签发依据变化、未锁订单仓资料更新会标记“需核对”，不会混入普通导出或自动重算。确需当时旧结果，可勾选后进入“其他订单操作 → 导出勾选旧结果（需核对）”，明确确认。
- 锁单只控制重新分配，不代表付款。“更新资料与重算”负责资料选择、顺序、预览和保存确认；锁定、更正、撤销、日志、当时资料仍在“其他订单操作”。
- 点击导出时冻结记录和目录。开始前依据被其他窗口更新则拒绝并要求刷新；任务开始后绑定已保存生成记录，不半途换单。重试时旧记录已被替换同样拒绝。
- 关闭正在导出的窗口会请求停止，安全结束当前文件操作后再关闭；不会强杀提交。部分文件完成即保留。

## 结构与性能

`lifecycle_home_ui.StageDialog(jst) → jst_results_ui.ResultsPage → history_read / HistoryReader → jst_results.read`。读取在现有后台进程进行，按业务日期读取全部仓单，不使用50条页面限制；汇总保持0.22.1的jst_review口径。

`ResultsPage.begin → jst_results.export_plan / validate_export → jst_exports.export`。仍用原Excel写出实现和原不可变gid，不调用分配或模型。每次全部或勾选导出范围固定，查询只改变可见行。

新增`jst_result_index.sqlite3`是可重建的独立查询缓存，缓存带来源、gid、摘要校验；命中时不重复解码完整商品快照，只有查看商品才读取明细。原JSON、SQLite业务表和历史快照格式不变。页面每3秒后台刷新，不阻挡已有结果导出。

应用0.23.0；模型0.3.3-rules、仓归属0.5.1、存储2保持。固定基线0.22.1提交63a1b18ee22693c21cbf1024198e43025df652e3。业务算法、默认配置、jst_orders、jst_allocation、jst_tasks、jst_exports不改。测试和真实EXE是否通过，以发行报告为准。

# 0.51.9 缺货率统一入口与考核品剔除

导航统一为“缺货率”，下设“门店缺货”“大仓缺货”。两个统计始终分开：门店按有月销的店品日统计，大仓按排除后的仓品日统计，不要求月销。模型仍为 0.3.6-rules，补货参数、预算、箱规、仓归属和订单业务不变。

## 先排除考核品

实际字段是聚水潭商品资料的“虚拟分类”，精确标签为“淘便考核”。逗号、分号或换行分隔的多标签可以识别；“非淘便考核”“淘便考核候选”等近似词不命中。

两个子页所有业务统计均固定将考核品从缺货数和基数同时排除，不能再通过“全量”视角把它计入。门店另行选择是否排除淘汰品，原停采/禁采、供货仓禁用开关继续保留；大仓继续排除淘汰、禁用和商品标签精确日配。重复命中只扣一次。“商品与待核”的已剔除明细保留原标签和原因。

旧分析查询也执行固定排除，卡片、趋势、切面、AI门店查询和导出一致；不批量改写历史库或原文件。原来因负库存口径尚待重算的更早门店日报仍需原件重算。资料未匹配或标签未知保持待核提示，不凭另一仓标签猜测；缺失库存不当0。

## 选择本次怎么跑

1. 门店分析首次使用，先进入“门店缺货”，点“选门店 / 采用补货侧设置”，采用门店主从仓及必卖清单。以后两边设置各自维护。
2. 在上方选择“只跑门店”“只跑大仓”或“门店与大仓一起跑”。旁边的山东/河北勾选是大仓输出范围；只跑门店时按已采用供货路线取得必要仓资料。
3. 点“按所选范围采集”，核对门店数、所需资料仓及大仓输出仓后开始。一起跑只为同一仓发起一次采集，两个统计消费同一份原件。单跑大仓不连接或核验翱象。
4. 看组合记录及下方中文状态。大仓已完成、部分门店未完成时，已完成结果保留，点击“继续原作业”补未完成部分。受理情况未知时查询原任务，不盲目再导出。
5. 离开默认安全暂停；要继续执行先勾选“离开后继续”。不会强杀正在提交的任务。

“全量”指两个分析在本次明确选择的范围一起跑，不自动扩大到全部已绑定门店。大仓已完成、翱象尚有异常时，可以另建只跑大仓作业；尚未核对完成的同仓原采集仍需先处理，避免重复发起。

## 用已采原件补算大仓

如果先只跑了门店，在上方选中该次组合记录，再点“原仓资料补算大仓”。确认其观测日期和仓范围，仅使用这次已留存的仓原件，不连接平台、不取新库存。山东单仓原任务只有山东资料时，不会补出河北仓结果。

没有原件、原件校验失败或结果已删除时，旧操作不会恢复已删数据，也不会借用其他日期资料。已采日期与已完成覆盖在各子页查询；未采日期不补0。

## 导出两个视角

上方“统一导出”可以选择门店、大仓或两者，设置共同日期，分别勾选各自已保存的自定义切面。沿用各子页最近的多维筛选，每套组合一张工作表，每行一个分组；工作表以“门店_”“大仓_”区分。附带明细可单独选择，导出全部匹配分组，不受页面分页限制。数值与百分比保留可计算类型，报表列明口径和覆盖。

每个子页原有导出仍可用。单独子页的数据、作业日志、重采、原件重算及删除仍按原入口维护；删除一个子页不会删除另一个子页或补货业务。组合记录保存必要任务关联，删除日志不等于删除结果。

## 每日计划与资源

原门店、大仓计划按原启用状态和范围兼容，同一时点可合并为一次仓采集。上方“每日计划”会列出当前计划；保存新计划明确替换列出的旧计划，按选定模式、时间和输出仓执行，不自动扩大范围。

未进入且计划关闭时不读分析明细、不建分析库、不启动分析工作进程。进入一个子页才构建该页，切换释放旧页，分析在工作进程执行。组合采集共用平台导出，首版原件仍由两个结果库各自留存副本，以保持独立删除和恢复；没有宣称物理文件已去重或已在低配业务电脑实测。

验收证据与交付状态见本版交付报告。仅隔离测试与模拟平台；真实平台速度、现场电脑和生产数据不作为已完成的验收结论。

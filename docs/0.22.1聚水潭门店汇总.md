# 0.22.1 聚水潭分配按门店核对

默认先看门店，点击一行再查看该店商品。适用于「预览库存分配」和「查看已生成分配依据」。无需逐个SKU翻看才能判断本次成果。

## 操作

1. 选单和仓资料后预览。上方显示本次门店/仓单数量、回传需求、已分配、减少金额、金额满足率，以及涉及、已安排、有减量、完全未安排和金额待核商品数。
2. 门店表一店一行，同店多仓汇总。重点看「减少（元）」和「减量SKU」。点击门店查看商品。
3. 店内支持仓库、全部/有减量/完全未安排/已安排/资料待核，以及编码、名称、原因、补货单号搜索。点「返回门店汇总」返回。筛选只影响查看，不改变分配或导出范围。
4. 确认生成后切换为本次已保存结果；停止、失败或尚未执行的预览不计为已完成。已锁/已生成而跳过的旧单单独提示，不计入本次。
5. 历史分配依据同样先按店汇总。下载当时商品资料原件时，使用下方仓单选择框；查看汇总不会替换或更新历史资料。

## 口径

|指标|定义|
|---|---|
|回传需求金额|回传数量 × 本次分配使用的对应仓基本售价|
|已分配金额|原分配记录的金额，直接读取，不重新分配|
|减少金额|同一计价口径的回传需求金额 − 已分配金额；可能包括缺货、箱规及资料问题，不统称节约|
|金额满足率|已分配金额 ÷ 回传需求金额；只含可计价行；需求金额为0显示—|
|涉及SKU|同一门店同一商品编码去重，多门店总体按门店SKU款次计|
|已安排|该店该SKU至少一行分配数量大于0|
|有减量|该店该SKU至少一行分配数量小于回传需求，可与已安排交叉|
|完全未安排|该店该SKU所有行都未分配正数量|
|金额待核SKU|有行缺失或无效的数量、价格、金额，不将未知值视作0|

缺价行不进入可计价金额；部分可计价标记「部分」，全部不可计价显示「待核」。真实0价格仍可计价。不可用不同商品数量总和表示完成率。门店详情上方是本店全部仓单合计，不随下方筛选改变。

## 边界与结构

`jst_review.py`只对已冻结分配行作只读投影，使用Decimal核算；`jst_review_ui.py`共用门店/商品查看组件；`jst_ui.py`装配预览及历史入口。默认只渲染门店行，点击后才组装该店SKU表格。未修改`jst_orders`、`jst_allocation`、库存占用、锁单、付款确认、计算模型、历史格式或Excel输出。界面合并同店多仓不等于合并执行订单；导出仍按原分仓方式。

版本0.22.1，模型0.3.3-rules、归属0.5.1、存储2保持。独立目录交付，0.22.0保留，不合并、不推送。

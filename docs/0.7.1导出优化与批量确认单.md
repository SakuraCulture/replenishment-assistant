# 0.7.1 导出优化与批量确认单

本轮基线为 0.7.0 / 850d31ded8595df72d221c7dc87358d522432ca7。模型仍为 0.3.0-rules，仓归属仍为 0.5.0，存储格式不变。旧安装包不覆盖；新构建与通过的验证记录见 releases/0.7.1 下对应构建目录。

## 怎么操作

工作页计算完成 → “选择门店并导出加盟商确认单” → 勾选门店 → 核对首次签发/同日覆盖 → 选保存位置 → 后台自动归档并逐店导出。

门店选择窗口默认勾选全部有效完成门店；支持全选、取消全选和逐店勾选。未计算、失败或过期门店不能选。导出范围不依赖当前打开的门店详情或商品筛选。一店选文件名，多店选文件夹，按选择表的原门店顺序逐店输出。每店一份 Excel；不追加内部全量汇总文件。内部批次明细导出仍保留原来的全量内容与文件组织。

首次签发或结果有变化时显示确认框，默认取消。同日旧单覆盖为同号新修订，旧修订保留；同时保存当天完整草稿。仅更新所选门店正常单，未选门店已归档单据不变。选择保存位置取消、目标已有文件、提交前取消均不签发。全批一次事务归档后顺序导出；中途失败/取消保留已归档单据及已完成文件，提示具体已生成/未生成文件，可历史重导。归档成功不等于文件全部生成，也不代表实际采购下单。

## 门店文件

三个工作表顺序仍为：往期新品、本月新品、中心仓动销补货清单。

三表只包含商品资料精确匹配的中心仓商品，地采和匹配待核不出给门店。新品关注决定本月/往期分组；所有中心仓新品候选仍导出，未选择、禁用/停采或预算未安排的数量为 0。动销表仍按已有模型执行安排筛选，数量/价格/预算算法不变。缺失箱规补 1、基本售价计价、库存单位等原口径保留。

保留原 A–T 的 20 个字段及顺序；U 是补货单号，V 是决策理由。去掉修订、明细ID、签发建议数、新品识别依据、分组依据、关注清单版本、安排说明七列，完整审计仍在应用归档内；不把它们移到另一个隐藏表。文件名和页眉仍可识别修订。

P 列中心仓价格显示两位小数，底层数值不取整，缺价保持空白/待核。R 列黑名单状态按文本显示；原始未提供标记简写为“未提供”，不会伪造为正常。保留真实状态值。决策理由从已有结果提取，最多几个字，例如动销补货、必卖补货、最低持有、一箱恢复、新品首铺、必卖首铺、新品未选、预算限量、预算暂缓、禁用不补、停采不补、资料待核；不重新计算。

## 性能与进度

内部单店明细复用不可变字体/对齐/表头样式对象，保持表、字段、顺序、值和样式等价。进度显示正在处理的门店、工作表、已写行数/总行数；格式处理与压缩保存单独提示，无法量化的阶段使用忙碌指示，不展示虚假百分比。压缩保存不能中途强杀，取消请求在保存后检查，清理本次临时文件。多店导出仍串行，没有并行导出、没有简要汇总。

计算队列原本会自动补位，不等归档导出：同时计算 4 店时，任一店完成即启动第 5 店。此次增加明确文案，并用实际 spawn 的 4+1 场景验证；未改计算调度算法。导出仍在当前计算任务结束后进行；不引入计算与归档并行访问同一草稿。

## 代码和验证

- xlsx_exports.py：内部报表共享样式与临时XML清理。
- export_progress.py / ui_tasks.py：行数进度及后台界面更新。
- merchant_selection.py / application_window.py：明确门店选择和确认流程。
- normal_delivery.py / normal_orders.py：后台签发、一次批量事务及失败收据；完整草稿只压缩一次复用。
- normal_exports.py：中心仓过滤、22列门店模板、简短理由。
- tools/export_qa.py：固定旧源码对照，3次交替计时、RSS采样、逐单元格类型/样式/顺序对比；完整真实样本另测一次。详见完整报告中的数据规模及白名单。
- verify_normal.py / verify_delivery.py / verify_export_exe.py：预算与归档回归、选店/取消/冲突/失败/重试、实际打包UI及4+1队列；所有验证使用独立QA数据目录。

本轮门店文件按用户要求改变筛选和列结构；不能把门店文件声称为与旧版完全等价。内部报表与计算结果要求等价。业务模型、默认配置和原始输入必须保持哈希不变。

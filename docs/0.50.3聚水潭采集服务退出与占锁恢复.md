# 0.50.3 聚水潭采集服务退出与占锁恢复

业务反馈：资料同步窗口提示 `database is locked`，关闭补货助手再开仍不恢复，重启电脑后恢复。没有取得该业务电脑当次进程与日志，不能断言现场唯一持锁者。

本轮在隔离环境确认并修复了符合此现象的代码缺口：`CatalogService.close()` 原来先断开浏览器，再释放任务库锁；浏览器断开抛错时会跳过释放锁，断开长期不返回时也会一直占锁。主程序消失后仅依靠标准输入管道关闭收尾，也缺少独立的父进程存活检查。

## 已修复

1. 关闭时先停止新动作，等当前操作及所有状态回写安全结束；之后的浏览器断连清理限定等待时间，任务库锁在 `finally` 中无条件释放。时间限制只针对闲置连接清理，不作用于正在提交或保存的任务。
2. 标准输入结束、关闭命令及父进程消失共用一次收尾。即使管道仍开着，监测到所属主程序已退出，采集服务也会停止派发、等待现有动作完成后退出，避免残留子进程继续持锁。
3. 服务完成收尾后结束自身进程，清理闲置连接残余句柄；不终止用户的 Edge，不强杀在途业务提交。
4. 主程序协议失效时先安全关闭自己持有的旧子进程，确认退出后才重建连接。子进程先退出时也会关闭主程序保留的管道句柄。每次启动使用独立技术选项文件，不覆盖另一个进程的启动选项。
5. 仍有有效服务占锁时，提示“聚水潭原采集服务仍占用本地任务锁”，附已知持锁进程号及恢复说明，不再只显示英文。原锁保护保留，不删除锁文件来抢占运行中的服务。

任务库 `jobs.json` 的业务格式、原任务号、账号配置、下载文件和采用回执不变。新增的服务归属记录只有本机进程身份和启动信息，不保存账号凭据。模型、预算、箱规、业务存储版本及翱象采购流水线不改。

## 业务端使用

完整解压本次交付，等原任务安全结束后正常退出旧版，再运行 `交付_0.50.3_rc2/补货助手/补货助手.exe`。无需初始化数据或重新绑定账号。关闭资料窗口仍保留健康共享连接；退出主软件才安全结束所属采集子进程。

如果提示另一个有效服务占用，先按提示等待或正常关闭那份软件；该服务可能仍在工作，本版不会替业务强制结束它。来自未修复旧版的未知残留也不按进程名称直接杀掉。业务端此前已通过重启清理占用，本版重点避免再次遗留并提供可识别提示；仍需在该电脑升级后观察，不能把隔离验证称为现场已复测。

## 验证范围

本轮先复现“浏览器断连失败后仍占锁”，保留失败证据；修复后验证断连失败、闲置断连卡住、重复关闭、原任务提交中的安全等待、晚到回执保存、独立父进程监视、实际子进程退出及同目录立即重开。只使用隔离数据库、合成队列和封闭连接，不调用真实平台。

实际 EXE 验收包含一个明确的闲置主进程异常退出模拟，以及资料窗口打开、复用、占用提示、主软件退出和重开。原任务文件逐字节保持。源码、固定构建、全量回归与实际 EXE 的结果见 `releases/0.50.3/rc2/交付报告.md`。

# 0.48.0 AI 分析、人工核对与签发恢复

本次从 0.47.7 主线 `f481cbe31a2ec82be97d8df83303aae64dd17bcc` 继续，分支 `feat/assistant-workflow-0.48.0`。复用现有补货、生命周期和缺货率服务，不重新开发计算模型。

## 已实施范围

### 门店缺货率 AI

新增六个 MCP 工具：`stockout_context`、`query_stockout_analysis`、`stockout_analysis_results`、`stockout_filter_values`、`stockout_evidence`、`export_stockout_analysis`。前五个只读业务资料，最后一个只在明确要求后写本地 Excel。

- 分析采用明确日期、筛选和维度，复用原生缺货率口径，默认剔除门店停采/禁采与实际供货仓禁用。
- 每次固定日报 publication 清单、快照依据和规则版本。新日报发布不会移动旧会话；原资料删改、会话过期或重启后明确报失效。
- 查询和商品分页在后台执行。分页最多 100 行，过长结果继续分页；缓存最多 3 个分析会话，每个最多 8 页，普通页约 512 KiB，单条异常超长证据不强塞到 MCP。
- 会话约 1 小时过期；关闭 AI 连接清空分析缓存。未进入分析或调用其工具时不加载分析库、事实表或分析能力。
- 同店同商品比较最近两个有观测日期：共同有效基数、缺货变化、新增/恢复、范围进出与缺观测分开。重复缺货统计自然日连续性，缺采中断；不能据此推断全天缺货时长。
- 商品证据包含原始库存、统计库存、原件摘要、原表行、资料版本及是否剔除。具体履约仍须准确原单，通过既有漏斗/历史工具查询；本期不自动猜测缺货记录与订单的关联。
- 页面增加“用 AI 分析当前范围”，提供五种中文业务要求；AI 常用业务增加进入独立分析板块的入口。复制文字不会执行操作。

自动给门店保存参数默认、跨门店候选优化引擎及自动采购闭环仍未实施。已有独立试算、参数字典和明确采用本次作业保持。提示模板是工作指引，不能当作自动配参算法。

### 人工核对可读性

签发、覆盖及预算等核对窗口使用可调整大小的对话框，保留取消默认与 Escape 取消、完整确认范围和差异导出。新增全文查看、复制、搜索；显示筛选不影响确认对象。

“显示与帮助”提供 10/11/12 磅与三种行距、本机列宽记忆及恢复默认。最终清单的筛选区可折叠，默认收起；四组列视角、选中行身份常驻和全文查看帮助横向阅读。表格按字体指标设置行高，窗口适配可用屏幕。显示偏好独立保存在 `display_ui.json`，不进入计算参数和签发快照。

### 签发、回传与导出恢复

用户已确认故障入口为“核对与签发 → 确认签发并导出”；尚未取得那次完整报错、失败日志和原件，不能宣称已确定用户原故障根因。

已确认当前源码本来就有 veryHidden 的“系统关联信息”，不是缺少签发单号。此次保留现有格式和校验，发布 Excel 前增加生成文件与原签发身份的一致性检查；不改业务列和数量。

回传识别新增候选/排除原因、精确旧修订诊断、只读关联信息查看；没有唯一身份时继续要求明确整单绑定。修改可编辑下拉框文字但未选择有效项，不再沿用旧选中项。损坏标记不得回退猜测。

签发和文件写出仍是两个阶段，签发事务原子性不变。新增独立 JSON 导出回执，记录任务、入口、原单/仓/修订/摘要、逐文件阶段、路径、文件摘要、错误和恢复结果，不迁移业务数据库。回执位于业务库旁 `export_receipts`，只在导出时产生。

“导出任务与恢复”核对最近 100 个本地任务；缺失/变化的文件恢复到新建目录，保留原文件、读取原修订，不重新签发。文件已生成但日志失败时核验后补记；原签发结果未知或原单不可用时保持待核。旧版本无回执的任务继续走原单重导。

归档批量导出在 Windows 使用同目录、拒绝覆盖的原子重命名发布，避免依赖硬链接；POSIX 继续保持不覆盖语义。清单写入失败与已完成 Excel 分开报告。相关文件摘要改为分段读取。

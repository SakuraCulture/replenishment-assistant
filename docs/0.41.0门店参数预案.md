# 0.41.0 门店默认与补货预案

本轮基线：main，620351285423e9017af1ee9edd7829d435836eae（0.40.4）。独立开发分支：feat/store-parameter-presets-0.41.0。不修改模型、预算、箱规、仓归属和订单数据；模型版本继续为0.3.4-rules。交付验证结果以 releases/0.41.0/rc1 为准。

## 业务人员怎么用

1. 进入“参数设置 → 参数预案”，从系统默认“复制新建”，设置分类参数、通用参数和各仓备货/到货天数。系统默认不可修改、不可删除。分类映射仍在全局维护；预算、主从仓不纳入参数预案。
2. 在门店列表勾选一家或多家，点“选择默认参数预案”，查看逐店差异后保存。当前作业不变，后续采用使用该默认。每个门店可以选择不同的预案。
3. 在“补货预案”新建线路，勾选门店、调整顺序，每行选择“跟随门店默认”或指定一个完整参数预案。可批量设置勾选门店的选择。跟随默认旁显示当前默认名称。
4. 采用线路到本次作业：按所选门店顺序，冻结完整参数。已完成结果按原规则失效，需重算。之后的单店调整只改本次，不串店、不反写预案。
5. 已经维护的门店参数无需重录。继续作为该店自定义默认，也可在“其他门店设置 → 将单店默认另存参数预案”复制为命名预案供其他门店使用。

## 三层关系

```mermaid
flowchart LR
    S[系统默认参数：只读且不可删除] --> P[复制建立自定义参数预案]
    P --> D[门店选择默认参数预案]
    D --> F[补货预案逐店：跟随门店默认]
    P --> E[补货预案逐店：明确指定预案]
    F --> J[采用时冻结本次完整参数]
    E --> J
    J --> M[单店本次调整与计算]
    M --> H[草稿及历史签发保存参数快照]
```

完整预案之间采用整套替换，不把多份预案逐字段叠加。预案内部仍沿用原有“分类参数覆盖通用参数、按归属仓使用周期”的计算口径。预算、供货关系、资质与拒收依旧独立。

门店没有保存默认时，参数使用系统默认；供货关系与预算缺失仍按原规则待设置，不据此猜仓或自动补预算。

## 修改、删除和生效边界

- 编辑命名参数预案，保存前提示关联门店及补货预案条数。已显式绑定的门店默认与预案更新同一事务提交；下次采用补货预案时使用最新配置。当前已采用快照不变。
- 直接修改/导入门店默认参数，保留改后的完整值，并解除其对命名预案的自动跟随，显示“门店自定义默认”。仅修改预算/主从仓不解除参数跟随。
- 自定义预案可以删除。删除弹窗完整列出门店默认引用、补货预案指定引用；有引用必须选择替换预案。同一事务替换引用并从可选库移除旧预案；并发改动时拒绝提交，要求重新核对。
- 旧版本参数内容保留供历史解释及原有恢复入口使用，不写回旧作业。恢复旧门店默认时，若原引用已删除或升级，恢复为独立自定义默认，避免复活错误的实时引用。
- 补货预案可删除，门店配置、参数预案、已采用作业与历史单保持。
- 参数设置本身不会删除门店。门店默认始终有系统基准可回到；可显式选择系统默认参数。已有的门店自定义值也不因升级自动清空。
- 保存默认不立即修改当前界面。原“重新检查文件时更新未手动修改的默认”行为保留；明确采用补货预案后按冻结快照，不受此自动更新影响。

## 旧数据、定时作业与 AI

旧补货预案原有“完整参数/勾选字段”的行为继续保留，列表标为“旧预案”。编辑旧预案仍进入旧编辑器；通过“将旧预案改为逐店选择参数”显式转换，核对后保存才切换。不会推断旧字段应该属于哪个新预案。

兼容方向是新版读取旧数据。0.40.4及更早程序不理解新预案的逐店选择，不应用旧程序处理新建/已转换的逐店预案；旧包用于保留旧环境，避免两版交替操作同一份新预案数据。

新预案采用后存储各店已解析的完整参数、预案名称、版本、来源（门店默认/补货预案指定）。草稿恢复不重新解析数据库里的新配置。预案库保存时不持久化旧的解析缓存，下一次采用重新冻结。

定时准备与 AI 试算共用 plan_record 解析，读取同一事务快照中的预案、命名参数及门店默认。定时条件签名包含实际生效参数；参数变化仍要求原有重新核对。AI 查询返回预案模式、逐店选择、来源及默认绑定，不增加写入或平台操作权限。

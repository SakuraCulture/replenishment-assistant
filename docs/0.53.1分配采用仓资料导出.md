# 0.53.1 分配实际采用仓资料导出

新增一个 Excel 核对入口，回答“这个分配批次到底用了哪份商品资料、哪个库存”。只读导出，不联网、不更新资料、不重新分配、不保存库存占用，也不添加新的业务确认审批。

## 入口

- 准备新分配批次：选资料并预览后，点击“导出本批采用仓资料”，明确标记未确认预览。
- 继续原批／重新分配窗口：可以直接导出原批冻结资料；重新分配预览标注本次尚未确认。
- 聚水潭导入单结果页：批次视图导出该批资料；日期视图按勾选仓单导出，没有勾选时导出当前筛选内有保存结果的仓单。按钮明确范围和数量。

## 一个工作簿核对三层信息

1. **资料批次**：仓、原文件、本机导入时间、库存依据建立时间、商品款数、资料版本、分配批次号、库存依据ID、原件摘要等。没有可靠平台导出时间时明确写“未留存”。
2. **采用字段_仓名_序号**：当时实际解析采用的商品字段，商品编码、名称、可用数等放在前面，关联标识放后面；筛选、冻结表头及长编码文本保留。不是原Excel全部列，完整原件仍走已有下载入口。
3. **分配核对**：需求、箱规、资料可用、分配前余额、实际分配、分配后余额、缺口、原因和准确关联标识。本批只列当前生效生成单，不把重新分配前的旧记录混算；显式历史记录注明历史状态。

## 来源与保护

按实际 `bid → jst_baselines` 读取完整冻结商品资料并校验摘要；同一仓多个不同依据分表保留，不能只按仓名去重。缺原依据、版本不一致或坏摘要明确失败，不改用当前默认资料。

读取时捕获一致的不可变依据，然后释放数据库读事务再写Excel，减少大文件导出对业务写锁的影响。取消不发布半成品；已存在的文件不覆盖；编码和公式样式的原文本按文本写出，不执行成公式。

库存刷新成功与旧批采用新库存是两回事：默认更新900后，旧批曾采用100就仍导100。导入时间不是平台库存时点；资料版本相同也不能证明没有刷新。导出展示可核对的事实，不保证平台实时库存与历史分配相同。

模型、分配顺序、箱规规整、库存不足有多少分多少、两仓归属及0.53.0独立执行规则均不改。新功能验收以独立交付报告为准；未完成的0.53.0完整全量验收不在本轮改名为通过。

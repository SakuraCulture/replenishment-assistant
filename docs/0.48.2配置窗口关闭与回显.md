# 0.48.2 配置窗口关闭与全局状态回显

用户反馈 0.48.1 的“翱象连接与门店配置”仍显示空浏览器和用户配置，直接关闭后连接状态失效，需要重新配置。

确认了两个代码缺陷：窗口初次只读取门店目录，没有读取已保存绑定与共享连接状态；主窗口在配置窗口返回后，无条件发起一次登录重查，即使没有操作、没有保存。这次重查会访问平台页面，失败后影响全局状态。没有发现“直接关闭”删除磁盘绑定的代码路径；不能将用户感知的失效直接等同于配置文件被清空。

本版变更：

- 去掉配置窗口关闭后的无条件登录重查。查看、关闭和重新打开均只读取已保存配置，不触发浏览器探测、重新绑定、门店查询或导出。
- 窗口通过既有共享组件读取已保存 Edge 路径、用户配置、下载目录、门店核验结果及当前登录状态。配置响应只加入这些表单字段，不暴露整个机器绑定记录。
- 明确区分“已保存门店核验”和“本次登录已核验”，不把所有目录门店重新标成未核验，也不将保存配置当作在线。
- 主动“检测本机已有浏览器”时优先选择原绑定；原绑定找不到就留待明确选择，不自动替换成第一个浏览器用户。
- 首次配置、新增门店、显式核验/停止/保存和底部统一连接修复入口继续保留。账号验证与共享连接所有权边界不变。

之前 0.48.1 的隔离走查只覆盖共享会话及启动交接，未覆盖实际主窗口配置入口的返回回调，因此漏掉“关闭即重查”。本次补上实际入口打开、检查回显、直接关闭及再打开补货建议的完整隔离走查。真实 Edge 状态变化仍需现场使用观察，隔离通过不冒充真实平台验收。

验证只使用独立资料目录和封闭模拟传输；没有登录平台、创建导出、采购或修改现有配置。最终计数、源码提交、包哈希及已知限制见 `releases/0.48.2/rc1/交付报告.md`。旧交付保留，不推送、不合并。

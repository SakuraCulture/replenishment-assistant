# 0.48.3 最终清单筛选与批量加减

入口：“核对与签发 → 最终清单 / 改量”。本版增加人工审计工具，不重新执行计算模型、预算分配或仓归属。

## 筛选商品

点击常驻的“类目 / 销量 / 库存筛选”。窗口关闭后，当前条件摘要仍显示在商品表上方；收起原筛选工具栏不会隐藏这些条件。

- 商品原始类目：采用本次结果留存的 `_category`，可多选。
- 补货模型分类：采用本次结果的 `U`，独立多选，避免把原始商品类目与模型分类混为一谈。
- 周销、月销：采用本次补货建议的 `I`、`J`，不重新取平台资料。
- 可用库存、在途：采用本次建议的 `K`、`L`，负数按原值筛选。
- 拟签发后持有量：与原最终清单一致，为 `max(K,0)+max(L,0)+当前拟签发数量`；资料不完整或不可调整时不造数。

各数值可选大于、大于等于、小于、小于等于、等于、含两端的区间或“资料缺失”。例如可用库存等于0表示严格为0，小于等于0同时包括负库存。空销量、空库存不当作0。类目列表中的“资料缺失”可单独选择；列表搜索只影响列表显示，不清空已勾选项。

同组类目多选为“或”，不同筛选组为“且”。本筛选与门店、仓、商品搜索、商品分组及原“更多筛选”叠加生效。所有类目不勾选表示不限；“重置本组条件”只重置当前窗口，主界面的“重置全部筛选”同时重置所有筛选。重置不清除商品勾选或人工修改。

例如：商品类目选择“饮料、休闲食品”，月销≥30，可用库存≤0，在途=0。应用后查看命中门店和款数，再勾选需要调整的商品。

## 批量加减或设置数量

主界面显示“命中门店 / 款数、已勾选、筛选外勾选”。默认批量操作范围是“当前可见勾选”；只有明确切换到“全部勾选（包含筛选外）”才处理隐藏勾选。直接编辑单行仍无需勾选。

点击“批量加减 / 设数量”，可选：

1. 增加 N 个最小出库单位。
2. 减少 N 个最小出库单位，最低减到0。
3. 每款设为 N 个最小出库单位。
4. 设置相同库存单位数量。
5. 清零。

加减基准是每行当前拟签发数量，包括尚未应用的本次人工调整。按各行本仓 `BD` 箱规计算；N须为非负整数。统一设库存数量也须满足每行箱规，任意一行不合法则整次不填入。不会自动四舍五入或改变箱规。

例如两款商品当前均补24个，箱规分别24和12，增加1个最小出库单位后分别为48和36个。减少量超过当前数量时归零。数量与金额一律按实际商品库存单位和本次单价计算。

填写1～200字统一调整原因后点“预览全部变化”。预览包含全部选中行的门店名称/编码、仓、商品名称/编码、调整前后数量、数量及金额变化，同时显示涉及门店、款数、实际变化款数和总金额增减。支持滚动及查看完整单元格，不只展示前20行。改变模式、数值或原因会清除旧预览，须重新预览；没有实际数量变化时不能填入。

“确认填入当前清单”只改当前编辑草稿，原因写入实际变化行。取消预览不修改任何数量。随后仍需“核对修改与预算”、确认实际列出的风险、点击“应用最终数量”。原有不可安排、箱规、库存额度、新品、预算、并发修改及历史只读检查保留。

“保留为待核对草稿”只暂存，不等于应用。正式签发前必须处理选中门店的待核对调整。

## 修正签发导出晚拦截与提示

用户截图显示“已生成0/4份；门店尚有待核对的签发前调整：CXT20260623”，同时弹窗建议关闭占用文件。源码确认：快速导出投影丢掉了 `preissue_drafts`，预检通过后完整草稿在归档阶段才被原校验拦下；通用错误翻译又误判为文件写出失败。

本版快速预检保留所选门店的待核对状态，让原签发保护在确认签发前生效；此类错误明确指向最终清单、原因、核对、应用流程，不再建议关闭Excel。未选门店的待核对调整不扩大到本次签发范围。没有放宽签发检查，也没有自动套用暂存草稿。

既有失败任务及原签发状态不自动修改。截图只证明当次本地流程被待核对调整阻止，不证明平台或文件权限有问题。

## 验证范围

隔离测试涵盖多类目组合、比较与区间边界、缺失与0区分、负库存、当前拟签发后持有量动态变化、隐藏勾选、各行不同箱规、加减截零、整次非法不部分写入、预览取消、统一原因、风险确认、应用、签发与隐藏关联信息。新包实际EXE采用合成数据及独立数据库，不调用真实平台。最终计数和包哈希见 `releases/0.48.3/rc1/交付报告.md`。

本轮没有重排整个“门店与参数”页面；此前提出的全局布局优化仍是后续范围。包内业务流程手册继续提供，新功能具体步骤以本说明为准。

# 0.40.2 删除与翱象任务状态

## 使用方式

订单跟踪、决策复查的“彻底删除订单”仍是原入口。先勾选订单，核对完整删除范围，再明确确认。删除不进入回收站。

- 同店同日两仓共用原计算快照，仍按门店当天父单整体删除；确认页列明全部仓单。没有改变原有删除范围。
- 本地采购准备因付款尚未确认等原因失败，且没有采购包、采购身份或上传证据：可以随选定订单清理，不必先确认付款。
- 还在排队的本地准备：删除预览列出阻塞原因，可“结束关联本地准备”后重新检查。只结束所选订单对应项，未选项继续保留。
- 正在运行：先停止并等待安全退出，再删除；不强杀正在上传的进程。
- 已有采购身份且上传结果不明：继续核对原任务，不能把浏览器未连接当作未上传。不会为了删除而重发采购。
- 已核实外部采购关联：原有外部影响确认继续保留。本地删除不撤销平台采购、不恢复实际仓库存。

“删除前处理关联任务”展示全部阻塞项，不静默跳过其中一部分。选择“查看并处理原任务”后退出删除流程、释放维护暂停，再打开原批次；处理完重新发起删除。预览与最终提交之间若订单或任务变化，拒绝旧预览，要求重新核对。

## 批次页面

“查看采购预览”仅在选中行确有预览包时可用。“查看失败原因”显示实际错误及下一步，本地付款检查失败不再误提示去收货页。

新增“结束所选本地准备”，默认取消，仅可结束未运行且未生成采购身份的本地准备；不是取消平台采购，也不是删除业务订单。需要继续时修正付款依据并重新准备。

进度条显示“已检查 / 总单数 · 就绪/成功单数”，同时明确待处理、未处理和已结束数量。检查100%不代表全部成功。没有排队动作后，底部显示空闲，不再停留“正在重新检查”。

删除部分订单后，批次剩余数量、状态及数据库状态字段一起更新。保留未选项的业务字段和顺序；内部位置重新连续编号。勾选按订单身份保留，避免删除后行号移动而误选另一单。

## 数据一致性边界

计算、预算、箱规、一箱例外、仓路由、签发/回传/付款/实收的业务口径及原Excel导出没有更改。存储格式版本不变；本地结束增加可选任务标记 `ended_locally`，旧任务不必迁移。

删除仍在原跨数据库事务中执行，提交前取消或失败整体回滚；最终提交阶段不可中断。删除后界面刷新失败会明确提示“已删除，页面未完成刷新”，不能误报回滚。预览指纹补充任务状态列及关联收货计划，避免预览后变化被遗漏。

“结束本地准备”和“永久删除订单”是两次分别确认的操作。已经明确结束的准备任务，不会因为随后取消删除而自动恢复；业务订单仍保留，可重新准备。

保留未选订单签发快照、计算结果、共享原文件及未选任务。全批删除时清理该本地批次及事件；部分删除时保留共享批次事件，再记一条范围变更事件。外部组件防重复采购身份留存，不在订单列表中冒充业务订单。

原磁盘Excel、已经导出的文件、旧备份、平台采购单不会被删除。SQLite文件不会保证立即缩小。仍需核验共享引用，历史大库不承诺秒删；本次解决错误拦截与状态一致性，不宣称整体删除提速。

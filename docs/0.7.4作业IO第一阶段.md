# 0.7.4 保存、归档和导出：第一阶段

固定基线 d3d0165（0.7.3 加加盟商文件名去后缀），独立分支 perf/work-io-stage1-0.7.4。
旧 EXE/ZIP 保留，本阶段不迁移每日作业、不引入分块数据库、不推送、不合并。

## 优化边界

- 保存准备产生一次原格式 JSON 字节和 SHA256；本次会话确认后复用该不可变字节完成压缩及原事务，取消则丢弃。不会在会话间缓存可变工作对象。
- 归档仍保存完整草稿及门店完整结果。门店业务指纹采用已有只读浅层投影，替代无意义的整树深拷贝；草稿摘要与已存记录相同则复用数据库已有压缩快照。
- 核对修订差异时先用原规范 JSON 比较整行；未变的商品直接跳过逐字段重复编码，变化商品仍按原字段顺序生成完整差异。不能用普通字典相等代替，以免混淆 0/False/0.0。
- 门店编码/压缩在事务外准备，事务内再次检查所有预期草稿和正常单修订，并原子发布全部内容。没有关闭同步写入、跳过汇总/编码唯一性/门店隔离检查。
- 自动归档界面只需要单号、修订和时间，提交成功直接返回这些已提交元数据，不为此再次解压全部归档。需要完整记录的原兼容 API 仍读取并校验来源。
- 导出先只传所选门店的当前结果及必要设置进行核对。全部已归档且未变时，不传整个导入批次/仓资料/其他门店结果。需要新签发时，补齐完整草稿后再让用户确认；不能用精简探测数据签发。
- 同一次导出准备中已读取并校验的归档可以复用；执行前重新检查单号身份、当前修订、指纹和保存时间，拒绝并发修订。导出始终绑定固定、已校验的归档，不引用最新可变配置。
- Excel 写表实现、商品过滤、22 列、三张表、单元格值/类型/样式/批注未改。文件名采用基线已授权的 `日期+门店名+（精简版）.xlsx`，已有文件仍拒绝覆盖。

## 进度契约

保存、签发、导出、完整作业读取和复制配置使用统一阶段进度框。显示当前阶段、实际可计量进度、累计耗时及最近进展时间。

- 字节哈希和压缩以已处理字节 / 总字节计量；门店准备、Excel 行写入使用实际计数。
- JSON 编码、数据库提交、Excel 最终压缩等无法精确计量的步骤使用活动条，不用时间生成假百分比。
- 传输显示已完成数据块数，总量不预扫描；这些块是传输协议单元，不是新存储格式。
- 进度条百分比明确属于当前阶段，完成全部处理并收到成功结果后才显示操作完成。
- 主界面定时器显示 elapsed 与最近进展间隔。操作系统报告进程存活只表述为“进程仍存活”，不等同于业务仍有进展，也不自动判定死锁。
- 写事务不可强杀；取消导出保留已归档修订和已生成文件，并列明未完成项。进程退出/传输失败报错，不伪装成功。

## 不变的格式与业务

SQLite 表结构、JSON 编解码规则、日期标记、原 SHA256 业务指纹、zlib 数据格式均保持。
作业/参数版本 1，模型 0.3.0-rules，需求归属 0.5.0。每日覆盖确认、历史只读、同号修订、明细 ID、配置和来源快照均保持。
这次没有实现下一阶段的内容块复用或历史迁移，原格式完整编码仍与数据规模相关。

## 独立验证和复跑

输出必须使用不存在的新目录，所有测试资料位于 qa/io_stage1_074，不连接日常用户配置。

1. `verify_normal.py --output <新目录>`：计算/新品/预算、同日修订和模板回归。
2. `tools/verify_io_stage1.py --fixture <payload.json> --output <新目录>`：两个独立进程运行固定基线和候选，固定同一时钟/UUID；完整 SQLite 行（含压缩 BLOB）、事件、作业和归档及 Excel 对照，空值/类型/顺序严格区分，不设置业务字段忽略白名单。
3. `tools/verify_work_io_controls.py`：取消、重试、修订冲突、事务注入失败及导出中断。
4. `tools/verify_io_stage1_controls.py`：所选门店探测、补齐完整草稿、并发冲突及 Qt 进度数值/状态。
5. `tools/benchmark_io_stage1.py --runs 3 --output <新目录>`：原五店全量，旧/新、新/旧、旧/新，逐个测量，包含进程启动/IPC/准备/提交/写表；外部每 50ms 汇总主进程及子进程 RSS。默认不启用诊断函数包装；`--profile` 仅诊断分段累计成本，不代替正式性能结果。
6. 实际 EXE 的 work-io、normal、delivery、history 验收，私有数据库副本，保留真实进度截图与日志。EXE 不代替源码独立对照。

性能结论及实际交付以 releases/0.7.4 对应发行记录为准；不把活动条改造宣称为耗时下降，不承诺所有操作秒开。

# 0.54.9：经营分析导出与空白错误提示

修复经营分析导出前重新构建完整分析导致的内存峰值。页面查询仍保留原结果；复核复用相同逐单读取、来源验证、仓单/生命周期/范围筛选和事实生成过程，只将新事实暂存到导出目录的私有临时流。外部关联附加完成后，逐行计算与旧JSON规范相同的完整摘要，不在内存中保留第二份全范围事实、历史复盘和派生汇总。初次查询的摘要也改为逐行编码，避免一次生成全范围巨大JSON字符串。

快照ID格式、模型版本、数量、金额、顺序、筛选、模板公式及单号关联保持。原来源损坏、修订/删除、付款/收货变化、外部采购变化、最终发布前的再次校验、取消和原子发布保护保持。不新增数据库结构，不采集平台，不跳过核验。导出内的已完成校验仍只在相同数据库与外部身份依据下复用。

内存仍受最大单仓快照、原有来源缓存与当前页面结果大小影响，不承诺在任何可用内存下都能导出。导出核验依然使用完整只读数据库快照；不会在Excel写出期间长期持有读事务。复核需要临时磁盘空间，优先使用用户选定的导出目录，不将大规模暂存默认转移至C盘。取消、异常和正常结束都会关闭并移除私有暂存文件；目标文件仅在全部最终校验成功后发布。

空白异常和MemoryError会显示异常类型、最后阶段以及本机app.log位置；原始堆栈仍留在应用日志中。原有非空业务错误、取消和既有WorkFailure提交状态说明保持。经营分析错误框提供可复制的技术详情，退出清理时继续遵守已有Qt窗口保护，不在后台线程创建窗口。业务机的这次实际异常仍需日志确认，隔离限额复现不等同于业务原单复现。

旧交付和全部验收证据保留，性能、内存与实际EXE结果见releases/0.54.9/rc1。

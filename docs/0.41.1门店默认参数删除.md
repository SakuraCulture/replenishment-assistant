# 0.41.1 门店默认参数删除与自动填写

本次按用户最新口径修正0.41.0：**门店默认参数可删除；系统内置参数只作兜底，不展示为可选预案，不可删除或修改。** 本文取代0.41.0说明中“系统默认参数出现在预案库”的设计，旧版交付记录保持原样。

## 使用

1. 参数设置中勾选门店，点击独立按钮“删除所选门店默认参数”。
2. 核对将删除的门店和参数，确认后删除；弹窗默认取消。未保存参数的门店不重复处理。
3. 门店显示“未保存参数”。供货仓、预算、门店名称、未选门店与订单均保留。
4. 下一次新建作业并进入计算准备，自动填入系统内置参数，可在计算准备查看、调整本次实际值。填入不等于永久保存；以后也不会凭空重新出现门店默认参数。
5. 如需再次长期使用特定参数，可保存门店默认，或选择自建的参数预案。预案库新增“新建参数预案”入口，无需先选系统默认才能创建。

删除不会暗中重配已载入的当前作业，也不回写历史草稿、签发或计算结果。正在处理的作业保持已冻结参数；如要更改本次参数，应在本次作业中明确调整。历史草稿恢复仍使用当时参数。

## 参数与补货预案

- 普通新作业：已保存的门店默认 → 没有时自动填写内置参数。
- 补货预案按门店设置：明确选择的参数预案优先；选择“跟随门店默认”时才走上述兜底链。
- 系统默认不出现在预案库、批量选择或新建补货预案的可选列表。历史中明确绑定旧内置预案的配置保持数值，编辑时标明“原有固定配置（兼容保留）”，不自动改变。
- 删除被引用的自建参数预案，可选择另一预案替代，或“取消引用，之后按门店默认或自动填充”。预览列出受影响门店和补货预案，同事务替换；当前和历史冻结快照不变。
- 全局分类映射继续独立维护，不因删除门店参数被重置。旧数据仅在门店记录里保存统一映射时，删除前将其等值保存到已有的全局映射存储。
- 供货仓与预算不属于本次删除范围。没有供货设置时仍需业务指定，软件不猜仓或预算。

## 数据与实现

`store_defaults.has_parameters`区分真实保存与临时兜底。数据库门店记录保留路由/预算，删除其`preset`参数载荷。Repository读出时临时补齐参数以兼容现有计算装配，写回时不会持久化未改动的临时兜底。直接编辑参数、Excel导入参数及明确保存会转为真实门店默认；只改仓或预算不会重新创建默认参数。

删除通过`parameter_presets.clear_defaults`进行：备份、写事务、完整预览版本核验、所选记录更新、变更记录。核对后数据变化则拒绝，要求刷新；现有变更记录可恢复，没有新增回收站。原有备份与审计保留属于维护记录，不参与有效参数选择。

模型、预算、一箱例外、仓路由与导出算法不改；应用版本0.41.1，模型0.3.4-rules、仓归属0.5.1。旧数据可由新版读取，不自动迁移门店数值。旧程序不理解删除后的“仅路由/预算”记录：旧包用于保留与回退，不应直接打开已经执行删除的新资料；如回退，应使用删除前的备份副本，勿覆盖当前资料。

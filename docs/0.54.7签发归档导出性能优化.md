# 签发归档导出性能优化

本轮保持数量、金额、商品及订单顺序、原校验、默认并发和整批最终提交规则。无需业务新增维护操作。

签发商家Excel在当前工作簿内复用完整、只读的字体与数字格式样式组合。缓存键包含单元格原有样式，保留日期等绑定值时已有的格式；文本标识、批注、隐藏关联信息及文件核验保持。样式编号不跨工作簿复用。内存写入、逐行写入和中途资源下降时重建未发布文件均走相同处理。

安全编码在单次编码内保存字符串键序列的保守大小开销，最多64项、保守保留量64KiB，长键、复杂键和字典子类沿用原计算。只缓存不可变字段结构，不缓存商品值、容器身份或业务有效性。值和节点预算仍逐项检查；明显超限的普通容器可以直接进入原流式路径。可选缓存内存不足时清空并回到原计算；快速编码失败时释放该缓存，保留原资源降级和流式回退。

JSON键序、分隔符、Unicode、日期、异常值拒绝、摘要、内容块身份及v2存储格式保持。现有动态资源预算、压缩缓存阈值、完整日草稿、父单与分仓快照、来源修订和CAS核验不变，不复用跨操作业务摘要。写锁、一次提交、取消、原修订补导出和失败恢复边界保持，签发文件仍按原顺序生成。

验证采用新建合成资料，不调用真实平台，不重放真实签发。性能比较包括完整工作子进程通信、签发归档和所有文件完成，人工确认停留不计时。独立新旧计时与内存结果、资源压力场景、实际EXE验收及限制以本版交付报告为准；单独剖析的耗时不当作正常速度。

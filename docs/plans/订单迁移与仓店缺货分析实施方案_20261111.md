# 订单迁移、单进程与仓店缺货分析实施方案

基线：0.50.5 rc3，`a91a811`，开始时工作区干净。开发分支：`feat/migration-and-warehouse-analysis-0.51.0`。本方案只覆盖用户指定的五项；完成实施和验收后独立交付，保留旧包，不推送、不合并。补货预测、预算、箱规、归属及必采最低持有规则保持。

## 1. 订单跟踪：完整迁移和参数导出

在订单跟踪提供独立的“导出完整订单迁移包”“导入订单迁移包”和“导出完整参数”入口。迁移包是可以还原的数据包，普通业务Excel继续用于分析和回传，不冒充迁移格式。

迁移范围为本机全部订单业务资料，界面明确显示全量范围，不把当前页或筛选结果误当完整数据。保留签发全部修订、工作快照及内容块、制单原件、回传、分配、聚水潭内部号、付款、翱象采购关联与防重事实、实收、事件和删除失效屏障。共享父单及共享资料保持原关联。资料文件同时保留校验值和原始来源；可迁移原件入包，原本缺失的原件明确列出，不伪造完整。

导出采用一致的数据库快照和文件清单，逐文件校验，分段读取，不能一边写入订单一边拼出不一致包。导入先验包及预览，采用完整还原而非静默合并：确认后备份原本机订单业务资料，再一次性还原；失败、取消及中断保留原库并可恢复。还原不得用旧后台回调覆盖新资料。浏览器Cookie、登录会话、本机浏览器配置、凭据不入包；导入后不自动执行旧计划或重发采购，订单和外部受理事实保留供原任务核对。

参数导出涵盖完整门店参数、供货设置、仓周期、分类权重及通用超参、全局分类映射、预案引用与清单依据；沿用现有V3可回导格式及既有参数服务，不只导出界面当前可见字段。历史订单始终保留当时参数，不能用当前参数替换历史。

## 2. 只保留一个主应用，重复启动唤醒已有窗口

在创建业务窗口和打开业务库之前建立当前Windows用户共享的主应用入口，跨交付目录和资料目录生效。后续启动只通知原主应用并退出，不建立第二个业务窗口；恢复被隐藏或最小化的主窗口并激活。启动过程中的请求在窗口就绪后处理；崩溃留下的入口可重新接管。

不把计算工作进程、Node采集服务或AI接口当作第二个主窗口，不强杀任何提交任务。隔离验收使用显式测试模式和独立入口名，验证同一套竞争与唤醒逻辑，不抢占真实主应用。

## 3. 决策复查：重做完整计算表的业务投影

替换原先递归展开全部JSON的导出。原实现会展开每行来源字典、文件指纹、列表索引等，生成大量无法业务分析的列；新报表用固定、可理解的字段集合，每行对应门店、商品、供货仓和签发修订。

保留输入、实际超参和输出，包括门店编码/名称、商品编码/名称、单位、原销量窗口、可用及在途库存、缺货天数、周转、分类/类目、商品标签、虚拟分类、商品状态、补货/采购状态、主从仓及供货仓库存、实际仓周期、趋势和权重、预测日均/修正/安全库存、净需求/整箱/额度、原建议、必采保底、预算候选与分配、人工改量、最终量和金额。数值保持数值，不把待核变0；历史未留存字段留空并说明。

完整参数按历史实际生效值导出，分类覆盖与仓周期优先，不用当前默认补齐旧记录。移除路径、哈希、临时ID、线程/进程、来源行数组以及原本未参与计算的冗余字段；字段说明解释计算阶段。商品资料原件继续用原有独立下载入口，不能在分析计算表里再次铺开原表和技术树。

## 4. 门店缺货率：预计销售天数

按每条店品日记录计算：`(可用库存 + 在途库存) / 月销 * 30`。库存保留原数值，不额外夹成0；月销不大于0或任一必要值缺失时不计算，显示原因，不把未知写成0。商品表、详情和商品明细Excel使用同一计算函数。

现有事实库已保存月销、可用和在途，无须重采或改变缺货率基数。不同商品库存单位不能混加成一个假“整类目销售天数”；本轮不增加未要求的汇总算法。

## 5. 独立大仓缺货率分析

新增独立入口和独立存储，未进入时不加载业务模块、不读取仓商品明细。只用所选仓的商品资料；采用已有资料须由业务明确操作，也可取得新的独立分析资料，不覆盖补货侧商品资料。

按仓、商品编码、观测日期冻结快照，同仓重复编码不能随意取第一条。分母是剔除后的商品支数，分子是其中可用库存小于等于0的支数；不要求有月销。默认剔除虚拟分类中所有淘汰品、仓库禁用品和商品标签精确“日配”的商品。原字段、剔除原因和缺失依据保留；必要字段缺失待核，不把缺库存视为0。

沿用门店分析的使用方式：日期范围、总览与趋势、商品与待核、仓库/供应商/类目/商品状态/标签等多维筛选、可自定义多维组合、按组合分工作表导出全部分组、编码和名称同时可读。采集及快照记录、暂停/继续、离开后的资源释放、每日计划、重采/原件重算、日志删除和数据删除保持同等能力；分析资料与补货和门店分析分别维护。没有原件或未采日期不补0，不借用门店月销作仓分母。

## 实施和验收顺序

先完成字段投影和预计销售天数，再完成进程入口与迁移，最后接入独立大仓模块。各阶段保留可运行提交，最终合并本分支内成果后统一打包。

验收按五项逐条核对：迁移前后逐表/逐订单业务签名、全部修订和原件哈希，损坏包/取消/中断与备份恢复；并发重复启动及隐藏窗口唤醒；新计算表每个指定业务字段、数值类型和无技术树；预计销售天数的正常、零月销、缺值及原缺货率等价；大仓剔除优先级、SKU基数、负库存、多维交叉、全量导出、重算、删除和未进入不加载。测试仅用新建隔离目录及模拟平台，不调用真实平台、不清理真实业务数据；全量回归、固定源码EXE、手册和交付清单完成后再认定五项全部交付。

# 预计可售天数与五段漏斗分析方案

日期：2026-11-06。方案已获授权并进入0.44.0实现；本文件保留设计口径，实际交付和验证以 `docs/0.44.0预计可售天数.md` 及 `releases/0.44.0/rc2/交付报告.md` 为准。原核对基线：主线 `339db81`，应用0.43.1、模型0.3.4-rules。

## 1. 目标与范围

帮助业务同时回答：本单安排了几天的货、执行过程减少了多少保障、现货是否可能撑不到到货，以及是否存在长期高库存。覆盖日常数据看板、手动 Excel 导出和 AI 查询/导出，三者使用同一指标服务。

本次新增的是分析指标，不是影响计算的新超参。名称采用“预计可售天数”；涉及可用加在途时使用“含在途覆盖天数”。不称为“实际库存周转天数”：后者需要期间库存和实际销售等连续依据，现有离散订单快照不能证明。

不改变预测、预算、箱规、最低持有、一箱例外、准入、主从仓和签发规则。不自动调参，不回写历史，不把分析风险转换成自动补货或自动削减。

## 3. 单商品指标定义

所有数量使用同一库存单位。预测日均 `d = AN × AM`，固定取制单时留存的预测及趋势依据，不临时改成月销÷30，也不使用最新参数反算历史。

设 K 为制单时可用库存、L 为制单时在途、Q_s 为环节 s 的数量。

| 业务名称 | 公式 | 解释 |
| --- | --- | --- |
| 现货可售天数 | K / d | 制单时货架可用库存的预计保障 |
| 含在途覆盖天数 | (K＋L) / d | 库存位置的静态保障，在途不代表已经可售 |
| 本单新增可售天数 | Q_s / d | 本环节的新增数量对应几天预测需求 |
| 签发后预计覆盖天数 | (K＋L＋Q_signed) / d | 基于制单时快照的静态计划覆盖，不扣等待期销量，不冒充实际到货库存 |
| 当时保护期 | AG＋AH | 当时有效备货天数与到货天数之和，不统一替换成固定天数 |

示例：d=2包/天、K=4包、L=6包、签发20包，对应现货2天、含在途5天、新增10天、签发后15天。

模型建议、签发、门店确认、实际下单、实际收货五段各自使用 Q_s/d。五段固定同一预测依据，便于区分执行减量与预测变化。实际收货阶段展示的是“这批收到的货能支持几天”，不得把实收量与几天前的 K、L 相加后称为“当前可售天数”，避免忽略期间销售、在途转实收及重复累计。

## 4. 有效性、分组与汇总

### 4.1 有效条件

- 日均必须存在、有限且大于0；零销量参考、缺字段和无效数值分别记录原因，不能用无限天数或0天代替。
- 单商品新增天数要求环节数量存在、非负、单位一致；数量0且该环节有效，结果才是0天。
- 现货指标要求可用库存有效；含在途及签发后指标还要求在途有效。负库存不隐式归零，相关新增分析指标标记待核并保留原数值；不借此改动既有计算或历史诊断的处理。
- 环节未取得、旧版资料不能确认、后续追加商品缺当时预测，显示明确缺失原因。
- 无价格不影响该商品数量/日均的天数；影响货值加权汇总。价格为0、负值、非有限值不进入货值加权，单列数量及原因。

### 4.2 纳入范围

沿用现有经营分析纳入、排除、待核规则，包含门店停采/拒收、对应仓禁用、淘汰标签及其他已实施准入依据。不用当前状态覆盖历史状态；未留存依据不能自动视为合格。继续区分必采、非必采、属性待核。

### 4.3 订单及门店汇总

不能把瓶、包、个合计后除以合计日销，也不能直接平均各商品天数。采用签发时价格 P：

`新增可售天数（按货值加权） = Σ(Q_s × P) / Σ(d × P)`。

这个数等价于按预测日销货值加权的商品覆盖天数，表示“本次商品”的需求保障，不是全店库存周转。分母为0时显示不可计算。

五段比较遵守固定样本：

1. 单订单先构造满足准入、预测、价格和单位要求的基准商品集合，包含数量为0的商品，不随环节正数量筛选而更换分母。
2. 标准生命周期导入已确认的缺行0按原规则作为有效0；未导入不能补0。
3. 单订单某阶段存在未知数量，则该阶段完整汇总不可得；可展示“已知范围”辅助值，不能伪装完整阶段。
4. 多订单看板按已选择的比较环节取共同有效订单/商品范围，所有展示的比较天数使用同一范围；显示参与及未参与订单数。没有共同样本时不画可比较漏斗。
5. 原有数量、款数、货值及转化率继续保持原口径，不为让新天数好看而重算旧指标。天数视图必须标明其有效范围可能小于原数量视图。

同日同店同SKU的跨仓数据先核对单位、日均和库存快照一致性：订单新增数量可按仓展示；门店合计时需求分母、K和L只能计一次。无法证明属于同一库存观察时，保留分仓结果，门店合计天数待核，不猜选一份。

多轮数据默认按业务日/轮次画趋势，不累加多轮库存。跨日门店区间汇总保留原数量货值指标；覆盖指标显示各轮或最新有效轮，并标注日期，不把累计补货天数当作今天还能卖几天。本期不新增含义不清的跨轮平均天数。

## 5. 交互与导出

### 5.1 默认路径

数据分析 → 选择门店、日期、仓、必采分组 → 查看五段漏斗 → 切换“预计可售天数” → 点击异常门店/订单查看商品依据 → 按需导出。

沿用原筛选，不新增一个需要业务维护的参数页面。指标切换为“商品款数 / 商品数量 / 商品货值 / 预计可售天数”。天数视图就地提示“按制单时预测，仅统计有效依据范围”。正常业务界面不显示 AN、AM 等代码字段。

详情分两组：

- 库存保障：制单时现货天数、含在途天数、签发后覆盖天数、当时保护期。
- 执行保障：五段新增天数，显示从签发到实收减少了多少天；只有相关阶段依据齐全时计算差额。

点击数值可查看中文公式、参与数值、日期、单位和不可计算原因。顶部先给有效范围及异常款数，详细字段按需展开，避免默认堆满表格。

### 5.2 Excel

- 现有精简经营分析表原字段、原顺序和原值保持不变，末尾增加模型建议、签发、门店确认、实际下单、实际收货五列“新增可售天数”。
- 订单行给出当轮结果；跨日门店汇总不伪造一个整体覆盖值，可另选“门店逐轮天数”导出，每行门店＋业务日＋供货仓＋必采分组。
- 不增加重复的五组天数比例。固定样本下与数量变化信息高度重复；优先展示减少天数。
- 可选商品明细提供预测日均、库存、在途、保护期、各环节天数和原因。
- 数值单元格为数值、显示1位小数，内部保留精度；缺失使用空数值和单元格说明/口径说明页，不把“待核”写成0，也不把数值整列转为文本。
- 说明页列出公式、有效订单/商品范围、缺失和缺价数量；不恢复用户已删减的文件路径、系统审计字段等无关主表列。

### 5.3 AI

使用同一指标服务，接口输出指标版本、依据日期、预测口径、聚合层级、参与范围及缺失原因。AI查询与导出和原生入口数值一致。展示值与证据分开，不能将“实收新增5天”说成“门店目前还有5天库存”，也不能直接依据天数修改正式参数。权限仍限已开放的查询、导出及独立试算。

## 6. 风险解释与多轮复查

- 现货天数短于当时到货周期：提示到货前断货风险；有在途且到店时间未知时，提示核对而非断言必然断货。
- 签发后覆盖高于当时保护期：先显示超出天数，不擅自新增业务拦截线。箱规、人工铺货、最低持有等另看现有实际生效原因。
- 上轮建议充足但门店确认/下单/实收减少，本轮缺货：优先核对执行与履约差异，不能直接判为参数不足。
- 上轮落实齐全且多轮仍缺货：列为预测、到货及时性和其他出入库的复查线索，不宣称已找到唯一原因。
- 多轮库存位置偏高：提示查销量变化和在途；少补新货不等于已经回收存量资金。

本期不引入连续销售反推、不推断实际到货日期、不根据滚动月销相减生成期间销量。

## 7. 代码结构、性能和兼容

建议新增一个轻量纯计算模块 `src/coverage_metrics.py`，接收既有冻结事实，输出单商品指标、聚合结果和有效性原因。没有 Qt、数据库写入或模型重算。

调用链：历史快照 → order_analytics 事实构建 → coverage_metrics → 看板 / Excel / AI。多轮复查复用明确的预测和有效性定义，原有数值行为的调整另立任务，不混入本期。

一次查询只解析一次已有快照，计算按行线性扫描；不逐商品重读 Excel，不为每个指标重复取完整订单。使用既有后台任务、取消及进度机制；可缓存同一快照、同一筛选、同一指标版本结果。生命周期或筛选变化必须失效，缓存不能跨不同历史依据复用。

不升级业务存储格式，不回填旧归档。已有字段够用即计算，不够用显示待核。分析导出新增指标版本供解释，不修改模型规则版本。真实周转能力需要未来另行确认连续库存、销售及金额口径，本期不实施。

## 8. 开发阶段与验收

1. 固定基线，完成纯指标及固定样本聚合；人工算例与自动化验证公式、缺失语义。
2. 接入看板、精简导出和逐轮明细，保持原统计和导出字段不变。
3. 接入 AI 查询/导出及多轮解释，完成独立验收，再按项目流程独立打包。

必测：正常商品、数量0、日均0、新品、缺字段、无价/零价、负库存、阶段未取得、有效缺行0、追加商品、不同必采组、禁采禁用淘汰、跨仓同SKU一致/冲突、同店多轮、老归档、取消和缓存失效。

验证要求：

- 单商品手工例子可复算；多SKU不同单位加权正确；五段共同样本不随正数量变化。
- 原五段数量、金额、款数、状态和顺序逐字段不变，原Excel字段值/类型/顺序不变。
- 原生页面、Excel、AI对同一快照同一范围结果一致；无日均或未完成阶段不变成0。
- 同一冻结输入测新增计算、渲染及导出开销，至少3次记录中位数和范围，不先承诺提速。
- 实际EXE验证指标切换、筛选、明细、导出、老资料和取消；源码测试不能代替EXE验收。

完成标准：业务能解释“这批新增货预计可售几天”“减少发生在哪个环节”，并能区分现货、在途和历史依据；原业务结果不变。0.44.0已实现并独立验收，范围和证据见本文件开头链接；逐轮趋势首期以表格呈现，未新增折线图。

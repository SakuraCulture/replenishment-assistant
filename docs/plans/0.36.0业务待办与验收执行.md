# 0.36.0 业务待办与验收执行

基线：0.35.1，`35b33de022be33958ec57851f722130feb328d7a`。独立分支 `feat/business-flow-acceptance-0.36.0`。保留旧交付、用户配置与原始业务资料；不自动推送或合并。

## 本轮顺序

1. 固定源码、输入与旧交付；准备隔离资料库。AI 客户端连接及自然语言验收已按用户最新指示暂缓；保留先前尝试记录，不把它计为通过，不继续修改连接配置。
2. 首页增加按环节的待办及明确入口；准备页折叠配置维护；门店页突出当前作业；核对页提供需处理入口和固定关键列；生命周期空态与连续处理明确保持范围。
3. 补验日期、仓、搜索、锁状态、跨页选择与导出范围组合。使用原模型及原导出做逐字段、类型、顺序对照；补充备份恢复与受影响页面性能测量。
4. 固定提交独立构建，实际 EXE 验证，保存报告、截图、清单和校验值。
5. 用户已提供实际已完成采购单，用其中一张核验主单/子单及实收。平台只查询与原生导出；本地记账验证在独立 QA 库。历史采购单缺少本应用原始付款关联时，明确区分真实原件与依据原件重建的验收参考，不冒充真实历史单已经绑定。新版多机部署仍须目标机器实测。

## 不变的边界

- 不更改模型、预算、箱规、准入、原签发、归档结构或导出业务内容及顺序。
- 首页是现有单据/任务的只读投影，不新增“跟进状态”，不把正常预算缺口当阻断错误。
- 页面跳转明确所选范围；跨页不暗中扩大对象。恢复/重试依旧调用原服务。
- AI 相关工作暂缓，保留既有功能与未通过记录，不写正式配置。
- 聚水潭自动网页下单、实际配货回拉、安全升级暂不纳入本轮。

## 证据分层

本轮报告分别列明源码回归、实际 EXE、真实 AI 客户端、真实平台和人工使用体验；未完成项保留原因及最小继续条件。旧版已通过的专项不重复开发，只补本轮影响和已有缺口。

## 2. 目标与保留项

让操作人员随时知道：本次在处理哪些门店和订单、当前卡在哪里、下一步做什么。保留四步补货导航、预算与需求汇总、订单状态卡片、每单下一步入口，以及手动导入和人工核对。

不以减少点击为理由取消签发、回传、付款确认。生成、导出、平台实际下单、实际配货、付款及实收继续明确区分。资料是否适合本批由业务判断，不增加文件新旧自动拒绝或强制刷新。

### 新增 AI 入口的体验边界

0.35.1 顶部“AI 常用业务”采用非模态表单，默认显示业务预览、技术指令按需展开；自动带入准确对象，采用前要求勾选确认。九案例的工具链和实际 EXE 证据见[0.35.1 rc1 报告](../../releases/0.35.1/rc1/交付报告.md)。这降低手工拼提示词的需求，但未做业务人员点击次数对照，也未验证不同 AI 模型对九条自然语言提示词的稳定成功率。现有工具链通过不能替代这两项体验结论。

## 4. 批次与库存的现行口径

以[聚水潭批次库存分配收敛方案](聚水潭批次库存分配收敛方案_20261104.md)和[0.33.0 使用说明](../0.33.0批次库存与处理范围.md)为准：

1. 日期范围只是查单范围；同一天可有多个分配批次。一次明确订单列表、顺序和每仓资料构成一个分配批次。
2. 新批从业务选定的库存起算，不继承其他批次本地预留。允许明确再次选用同一文件，不推断它是否已反映平台扣减。
3. 继续原批、重试及本批重分配沿用冻结依据；刷新列表只查询。更换资料供新批使用，不通过刷新按钮隐式改量。
4. 重复导出不扣库存、不生成付款事实。导出当前筛选与导出勾选分别显示份数；选择整批时说明范围切换。

原体验审查提出的“更新仓资料并重新分配”只是旧版按钮语义建议，现已由上述批次动作取代，不作为另一个开发入口。

## 5. 后续优先级

第一优先：复用已有范围、状态、参数和主动作的专项证据，只补未覆盖的跨页/组合场景；出现新改动再复验受影响部分。先消除可能误选订单或误判完成的问题，不重复开发已交付入口。

第二优先：首页待办重组、付款空态细分及下一步引导、结果页需处理原因、日常步骤②精简。参数维护分组已经交付，不再作为整块待开发工作。按独立小改动交付，不同时改变计算与库存规则。

第三优先：固定关键列、布局密度、缩放和键盘可用性。视觉整理不能隐藏处理范围、关键金额或当前状态。

## 6. 可执行验收清单

下列是完整体验验收条件；未勾选表示尚未取得该条全部覆盖的证明，不否定上表已有专项通过。后续只补缺口并引用原证据，不借历史截图宣布全项完成。

- [ ] 从订单总览分别以勾选、日期范围、仓、搜索及锁状态进入各环节；显示和执行的订单集合一致，不默默扩大到当日全部。
- [ ] 切换筛选后勾选状态和提示一致；导出份数、实际文件集合及文件顺序对应所选范围，隐藏订单不被意外处理。
- [ ] 选择整个分配批次、解除所选限制及返回日期范围时，范围变化清楚可见。
- [ ] 查询结束后不残留表示加载的100%；待回传、待分配、生成失败、零分配和可导出0份分别给出原因与可用下一步。
- [ ] 准备页自动获取入口前置，手动导入仍可用；签发页主动作清楚且保留核对确认。
- [ ] 参数维护的分组、单店/批量和默认/本次语义沿用 0.34.0 已有证据；补验步骤②到参数维护再返回时，人员能辨认当前实际值及需要重算的门店。
- [ ] 刷新列表不改数量、占用或分配依据；继续原批与新建批次能被操作员正确区分。
- [ ] 付款页无记录、筛选无结果、上游尚未完成分别可解释；人工采用生成单与平台实际资料来源可识别。
- [ ] 后续首页待办与实际未完成订单一致；结果页正常预算缺口不被误标为阻断错误。
- [ ] 窄窗口、高缩放、键盘预算编辑与焦点顺序可用；不只用颜色表达状态。对比度和读屏需专门测试，本次未验证。
- [ ] 用同一组合成订单记录改前改后的页面切换、重复选门店及查说明次数；另检查相同业务输入下数量、金额与导出顺序。没有对照数据前不承诺提速比例。

## 1. 结论及核查基线

**当前0.51.3的销售型“断货保底”不符合新增条件。** `sales_floor`允许可用≤0、在途>0但净缺口>0时触发，且BP取`max(普通候选,一箱)`，可以在BI=0时补一箱。已有“正向在途不能突破库存额度”保护只能拦截BK不足的部分情况，BK足够时仍会追加。

当前分支：`feat/first-fill-and-funnel-0.51.4`；HEAD：`edf459b79c271d3a43b76f31d874947f1714471a`。分支名是待开发范围，应用仍为0.51.3、模型执行规则0.3.5-rules；最新固定交付为0.51.3 rc1，构建源码`758ca2b03e651f5b422f0789fc649f7fb01b68d4`，与HEAD的业务源码相同。

核查开始时工作区干净，上一条首铺默认量及经营分析重排请求尚未改业务文件。本次仅增加本方案与隔离QA文件；全部`src/*.py`前后SHA256一致，原版本、默认参数与交付保留。

## 2. 建议的最小业务改动

新增前提建议实现为：**K、L都是有效数，且K==0并且L==0**。这等价于“非负库存下K+L==0”，同时避免负数抵消。保留原有有销量判断、箱规、额度、资金、准入等约束。

不能只裸写`K+L==0`：K=-40、L=40也会成立，明明仍有40在途。K=-5、L=0则总和不是0，建议不触发本条保底；其普通净需求仍按原负库存规则计算，不一并禁补。若业务希望负可用库存按0判断保底，应单独确认，不能把这一口径偷偷混入。

最小完整改动包括四处，不能只改一个条件：

1. `model.py`的`sales_floor`增加上述双零前提。`ordinary=AR if BI==1 else 0`保持原样，不能把新条件包在整个BP/普通需求外面。
2. 同步收紧BQ中“有销量”的最低恢复分支；零月销短期恢复与极端缺货恢复分支保持。否则小额在途仍可借BQ保住一箱。
3. `input_adapter.business_checks`中仅销售型“应最低恢复”断言使用相同前提，缺货零销量恢复的既有断言保留；整箱、非负、额度、资金等校验继续执行。候选试算已实际触发并记录旧校验的误拒，不能靠关掉整套校验解决。
4. 导出理由记录实际贡献来源。只有销售型保底实际把最终量抬高才标“断货保底”；普通需求、独立一箱例外、必采最低持有、零销恢复分别标明。新规则使数量归零时，显示“普通资格未通过/目标已覆盖/库存额度限制/资金限制”等实际原因，不继续显示“动销补货”。

建议新结果保留最小的保底审计字段（双零资格、普通候选、保底是否实际贡献、BQ来源），便于导出与回溯；若采用该字段，只是可选审计元数据，不修改历史签发。正式实施时升级模型执行规则版本并跑回归，不能沿用旧版本标签冒充相同行为。

## 3. 试算入口、参数及方法

实际调用链：`engine.load_records → engine.run_calculation → input_adapter.execute_one → model.calculate → 既有一箱例外 → 既有必采最低持有/预算 → normal_exports.decision/result_semantics.explanation`。没有自行重写预测公式。为展示缺失库存行，加入一条无需求的健康对照SKU，避免整店全无有效行提前终止；对照SKU无必采、无需求、无预算占用。

候选函数从同一份源码在隔离进程内加载，只替换上述销售型BP/BQ及对应销售型校验前提。`src`文件没有变动；离开临时上下文即恢复原函数。比较三种情况：现状、只改sales_floor、完整候选。导出短/长理由使用现有实际函数，未伪造为已经实现的新理由。

上表如B从20变0，现有短理由会由“断货保底”落到“动销补货”；这正是实测发现的展示问题，不能把它当成拟交付文案。建议B/B2显示“普通补货资格未通过，有在途不触发断货保底”；D显示“目标已由可用/在途覆盖”；F1显示“资金约束后未安排”。A2实际靠销售型保底恢复，建议统一标“断货保底”，与F3的“必采最低持有”区分。

## 6. 输出变化、保持不变与实施验收

会变化：有在途或负库存而原靠销售型BP/BQ抬量的行，其BP/BQ/BR/BU/AS、金额、预算候选、下游分配、汇总和签发导出可能减少；同一门店释放出的预算可能重新分配给其他合法候选。理由、最低恢复标记及依赖旧`_inbound_cap`的部分风险提示可能变化。应核对风险提示来源，不能伪造旧保底审计以维持提示。

应保持：预测AN/AM/AP、安全库存AL、净需求AQ、普通资格BI、需求取整BJ、库存额度BK、普通候选AR、主从仓、价格与箱规。在27组试算中这些字段前后一致。C有在途且正常资格通过仍补20；已覆盖目标、缺失库存待核、准入排除、正常预算分配不变。历史签发及已导出文件不重算、不改写。

正式实施需至少增加A–E专项、正负抵消和微量在途、正常资格两分支、额度/资金/BQ穿透、一箱例外开关、必采与预算、导出理由一致性测试；保留取消、旧结果和回滚。旧测试若断言“小额在途必须保底”或必有旧cap审计，应根据已确认的新规则替换为明确的新数量/来源断言，而非删掉完整性检查。再跑适用回归及隔离EXE验收，用户未要求前不发布。

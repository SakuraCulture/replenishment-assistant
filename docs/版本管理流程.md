# 本地版本管理

0.3.0基线：main / 7b8da6b / v0.3.0-baseline。保留既有标签、历史提交和交付包；无远程发布。
根目录验收记录.txt为0.1.0历史，当前基线证据只在releases/0.3.0。

## 日常流程

1. `git status --short --branch` 检查用户改动；`git switch -c feature/功能名`。
2. 修改后更新src/version.json、使用说明和变更说明。应用版本和模型版本分别管理；更改计算规则才更新模型版本。
3. 使用明确输入路径及新的QA目录验证；不得覆盖旧QA证据、业务Excel或本机用户配置。
4. `git diff --check`，提交本次源码。打包脚本只接受干净工作区。
5. `powershell -File build.ps1 -BuildId 候选编号` 从已提交源码构建。版本读自src/version.json，每次构建目录和交付目录独立，已存在即拒绝。
6. 对该EXE运行打包界面验证，核对业务回归、并发等价、输入文件和0.3基线未变。
7. 用assemble.py传入本次构建目录及本次验收报告。工具核对源码提交/版本，生成独立发行记录及ZIP，不借用旧验收结论。
8. 提交发行证据后创建新的带注释标签，例如 `git tag -a v0.4.0 -m "0.4.0 release"`。不覆盖已有标签。记录中保留打包源码提交；标签指向包含发行记录的提交。

## 证据含义

文件清单及ZIP哈希只证明文件完整性。业务回归、EXE交互、可复现构建分别报告；本机成功不等于已验证全新电脑或逐字节可复现。
虚拟环境、build目录、交付目录、QA临时文件及本机配置不进入Git。默认必卖清单是获准随应用交付的业务配置；日后共享仓库需另行确认受众。

## 验证入口

以下使用本项目`.venv\Scripts\python.exe`执行；路径必须指向已获准的测试集，输出目录必须是新的。

```powershell
.\.venv\Scripts\python.exe tools\audit_baseline.py
.\.venv\Scripts\python.exe verify_budget.py --source-dir <测试集目录> --original <原模型目录> --reference <首次验算trial.jsonl> --output qa\本轮\budget
.\.venv\Scripts\python.exe verify_batch.py --sales <补货建议.xlsx> --products <商品资料.xlsx> --output qa\本轮\batch
.\.venv\Scripts\python.exe verify_warehouse.py --sample <分仓资料模板.xlsx> --output qa\本轮\warehouse
.\.venv\Scripts\python.exe verify_workbench.py --sales <补货建议.xlsx> --products <混合仓商品资料.xlsx> --output qa\本轮\workbench
powershell -File build.ps1 -BuildId rc1
.\.venv\Scripts\python.exe verify_exe.py --exe <新包\补货助手.exe> --sales qa\本轮\batch\multi.xlsx --products <商品资料.xlsx> --output qa\本轮\ui
.\.venv\Scripts\python.exe verify_warehouse_exe.py --exe <新包\补货助手.exe> --fixtures qa\本轮\warehouse --output qa\本轮\warehouse-ui
.\.venv\Scripts\python.exe verify_work_exe.py --exe <新包\补货助手.exe> --fixtures qa\本轮\workbench --output qa\本轮\work-ui
.\.venv\Scripts\python.exe assemble.py --delivery <新包目录> --budget-report qa\本轮\budget\backend_report.json --batch-report qa\本轮\batch\batch_report.json --ui-report qa\本轮\ui\ui_report.json --warehouse-report qa\本轮\warehouse\warehouse_report.json --warehouse-ui-report qa\本轮\warehouse-ui\warehouse_ui_report.json --workbench-report qa\本轮\workbench\workbench_report.json --work-ui-report qa\本轮\work-ui\work_ui_report.json
```

预算回归是已知鹿泉数据的固定验收，不可换任意数据后套用断言。批量回归中的第二家门店是明确标注的合成测试，并不冒充真实门店效果。先查看`--help`和输入检查，测试不触碰日常用户配置。


## 0.6.1结构整理的附加门槛

本轮固定0.6.0提交e50072c，原基线包及旧标签仍保留。阶段1/2/3/4各自验证后提交；最终从干净构建源码提交打包。模型、归属及存储格式版本不随结构整理升级。

assemble现在还必须提供 `--structure-report`、`--memory-lxml-report`、`--memory-etree-report` 三份本轮报告；核对提交、源码哈希、零差异与两种XML环境，拒绝旧报告。源码提交、发行证据提交和标签所指提交分别记录，不能混称。

结构对照命令见0.6.1代码结构文档。verify_memory_adapter分别用正常环境及 `$env:OPENPYXL_LXML='False'` 的独立进程执行；后者对应包内排除lxml的环境。原始输入、用户资料及所有旧发行包哈希在最终结构对照中复核。EXE验收使用独立settings，不读取日常用户配置。

此任务仅授权本地提交、打包和标签；不合并main、不推送远程、不发布云发行。

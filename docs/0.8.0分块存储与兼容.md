# 0.8.0 存储后续阶段与定向缺货修正

固定基线：39f49442c66bec6885873f75858514406a43cf45（已交付0.7.4）。分支 perf/chunked-storage-0.8.0；不合并、不推送，不覆盖旧交付包。

用户授权：在阶段1基础上完成阶段2分块存储及旧格式兼容、阶段3按需读取、阶段4迁移回滚/性能/EXE验收。缺货修正只处理 N>30 且 J>0；不取消零月销缺货恢复，不应用13天硬兜底，不扩大新品池。

## 已完成的定向修正

model.py 保留原N，只有上述冲突输入在预测计算中使用有效N=0，并记录原因。日/周/月销量、销量窗口异常独立回退、权重和公式不变。84,693条归档记录逐条对比，13条命中、最终量无变化，其他所有计算字段一致；合成趋势案例验证修正确实生效（28→42）。模型版本为0.3.1-rules；应用版本0.8.0。

## 阶段2：不可变内容块与双格式读取

- 现有SQLite内新增内容块表，SHA256标识不可变规范JSON块；清单覆盖完整结构、字节摘要和块引用。旧zlib/JSON记录继续读取。
- 规范JSON、日期标记、字段类型和列表次序保持。完整读取校验各块与整体SHA；按需读取校验清单及实际读取块，不能伪称完成未读取块的校验。
- 数组及大字典每256项一个块，未变块不重复压缩/写入。草稿和归档复用相同内容；没有有损字段投影或数值转换。
- 同日确认、预期修订、归档事件及内容块在同一事务发布。失败回滚不留下已发布的半份作业。
- 首次新格式写入前用SQLite backup保存完整升级前副本；不自动转换所有历史，不清理历史块，不覆盖备份。
- 旧EXE不能直接读新格式记录。阶段4提供向独立路径导出旧格式完整副本；不得把旧EXE直接指向升级后的库。
- 阶段2验证：qa/storage_080/stage2/report.json（新旧格式、规范JSON、损坏拒绝、块复用、失败回滚、备份和CAS）；qa/storage_080/normal_stage2/normal_report.json（原正常单/新品/预算/导出回归）。

## 阶段3与阶段4

阶段3已完成：覆盖核对只读取参数/来源版本，复制配置只读取门店设置；历史商品投影和已签发导出只读取所需结果字段。固定修订绑定，完整读取入口保留。qa/storage_080/projections/report.json：同一合成归档全读232块、导出投影33块，Excel完整值/类型/顺序/样式一致；未访问块损坏由全读检出，投影不冒称全库验证。io_controls_stage3和selected_controls_stage3验证进程取消、重试、修订冲突、回滚和进度。
阶段4实现：首页“存储维护 / 旧版兼容副本”。仅生成新路径；全记录回读校验，保留正常单号、修订、事件和参数表；转换中取消不发布，已有目标拒绝覆盖。支持EXE命令行 `补货助手.exe --storage-copy legacy 源.sqlite3 新副本.sqlite3 --report 新报告.json`，`upgrade`生成完整分块副本。此命令也不修改源库。

旧版回退：关闭所有补货助手，保留当前库和备份，用维护功能产生的旧格式副本创建独立资料目录（`workbench.sqlite3`），通过 `REPLENISHMENT_DATA_DIR` 指向该目录启动旧版。目录中的商品资料/必卖配置等其他文件也应从完整用户目录副本取得，不要跨版本同时写同一库。新模型结果在旧版只读，历史导出保留当时结果；继续计算使用相同参数重新算。自动备份是首次分块写入前的数据库快照，不包含之后的新作业；回退且保留后续数据应生成旧格式副本。

分块存储没有后台自动全库迁移或GC：旧记录按原格式保留，新保存写内容块。不同修订可共享相同块；未变字段仍须遍历编码以获得完整摘要，未宣称所有操作瞬时完成。完整恢复仍须读取全快照及传输；投影校验不能证明未访问内容没有损坏。异常掉电/强制杀进程可能留下未发布的临时副本，原库不受转换影响。

预跑发现并修正：原型将商品编码字典拆成约18万单值块，导致约29秒SQL查询开销；最终将大字典按256条分块；完整恢复拼接经过逐块校验的规范JSON后只解析一次，复用解析器的字段名字符串，避免逐块重复分配。保留预跑报告，不使用其时间作为最终收益。正式性能报告按新旧交替各三次，完整动作计时包含spawn、IPC、签发核对与写出；内存为50毫秒采样主进程加所有子进程RSS，共享页重复计数。OS文件缓存未清空，不外推其他电脑。

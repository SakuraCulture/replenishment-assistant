# 0.35.1：AI 常用业务与提示词

打开补货助手顶部 **AI 常用业务**，选择要完成的事情，填写门店、任务或商品，点击 **复制并返回工作台**，到 Codex / WorkBuddy 粘贴发送。无需记工具名、参数路径或自己拼提示词。

首次使用先到 **AI 协助 → 启用本机连接**，按《0.35.0AI协助使用与结构》添加客户端连接。本页仅生成提示词；点击复制不启动业务任务，不自动发送给外部 AI。

## 九个场景

| 场景 | 人员需要确定 | AI 执行结果 | 对当前作业的影响 |
|---|---|---|---|
| 开工检查与参数核对 | 当前勾选门店，或准确门店编码 | 数据登记、预算、实际参数、需要处理的事项 | 只查询，不代表已经完成文件校验 |
| 按当前参数试算 | 门店及顺序 | 独立试算、各店金额及异常 | 不替换原结果 |
| 比较两种备货天数 | 一家店、供货仓、两个天数 | 两次试算、金额差及商品数量变化 | 只改指定店指定仓的备货天数，其他参数不变 |
| 核对结果与异常 | 具体 AI 任务 | 各店结果、待核、风险及待办 | 只查询 |
| 解释某商品为什么补 | AI 任务、门店、仓、商品编码 | 当次销量库存、参数和已计算过程 | 不重复计算、不改量 |
| 复查历史签发原因 | 完整补货单号、仓、商品编码 | 当时快照及缺失依据 | 不用当前资料补写历史 |
| 继续失败或停止的门店 | 原 AI 任务 | 沿用原快照重试失败/停止门店并汇入原批次 | 不改变成功门店，仍不采用 |
| 停止任务后续门店 | 正在进行的任务 | 当前门店安全结束，后续停止 | 已完成结果保留 |
| 采用已核对的试算 | 已完成试算，并勾选“允许采用” | 采用到本次工作台 | 尚未保存草稿或签发 |

推荐第一遍：先选两家测试门店，执行“开工检查” → “按当前参数试算” → “核对结果” → 看一个商品原因 → 满意后单独选择“采用”。保存草稿、签发、导出仍在原页面完成。

## 人员需要知道的边界

- 普通预览使用业务名称。完整提示词自动附带作业标识与工具调用约定，需要时才展开查看。
- 门店编码精确匹配，按选中/填写顺序处理；同名门店不由 AI 猜。比较和商品解释只接受一家店。
- 选择任务时显示时间、门店、状态和编号短码，复制内容保留完整任务号。只提供当前会话仍可用的任务，旧日志不冒充仍可恢复的结果。
- 作业、参数变化后，旧提示词不能继续用于采用或新计算。刷新页面后重新复制；复制时也会复核。勾选门店变化同样要求刷新。
- “采用”必须勾选确认；切换任务、切换场景或刷新都会清除该勾选。当前有新品安排、人工改量、过期或准入变化时，仍由原接口拒绝并要求核对。
- AI 不应使用终端、脚本、SQL 或浏览器绕过接口。页面不是自动执行器，不在应用内调用模型，也不新增 AI 费用配置。
- 页面为非模态窗口，打开它不会使后台接口被“等待弹窗”阻塞。复制时不执行任务；不要把“已复制”当作“已完成”。
- 多页结果必须分页读取。未读完必须说明范围；未知金额不能当作 0。重试沿用原快照，不新建替代任务来绕过过期检查。
- 临时结果仍受原有会话和缓存限制：最近 3 个计算根批次、最近 5 个检查预览。退出前需要的正式工作仍须保存草稿。

## 代码与验证

提示词及范围校验：`src/automation_playbooks.py`。界面：`src/automation_playbook_ui.py`。顶部入口：`src/automation_ui.py`。

本次不新增 MCP 业务命令，仍是原 12 个工具；模型、预算、箱规、签发、生命周期及导出算法不变，模型版本保持 0.3.4-rules。

可复跑命令（使用项目依赖齐备的 Python；输出目录必须为新目录）：

```powershell
python -m unittest discover -s tests -p 'test_automation*.py' -v
python tools/run_automation_ui.py --out qa/ai-recipes-new --codex-client
python tools/run_automation_ui.py --exe '交付_0.35.1_rc1/补货助手/补货助手.exe' --out qa/ai-recipes-exe-new --codex-client
python tools/verify_ai_playbooks.py freeze --qa qa/ai-recipes-compare-new
python tools/verify_ai_playbooks.py before --qa qa/ai-recipes-compare-new
python tools/verify_ai_playbooks.py after --qa qa/ai-recipes-compare-new
python tools/verify_ai_playbooks.py compare --qa qa/ai-recipes-compare-new
```

九个业务案例通过真实 stdio MCP、Qt 工作台及 Windows 计算子进程重放，并与原业务服务逐行核对；实际 EXE 另测。`playbook-report.json` 保留案例、工具请求/结果和生成的提示词，`automation-report.json` 保留原接口回归与客户端检查。合成数据明确标注，不使用用户日常资料库。

验证范围须区分：工具链重放与 Codex 实际 MCP 客户端调用，不等于各 AI 模型都能稳定理解每条自然语言；首轮未做 Codex/WorkBuddy 模型对这九条提示词的多次成功率统计。提示词包含范围和步骤约束，最终采用仍靠原接口校验。完整结果见本版本交付记录。

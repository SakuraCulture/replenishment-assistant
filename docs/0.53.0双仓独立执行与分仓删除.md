# 0.53.0 双仓独立执行与分仓删除

本轮改变签发、执行和删除的仓单范围，不改变补货计算规则。应用 0.53.0，模型仍为 0.3.6-rules。

## 业务操作

1. 参数中的单仓/双仓、主仓/从仓、资料来源和主从顺序照常设置。按原配置计算，包含原预算分配及商品归属。
2. “确认签发”或“确认签发并导出”选择本轮执行的门店及仓。双仓店可以只勾河北、只勾山东，或两仓一起。未选仓不会转为地采、待核或未完成订单。
3. 同一天、同一计算方案，先签河北后可补签山东；未变仓单不增加仓单修订。仅另一仓修订变化，不使已经签发仓单的回传、付款和分配失效。
4. 过几天另一个仓供货时，新建当天业务任务，采用当天资料重新计算，再选该仓执行。不会自动把几天前的销量库存当成今天的数据。
5. 订单跟踪删除时只处理明确选中的仓单。选择两仓才删除两仓；单选一仓保留另一仓的身份、历史、已保存单据及共享批次成员。外部平台订单不会因本地删除撤销。

永久删除的同日同仓身份不能由旧草稿、旧任务或隐式全选恢复。需要再次开展该仓业务时，应新建业务任务。正常回传更正仍走原生命周期入口。

## 数据与兼容

- 原父单仍承载完整计算证据；新增按 `oid + warehouse` 的生效仓单及独立投影快照。仓单签发序号与原来源修订分别保存，原 Excel 隐藏身份仍能定位原签发依据。
- 首次写入旧父单前，在同一事务保存其各仓历史；只读查看旧资料不会初始化新表。未选仓的商品数量、路由和预算不重算。
- 历史、付款认单、生命周期、导出恢复、经营分析、货盘和 AI 解释读取各仓自身生效快照，不能使用另一仓更新后的父单当前修订替代。货盘共同地采和待核只计一次，并说明执行范围。
- 永久删除裁剪全部历史版本中的所选仓行、SKU 业务注解和关联链接；共享原表、供货配置、共同预算审计及仍被其他单据引用的文件保留。无逐订单金额归属的采购原始行不猜测拆金额。
- 共享任务和库存批次按稳定身份裁剪；删除代次阻止旧草稿、晚到工作结果和旧命令恢复已删除仓单。组件以主库已提交证明执行纯本地分仓退役，失败留待办，不查询平台。
- 完整迁移带入新表。新增合并仍按原父单完整关联图去重和冲突隔离：本机已存在父单时，不静默补入另一仓；重复导入不重复新增，删除标记防止旧包复活。
- 新版资料使用独立仓单元数据。保留旧 EXE 和恢复副本；旧版不能作为新版资料的并发写入者或回退写入工具。

## 验证边界

只使用隔离合成资料，不迁移、删除真实业务数据，不调用真实平台。回归覆盖单仓首签、同方案补签、两仓不同来源修订、共享分配、单仓删除、晚到回写、旧草稿、原修订补导出、Excel 身份、混合回传、合并迁移、取消和跨库回滚。实际 EXE 另验真实窗口操作、生成文件及退出重开。

本次未调整模型、数量、箱规、最低持有、预算、商品归属或默认并发。不承诺性能提升；新增仓单快照按现有内容块去重保存，空间和耗时仍受历史规模影响。

最终测试数量、失败留证、实际构建来源及交付路径以独立交付报告为准。本轮不提交、不推送、不合并，也不自动替换正在使用的软件。

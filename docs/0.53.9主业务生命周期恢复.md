# 0.53.9 主业务生命周期恢复

本轮在0.53.8主线之上修复核查已复现的取消、再次确认、分配切换与提交后收尾问题，并给回传、运营签发、付款、收货增加原保存任务的就地恢复。独立包的实际通过范围、性能数据和剩余限制以本版交付报告为准。

## 业务如何继续

| 遇到的情况 | 在哪里处理 | 恢复实际做什么 |
| --- | --- | --- |
| 取消采购排队后，同一预览再次确认无反应 | 翱象批次中的确认上传，或恢复并继续原任务 | 衔接同一原执行和采购包，先查原状态；不另建采购身份 |
| 同批有已受理项，还有未开始项 | 取消未开始部分后，点已受理行的继续核对原受理结果 | 只恢复该行原结果核对，其他已取消项不重启 |
| 明确要恢复被取消的原未开始项 | 翱象批次中的恢复并继续原任务 | 明确重新排入原任务范围，成功项保留 |
| 首次分配前失败，原批也停了 | 新版会按持久的本次切换记录恢复；旧任务可在原分配批次中恢复分配状态 | 仅恢复本次造成且未被后来人工改变的控制状态，不全局激活暂停批次 |
| 分配已保存，但最后批次状态写入失败 | 生成窗口或原批结果页的恢复分配状态 | 核实已保存清单，补齐控制状态；直接导出原结果，不重新扣库存 |
| 回传、运营、付款或收货保存中断 | 本环节页面、批量导入页的恢复入口，或显示与帮助中的恢复并继续原操作 | 核对原完整批次。已保存时返回原结果，未提交时恢复原核对内容，再按原校验原子保存 |
| 签发已完成但文件没导出完 | 恢复窗口中的签发与导出原任务恢复 | 沿用已有确切修订恢复导出，不重新签发 |

恢复页按所选订单查找，但会明确展示原完整保存批次。整批原子保存规则保留，不能静默删掉其中失败单再保存剩余单。若只想另行处理一单，请回到导入页重新明确范围和核对。批次的筛选条件不等于恢复保存范围。

## 保留的业务边界

不修改模型、箱规、最低持有、预算、数量、金额、仓库归属或默认并发。分配仍使用冻结资料和原顺序，失败仓的后续成员不越过前序消耗库存。自然转运营、自然转付款和普通文件导入都沿用原校验。

已提交的付款、采购、实收事实不倒退。原上游、签发修订、本环节版本、文件摘要或删除代次发生变化时，恢复会具体提示重新核对；不强制绑定、不跳过完整性校验、不猜测结果未知的请求未被平台受理。外部平台单据不会由此撤销或重建。

旧版勾选重试生成入口已停用并解释下一步，防止把单选扩大为整批后台执行。当前正常界面仍使用明确原批、原范围的分配入口。

## 恢复资料与资源影响

回传等保存前，在当前数据目录的`lifecycle_recovery`子目录留存小型身份记录及压缩的必要预览。预览不包含重复的展示差异、重复签发商品及可跨进程信任的读取证据。恢复时重新读取并核验原单，完整性和业务校验保持。

数量未变化的保存只记录小型状态，不压缩整份预览。保存完成并写回回执后，清理本次临时预览，只留下任务身份和保存结果。失败时保留原始异常和必要预览，便于再次恢复。不会为每次点击复制整个数据库，不在启动时加载这些商品明细。

不增加或改写业务表结构。新侧目录不影响旧版本读取已有业务单据；旧版本没有新版恢复入口。整个数据位置搬迁会随目录保留；完整订单迁移包沿用既有导出白名单，不把未完成的本机保存预览带到另一台机器自动执行。性能与内存开销须以本版新旧实测为准。

删除订单后清理对应恢复预览；原原子保存批次中若包含被删仓单，则不再回放其剩余子集，未选订单的业务单据保留，可重新核对有效范围。晚到回执不能重新发布已删来源的恢复材料。清理失败保留诊断，可由已有原件清理流程重试，不把业务已删除误报成尚未删除。

## 历史记录与限制

0.53.9之前的回传等失败没有本次操作前检查点时，不能凭空恢复未保存的编辑内容，应按原件或已有单据历史重新核对。采购已有的原任务号、分配步骤、库存预留、原批成员及签发导出回执仍可核实后继续。

恢复能力不包含：给冻结执行批次任意追加成员、自动作废平台采购、强行回滚已收货单据、清锁文件或绕过仍在运行的实例。隔离模拟验收也不代表业务机已经在线验证。

# 0.45.0 货盘结构分析

## 怎么用

打开“订单跟踪 → 货盘结构”，选择日期和门店，点击“查询货盘”。这是已签发历史的只读分析，不需要重新计算。计算完成后的“核对与签发 → 查看本轮货盘”提供签发前汇总预览，不把预览当作正式历史。

默认查看结束日的现货大盘；切换在途、现货＋在途后点击查询。可选“各店最新”，界面列明依据日期，不能当作同一时刻库存。多轮按门店和日期列出，不把库存跨轮累加。

大盘分成中心仓、地采、来源待核。中心仓再分别查看启用／备用／禁用和必采／非必采；两组是不同维度，不能互相相加。禁用、停采、淘汰、拒收、资质受限、有库存但补货0的商品仍在货盘中。

双击门店轮次，展开当时商品及变化，显示该店逐轮趋势。明细可组合来源、仓、状态、必采和商品搜索；双击商品查看中文估值公式、上轮数量与价格、变化贡献。橙色趋势点表示范围不完整或估值有待核，前后不连线。明细筛选不会暗中改变上方全查询大盘。

两个导出入口分别是“查询范围汇总”和“查询范围及全部商品明细”，名称中的查询范围指已成功查询的日期和门店，不是尚未点击查询的新条件，也不是下方商品筛选。汇总四张表；详细版多一张“商品与变化明细”。旧五段经营分析Excel不变。

## 金额到底是什么

- 门店持有库存按制单时归属仓基本售价估值，不是大仓库存，也不是采购成本。
- 现货=当时可用库存×单价；在途=当时在途×单价；总持有=(现货数量＋在途数量)×单价。
- 当前标准资料缺少可靠地采单价。实际缺价地采显示“未计价”，并单列款数；不取另一仓价格、不猜0、不把部分金额说成完整大盘。
- 已计价货值是已知部分；完整货值在任何数量无效或正库存未计价时留空。明确0库存货值为0，仍保留缺价提示。负库存、未知单位、冲突SKU不静默合并或截0。
- “计价覆盖率”=有效正库存SKU中成功计价的款数比例，不是金额覆盖率。
- 每轮使用门店父级完整结果一次，双仓分单不重复计价；只证明“本次导入范围”，不能由记录存在推断全店齐备。
- 必采按当时清单，缺依据是“属性待核”；商品状态只接受原值启用、备用、禁用，其他值待核。

## 上轮比较

前一有效业务日可在查询开始日期之前，界面仍列出具体上轮日期。同日只统计当前有效修订一次。共同且单位、数量、价格都有效的商品：

数量影响=(本轮量－上轮量)×上轮价；价格影响=本轮量×(本轮价－上轮价)。两者之和等于共同可比集合的货值增减。

首次出现、未提供、单位变化、缺价进入／退出估值范围分开提示。来源／仓／状态／必采迁移按本轮货值单列，其维度彼此独立。减少不等于销售、增加不等于模型多补。未提供记录不推断库存清零。

历史仅引用冻结快照；当前资料更新不回填历史。部分仓被删除会标“不完整范围”，整单删除后不能从分析缓存重新出现。签发或删除状态改变后，导出和AI立即拒绝旧依据；页面可见时每30秒校验并清空旧显示，重新查询即可。

## AI使用

新增三个能力，不增加签发、采购、删除或改默认权限：

1. `workbench_context`核对环境。
2. `query_inventory_structure`传新的operation_key、context_token和query：from/to日期、stores精确编码（可空）、view=stock/inbound/position、overview=end_day/latest。
3. `task_status`等待完成，按after续查；已受理不等于完成。
4. `inventory_structure_results`按next_offset分页，limit不超过100。默认rounds，返回完整口径、计价覆盖与轮次摘要。
5. 需要商品时，新的查询同时传`detail_store`和`detail_day`，在后台载入这一轮，然后分页读取level=detail。不在MCP请求线程里解码大快照。
6. 人员明确要求后，`export_inventory_structure`指定task_id、snapshot_id、context_token、operation_key和本地directory；include_details控制是否附商品明细。

页面提供可复制业务指令。AI必须先说明缺价、缺轮和日期，再解释资金结构；不以货值变化自动判断销售、滞销、采购或模型错误。

## 结构与边界

`inventory_structure.py`负责纯指标、冻结只读读取、两轮比较和失效校验；`inventory_structure_exports.py`负责独立Excel；`inventory_structure_ui.py`负责后台查询与按需明细；`automation_inventory.py`适配既有任务协议。所有出口共用同一指标版本`inventory-structure-1`。

SQL先取轮次元数据，每店仅解码当前和前一轮；不将百万商品全部塞入汇总页面。明细按一店一轮后台读取、每页100行。数据查询不写用户数据库、不新增维护表、不解析最新商品Excel、不重跑模型。不使用多进程并行写库。

当前明确限制：地采实际价格字段/单位契约尚无可靠业务依据，因此缺价地采保持未计价；未提供分析专用价格导入UI。历史源表未标可靠更新时间时留空。首期趋势展示所选门店大盘已计价部分，未提供来源堆叠趋势、另一仓原表弹窗和独立筛选明细导出；来源/状态/必采可在摘要、组合筛选及Excel中核对。当前预览仅汇总，正式历史才有商品追踪和导出。未把这些限制伪装为已完成。

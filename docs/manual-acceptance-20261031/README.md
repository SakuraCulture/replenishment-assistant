# 业务人员手工验收包

本包用于亲自跑通 **补货出单、订单跟踪、决策复查、参数设置** 四条主干。全部为虚构数据，不含真实门店、用户数据库或原业务Excel。

**下载 [业务验收练习包.zip](业务验收练习包.zip)，完整解压后打开 `从这里开始.html`。** GitHub若显示二进制预览，请点 Download raw file。只查看说明可直接打开 [38条用例](用例索引.md)。

业务人员不需要Python。需要已有完整的Windows补货助手交付目录（EXE和_internal一起保留）。本包不自带EXE，也不更新软件。

## 怎样开始

1. 关闭已打开的补货助手，双击 `开始补货练习.cmd`，首次选择已有补货助手.exe。入口会给这个练习单独设置数据目录和导出目录。
2. 按 A01–A08 从导入到分仓签发走完。新品关注清单的业务月份选实际测试月份；现算单使用实际当天日期。
3. 关闭练习，双击 `开始生命周期复查练习.cmd`。它复制预置四张 **2026-10-31** 分仓签发到新练习，不修改原种子。
4. 点“全部未完成（不限日期）”，按 B01–B04 批量导入回传→付款→收货；完成后切“全部记录”，日期包含2026-10-31。
5. 对照 `05_预期结果/逐商品核对答案.xlsx`，在 `业务验收记录.xlsx` 写实际结果和证据。38项默认均为“未执行”。

同一个“开始”入口会继续原练习；“新开”入口另建干净练习，旧练习保留。目录均在解压包的 `练习记录` 下。可以在“导出设置”核对配置文件位置，必须指向本练习。不要直接打开日常EXE导入测试文件。

预置回传文件只对应预置单号，不能混给当天现算单。不要把逐单文件和混合三环节文件一次全选：二者是替代演练方式，会形成同单同环节多份候选。

## 材料与数字

| 内容 | 数量 / 用途 |
|---|---|
| 练习甲店、练习乙店 | 2店 × 16商品 = 32条销量库存输入；反向主从仓 |
| 两仓商品资料 | 河北15行、山东14行；含禁用/无货/缺价/缺箱规/未知分类 |
| 原签发参考 | 4份，店仓分别导出；由现有0.17.1代码生成 |
| 逐单生命周期 | 回传4份、付款4份、收货4份 |
| 混合生命周期 | 1个工作簿、3个反序工作表、12份来源单 |
| 异常练习 | 同店同品冲突、负数、未知单号、额外商品、同单第二份、列顺序变化、无号13列付款 |
| 业务用例 | 38条，含前置、具体操作、成功标准、记录位置 |

四张签发的数量依次为110 / 36 / 17 / 133；已计价金额186 / 108 / 34 / 345元。甲、乙各一款缺价，明确待核，不能把缺价视为0成本。付款文件是另一组虚构业务事实：缺价商品的付款单价假设2元，不回写商品资料。

## 验证证据与已知限制

- [核查结论](核查结论.md)：冷索引、增长、版本、回归分层及参数治理的当前证据和建议。
- [0.17.0用例文件验证](validation-0.17.0.json)、[0.17.1用例文件验证](validation-0.17.1.json)：四仓22条签发候选，逐单/混合结果行、顺序和数量一致；非法文件、手工绑定、原件字节、原签发表不变均有断言。
- [EXE检查记录](EXE检查记录.md)：实际0.17.1隔离打开、四仓单、历史入口和退出；不是完整38条人工验收。
- [文件校验清单](package-manifest.json)：完整包文件哈希及ZIP哈希。
- 0.17.0同名签发导出尚不具备0.17.1覆盖修复；A09在旧版标为不适用/已知旧问题。
- 小数据不能检验大文件停止窗口或一年历史性能；用例C06记录本机实测，不预填10秒或19.7秒。历史旧版本兼容和模型全量真实数据回归不是这套小包的替代品。
- 本次仅测试资料与核查文档，不修改业务逻辑，不替换既有EXE，不合并主线，不上传0.17.1应用分支/标签。

## 开发人员复跑

解压ZIP到一个新目录，使用项目规定的Python依赖环境。`--out` 必须是独立QA目录。下面只读包内种子，实际导入写入随机命名的QA数据库副本：

```powershell
.\.venv\Scripts\python.exe docs/manual-acceptance-20261031/prepare_pack.py verify --source . --package 'D:\测试\业务验收练习包' --out qa/manual-recheck
```

`--source .` 在此文档分支验证云主线0.17.0；验证0.17.1时将 `--source` 指向固定提交7360b03的独立解压目录（src必须完整），无需切回或覆盖主线。报告标明实际读取的软件版本。

用例Excel由 `build_workbooks.mjs` 使用artifact-tool制作；重建需要该库运行环境，消费已交付文件与上述验证不需要它。`prepare_pack.py inputs` 生成输入规格，先写输入Excel，再 `seed` 生成真实计算签发和生命周期规格，再写生命周期Excel；`make_guide.py` 生成38项说明与验收记录规格。不要在已有练习包上重跑seed，使用新空目录。实际发行签发参考由现有normal_exports生成。

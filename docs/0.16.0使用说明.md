# 补货助手0.16.0：门店回传、付款与收货核对

本轮从0.15.1升级，计算模型仍为0.3.3-rules，原签发建议独立保留。原商品资料、作业、签发、归档导出和默认导出目录用法不变。

## 日常使用

1. 工作页计算并确认归档后，订单已经签发。山东、河北按仓独立关联。
2. 导出门店确认单（即签发单）发给门店；门店直接修改“补货数量”。保留原工作表、商品编码、补货单号和仓库，回传后在首页下一步入口或订单生命周期中导入“门店回传单”。支持选择文件和拖拽。
3. 预览中核对原签发数、门店确认数、差额，以及“明确填0 / 空白按0 / 缺行按0”。筛选只影响查看，保存仍是整单。确认完整单据后，三种情况有效数量均为0，来源区分保留。整单没有导入不当作0。
4. 选择对应店仓订单，导入“门店付款单”。可直接使用现有13列表头：内部订单号、线上订单号、店铺名称、买家账号、下单时间、平台站点、商品编码、商品名称、箱规、数量、商品单价、商品金额、辅助码。一次处理一张来源订单；付款多单批量导入暂缓。
5. 付款数量对照回传要货数大于0的商品；商品金额直接作为支付金额留存，数量和回传单位一致，不乘箱规。无需另加门店编码、单位或付款时间。下单时间仅作为原表字段留存，不替代实际付款时间。
6. 到货后导入“门店实际收货单”，以付款数量大于0的商品核对。模板可以下载；也可通过字段映射导入已有表。

付款/收货也区分明确0、空白和缺行。非法数量、缺数量列、公式没有缓存值或错单会提示错误，不会当作0。清单外商品须额外核对。空文件不会自动表示整单不要货；需要时可用对应的“整单全部0”独立操作并确认。

## 更新、历史和导出

- 每次保存独立版本，原始Excel可以下载；回传、付款、收货不覆盖签发数。
- 上游改版后，下游数量仍保留原值，首页提示重新核对。按回传→付款→收货顺序重新核对，保存新版本并绑定新的上游版本；不自动替换旧依据。预览后依据被其他窗口修改，提交会拒绝，须重新预览。
- 后环节先收到可以保留待核，补齐上游后重新核对。上游未就绪时，不生成缺行0。
- 回传全0提示无需付款和收货；付款全0提示无需收货。不伪造后续单据，也不增加人工跟进状态。
- “门店回传单”导出沿用签发三张表及格式，写已确认数量，保留归零商品；签发建议始终保留在原签发单。
- “门店付款单 / 门店实际收货单 / 生命周期对照”独立导出；对照表查看四环节数量和差额，原始依据单独下载。
- 支持选中多张订单后分别导出，或同仓合并多单；山东、河北不会混在一张确认单中。导出前显示所选订单及文件范围。没有阶段数据不生成假0单。
- 同仓合并回传单不允许同时含同一订单的多个修订，以免相同单号产生歧义；这类历史版本请分别导出。

## 兼容与本轮限制

旧生命周期记录按原口径读取。使用新规则重新核对会生成新版本，不改写旧历史。0.16.0新增环节记录格式为schema2；旧程序不能读此新格式，回退时须使用旧资料/安全备份，不能让旧程序继续写新版数据。作业分块格式仍为2。

付款原表适配已按截图的13列表头实现；实际ERP原Excel尚未提供，同表头合成样本不等于已验证全部真实ERP文件。金额不擅自按模型价重算，原单未提供币种时保留未提供。

商品资料保存时点见随包《商品资料保存链路_0.16.0.md》。默认导出位置只决定导出落点，不迁移用户数据库和仓资料。旧包保留；正式验收和校验值见源码目录releases/0.16.0下本次交付报告。

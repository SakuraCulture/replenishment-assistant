# 0.12.0 历史批量独立导出

以0.11.0 / d7387d0815f96a65f8b22be25a3c1febd4cf8f16为固定基线。模型仍为0.3.3-rules、仓归属0.5.0、业务存储格式2。本次不重算、不修改历史建议、不迁移日常数据库。验收证据以releases/0.12.0/rc2为准。

## 使用

进入历史归档，在查询条件下方使用三个独立入口：导出完整计算表、下载商品资料原表、导出签发建议。先勾选仓单，支持本页、全部查询结果、跨页勾选和已选明细。更改查询条件会清空选择。刷新后已不在查询范围或修订已变化的选择会移除。

计算表/签发建议支持“分别导出”和“合并导出”。分别模式每个日期、门店、仓库、修订一个文件；合并模式每仓一个文件，同一张明细表包含多个订单。选择河北6单、山东4单，分别是10个文件，合并是2个文件；不会把两仓混在一张表里。每个文件只包含这一类内容。

身份列固定在左：业务日期、门店编码、名称、仓库、单号、修订。各订单内的原始商品与分组顺序不变，不跨单累加SKU。共享全店预算重复展示用于核对，不可按行或按仓相加。历史缺失字段留空，不能当0；字段并集不拿当前参数补历史。

商品资料默认下载原始Excel字节，保留原文件全部工作表、公式、样式。可分别复制，或选择同仓同SHA原件只下载一次。确认面板和导出清单列出所有关联订单。原表状态“已留存（导出前校验）”只表示库内有原件，导出前会校验内容哈希。未留存、损坏均不能冒充成功。

如选择“多订单资料核对表（加工表）”，按精确商品源行展开原字段和列序，只包含选中订单涉及的商品。公式以原文字显示。它不是原Excel全表，不保留原文件全部样式。缺少原行绑定时拒绝该单，不猜测匹配。原件和加工表的名称、提示明确区分。

旧的“当时商品资料快照”详情表单改为原表下载入口；不再把核对项目/当时值/类型导出成原表。参数等其他核对表单明确标记“非原表”。单据详情及操作记录均提供三个独立入口。工作页加盟商确认单不变。

## 失败、取消和历史保护

导出前核对确切修订、行数、文件数量及不可用项；默认不导出缺失部分，需显式勾选“仅导出可用部分”。每次新建任务目录，不覆盖旧文件。分别导出时单项失败不阻塞其他单；合并时每仓文件是完整发布单位，任何单据失败均不发布该仓半份结果。

后台展示核对单数、写入行数、压缩保存阶段和用时。取消停止后续文件，不强杀写入，当前安全阶段结束后退出；已经完成的文件保留，未完成文件不发布。完成页可打开目录及按原修订重试失败/取消项。Excel压缩、快照解码和单个原文件读取暂不能实时中断。

回收站单据需先恢复。历史原件缺失无法自动修复；同名当前文件不能替代原件。本版本不会改写用户历史来补资料。文件组织偏好保存在资料目录archive_export_ui.json，独立于门店参数及历史快照。

## 代码与验证入口

- archive_batch.py：精确修订读取、准备预览、原件校验、分组、顺序流式写入和原子发布。
- archive_batch_ui.py：多选、独立入口、预览、结果与重试。
- archive_exports.py：既有计算字段和签发行生成共用；三表函数仅保留给旧内部调用，界面不再提供三表总按钮。
- history_read.py：派生索引版本3补充原件状态。旧缓存自动重建，业务数据库不迁移。
- application_window.py、history_ui.py：列表、详情和操作记录接入。

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -O -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools\verify_warehouse_exe.py --exe '交付_0.12.0_rc2\补货助手\补货助手.exe' --fixture qa\verified_092\fixture\payload.json --output qa\batch_archive_012\另一个新的EXE验收目录
```

便携单测自行生成Excel/SQLite，不依赖Qt或真实业务文件；实际EXE验收使用已冻结合成夹具、独立settings，两次启动，另行标明真实业务对照，不把合成记录当真实业务。

限制：合并超过Excel容量时拒绝，不自动截断或拆sheet；导出串行，不引入并行导出。首次查询需重建派生索引，较旧大库仍有冷加载成本。先后核对与写出各读一次精确快照，以控制跨批次内存；本版本不承诺所有大批量操作提速。

# 补货助手 0.34.0：参数分组与预案

本版以 0.33.1 的 c125e4b4d06e61131c351e62be2bef0fabf2163b 为基线。模型仍为 0.3.4-rules，不改变系统默认值、模型计算、预算、箱规或签发规则。交付验收以 releases/0.34.0/rc1 为准。旧包保留；本次不推送、不合并。

## 参数放在哪里

| 内容 | 入口 | 生效范围 |
| --- | --- | --- |
| 备货天数、到货天数 | 参数设置 → 设置所选门店补货参数 | 每个门店、每个仓独立 |
| 快销、日百等分类权重与分类超参 | 同上 | 每个门店独立，两仓共用 |
| 通用超参 | 参数设置 → 设置所选门店通用参数 | 每店可自定义；不维护即系统默认通用方案 |
| 商品分类到分类组的映射 | 参数设置 → 全局分类映射 | 全部门店一份，不按门店维护 |
| 门店名单及预设参数 | 参数设置 → 补货预案 | 明确采用后作用于本次名单 |
| 主从仓、预算、补货策略、资质、拒收 | 参数设置 → 其他门店设置 | 各自维护，不随补货参数表改变 |

## 最少操作

- 设置一家店：双击该店，或勾选一家后点击“设置所选门店补货参数”。
- 批量设置：搜索门店 → 勾选当前筛选 → 设置所选门店补货参数 → 勾选要改的字段 → 核对 → 保存。未勾选项保持各店原值；不同门店的值显示“多种值”。
- 单独维护通用值：勾选门店 → 设置所选门店通用参数。可直接点击“全部采用默认通用方案”，核对后恢复；分类专用值保持不变。
- Excel 导入：下载完整门店参数模板 → 填写 → 拖入“导入完整门店参数” → 核对 → 选择保存默认、应用本次，或两者都做。
- 使用预案：补货预案 → 新建 → 勾选门店并拖动确定顺序 → 设置需要采用的补货参数/通用参数 → 保存。准备数据页选择预案，再按原流程导入、计算。预案不会自动取数或签发。

“保存默认”只影响以后；“应用本次”使变化门店的结果失效，需重算。选择两者时，对两份配置分别修改所选字段，不把本次的其他临时修改覆盖到默认。历史签发始终使用原快照。

## 模板与空白

新模板使用分类参数 V3 标识，可调换列顺序，按表头识别。

| 模板 | 数据页 |
| --- | --- |
| 完整门店参数 | 分仓周期、分类参数 |
| 门店通用参数 | 门店通用参数 |
| 全局分类映射 | 全局分类映射，仅商品分类、目标分类组，不填门店编码 |

门店模板中，空白、缺列、缺行保持原值；`0` 是实际数值；填“系统默认”才恢复。分类专用参数的“系统默认”表示沿用该店通用值。没有默认记录的新门店从系统标准开始。全局映射是完整表替换，未列出的商品分类不再映射；导入只填表单，明确保存才生效。

旧 V2 模板继续保留“已有参数列空白恢复系统默认”的原含义；更老的混合表空白保持。不会按新含义悄悄解释旧表。旧表含门店分类映射时，导入界面阻止整批应用，提示把映射移到全局入口单独核对；去除该表/列后，其余旧参数仍可导入。

未知分类、无分类跟随快销以及其他原业务规则不变；未新增数值转换或改变参数允许范围。

## 全局映射首次使用与历史

首次读取检查已保存的门店默认：全部一致时可作为统一参考；不一致时不取第一家，不修改旧数据。全局映射页面可查看所有旧门店的映射差异，选择起点、编辑，保存前再次核对逐店差异。

尚未统一的冲突会阻止新作业计算并指向该入口。保存全局映射只影响新作业；已载入作业需点击“应用已保存映射到本次全部门店”，确认差异后再计算。恢复的历史作业仍使用旧映射快照。共享映射可整表编辑、导入、导出和下载模板。

更新映射时并发复核映射版本及门店默认；预览之后被其他窗口更新会拒绝保存。原始门店配置不被批量回写。快照中记录所采用全局映射的版本与摘要，供追溯。

## 默认、分类与预案的生效关系

1. 新作业先取得该店已保存默认，没有则取系统标准。
2. 若采用预案，仅将预案明确勾选的参数应用到本次，其他值保留；映射统一使用全局依据。
3. 本次明确编辑的字段在应用后生效。
4. 到货/备货周期由各仓周期决定。分类专用超参优先于本店通用值，未设置专用值则沿用通用值。

没有增加隐式“参数方案引用链”：计算前装配成一份完整配置，计算只使用这份快照。标准值不可被表单覆盖写坏；恢复默认是明确的表单动作。旧完整方案库保留在“变更记录 / 恢复”下供兼容查看、复制；新日常设置通过分组入口。

旧补货计划兼容读取，旧计划没有字段选择记录，仍保留其原有完整参数选择；采用时映射取全局。旧作业中已采用的旧计划不被重新解释。编辑旧计划时显示参数选择，业务可缩小范围；新预案默认不选任何参数，只选择需要带入的项目。

## 结构与存储

```mermaid
flowchart LR
  UI[分组编辑 / 导入 / 预案] --> PATCH[所选字段与差异校验]
  PATCH --> DEFAULTS[门店默认]
  PATCH --> CURRENT[本次完整参数快照]
  MAP[全局分类映射] -->|新作业或明确应用| CURRENT
  DEFAULTS -->|新作业| CURRENT
  CURRENT --> CALC[原模型与预算计算]
  CURRENT --> HISTORY[草稿与历史签发快照]
```

- `parameter_maintenance.py`：可编辑字段、定点修改、通用默认、全局映射版本及预案选择字段装配。
- `parameter_maintenance_ui.py`：批量/单店表单、混合值显示、全局映射核对。
- `parameter_tables.py`：V3 新模板和 V2/旧表兼容；`global_mapping_io.py`：独立映射表。
- `parameter_scene.py`：业务入口；`store_parameter_ui.py`：差异预览、并发保护、持久化后再更新本次。
- `workbench.py`：新检查装配映射，恢复历史保持快照；`replenishment_plans.py`：预案字段选择与采用。

SQLite 仅新增 `global_category_mapping`、`global_category_mapping_events` 两表；在明确保存映射时创建，并沿用安全备份。预案增加可选 `parameter_fields`。核心参数字典、旧 JSON、作业块存储和历史签发格式不迁移；应用版本改变，模型/参数配置/作业存储版本不变。

## 业务人员试用

1. 两店原山东仓周期不同，仅批量改河北仓备货天数：山东周期、分类值、预算都应保持。
2. 一店通用概率 95%，分类概率另设 99%；恢复通用默认后，分类 99% 仍在。分类改成沿用门店后，才使用通用概率。
3. 新模板某列留空、填 0、填系统默认分别导入，检查“保持、数值零、恢复”的差异；无效参数整批不应用。
4. 设置只保存默认，本次已载入参数不应跳变；新建检查才带入。选择两者应用时，临时预算等未选内容不应进入默认。
5. 预案只选一个仓的备货天数，采用后检查其余参数各店仍不同；名单顺序与预案一致。
6. 全局映射修改保存，旧作业和签发不变；明确应用本次后，变化门店需重算。

可复跑验证：`python -m unittest discover -s tests -v`；`python tools/verify_parameter_workspaces.py freeze --qa <新目录>`，随后 before、after、compare 使用同一 QA 目录；实际 EXE：`python tools/run_parameter_workspace_ui.py --exe <EXE路径> --out <新隔离目录>`。完整报告提供每次命令、差异与限制。本机正式配置不会因本次开发自动迁移或注入。

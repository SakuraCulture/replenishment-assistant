# 0.15.0 订单生命周期与交互方案

基线：0.14.0 / 0ffb88abb2f5d1fe5ae00287c5770ce33dbccdb1。应用独立升级，模型仍0.3.3-rules，安全依赖升级暂缓。验收结果另见 releases/0.15.0 对应构建记录，本文件不代替验收。

## 业务口径

工作页负责准备、参数、计算、核对和确认归档。确认归档成功即已签发，不再添加“模型推荐”或“待签发”生命周期阶段。

```mermaid
flowchart LR
  A[工作页计算与核对] --> B[确认归档：已签发]
  B --> C[导入门店确认单：门店回传]
  C --> D[导入门店付款单：门店付款]
  D --> E[导入门店实际收货单：门店实际收货]
```

签发单与对外加盟商确认单是同一份业务单据，界面统一称“门店确认单”。四个数量分别为门店推荐数（签发时）、门店确认数、付款单商品数量、实际收货数。预测、候选、预算中间值仍在计算依据中保留。

每个业务日期、门店、仓库的订单独立追踪，关联到确切签发修订；河北与山东不混用。更版签发不自动承接旧版下游资料。旧实际下单资料不等于付款资料，保留独立历史入口，不自动转成付款。

不设置部分单、暂缓跟进、恢复跟进、已跟进等人工工作状态。首页只显示最早缺失的单据和对应导入动作。后环节先到可先存，前环节仍提示补齐；数量差异单独展示，不决定环节是否完成。缺失单据不阻塞工作页的新计算。

## 整单导入与数量

每次导入为所选仓单某环节的完整版本，更新不按增量累加。批量可包含多单，每单明确绑定一个签发修订，无拆分分摊。预览显示旧/新数量、来源、遗漏商品和额外商品；用户确认整单范围后才能保存，默认取消。已提供行的数量必须明确为有限非负数；空白数量不能自动补0。未出现的商品保持“本阶段未列出”，不视为0，也不因与原建议不同变成“部分单”。零数量整单可通过明确填写0记录。

门店确认单可读取现有导出格式（补货数量/补货单号/商品编码及文件修订信息），也可使用最低标准模板。付款与收货使用相应模板或显式字段映射：付款须提供付款日期、付款单号、商品数量及实际金额；金额按源单记录，不使用模型价格推算。不同币种不合并成一个总额。收货记录实际数量、日期、收货单号。数量使用库存单位；其它单位需要显式换算系数和依据。模板不含伪造的示例业务行。

## 界面分组

- 首页：待回传、待付款、待收货、已收齐四个互斥计数；每单列出三个单据是否已导入及最早下一步。日期/门店/仓/单号查询，分页50，批量勾选导出生命周期对照。
- 工作页：保留原计算流程。按钮统一“导出门店确认单”，辅助提示会确认签发并自动归档。
- 订单管理：保留现有历史查询/回收站；“订单生命周期”放三个固定导入按钮；“数据导出”保留三个原有独立入口；维护操作独立。
- 单据详情：四阶段数量对照；“订单生命周期”三个导入；“单据与依据”查看各阶段版本、原件及签发计算依据；“数据导出”确认单/付款单/实际收货单与生命周期对照。旧版回传/实际下单资料单列在历史兼容入口。
- 每个导入窗口支持多文件拖拽、文件选择、最低模板下载；明确显示阶段、门店仓单和修订。没有数据的导出按钮禁用，不输出空造单。

## 存储与边界

新增独立生命周期版本、原文件及事件表，不迁移、不覆盖旧签发、每日作业、回传、采购或跟进记录。旧完整回传可只读识别为已回传；旧部分资料显示“已有旧回传资料，请导入完整门店确认单”，不增加部分阶段。旧备注不再影响待办。

预览绑定签发digest/当前修订/回收站token及该环节旧版本。保存前重新校验原文件SHA；持锁后复核，冲突整批拒绝。准备与等待锁可取消；短事务最终写入不可强杀。原件和全部旧版本保留。取消可能产生安全备份，不宣称数据库文件完全未触碰。

不改变模型、预算、新品、仓归属、在途保底或原有导出单元格/样式。新增付款/收货/生命周期对照导出单列，不混入原确认单或计算表。

## 实施与验收

1. 独立单据服务、整单校验、版本/原件、旧资料只读兼容；便携测试验证空值/零/漏行/差异、顺序、并发、取消、修订和仓隔离。
2. 首页与订单管理分组，固定镜面命名、下一步引导、拖拽模板、版本查看/独立导出；移除人工跟进入口。
3. 固定0.14.0对照真实计算、组合与原导出；实际EXE验导入/取消/错误/更新/重启/导出；新目录打包，记录构建提交和SHA，不合并不推送。

限制：尚未取得真实付款/收货ERP文件，先验证标准模板和显式映射，不声称所有外部格式可自动识别。原件首行表头；公式需已缓存，不推测单位、单号、付款状态或修订。同一文件表头完全相同的页默认一起读取，明确列出范围，兼容确认单的往期新品/本月新品/动销三页；不同表头的页需另选映射，不自动混读。

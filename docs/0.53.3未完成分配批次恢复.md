# 0.53.3 未完成分配批次恢复

“所选订单已有未完成批次，请继续原批或明确撤销”表示本机曾建立分配批次，所选订单仍有等待或失败任务。它不表示没有仓库存，也不能仅凭提示认定任务已经失效。原保护用于避免同时重复分配；此前新批预览只有错误弹窗，缺少就地恢复入口，容易使业务无法继续。

## 业务如何继续

1. 正常关闭旧软件，解压独立0.53.3包，打开新目录的补货助手.exe。资料沿用原位置，不初始化。
2. 订单跟踪 → 聚水潭导入单 → 勾选本次订单 → 准备新分配批次；照常选用本批仓资料，点击“预览库存分配”。
3. 若存在原批未完成项，页面列明原批次、所选仓单、门店、仓和任务状态。
4. 要沿用原批库存：选择原批，点击“继续此原批剩余N单”。先预览该原批全部剩余订单及其冻结库存、原顺序，确认后才生成。它不是刷新仓库存。
5. 已决定按当前新资料重做本次所选未完成项：点击“结束所选未完成项并重新预览”。只结束上表列出的未完成任务；保留已生成单、未选单及库存记录。原批其他未完成项暂停，之后可按原批继续。本次重新预览仍不生成订单，核对后再点“确认生成”。
6. 不确定选哪条路线：点击“返回，不改动原批”，查询原批及实际仓资料后再处理。

若核对期间其他任务已提交、暂停或状态变化，显示“原批任务已变化，未结束任何任务；请重新预览并核对”。本次不清理部分任务，也不跳过写锁。

## 安全与影响范围

处理为本地批次任务状态变更，不调用聚水潭或翱象，不撤销外部订单，不删除仓单，不覆盖回传或付款。所选项的旧执行预览失效，晚到执行必须重新校验；不能恢复已结束项。保存生成及导出仍走原入口，需求、箱规、库存不足时尾数分配、价格、顺序、模型及默认并发保持。

rc2按用户新增要求，将商品状态“备用”加入分配允许名单，与“启用”等已允许状态采用相同库存、箱规和预留计算；禁用、停采、日配等现有排除逻辑保留。业务电脑原库未被读取或修改；本次能确认是代码中的未完成批次拦截及恢复入口缺失，不能据截图判断现场原批为何中断或该批是否仍在运行。

0.53.2的单进程组合回归原生异常、0.53.1偶发purecall仍是已知未关闭问题，本修复不声称解决它们。

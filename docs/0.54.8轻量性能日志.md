# 0.54.8：轻量性能日志

默认记录，业务无需提前开启。出现慢、卡顿或资源异常后，打开“显示与帮助 → 轻量性能日志（近24小时）… → 导出近24小时性能日志”，把生成的ZIP发给排查人员。正常关闭软件后也会保留最近日志，重开可导出。

每5秒采样主程序和至多16个直接持有的Python/翱象/聚水潭组件进程；不扫描全机进程，不读取外部Edge页面、请求或账户。采集CPU时间、私有提交、驻留、逻辑I/O、系统可用内存和提交额度、界面心跳延迟。保存、核对、签发、导出、回传等通用后台任务，以及组件请求，记录总耗时和固定分类阶段耗时。没有逐SKU或逐行磁盘记录。

原始记录自动清理24小时前的日志文件，合计最多16MiB；忙碌时会提前轮换最旧文件。导出严格筛选近24小时的有效记录。正常每5秒批量写盘，无逐行flush/fsync；队列最多256项，活动操作最多32项。日志自身的CPU时间、已写字节及丢弃/错误计数也会记录。日志目录不可写、资源计数失败或队列满时，丢弃诊断记录，不修改业务结果或阻断业务提交。

日志位于本机控制目录的diagnostics/performance内，与可搬迁的业务资料目录分离，避免记录线程占用原资料目录。此小目录上限16MiB。显式导出时，后台先尝试刷新刚结束的操作，最多等2秒；刷新不成功仍可导出已有记录，并在摘要中标明，业务操作不等待这次刷新。

不记录商品、门店、金额、单号、文件路径、业务参数、SQL、请求/响应、Cookie、账号或原始异常文字。进度文字仅映射为固定阶段名和数字进度，不保存原文。ZIP只包含说明、精简环境、性能记录和摘要，不能顺带打包app.log、数据库或浏览器资料。

CPU cores=1表示用满一个逻辑核心。私有提交不是物理内存；多进程驻留相加可能重复计算共享页。逻辑I/O包含管道读写，不代表物理磁盘吞吐或等待。5秒采样可能漏掉短峰值，短操作另记总耗时。并发、嵌套操作的耗时不可相加作为总耗时。阶段分类属于诊断线索，不构成自动根因判断；GUI主线程被阻塞时，后台采样和心跳延迟记录仍可提供线索。崩溃/断电可能丢失最后约5秒尚未落盘的记录。

记录线程只做诊断，使用有界内存和临时打开的日志文件，不触碰业务库。退出阶段停止记录，不创建Qt窗口，不保留浏览器、业务数据库或进程句柄，不改变实例保护、迁移、业务数量、金额、顺序、校验、并发或整批提交规则。

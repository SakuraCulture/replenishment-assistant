# 0.6.0 每日作业与完整参数方案

按用户批准的设计实施。标准方案沿用0.5已验收规则；应用提供可维护配置，不自动引入历史试验。完整参数中文名、单位、影响和调整提示以`src/parameter_schema.py`为单一来源；原model/input_adapter/one_box_exception/allocation及两份默认JSON不改。

## 日常操作

1. 新建今日作业，添加补货建议并检查；或从“作业记录”打开当天快照继续。
2. “门店与参数”中设置主从仓、预算；点击门店参数按钮选择完整方案。内置“标准补货v1”包含所有超参、两类权重、分类映射、两仓周期和一箱例外。
3. 在“各仓周期”维护该店真实备货与到货天数。模型超参页的通用depth/lead只展示，明确由各仓周期覆盖；极端缺货30天固定展示。w3自动计算，不能直接编辑。
4. 参数窗口提供作用解释、方案默认值和本店调整标识。“仅用于本次”不改门店默认；“保存为本店默认”供重启和下批复用。主表也能保存所选店完整配置，含方案、预算及主从仓。重新检查本批输入时保留当前店配置。
5. “复制另存方案”保存完整配置；“保存方案新版本”递增版本，旧门店和作业仍引用旧值。标准只读。归档仅移出可选列表，不删除已引用内容。自定义配置的业务效果需试算，不标成已验收最优方案。
6. 可在参数窗口对所选门店做同快照试算，显示金额、缺口、变化SKU及分箱规的预测持有天数分布；不自动覆盖正式结果或作业。试算完成后仍需明确应用和正式计算。
7. 计算完点击“保存作业”。首次日期直接保存；同日已存在必须确认覆盖。列表每天一条，覆盖整个当前作业而非当前筛选。弹窗展示减少、增加、完成变失效的门店及完整差异；取消默认，取消不丢当前结果。
8. 保存门店默认与保存作业互相独立。计算不自动保存默认或覆盖作业。关闭/新建时未保存变更会询问。

## 快照与日期

按中国标准时间记录日期。跨午夜不自动改日期，保存时选择原日期或转为今日；目标日存在仍须确认。历史日期及不兼容模型的记录只读，可查看有效结果并导出；复制配置用于今日不带旧销量库存，需添加今天数据。

作业保存当时完整已检查输入、仓资料、必卖清单、各店生效参数、结果和状态，原文件移动后可恢复查看、在兼容模型下重算及导出。包括冻结的旧混合商品资料快照；已保存的重复冲突可从快照继续选择。未检查输入只是文件引用，仍需原文件。

打开记录不自动使用当前资料。点击“使用当前资料重新检查”才刷新仓资料和必卖清单，并按当前输入文件重新检查，原结果失效。失败、未运行、待重算留空，不作为执行金额0。支持保存部分完成和准备中状态；计算运行中禁止保存。

## 保存可靠性与配置迁移

数据库为本机设置目录中的`workbench.sqlite3`。每日日期唯一；压缩JSON快照带摘要校验值；事务完整替换。界面确认对应当时修订号，若另一窗口抢先保存，旧确认不能覆盖新内容，需重看差异后再次确认。无永久同日完整历史副本。保存失败原记录保留。

现有预算和主从仓JSON只作为没有新配置的门店的回退来源，未删除或覆盖；保存新默认后以SQLite完整配置优先。过去未持久化的周期无法找回，使用标准值，不伪造历史。用户数据和数据库不入Git、不上传云端。

配置优先：完整方案→门店配置→本次修改。商品资料的明确补货模型分类优先于分类映射；缺少对应权重时待核，未知分类按无分类快销。计算时在选仓之后重新应用每店权重，确保界面修改实际进入计算，并发不串店。单店及批量导出记录实际生效配置与方案版本。

## 验证入口

`verify_workbench.py`验证逐店参数实际效果、真实14244行标准方案等价、方案版本、每日唯一、覆盖确认令牌、并发修订冲突、事务写失败回滚、无源文件恢复及试算不污染。
`verify_work_exe.py`验证真实EXE参数编辑/另存方案/保存门店默认、每日覆盖取消/确认、重启恢复、只读历史和未保存退出。
原预算、多店、分仓及其EXE验证继续运行；发行归档必须提供七份同源码提交、同版本报告，三份UI报告绑定实际EXE哈希。

限于当前阶段：没有云同步作业、自动覆盖、自动优化参数、推荐稳健/敏感新算法方案、库存预占或订单下发。标准方案已有旧算法基线；本机配置保存和UI功能另以当前发行验收为准。

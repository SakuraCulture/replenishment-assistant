# 0.50.4 补货建议重导与采集恢复

## 业务怎么操作

正常获取仍可复用今日已验收原件；“继续原采集任务”沿原任务号查询、下载和保存。明确没有点击提交的菜单异常自动恢复一次；有可靠原任务号的可恢复异常也只接续原任务一次，不制造新导出。

需要获取新文件或旧采集长期待核时，在“获取翱象补货建议”上方勾选门店，点击 **重新导出所选门店**。范围确认只有一次，默认取消。确认后结束所选旧项、保留原记录与原件，再建立独立的新导出；无须先去平台核对或取消旧导出。旧平台任务仍可能完成，可能多出导出文件。

“结束本次采集”可以结束受理未知、缺失回执、部分失败和已受理未完成的本地采集。当前页面动作先安全暂停；不等待平台生成完成，不强杀写入。结束不等于删除记录，也不撤销平台任务。删除记录仍单独确认。

部分重导只处理勾选门店。同批其他任务身份、顺序、结果保留；原先运行的其余项在安全退役后继续，原先暂停的不会自动启动。取消重导确认不退役、不派发新导出；准备时若已安全暂停，可用原继续入口恢复。

## 缺货率分析

在“门店缺货率 → 采集与快照”的门店表中选中行，按 Ctrl 可多选，点击 **重新导出选中门店**。新建分析修订，沿用当时分析供货设置和已冻结仓资料；未选且已完成的门店复用原快照，未完成门店继续原任务。原分析记录、日报和原件保留，新修订完成后才按现有规则发布。

此入口用于当日作业。历史观测不能混入今天的库存；历史作业使用“重新采集今日资料”建立今日数据，或“用留存原件重算”离线重算。聚水潭仓资料尚未留存的作业继续沿原仓任务恢复，不新增无依据的仓资料。

补货和缺货率分析分别登记采集用途、拥有者和当前原件；共享浏览器仍串行操作。一个板块的旧采集不长期占住另一个板块，也不会被另一个板块的重导隐式结束。旧版任务按本机原始上下文登记用途，不按店名或日期猜测。

## 实现边界

- 本地退役在组件事务中保存，所选 run 保留持久失效标记；run/item/attempt、文件发布及命令项回写均检查失效。旧回执只追加到旧任务证据，不改变其状态、原任务号或新任务。
- 组件重导预览按商家、用途、门店限定范围，确认 token 检测变化；应用端在组件退役回执后才创建新不可变命令。回执丢失可查询并重复确认同一退役操作。
- 新任务原件使用独立 `.collections/<run_id>/` 版本目录，应用采用仍使用独立 `command-files`。当前缓存与原件分开，旧版晚到发布不能倒退当前指针；已退役保存现场留档，不阻塞新版本。
- 已有原件、草稿、签发、采购和收货数据不会由重导自动替换。模型、预算、箱规、默认参数、仓归属和缺货率公式均不改。
- 商家/门店、实际查询范围、任务与文件行数、关键字段、编码精度、文件 SHA 校验继续执行。登录或商家异常停止后续平台操作；一店受理未知保留该项，其余门店各自重新检查范围后继续。
- 没有浏览器配置、输出盘不足、状态库损坏、原任务归属不明，仍会明确停止；不清空库、不伪装成功、不通过“最新任务”猜测匹配。

## 验证与升级

隔离测试、实际 EXE 结果与限制见本版交付报告。模拟平台等待不能当作现场提速；本轮不访问真实平台，不删除业务数据。业务端请等当前动作安全结束后正常退出旧版，完整解压新包运行，无需初始化资料或重新绑定登录。

# 0.47.3 分析供货设置与名称显示

缺货率分析采用“参数设置 → 已保存门店配置”里的主从仓。0.47.2及之前的分析采用入口错误地只读取旧的独立供货缓存，可能漏掉已保存的门店设置，导致没有采集仓资料、供货来源和虚拟分类全部待核。本版修正读取来源，只读取所选门店的供货字段，不初始化、更新补货业务库，也不加载历史作业。

## 使用

1. 正常退出旧版，完整解压0.47.3交付包，运行其中的补货助手.exe，旧包保留。
2. 在“参数设置 → 已保存门店配置”核对各店主仓和从仓。只修改本次作业的临时参数不等于保存默认。未配置的门店不按地区猜仓。
3. 进入“门店缺货率”，点击“选门店 / 采用补货侧设置”。列表同时显示门店名称、编码和单仓/主从顺序；保存后用“查看已采用供货设置”逐店核对。
4. 再创建新的分析采集。采用设置只影响新任务，旧日报、旧任务仍使用原先冻结的设置。“继续原任务”不会偷偷替换旧任务依据。需要更新后的分析时应创建新任务；不能用今天仓资料冒充此前观测日依据。

页面会显示已取得供货关系的门店数。缺供货设置的门店可以保留全量销量/库存统计，但仓、供应商和虚拟分类分层待核，需保存默认后重新采用。分析资料与补货资料继续独立，参数后续变化不会自动回写分析，分析也不会修改补货设置。

## 供货与资料规则保持

| 设置 | 判断与资料取用 |
| --- | --- |
| 单仓 | 只看选定仓；该仓无该商品按本次地采，不借未选仓资料 |
| 双仓 | 先主仓；主仓禁用、无货或无该商品时按原规则转从仓；主仓有商品而从仓无该商品时保留主仓资料 |
| 最终归属仓 | 类目、供应商、虚拟分类取该仓同编码商品，不把两个仓的字段拼在一起 |
| 整份所需仓资料缺失 | 分层待核，不等同于仓中没有该商品，也不直接归地采 |

补货模型、仓归属规则、预算、箱规、必采及标签识别规则没有修改。门店缺货仍按“月销>0且可用库存=0 / 月销>0”；负库存保留原值与异常，不自动当作0或改为“库存≤0”。

## 名称与编码

切面、商品明细、筛选提示和分析Excel同时展示门店名称/编码、商品名称/编码。汇总和筛选继续按编码，同名不同编码不会合并，同编码跨日/跨店名称不一致时显示提示，具体名称见明细。名称来自分析已留存的快照，不读取当前商品资料覆盖历史名称。

本版结果与边界见[交付报告](../releases/0.47.3/rc1/交付报告.md)。源码测试及EXE使用隔离资料，不调用真实平台；此前已发布结果不会因升级而自动修复。

本轮窗口验收还发现并以确定性用例复现了结果接收时序：子进程在等待超时后刚好返回结果并退出时，主进程可能漏收结果而显示异常退出。现先收取已返回结果再判断；真正无结果退出或明确失败仍报错。失败记录保留，不自动重放采集或采购。

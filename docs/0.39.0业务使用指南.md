# 0.39.0：看漏斗、复盘缺货、试算安全库存

## 日常经营分析（不用 AI）

1. 首页点击“经营分析与报表”，或“订单跟踪 → 经营分析”。
2. 选签发业务日期；可按补货计划带入门店范围，或填写精确门店编码。仓、必采属性、分类组均可筛选。点击“查询”才应用筛选。
3. 先看必采/非必采五段货值，再双击门店 → 仓 → 订单 → 商品。未导入显示未确认，不能解读为0；“资料待核”单独核对。
4. 选择“门店经营对比 / 订单漏斗明细 / 当前商品明细”，点击“导出当前范围”；订单页支持多选和跨页选择，用“导出所选订单”。导出全部筛选页，不只当前100行。
5. 常查范围可保存为固定日期或滚动日期视图。报表进入已配置的默认导出目录；未配置时选择保存位置。

五段为自动模型建议（含启用的例外、总预算前）、最终签发、有效门店回传、已确认付款数量、有效实收数量。聚水潭仅生成或仅导出不算实际下单。统一签发价比较货值，实际付款行金额及原单合计分别保留。

门店禁采/拒收、对应仓禁用及“虚拟分类”中的已核实标杆淘汰系列，从五段统一排除。未知淘汰词不猜；缺少当时原件不能拿当前商品资料补历史。必采沿用当时必卖清单，清单未留存时单列属性待核。

## 多轮缺货复盘

选择“多轮复盘·近90天”，默认最近8轮（不同签发业务日）。先查前一轮在哪一段减量，再看当前库存和在途。同SKU跨仓保留每轮来源，同日重复依据存在歧义时不强行归因。

“上一轮都落实、这一轮仍缺”只形成预测或保护期疑点，仍须核实到货时间、销售变化和其他出入库。月销是滚动窗口，不能相减伪造期间销量；收到过货不证明准时收到。

## 本次安全库存与资金诊断

1. 在可编辑工作台完成文件检查与参数核对；进入“④核对与签发 → 缺货与资金诊断”，或经营分析页的同名入口。
2. 选门店、分类组、小档变化。只调库存目标分位概率；“上下各2.5个百分点”例如95%→92.5%/97.5%。整个店预算重新分配，两仓共用分类参数。
3. 试算默认不采用。先看门店最终执行货值、必采货值与缺口，再查箱规/单件覆盖、逐商品增减和风险。保护期不变，不能仅因金额低就认定更好。
4. 选择完整候选、填写原因；若增加软风险须勾选已核对风险。关键待核或作业已变化不能靠勾选绕过。确认默认取消。
5. 采用仅影响本次参数和结果；按原流程保存草稿或签发。未再编辑/保存/签发时可以撤回，永久默认和历史不变。

已有人工改量、新品安排的门店须先回原页核对，本版不清除这些安排后假称节省。也不支持把不同候选商品拼成一个未经重算的结果。

## AI 与 CLI

在“AI协助”启用连接。经营分析页“复制AI分析指令”带入最后成功查询的范围及工作台上下文；复制不等于发送或执行。

常用调用链：

- `workbench_context → query_order_funnel → task_status → order_funnel_results`；按 `next_offset` 读取，单页最多100。
- `export_order_funnel` 导出同一 `task_id + snapshot_id`；`store_history_review` 读取多轮证据。
- `start_stock_diagnosis → task_status → stock_diagnosis_results`；人员明确候选和原因后 `adopt_stock_diagnosis`，可撤回时 `undo_stock_diagnosis`。

参数含义仍用 `parameter_definitions`。`steps=[-0.025,0.025]` 是百分点增减，不是最终概率。每次新查询/试算用新 `operation_key`；状态未知查原任务。不自动签发、采购、保存默认、删除或上传报表。连接不可用不要读取数据库绕过接口。

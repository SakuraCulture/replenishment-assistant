# 0.36.2 底部浏览器连接状态

主窗口右下角固定显示三项：翱象、山东仓、河北仓。切换首页、补货出单、订单跟踪、决策复查和参数设置后仍能看到。

| 状态 | 含义 | 使用建议 |
| --- | --- | --- |
| 绿色「已连接」 | 对应浏览器连接及组件拥有的作业页面仍在 | 可以继续原业务操作 |
| 灰色「未连接」 | 当前没有建立对应连接 | 需要使用时到原连接窗口连接 |
| 黄色「连接中」 | 当前正在建立连接 | 按浏览器提示完成授权并等待 |
| 黄色「待确认」 | 组件尚未就绪、状态查询超时或返回不完整 | 可进入对应窗口检查，不自动重发任务 |
| 红色「已断开」 | 已有连接的进程、浏览器连接或作业页面断开 | 到对应窗口检查，需要时主动重连 |

约每 3 秒更新。状态同时使用文字与颜色，鼠标悬停可看说明。绿灯仅说明浏览器连接存活，**不代表网站登录有效、门店核验通过或业务任务完成**。电脑休眠、网络中断等可能要等连接层检测到断开后才反映；页面登录过期需要原业务检查。

状态灯只观察已有连接。首次打开软件不会为了亮灯启动组件、打开浏览器或触发远程调试授权；查询失败也不会自动重连或重复提交导出、采购。它不是另一个操作按钮，连接和重连仍在原业务窗口完成。0.36.1 的跨窗口连接保留行为继续生效。

## 实现边界

- `src/browser_status_ui.py`：全局状态栏；后台轻量查询，每个组件最多一个在途观察线程；超时 1.5 秒；迟到的旧连接回复不会更新新连接。
- 翱象 `browser-worker.mjs` / `browser-connection.mjs`：监听已有浏览器和作业页关闭事件，通过现有 IPC 发送状态；`session.health` 只读本地状态，不新建浏览器连接。
- 聚水潭 `service.mjs` / `job-store.mjs`：`session.health` 读取账号及已有会话状态，不克隆全量历史任务，也不排在业务下载队列后面。
- 退出主窗口前结束观察线程，再执行原有安全关闭。取消关闭后恢复观察。两仓状态独立，某仓故障不改另一个仓的状态。
- 没有修改模型、预算、箱规、仓归属、默认参数、业务记录或导出格式。

## 可复跑检查

在仓库根目录使用锁定 Python 环境，输出均放独立 QA 目录。`freeze` 只能对新目录执行一次：

```powershell
$py = '.\qa\v0350\locked-venv\Scripts\python.exe'
& $py -m unittest discover -s tests -v
& '.\components\aoxiang\runtime\node.exe' --test components/aoxiang/test/*.test.mjs
& '.\components\aoxiang\runtime\node.exe' --test components/jst_catalog/test/*.test.mjs
& $py tools/verify_browser_indicators.py freeze --qa qa/v0362_repeat
& $py tools/verify_browser_indicators.py before --qa qa/v0362_repeat
& $py tools/verify_browser_indicators.py after --qa qa/v0362_repeat
& $py tools/verify_browser_indicators.py compare --qa qa/v0362_repeat
```

实际 EXE 的状态灯验收使用 `--browser-status-smoke <新输出目录>`，须设置 `REPLENISHMENT_DATA_DIR` 为隔离目录。该验收模拟连接状态，用于检查真实 Qt 与 EXE；实际 Edge 断开和连接复用由 `tools/verify_browser_connection_retention.mjs` 在临时浏览器配置及本地页面中验证，二者的证据不混称真实平台登录验收。

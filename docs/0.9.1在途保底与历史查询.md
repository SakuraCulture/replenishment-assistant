# 0.9.1 在途保底与历史查询

固定基线：`364929c69ed16d933d5dffaff7c2424323730af0`（已交付 0.9.0 rc2），分支 `fix/inbound-cap-history-0.9.1`。应用 0.9.1、模型 0.3.2-rules；参数、作业、存储格式不变。最终打包验收以 `releases/0.9.1/rc1` 为准，不以源码测试代替 EXE。

## 本次规则

- 正常可计算、L>0 且库存额度启用时，保底后 BP 不得超过原 BK。沿用现有库存额度日均及 cap_days（标准为 21），不改成预测日均限额。
- 同一目标的后续一箱例外不再自动补回；即便可用大于0、没有进入BP保底分支，一箱例外也不能给已有在途的库存额度拦截重新放行。此边界在本批旧结果中没有命中商品，增加合成测试防回归。仅资金约束的原例外不扩张修改。L=0 的最低持有、箱规倍数、极端恢复原分支保持。禁用/停采和总预算仍可限制执行，不能把“双零持有”解释为越过这些原有规则。
- `_inbound_cap` 保存原保底量、允许量、额度天数及原本会形成的建议量；重新计算先清除此标志，避免旧审计带入新输入。BP>BK 只能来自一步长保底；原保底是否进入最终建议由原月销退出门槛/BQ 门槛决定，不重跑全模型生成归因。
- 校验器同步区分双零最低持有与已有在途限额，并明确拒绝已有在途的建议超过 BK。
- 风险提示不参与任何数量、金额或预算计算。只提示本次确实削减建议且现有量不足 `3.5+AH` 的商品；3.5 是下一轮复核情景，不是 AG 参数替换。没有实际在途 ETA，不保证期间不会断货。负可用在风险数量筛查中按 0，但原值不修改。
- 当前真实批次 10 店 164,722 行，306 条中间值命中、64 条执行变化；240,467.53→237,962.58，减少 2,504.95 元；提示恰好 5 条。其他记录的数量金额不变，双零 5,567 条记录保持原样。

## 使用

1. 新版本重新计算后，汇总“提示”栏显示“在途衔接风险 n 条”；点该栏直达商品筛选。商品页也可选择“在途衔接风险”，点商品看覆盖缺口和核对建议。这些商品仍为 0，不自动补回。
2. 历史归档支持业务日期、门店和多关键词组合。例如 `塔谈 卫生巾`；回车立即查询，“清空条件”恢复全部。查询不改变记录顺序。
3. 打开历史单，选择商品后点击“查看参数 / 所选商品依据”或双击商品。左侧按名称/编码搜索、点选；右侧切换当时参数、销量库存、商品资料、完整计算依据。无需记住或手输长编码。Ctrl+F 聚焦商品搜索。
4. 每个历史窗口拥有独立读取进程，主页面刷新不会取消子窗口读取。切换只接收最新请求，关闭回收该窗口进程；读取失败可重试。
5. 表单导出绑定当前单号、修订、商品及范围。文件名包含这些身份；导出完整字段，不受表单字段搜索影响。导出未就绪或编码不属于本单时不可用。此文件不是加盟商确认单。
6. “导出此修订确认单”仍是原中心仓模板与原业务范围，不受历史商品搜索影响。“操作日志”只导出筛选后的操作过程，支持日期/操作类型/关键词；双击回溯精确修订。原文件下载只提供真正留存的文件，不拿当前路径内容冒充历史。

历史签发单保持旧数量和当时参数；例如截图商品旧单仍是 24 包，新计算才变成 0。旧作业模型版本不匹配时按原兼容流程只读/重算，不改写旧快照。旧 0.9.0 包保留。不同版本尽量不要同时对同一日常资料操作。

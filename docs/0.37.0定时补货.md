# 0.37.0 定时补货（候选试用）

用途：选定已有补货预案，按北京时间自动获取门店补货建议、更新所需仓商品资料、完成计算并保存独立结果。人员上班后进入原“核对与签发”页。不会自动签发、采购或确认付款。

## 怎么用

1. 在“参数设置”维护好预案门店、主从仓、预算及默认参数。预案负责门店名单和选定参数；预算和供货仓仍来自已保存的门店设置，缺项会明确拦下，不猜无限预算或默认仓。
2. 首页或“准备数据”点“定时补货”。新增安排，选择预案、开始时间、每周星期或单次日期。计算并发默认2店，可选1至4。
3. 点“检查运行条件”，按需在浏览器允许连接。核验只查询登录、门店和仓账号，不创建平台导出。通过后保存并启用；未通过也可仅保存。
4. 上班后首页可见任务状态，进入运行记录，再点“核对已完成门店”。计算结果进入原第四步，由人审核签发。原工作台未保存时仍走已有确认流程。

“今天立即执行一次”使用今天的业务日期，不改未来安排。运行中关闭详情窗口仍继续执行。

## 遇到问题

| 动作 | 作用 |
| --- | --- |
| 暂停本次 | 停止后续步骤；正在计算的门店完成并保存后暂停。平台提交不强杀 |
| 继续原任务 | 沿用本次冻结参数、原平台任务和成功文件，不新建同一份导出 |
| 重试所选失败门店 | 只安排选中未完成门店计算，成功结果保持 |
| 结束本次 | 本次不再自动推进，成功结果和原文件保留；未决平台任务仍需在原采集入口核对 |
| 暂停未来执行 | 不再按时间启动；当前任务保持 |
| 删除执行安排 | 移除未来安排，已有运行记录保留 |
| 删除已结束记录 | 删除该任务及其独立结果引用；不删除已采用草稿、签发或共享原件，无回收站 |

连接失效、未核验门店、资料异常、冲突、预算或路线缺失都会停在“需处理”。不会自动改参数、改单仓、用旧仓资料或重发状态不明的提交。成功部分可以先核对；失败不记为0元成功。

运行前预案/默认参数/准入依据变化，需要重新检查运行条件。已经开始的任务固定原依据，重试不会混用当前工作台的必卖清单或临时改量。

## 资料与数据边界

- 每个任务按预案门店顺序执行；每个所需仓获取一次，再冻结用于整批计算。不改聚水潭库存分配基准。
- 新仓资料先保留在本次任务。全部门店算完后，工作台空闲且没有载入资料或未保存变更时自动更新默认资料；否则等待空闲。也可明确点击“采用本任务仓资料为默认”。与采集前版本不符时拒绝覆盖，转人工核对，不影响本次计算结果。
- 自动结果不占用“每天一份草稿”，不自动覆盖已有草稿；人员打开后再按原流程保存，原覆盖确认保持。
- 与本日已有签发、较早自动任务、当前工作台相同门店重合时等待核对，不静默替代。
- 只有计算结果落库成功才标记“可核对”。原始输入、参数、必卖清单、关注清单、准入依据、仓资料和结果都保留。
- 原计算、预算、箱规、仓归属、准入、理由及导出字段规则保持。模型版本仍为0.3.4-rules。

## 运行条件和已知限制

- 这是软件内定时器。电脑必须开机、不休眠，补货助手保持运行；不会唤醒电脑或后台启动Windows服务。
- 开始时间超过60秒未能触发会记“错过”，不批量补跑旧日期。可以明确执行今天一次。
- 一个自动任务执行，其他任务排队。浏览器按已有组件操作权协调；人工计算需先暂停自动任务，避免两个计算池争用资源。
- 传输连接存活不等于网站登录仍有效。首次授权、登录失效、验证码可能需要人员在浏览器处理，不能保证完全无人值守。
- 自动结果跨天打开沿用原只读历史行为，不自动更改业务日。
- 浏览器已受理而状态不明时保留原任务关联，结束本地任务不等于撤销平台动作。应在原采集记录核对后继续。
- 没有实现参数修改后在同一运行内重算、Windows任务计划/唤醒、通知到微信。需要新依据时新建任务，历史结果保持。
- 旧版包保留。旧版不认识新增定时记录，不应用旧版执行包含定时记录的数据库清理；回退使用升级前备份或独立数据目录，不能以保留旧EXE推断新数据维护兼容。

## 结构与查找

```mermaid
flowchart LR
  UI[首页/定时补货] --> S[安排与运行记录]
  S --> R[后台编排]
  R --> AX[原翱象组件及共享连接]
  AX --> C[原聚水潭商品资料组件]
  C --> B[原文件检查与多店计算]
  B --> V[独立任务快照/逐店结果]
  V --> W[原工作台第四步]
  W --> H[人工核对/原签发与导出]
```

| 文件 | 内容 |
| --- | --- |
| `scheduled_replenishment.py` | 北京时间触发、唯一键、版本条件更新、独立快照、运行摘要分页、跨实例锁 |
| `scheduled_execution.py` | 已保存设置冻结、重合保护、原服务编排、按门店保存、恢复工作台 |
| `scheduled_platforms.py` | 原AX/JST连接租约、稳定原任务ID、回执验证、任务范围资料采用 |
| `scheduled_ui.py` | 执行安排/运行记录两页、核验、阶段进度、失败处理及接入原第四步 |
| `data_maintenance.py` / `storage_maintenance.py` | 新任务快照作为存活引用；复制转换兼容新增表 |

新增表：scheduled_arrangements、scheduled_runs、scheduled_values、scheduled_events；大对象复用现有校验分块。事务外读取和编码、事务内检查轮次并短提交。事件序号单调，迟到结果不得写入新轮次。

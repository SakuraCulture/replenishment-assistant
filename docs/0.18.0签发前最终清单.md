# 0.18.0 签发前最终清单

基于0.17.1（7360b03e8aab129f6ff2d28e43e8013f76d153a1），独立分支 `feat/preissue-adjustment-0.18.0`。模型规则仍为0.3.3-rules，仓归属0.5.0；不重跑模型或预算来覆盖人工决定。正式验收、构建提交和校验值见 `releases/0.18.0/rc1/交付报告.md`，源码测试不能代替EXE验收。

## 业务使用

1. 按原流程导入、检查并计算门店。在“查看与导出”点击“最终清单 / 改量”，选择门店；本店明细也有“编辑本店最终清单”。
2. 在同一张最终清单直接双击修改“拟签发数量”，选择原因。自动安排量只读。箱规24只能0、24、48……；上下键按箱规增减；非法键盘/粘贴输入显示错误，不会悄悄取整。
3. 多行操作先勾选，支持“每款N个出库单位”或统一库存数量。筛选外勾选数仍显示，任何非法行使该次批量填数不应用。
4. “核对修改与预算”展示整店金额变化、双零不补、超库存额度和有限超支等风险。明确确认后“应用最终数量”。应用到当前草稿，仍需保存草稿或确认签发。
5. 未核对完可“保留为待核对草稿”；会调用现有保存流程，同日覆盖仍需确认。这些门店不能签发。下次打开最终清单继续核对；“放弃所选门店全部调整”恢复自动结果，清除缺失商品旧调整后也须核对应用。
6. 通过原“确认签发并导出”归档、分仓导出；文件仍按河北/山东拆分，字段、顺序和命名保持0.17.1约定，同名签发文件完整写好后替换。

## 新品、活动和计划清单

“参数设置 → 管理铺货清单”可预先维护；最终清单内“按清单补足”直接使用。支持拖入多个Excel、下载最低模板、选择工作表及按表头映射。只要求商品编码；名称、目标持有量、备注、关注可选。

- **有货即可**：可用和在途均0，补1个最小出库单位；任一有货，不额外增加需求。
- **补足目标持有量**：扣除可用与在途，差额按箱规向上取整。最终量取当前拟签发量与差额需求的较大值，不重复相加。
- 可选双零、有在途无可用、已有可用三类参与范围；行目标优先于统一目标，全部行有目标时统一目标可留空。
- 默认保留人工修改（包括0）；覆盖须明确选择，且只覆盖本清单与所选库存状态中的商品。
- 缺本店记录、禁用/停采、地采、缺价、箱规或计算待核列出明细；可导出全部未应用明细，再明确使用有效范围或取消整次操作。缺数据不假定为0。
- 同商品目标或关注冲突要求回原表明确选择后重新导入。没有加入自动猜测或按文件先后取最后一条的逻辑。
- 清单可另存、保留历史版本、保存日期范围，原Excel按哈希留存。用于本次与保存长期清单分开；修改长期清单不会回改已签发订单。

仅本次实际参与清单、且有效月销0/可用0的商品归“本月新品”，在途和缺货天数不额外限制此分组。没有全局改动原新品识别。新增量理由分别为“新品补足”“计划补足”“活动补足”；人工增、减、0分别显示简短人工理由。只涉及分组但数量未变时保留原数量决策理由。

## 约束边界

- 所有数量使用库存单位，价格沿用当时基本售价。原模型字母字段、预测、保底、箱规、一箱例外、在途21天约束、原自动预算均保留。
- 人工0可覆盖双零最低持有，但需原因及缺货风险确认；不会后台补回。
- 增量超过当时普通库存额度时逐项确认。额度使用原BH/BN口径及实际cap_days，默认21，0为关闭；持有天数另按预测AN×AM展示，不混为同一口径。
- 整店预算覆盖两仓、筛选外和未编辑商品。0预算不安排正数量；不限预算单独表示。超过目标只允许有明确来源的一个末尾出库单位，整店≤105%，去掉该单位后≤目标；不累计领额度、不借用任意原有高价SKU作证明。
- 只修改明确选中的商品；减少金额不会自动分给其他商品。修改预算/参数后主动重算，旧调整进入待核对，不自动套用。
- 参数、来源、价格、箱规、路由或结果变化使旧依据失效；预览后的编辑清空风险确认。界面与签发服务均验证。其他窗口修改当天草稿后拒绝应用，要求重新读取核对。
- 多门店全部校验成功后才发布到作业；线程取消后等安全步骤结束，不把部分结果当全部成功。签发仍使用原事务与原取消边界。

## 保存与复查

每日草稿增加可选 `preissue_drafts`；结果增加可选 `preissue`，仅调整行增加 `_preissue`。保留自动结果字段的原值、存在性、顺序、原汇总/预算、前后量价、理由、时间、清单快照及风险确认依据。无登录身份不虚构操作人。

历史“当时的补货依据”可选“签发前调整”，按商品查看原自动量、最终量、原因、当时价格库存、清单来源和风险。原始附件中可找到清单文件。签发后生命周期“门店推荐数”使用实际签发量，不拿原模型AS冒充签发量；回传、付款、收货独立留存。

SQLite增加可选 `stocking_lists` 表，原文件复用 `source_files`，旧表和分块格式不迁移。0.18读取旧作业/归档无需补字段，不回写旧单。旧应用并不了解新人工覆盖的约束，**不要用旧EXE继续编辑或重新签发0.18生成的草稿**；旧版包保留供旧数据使用。备份/拷贝仍按现有整库路径，清单随库迁移。

## 代码索引与验证

```mermaid
flowchart LR
  A[原模型/例外/排除/预算] --> B[最终清单 preissue_ui]
  L[清单导入/版本 stocking_lists] --> B
  B --> C[preissue 数量/额度/整店预算核对]
  C --> D[草稿与正常单事务]
  D --> E[原分仓签发导出及生命周期]
  D --> F[签发前调整历史表单]
```

- `preissue.py`：纯校验/覆盖/恢复；不导入Qt，不调用分配或模型计算。
- `stocking_lists.py`：表头映射、精确编码、哈希、版本、原文件留存。
- `stocking_ui.py`：清单管理、拖拽映射、后台任务安全关闭。
- `preissue_ui.py`：步进编辑器、过滤、多店批量、风险确认、待核对草稿。
- `normal_orders.py` / `normal_delivery.py`：签发入口重验；其余业务事务与导出兼容。
- `tests/test_preissue*.py`、`tests/test_stocking_lists.py`：可移动合成测试。
- `tools/preissue_qa.py`、`tools/verify_flow_parallel.py`、`tools/verify_interaction_exports.py`：冻结真实数据与旧版对照。
- `tools/benchmark_preissue.py`：相同真实14244行，旧/新交替串行各三次；新增减量场景单列，不冒充旧业务结果。
- `tools/verify_preissue_exe.py`：实际程序导入、计算、最终改量、清单、草稿、签发、重启及历史复查。QA路径必须独立；数据文件不入Git。

性能和验收结论以发行报告为准；不宣称本次功能消除了历史全量读取、首次索引或Excel写出的等待。

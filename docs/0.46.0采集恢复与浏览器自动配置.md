# 0.46.0 采集恢复与浏览器自动配置

接续本地 `v0.45.2-rc1`，应用版本 0.46.0。计算模型、预算、箱规、默认参数、仓归属和业务存储格式均不变。删除实现保持 0.45.2。

## 异常中断后如何继续

截图中的 `TASK_NOT_FOUND` 表示历史列表暂时没有找到明确受理过的任务，不能据此认定平台没有受理。

- 同一批次某店暂时查不到任务，其余门店继续轮询和收取；完成后该店仍保留为中断状态。
- 中断后“停止后续取数”显示为“已停止取数”，避免把已经停止误认为无法停止。“继续原采集任务”保留原 run 和任务号。
- 采集组件退出后，刷新、继续、结束和新建动作会重新建立本地连接，先读取原持久记录，不盲目重发导出。
- 可以先“结束本次采集”，再选择门店获取。明确已受理、单一任务号且范围确定的任务会保留；新批次继续收取这些原任务。文件仍记录原采集日期和原查询依据。
- 受理不明、同一意图出现多个任务号、迁入任务未核清等状态仍须核对，不能用结束或删除绕过防重。保留未决平台任务的记录仍不能直接删除。

结束只影响本地采集记录，不取消平台已经受理的任务，不删除已采用文件、草稿、签发数据或下载原件。确认框会列出范围和保留任务数量；默认仍为取消。

## 聚水潭自动配置

在“聚水潭商品资料”选择山东仓或河北仓，点击“自动配置所选仓浏览器”。程序为该仓准备独立 Edge 配置、启动本地调试连接。首次在专用浏览器正常登录对应仓库账号后，程序自动核验公司及账号身份并保存，无需选择目录、勾选仓范围或再次保存。

两仓浏览器、账号和连接继续隔离。已有绑定的账号身份不允许被自动替换；同一身份不能同时绑定两仓。原绑定有未收取任务或待采用文件时，也不能迁移到新目录。相同绑定重新核验不会改变版本、使旧任务失效。取消登录等待不会保存未核验账号。

旧手动配置入口保留在“手动配置与启停（高级）”。自动配置使用新的独立目录，不复制 Cookie 或登录态，因此从旧手动配置迁移时可能需要重新登录一次。公司无法唯一识别、Edge 未安装或组织策略禁止调试时会明确报错，不猜测身份，不修改全局策略。登录、验证码和平台权限仍由用户正常完成。

本机已用两个全新 QA 浏览器配置验证自动启动与连接；只访问本机页面，未调用真实平台。账号核验、重复绑定、取消及配置冲突用隔离测试验证，不能代替两仓真实账号登录和导出的业务验收。

## 删除性能复核

0.45.2 已将大库有缓存的删除耗时中位数从 39.34 秒降至 24.53 秒，删除进程峰值 RSS 从 231.0 降至 214.0 MiB。这是上一轮同机交替对照结果，详见 [0.45.2 报告](../releases/0.45.2/rc1/交付报告.md)。

本轮在真实冻结历史的独立副本上加函数计时，首次无引用缓存删除一张父单：总计 238.40 秒，准备阶段 232.00 秒；旧格式引用解析 146.93 秒（28 次调用，10 次缓存缺失），内容块核验 69.16 秒（16,222 块）。峰值 RSS 232.02 MiB，进程读 2254.94 MiB、写 108.77 MiB，准备临时库 7.67 MiB。输入文件哈希不变，与 0.45.2 同样本的预览、结果及逐表业务签名一致。

删除少量订单仍需处理大量历史数据，原因包括所选门店属于完整的日作业快照，以及回收共享附件前必须核对其他存活历史的引用。只扫描选中订单会漏掉未选订单和共享原表的所有者，不能这样缩小范围。

还有优化空间，主要在旧 JSON 逐值处理、首次建立引用缓存的开销。进一步改为写入时维护引用或提前建缓存需要覆盖历史迁移和各保存入口；不能简单跳过首次完整核验。本轮未把这些尚未验证的方案混入修复，没有改变删除范围、回收时机、事务原子性、secure_delete 或存储格式。

本次是单轮带计时诊断，不能与上一轮中位数相减宣称进一步提速。Windows 进程读写含系统缓存，RSS 为删除工作进程采样峰值；不是物理磁盘占用率或整机内存，尚未在低配业务电脑实测。

验收、构建提交及已知限制见 [0.46.0 交付报告](../releases/0.46.0/rc1/交付报告.md)。旧 0.45.0、0.45.1、0.45.2 交付保留，仅本地提交和打包，不推送、不合并。

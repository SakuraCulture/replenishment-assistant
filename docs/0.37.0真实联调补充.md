## 定位和修复

“没有看到连接提示”对应的实际失败不是授权弹窗，而是商品采集组件等待主应用提供查询前库存依据：`WAIT_HOST`，最终 `HOST_TIMEOUT`。旧定时入口持续轮询状态，没有执行 `sync.provide_observation`；显示仍停在此前的连接阶段。

只修改 `src/scheduled_platforms.py`：

- 复用人工商品同步入口已有的 `catalog_sync.stock_observation`，按仓读取查询依据。
- 回答当前原批次、原商品任务的 observation token；同一 token 在本轮只回答一次，恢复仍沿用原 operation/batch。
- 读取依据前后检查取消，取消后不继续提交依据。
- 等待该交接时显示“准备仓查询依据；尚未提交商品导出”，不以旧 CONNECTING 文案覆盖当前阶段。

没有调整模型、预算、箱规、准入、仓归属、库存分配或商品资料版本规则。查询依据是原协议的只读交接，不建立或改写聚水潭分配库存基准。

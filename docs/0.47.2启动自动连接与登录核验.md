# 0.47.2 启动自动连接与登录核验

正常打开应用后立即在后台尝试接通翱象和聚水潭两仓，并核验网站登录。手动连接留作自动检查未完成后的调试入口，不再是每天使用前的必做步骤。主窗口可继续使用，不等连接完成才显示。

## 日常使用

完整解压新运行包，正常退出旧版后运行新版补货助手.exe。已有三套账号和浏览器绑定继续复用，不需要重新选浏览器目录。底部会分别显示翱象、山东仓、河北仓的检查结果。

| 显示 | 含义及处理 |
| --- | --- |
| 连接核验中 | 正在自动打开或复用浏览器、检查登录，稍等即可 |
| 登录已核验 | 最近一次检查的账号身份与绑定一致；业务仍会在执行前核验范围 |
| 需要登录 | 在对应浏览器正常登录，程序每15秒复核一次，最长等待5分钟；之后可点重新检查 |
| 账号不符 | 登录了与原绑定不同的账号；切回原账号，再重新检查，不自动替换原绑定 |
| 等待原操作 | 原任务正在使用连接，先完成原任务，稍后自动检查 |
| 需要配置 / 连接异常 | 点“连接检查 / 修复”查看本平台原因与下一步；其他平台可独立使用 |

“连接检查 / 修复”提供单个平台重新检查及原配置入口。浏览器连接仍存活不等于登录有效；悬停可见最近核验时间。网站登录过期、验证码及浏览器自身授权仍由用户正常完成，程序不会替用户输入密码或绕过授权。

## 自动配置与业务边界

- 聚水潭已有绑定优先复用，包括之前手动指定的专用浏览器目录；不把旧目录自动迁移到新目录，不改变账号、绑定版本或已停用设置。尚无绑定时自动准备按仓隔离的专用目录，账号核验通过后保存；两仓不能使用同一身份。
- 翱象复用已保存的商家、浏览器和门店绑定，只检查浏览器与商家登录，不重新查询所有门店。首次从未建立商家与门店绑定时，仍须在“翱象配置”完成业务范围确认；启动检查不会猜账号或门店归属。
- 已断开的翱象浏览器不会因上次成功记录继续被当作可复用连接。需要登录时保留登录页；自动复核使用原连接，不不断新开页面。
- 启动不创建导出、采购，不更新两仓业务资料，不恢复或重传平台任务，也不打开缺货率数据库或加载其大表。只有连接检查会在启动时自动执行。
- 原任务先取得操作权时，自动检查等待；用户主动进入业务时，检查安全让行。正常关闭应用会先停止检查、交还操作权，再退出，不强杀正在提交的任务，不关闭用户整个浏览器。
- 后续浏览器或网络断开可在修复入口重新检查。这里的“自动”指启动和上述有限登录复核，不承诺无限后台重连或自动登录网站。

原缺货率批量导出与重复表头修复继续保留，见[0.47.1说明](0.47.1缺货率翱象并行导出.md)。本轮实际验证、固定构建和限制见[交付报告](../releases/0.47.2/rc1/交付报告.md)。

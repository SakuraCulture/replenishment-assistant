# 0.9.0 业务日志、原文件与门店回传

本轮基线为 `e45b9d08cddbced1bf8566281987431534bbf5b7`（0.8.0），独立分支 `fix/business-history-0.9.0`。应用升级为0.9.0，模型仍为0.3.1-rules，仓归属仍为0.5.0，原快照格式仍为2、逻辑作业格式仍为1。保留旧包；仅本地提交和独立打包，不合并、不推送。

## 三步功能

1. 历史业务表单：历史正常单双击进入，原签发明细只读。点击“当时参数 / 销量库存 / 商品资料”，切换单据概况、当时参数、商品建议与销量库存、当时商品资料快照、商品完整计算依据。商品按精确编码查询。数值取自该签发修订及其关联的完整作业，不读取当前方案替换历史。空值显示“未提供”，空字符串显示“空文本”，0保留为0。可下载当前完整表单Excel、当时原文件。操作日志为可查询的业务表格，导出当前查询的全部记录。
2. 导入统一入口：补货建议、分仓商品资料、旧版混合资料、必卖清单、新品关注清单、门店回传都支持拖拽和最低标准模板。分仓、必卖和新品按钮先打开可拖入的导入窗口；补货建议及混合资料保留原卡片直接拖入。先读取校验再沿用对应核对步骤。模板第1张表为空数据区，第2张表为填写说明；必需和可选表头区分颜色，编码列为文本。仓库仍在入口选，不由文件名猜测。
3. 加盟商回传：历史页“批量导入加盟商回传”，或单据内“门店确认 / 导入回传”。可选择多个文件，核对各单差异后一次保存，失败整批回滚。签发建议与回传数分别保存、展示和导出，可查看每版回传的文件/工作表/行号、备注并下载原文件。当前不接实际下单、实际收货和任意历史资料的模糊关联。

## 回传规则与边界

- 最低表头：补货单号、商品编码、门店确认数量。商品名称、备注可选。原确认单的Q列“补货数量”也可直接作为回传量，不改原22列模板。
- 原导出Excel自带单号及修订文档属性，按其精确关联；属性缺失的文件必须人工明确选择签发修订，默认不选择。单号未知不能按名称或时间猜测。同一单号的不同修订分开导入。
- 仅接受该修订中心仓确认单中已有的商品；未知/地采商品明确报错，不进入计算结果。完全重复的同商品同数量合并并保留来源行；冲突数量阻止保存。
- 数量为库存单位。非负数字有效；0表示明确不补，空白表示未确认且不清除上次有效回传。当前不接收数量公式、负数、错误文本或无法可靠识别的长数值编码。
- 回传不强制箱规规整，也不重新分配预算。非箱规倍数、按原基本售价估算高于签发金额均提示，保留门店实填数量。缺价不编造金额，未计价项保存在回传记录中。
- 同一内容再次导入不新增回传版本；数量发生变化才新增。每版保留输入文件SHA256和逐行出处。纯备注变化、纯空白回传不产生数量版本，不能用它清除已有确认值。
- “已确认”表示原签发正数量商品都有门店回传；有遗漏为“部分确认”。0数量新品候选不是必须确认项。原单没有正数量商品时显示“暂无待确认项”，不冒充门店已确认。
- 预览后原签发当前修订或回传版本被另一窗口更新，提交拒绝并要求重新核对。V001回传不自动套用V002；同日签发修订仍按原流程确认覆盖。
- 回传数量估算金额只用于对照，不等于实际采购订单金额，不改原签发、预算结果或日常工作区。

## 原文件与历史兼容

新导入通过原校验后，在后台将源文件字节按SHA256存入同一SQLite的`source_files`，相同文件只保留一份。模型输入、仓快照JSON和签发业务指纹不增加忽略字段、不加二进制附件。原有快照中的源哈希用于精确查找原文件，原始表格字段可按当时的工作表/行号展开。

0.8.0未留存的原Excel不能还原成完整原文件。此时显示当时已保存的选取字段，标注“历史原文件未留存”，不从同路径的现文件补填。新增附件与回传表随SQLite一致性备份和旧格式/新格式副本转换完整保留；旧版软件不会显示新回传功能。原签发快照不回写、不重新计算。

新增表只有`source_files`和`merchant_feedback`。后者主键为签发内部ID、签发修订、回传版本；通过`normal_events`记录独立回传动作。原作业、正常单及修订数据结构保持不变。未清理历史附件；数据量会随不同原文件增长。

## 三项0.8.0问题的修复

### 取消与提交边界

取消传入`normal_delivery → normal_orders.confirm`，准备/编码/备份进度点、进入事务前、等待写锁重试、取得锁、写块、逐门店写入及最后提交前检查。等待写锁使用100ms SQLite等待窗口并在重试间检查取消，总等待上限保持10秒。提交前取消通过事务上下文整体回滚，不新增/覆盖草稿、正常单、修订或业务事件。

最后一次取消检查之后，发出“正在最终提交，暂不可取消”信号并调用SQLite COMMIT，这段是不可中断边界；不强杀写入进程。成功后恢复后续导出的取消能力。此时取消只停止未完成Excel，已签发修订保留，提示已完成/未完成文件，可从历史页按原修订重试。多店仍同一归档事务。

取消可能留下升级前安全备份、空物理表/存储元数据、独立导入阶段留存的原文件；不能以“业务记录未提交”宣称数据库字节完全未变。旧安全备份机制保留。

### 批量覆盖差异

后台复用`normal_orders.revision_diff`生成批量核对结果。门店按用户选序，商品按既有行序。显示原/新修订、总金额、增加/移除/执行数量或金额变化的商品（编码、名称、原值、新值），以及参数、来源、首铺选择、关注清单和其他商品字段差异。预览最多200条，明确截断，可导出完整差异Excel。默认取消。提交仍以确切已预览修订CAS核对，过期必须重新确认。

### 决策理由

仅改导出理由，不改模型字段。用已保存的AR、BI、BP、BQ、BR、BU、AS判断取消最低恢复后可达到的常规数量，只有最终建议确实被抬高才归因为恢复规则；BQ>0或AS==BQ都不是充分条件。保留预算限制、首铺、一箱恢复优先解释，再解释极端/零销/断货/最低持有与常规动销。缺少必要旧字段时给“补货建议”等保守描述，不回填确定原因、不重跑模型。

允许差异：取消是否提交、签发确认预览、加盟商Excel V列“决策理由”的文本、新增业务表单/回传表/附件/回传事件。未新增模型归因字段。原计算输入、中间值、建议/候选/执行量及金额、所有顺序和原导出其他内容必须严格一致。仍保留N>30且J>0时有效缺货天数为0而原N不变；不实施无销量统一首铺或8.5天目标。

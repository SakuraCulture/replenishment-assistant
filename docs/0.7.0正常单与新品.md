# 0.7.0 首页、正常单和新品

本轮范围对应统一方案 A/B/C。历史外部确认、下单、收货资料的导入关联仍属于后续 D 阶段。发行验收以 `releases/0.7.0/<构建编号>` 为准，开发中的检查不当作发行通过。

## 操作

1. 首页进入工作页，沿用准备数据、门店与参数、计算、查看四步。首页和历史页切换不销毁工作区。首页的“继续已保存的今日草稿”恢复当时快照。
2. 有效计算后，在本店结果或门店汇总点“选择本店新品 / 预览预算”。月销、可用、在途为有效数字0，缺货天数为0或空白才进入候选，默认不选。可按本月/往期、必卖、已选、未获预算、仓、分类及商品搜索；隐藏不清空选择。批量操作针对当前筛选，清空全店单独确认。
3. 首铺数量必须为最小出库单位倍数。预览列出候选及执行数量、金额和最低持有缺口变化，点击“应用到本店草稿”才生效。取消维持原选择和分配。
4. “保存草稿”只保存作业。“确认所选门店并自动归档”只处理门店页勾选且有效完成的门店，同时保存完整当前草稿，弹窗展示两者覆盖影响，默认取消。
5. 第一次每店生成 `BH-日期-门店编码-ZC / V001`。同日重算不改归档；再次确认业务变化才成为同号 V002。完全相同结果不增加修订。其他店未被选中或从草稿消失，不删除其正常单。历史旧修订只用于审计，首页金额按当前修订统计。
6. 准备数据页另行“导入新品明细 / 关注字段”，选择月份、工作表、商品编码列和关注列，预览确认后保存复用。没有清单须明确选择“本月无关注新品”，不能把未导入当作无关注。关注不等于必卖或自动选品。清单随草稿和签发修订冻结，换清单需重新确认，即使数量没变也产生新修订。
7. “导出加盟商确认单（带号）”从已确认快照导出当前门店，每文件一家门店。文件名 `YYYY-MM-DD门店名称（精简版）(修订整数).xlsx`；三张表顺序为“往期新品”“本月新品”“中心仓动销补货清单”，前20列及宋体11、默认列宽9/行高13.5、General格式与用户模板一致。新品全部导出：候选中关注的进本月，其余进往期；未选择、预算未安排或不可选的数量0。非新品的原模型自动安排进入中心仓动销清单。三表商品互不重复，罕见日/周销量与月销矛盾的新品候选仍在新品表保留原自动执行数，禁止追加首铺。Q列为最终执行数，可供门店修改；隐藏U:AB保留单号、修订、明细ID、原签发数、识别/分组依据、关注版本和安排说明，A1批注与打印页眉也带号。P列仍取基本售价，不执行模板里的旧新品数量公式，不伪造缺价或黑名单“通过”。
8. 正式导出不受商品筛选影响。原全量/当前筛选/批次导出仍在，明确标为内部明细。目标文件已存在一律拒绝覆盖；可另选文件名重导同修订。导出失败不撤销成功归档。
9. 历史归档按日期、门店、单号、商品查询；双击查看当前/旧修订、逐商品明细和完整审计。操作日志可查询并导出JSON，当前记录内部签发、同日修订和带号导出，不等同后续采购/收货流水。

## 边界

- 新品依据本店原输入 J/月销、K/可用、L/在途为有效数字0；按2026-10-30用户确认，N/原缺货天数为0或空白均可识别。原始N空白仍保留，选品审计注明按0识别；J/K/L的空值、N的布尔值/负数/待核文本不按0。不用模型Q新品或修正BA替代。日/周销量矛盾、禁用、停采、地采、缺价或其他待核不可选。缺箱规沿用1，并提示来源。
- AS/BV 和全部模型中间值保留。新品独立 `_new_requested`、组合 `_candidate_*`；有预算使用原 allocation，无预算由显式 `_execution_*` 取候选。必卖新品优先于普通动销，同组仍使用原排序。未选新品逐字段兼容旧版本。
- 重新计算已有新品选择的门店，先明确提示并默认取消；确认重算后需重新选新品。刷新输入同样重新建立工作结果。新品选择只属于本次作业，保存恢复可复用，不传播到其他门店、下一天或门店长期默认。
- 过期、计算中、失败、只读历史不允许签发。跨天不能签发旧业务日期，必须新建今日作业。0金额有效结果可以归档，缺价/待核不伪装零成本可购商品。
- 当前应用仍用既有本机 settings 文件夹。首次增加归档表前，用SQLite backup生成 `workbench.before-normal-orders.<UUID>.sqlite3`。现有JSON及schema1作业不迁移，增加可选新品基础结果/关注清单快照及独立表。0.7可读取旧草稿；含新品的0.7草稿应在0.7继续，旧程序不能解释新增新品执行字段，不应交替编辑同一天草稿。
- 不处理加盟商回传、不生成实际下单、不预占仓库存、不回写Excel、不自动发送。原0.6.2交付包保留；不自动推送或合并Git。

## 代码索引及数据链

```mermaid
flowchart LR
  App[app启动] --> Shell[ApplicationWindow首页/工作/历史]
  Shell --> WB[原Workbench四步工作区]
  WB --> Engine[原engine/一箱例外/排除]
  Engine --> Base[原预算结果]
  Base --> NP[new_products显式候选]
  NP --> Budget[原allocation再次分配]
  Budget --> Draft[当前门店草稿]
  Draft --> Confirm[确认弹窗与修订检查]
  Confirm --> DB[正常单+不可变修订+完整草稿事务]
  Focus[独立新品明细关注清单] --> Draft
  Focus --> Confirm
  DB --> Export[normal_exports按冻结修订导出]
  DB --> History[查询/审计/日志]
```

| 文件 | 职责 |
|---|---|
| `application_window.py` | 保持Workbench实例的顶层导航、归档确认、只读历史及新选择编排 |
| `new_product_ui.py` | 商品资格、数量、筛选及当前筛选批量选择 |
| `new_product_focus.py`、`new_product_focus_ui.py` | 独立新品关注导入、字段映射、校验、按月复用；不参与计算规则 |
| `new_products.py` | 缺货空白按0的四项识别、候选资格、组合预算、数量差异；不修改原算法 |
| `normal_orders.py` | 每日每店唯一正常单、CAS、SQLite事务、修订、完整来源工作快照与事件 |
| `normal_exports.py` | 冻结签发建议、逐店分组Excel、安全文本、拒绝覆盖 |
| `result_semantics.py` | 新增无预算新品执行口径；未选新品原字段不变 |
| `verify_normal.py`、`normal_smoke.py` | 独立合成业务验收与实际Qt窗口/EXE验收 |
| `tools/normal_equivalence.py` | 固定a417622源对照，使用独立进程捕获，严格业务值/类型/顺序/Excel比较 |

归档主键 `(day,store,normal_model)`；单号和内部ID固定；修订以整数递增。明细ID为订单UUID与精确商品编码确定的UUID5，排序不改变身份。旧修订保留原结果、配置、来源和对应完整作业修订；单独保存草稿不会删除该签发依据。

签发幂等比较只从结果根节点排除 `created`、`task`、`version`（时间/进程/构建诊断）；原快照仍完整保存；已设置关注清单的版本也纳入签发指纹，旧无该字段的快照仍可读取，但有新品且未设置分组的旧试用签发不可猜测分组重导。等价验证使用另一套更严格的叶级白名单，不能用签发指纹代替逐字段验收。

先固定基线源与输入哈希到独立qa目录；基线源码为a417622，运行代码等同已交付0.6.2，含后来批准的设计文档。

## 用户模板与保真边界（2026-10-30补充）

模板 `2026-10-27优团生活·精品超市（郓城店）（精简版）(1).xlsx` 的SHA256为 `1cc7a8e9f99fec764d17286c6b0a028a7ea79416add7178a64e91512f311f7c6`。只提取格式契约，不把模板商品或旧公式当作新模型输入。原件不修改，不随Git上传。

前20列映射：A:N取原输入A:N；O取最小出库单位BD（缺箱规1，待核不补造）；P取V基本售价；Q取预算/排除后的最终执行数；R取AT黑名单信息（当前接口未提供则保留“未提供”，不虚构通过）；S取AU需求归属仓；T取AV商品等级。禁用/停采/地采/缺价等新品仍列入候选表但不追加首铺，安排说明保留在隐藏AB列及零数量批注中。缺货空白N仍留空；新品的零数量是未安排，不是加盟商已确认取消。

关注列支持关注/已关注/是/1/true/√/✓，未关注支持空白/未关注/不关注/否/0/false；其他值报错。首行须为表头；商品编码精确匹配，文本前导零和长编码保留，超过15位数值编码拒绝。同SKU同状态合并源行、状态冲突拒绝，导入前后校验文件哈希。按月匹配业务日期，跨月签发先换清单或明确无关注。当前只有一份默认关注清单，历史月份在每日作业和正常单修订中保存；本阶段没有关注库的跨月自动管理。

正式导出范围不受界面临时筛选影响。模板的原默认窄列会截断长文本，按用户要求保留；Excel中可自行拉宽。隐藏追溯列不是加密，供回溯关联，后续外部单据回传关联仍未实现。

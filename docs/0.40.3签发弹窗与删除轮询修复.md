# 0.40.3 签发弹窗与删除轮询修复

基线为 0.40.2 证据提交 `49dbeb80c72cf3f73023688f326a682376c7b7d5`。独立分支 `fix/gui-maintenance-callbacks-0.40.3`；旧发行包保留，不推送、不合并。

## 已定位的问题

1. 签发导出先加入差异表，再设置说明、按钮。QMessageBox 会重建内部 QGridLayout，而 `readable_ui.review_table` 的延迟回调仍持有旧布局，触发截图中的 `Internal C++ object ... QGridLayout already deleted`。错误可在不创建任何真实订单的情况下复现。
2. 删除持有 SQLite 排他锁时，`scheduled_ui.Manager.poll` 每两秒在界面线程调用 `repo.exists()`，锁异常没有进入后台失败处理，可能冒出“操作未完成”。同样能在隔离数据库复现。用户当时日志为空，不能据此断言真实删除失败，也不能把所有锁冲突都归结为这一处。

## 修改范围

- 公共差异表在窗口显示或布局被重建后，获取当时的有效布局并重新挂载。观察器随弹窗销毁，不保留内部布局，也不形成对弹窗的反向引用循环。保留原确认角色、默认取消、Esc 取消、搜索及“导出完整差异后继续核对”。
- 定时检查全部放在后台线程；保存、签发和数据维护期间暂缓轮询。数据库暂时忙时显示等待，下次轮询重查，不弹出界面未捕获异常，不重放签发或删除。
- 定时执行/资料采用尚未安全结束时，删除入口明确等待，避免新的维护操作与它重叠。
- 强制配置带时间的应用日志处理器，避免已有日志处理器使文件日志配置失效。

不改变模型、预算、箱规、默认参数、签发/删除事务、订单范围、导出字段与文件内容、平台订单或存储格式。没有增加自动删除、自动重签和强杀进程。

## 验证与复跑

使用项目 `.venv/Scripts/python.exe`。所有验收只用独立 QA 资料；界面脚本检查环境目录，文件选择器只返回该目录。测试用合成两店双仓，禁止套用到用户资料。

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -p test_gui_maintenance_callbacks.py -v
.venv/Scripts/python.exe -m unittest discover -s tests -v
.venv/Scripts/python.exe tools/reproduce_gui_callbacks.py --source .
.venv/Scripts/python.exe tools/verify_gui_maintenance.py --fixture qa/deletion_0321/inputs --output qa/新验收目录/source
.venv/Scripts/python.exe tools/verify_gui_maintenance.py --exe '交付_0.40.3_rc1/补货助手/补货助手.exe' --fixture qa/deletion_0321/inputs --output qa/新验收目录/gui-exe
.venv/Scripts/python.exe tools/verify_deletion_workflows.py exe --exe '交付_0.40.3_rc1/补货助手/补货助手.exe' --fixture qa/deletion_0321/inputs --output qa/新验收目录/deletion-exe
.venv/Scripts/python.exe tools/verify_deletion_workflows.py compare --baseline 49dbeb8 --fixture qa/governance_032 --output qa/新验收目录/comparison
```

`reproduce_gui_callbacks.py --source <固定基线目录>` 可独立重现旧版两种异常。真实样本与合成 Excel 为本机 QA 输入，不随源码分发；定向八项单元测试自行生成临时数据，可脱离业务文件运行。完整输入哈希、对照范围、运行结果和实际 EXE 证据见本轮发行记录；不借用旧报告作为新版通过依据。

实际 UI 验收包括：取消签发无归档 → 再次进入 → 导出完整差异 → 原弹窗再次核对 → 确认签发 → 两店四份文件；强制数据库独占时维护避让、界面心跳、释放后恢复；另外重跑实际删除取消/重试、未选店保护。

## 使用边界

遇到旧版弹窗，不要只凭弹窗判断是否已经签发或删除。先查看订单跟踪及导出文件；已经签发的按原签发重导。新包修复界面和轮询，不修改此前实际记录，也没有替用户执行重试。

其他程序长期持锁仍可能使真正的业务写操作等待或失败，本次没有吞掉这些错误；定时任务也不会被强杀。没有做真实大库耗时承诺、新电脑验证或平台采购操作。最终交付状态以 `releases/0.40.3/rc1/交付报告.md` 为准。

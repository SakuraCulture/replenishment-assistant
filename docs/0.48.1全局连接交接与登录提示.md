# 0.48.1 全局连接交接与登录提示

用户反馈：启动完成连接后，获取翱象补货建议又出现 Edge 调试许可，随后提示未登录。2026-11-08 的本机原任务只读记录显示 `WAIT_LOGIN / 未取得有效翱象身份`，对应的是页面或身份响应获取失败的兜底提示，不能据此确认平台明确返回登录失效。

## 全局共享边界

同一资料环境、同一应用实例内，翱象使用 `aoxiang_workflows.session` 及已保存的浏览器/商家绑定；补货建议、缺货率、定时补货、采购与收货查询复用它。聚水潭使用 `catalog_sessions.session`，山东仓和河北仓分别保持各自账号及浏览器隔离。业务模块只取得操作权，不另建连接配置。分析原件、门店供货设置快照与计算数据依然独立，不因连接共享而互相覆盖。

用户应从统一的“连接检查 / 修复”处理连接问题。业务执行前仍检查账号与本次对象；连接共享不等于跳过登录、商家或订单完整性验证。浏览器关闭、真正断线、账号切换或软件重新启动后，仍可能需要重新建立连接及 Edge 许可；本版不绕过浏览器安全授权。

## 修正

- 前台采集或缺货率向启动检查请求交接时，启动检查完成当前有超时上限的只读步骤，再交接原连接；不因业务抢占直接取消并关闭浏览器。显式退出/取消仍保持安全停止。
- 启动身份查询失败但传输仍存活时，保留原浏览器工作进程。释放操作权时交给共享连接池，标记身份尚未核验；下一业务在原工作进程复核，不把失败当作已登录，也不直接重新打开第二个调试连接。
- 已保存配置发生变化、账号不符、传输断开时不复用错误会话。未知提交仍不能重放，采购上传和导出创建没有增加自动重试。
- 页面/身份查询未完成使用 `IDENTITY_CHECK_FAILED`，说明尚不能判断登录失效；原明确 `WAIT_LOGIN` 和账号不符继续拦截。
- 浏览器工作进程回传本次身份核验状态，底部状态同步业务失败，避免持续显示上次的“登录已核验”。

## 验证与限制

新增隔离测试覆盖业务交接不取消原检查、显式关闭仍取消、身份失败后复用同一工作进程且必须重新核验、页面失败与真实登录错误区分，以及业务失败清除过期绿色状态。实际 EXE 启动走查采用封闭模拟传输，不会登录真实平台或创建导出任务。

原故障的身份误报路径已由日志和源码对应确认；原先二次许可具体由哪一次取消/断线触发，旧日志不足以唯一判定。本版修复已复现的交接缺陷，不宣称涵盖所有浏览器断线原因。

业务流程版手册继续随包提供；正文及截图标注的 0.48.0 操作仍适用于本次连接修复版，不将旧截图改写为 0.48.1 平台实测。最终构建、测试数量及交付哈希见本版发行报告。

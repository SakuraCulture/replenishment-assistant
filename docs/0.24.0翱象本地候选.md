# 0.24.0 翱象接入本地候选

应用0.24.0，模型0.3.3-rules，仓归属0.5.1，业务存储格式2。旧0.23.0保留。当前按用户要求暂缓真实平台联调；本文件不是平台验收通过声明，最终实际EXE证据以发行记录为准。

## 三个业务入口

1. **补货出单 → 准备数据 → 获取翱象补货建议**。先在“翱象连接与门店配置”导入门店目录、核验账号和门店并保存。选择已核验门店，获取完成后明确采用成功文件，进入原检查、计算与核对。原手动输入入口保留。
2. **付款核对 → 打开翱象采购**。采用已经确认的付款数量及金额，获取并核验最新采购模板，生成预览后另行确认上传。建单保留待提交，后续提交由业务在翱象操作。也可勾选已确认付款仓单，批量生成预览并选择上传。
3. **收货核对 → 查看 / 同步翱象收货**。只处理已核验绑定的采购单。立即同步与周期计划分别操作；周期默认关闭，只在应用运行时执行。平台状态“已完成”停止常规监控，完整原件校验通过才保存正式实收。

各窗口提供原任务状态、停止后续动作和安全关闭。停止不撤销平台已受理任务，上传结果未知不重传。已有采购单可用准确单号、制单日及原因核对原生主子单，再明确确认本地关联；不能凭一个单号或相同总额跳过逐商品核对。

山东仓供应商默认 `ZXC2025`，河北仓默认 `2078246`。商品编码与基础单位按已确认的一一对应关系使用，不另做箱规换算。付款金额为原事实，不用模型价替代。聚水潭相关作业仍使用现有人工方式。

采购和收货窗口在打开或刷新时，后台核对当时采购依据与当前付款、门店绑定及供应商设置，明确显示“依据一致”或“采购依据待核”。付款已更新、文件缺失、依据被修改或配置变化不能显示为有效；未上传的过期预览禁用上传。原采购号、数量金额和原观察记录保留，不自动改量、取消或重建。提示是最近一次核对结果，上传/关联确认/实收保存仍在执行前进行原有严格校验。
